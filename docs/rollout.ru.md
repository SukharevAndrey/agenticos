# Разверните и эксплуатируйте AgenticOS { #deploy-and-operate-agenticos }

AgenticOS — приложение, которое эксплуатирует ваша организация. Начните с [одной
проверяемой задачи](howto/first-document-agent.md), затем решите, кто сопровождает
экземпляр и кто отвечает за работу агента.

## Кто за что отвечает { #who-maintains-what }

| Область | Ответственность за эксплуатацию |
| --- | --- |
| Хостинг и обновления | Развёртывание сервисов, контроль мощности, обзор выпусков и планирование обновлений |
| Резервное копирование и восстановление | Резервные копии баз данных и нужных данных рабочих пространств, защита ключей и проверка восстановления |
| Источники и поведение | Поддержание актуальности документов, инструкций, навыков и опубликованных версий |
| Доступ и секреты | Ведение учётных записей, выданных доступов к ресурсам, учётных данных провайдеров и их ротация |
| Сбои и согласования | Разбор запусков, маршрутизация инцидентов и назначение уполномоченных, принимающих решения |
| Внешние сервисы | Проверка, куда уходят данные: модель, парсер, эмбеддинги, инструменты, песочница, каналы и трассировка |

Подробности реализации — в разделах [установка](install.md),
[развёртывание](deployment.md), [секреты](secrets.md), [разрешения](permissions.md) и
[безопасность](security.md). Храните доказательства восстановления и контакты
эксплуатации вместе со своим экземпляром. Опубликованный агент эту работу не заменяет.

## Расходы и варианты поставки { #costs-and-delivery-options }

Учитывайте использование моделей, инфраструктуру, внешние сервисы, внедрение и постоянное
время эксплуатации. Записанные расходы запусков — лишь часть этой суммы. Проверьте
[лицензии проекта и компонентов](licenses.md) для своего экземпляра.

Вы можете эксплуатировать AgenticOS сами. Vstorm может отдельно помочь с развёртыванием в
инфраструктуре клиента, документацией, созданием процессов и доработкой под заказ.
Постоянное обслуживание требует согласованного объёма и обязанностей. Установка проекта с
открытым исходным кодом не даёт ни стандартной цены, ни включённой поддержки, ни SLA.

За помощью с внедрением обращайтесь в [Vstorm](https://vstorm.co/) или к Kacper, указав
задачу, типы источников, ограничения инфраструктуры и ответственного за эксплуатацию. Для
первого разговора закрытые документы не нужны.

## Границы, которые нужно проверить { #boundaries-to-verify }

Самостоятельное размещение не означает работу без сети. Локальная чат-модель меняет один
путь данных; разбор файлов, эмбеддинги, инструменты, размещённые песочницы, каналы и
трассировка по-прежнему могут обращаться к внешним сервисам. Изучите [описание потоков
данных](security.md).

Охват согласований зависит от выбранной возможности и конфигурации. Проверки бюджета
используют записанные расходы до вызова модели и не гарантируют нулевого перерасхода.
Выданные доступы к коллекциям не означают наследования списков доступа к документам каждой
исходной системы. Проверьте на реальных учётных записях и задаче, используя
[управление](governance.md) и [доступ к коллекциям](file-processing.md).

## Оцените пилот { #evaluate-the-pilot }

Зафиксируйте нынешний способ выполнения задачи, вопросы приёмки, версию источника, модель,
инструменты и фактические результаты. Включите недостающую информацию, сбойные запуски,
трудозатраты на проверку и использование. Измените один факт в источнике и повторите,
прежде чем расширять объём.

Используйте [сравнения](about/comparison.md) при выборе платформы и [помощь](help.md) для
воспроизводимых проблем. Пилот может обосновать расширение, исправление или остановку
применения для этой задачи; он не является обещанным бизнес-результатом.
