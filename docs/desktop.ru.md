# Приложение для компьютера { #the-desktop-app }

Вход через OAuth в самом приложении использует S256 PKCE. Приложение хранит закрытый верификатор, а обратный вызов несёт только его открытую часть (challenge). Верификатор уходит в теле запроса обмена, никогда в URL. Выход из учётной записи очищает встроенные предпросмотры уведомлений на телефоне.

Отвязка компьютера, выход из учётной записи или смена сервера очищают одобренные папки, локальные сервисы и согласия на весь компьютер и на экран. При сопряжении приложение сначала показывает учётную запись и только потом использует одноразовый код. Общие разрешения для папок автоматизаций переживают истечение сеанса и повторное сопряжение с той же подтверждённой учётной записью и тем же сервером. Они остаются неактивными, пока эта личность не подтверждена снова; явная отвязка, выход или смена сервера либо учётной записи удаляет их.

Опубликованный агент-исполнитель, которому нужен этот компьютер, может попросить доступ через тот же чат, даже если его основной агент работает в облаке. Согласие принадлежит основному агенту, который начинает запуск. Локальные агенты-исполнители для работы с кодом запрашивают полный доступ; вложенные агенты-исполнители используют это одобренное рабочее пространство устройства, не делясь им с посторонними облачными агентами-исполнителями. Отмена команды или истечение её тайм-аута завершает и её дочерние процессы.

AgenticOS работает в браузере, и большинство людей пользуются им именно так. Приложение
для компьютера — для тех, кому нужно больше возможностей на собственной машине:
консоль в отдельном окне, «Быстрый вопрос» откуда угодно, Blobby на рабочем столе и —
то, чего браузер не умеет, — собственные агенты, работающие в папке на этом
компьютере и на его экране. Платформе оно не нужно.

> **Скриншот будет добавлен — приложение для компьютера, Blobby и «Быстрый вопрос».**

Приложение внутри окна — та же консоль на Next.js, которую сервер уже отдаёт; она
загружается с сервера и потому несёт тот же вход, те же разрешения и те же проверки
организации, что и вкладка браузера. Это оболочка на [Tauri](https://tauri.app) в `desktop/`.

!!! note "Это оболочка, а не сборка фронтенда"

    `frontend/` — приложение на Next.js с серверной половиной: обработчики маршрутов,
    проксирующие запросы к бэкенду, cookie сеанса, которые они ставят, middleware,
    выбирающее язык, и страницы, отрисованные на сервере. Ничего из этого не работает
    внутри двоичного файла для компьютера, и оболочка к этому не стремится: она
    открывает URL экземпляра так, как это сделал бы браузер. Экземпляр — то, что вы
    устанавливаете; приложение — то, чем вы его открываете.

Без сохранённых предпочтений приложение запускается с темой **Системная** (System) и стилем **Стекло** (Glass). Явно сохранённые тема или стиль имеют приоритет.

В **Управление чатом → Управление компьютером** (Chat controls → Computer use) выберите **Локальный компьютер** (Local computer), чтобы дать этому диалогу инструменты снимков экрана, мыши и клавиатуры, даже если у агента нет привязки «Управление компьютером». Выбор не зависит от «Браузера» и «Где работать»: он не даёт доступа к папке или командам, а опубликованный агент остаётся неизменным. У человека, который начинает диалог, должно быть подключено собственное сопряжённое устройство; согласие на экран и системные разрешения по-прежнему действуют.

Возврат из Системных настроек обновляет готовность, даже если webview остаётся на экране. Если запись экрана включена, а доступ всё ещё запрещён, закройте и снова откройте запущенную копию, затем обновите проверку. Разрешения могут различаться у установленной сборки и у тестовой копии, подписанной ad-hoc.

Локальные задачи ACP останавливаются после 16 384 входящих событий или 8 МиБ суммарных сериализованных обновлений, включая повтор сеанса. Ошибка сообщается явно, а адаптер закрывается.

Закрепление сертификата издателя в репозитории требует соответствующего материала для подписи: если `MACOS_SELF_SIGNED_P12` отсутствует, выпуск останавливается. Подпись ad-hoc при выпуске доступна только тогда, когда сертификат не закреплён.

## Установка приложения { #installing-the-app }

Скачайте пакет для своего компьютера со страницы [релиза на GitHub](https://github.com/vstorm-co/agenticos/releases/latest). Чтобы установить готовый выпуск, Rust и инструменты разработчика не нужны.

- **macOS:** выберите Apple silicon или Intel, откройте `.dmg`, затем перетащите AgenticOS в **Программы** (Applications) по стрелке. Запустите его из «Программ» и извлеките образ диска.
- **macOS без предупреждения:** `curl -fsSL https://raw.githubusercontent.com/vstorm-co/agenticos/main/scripts/install_macos.sh | bash` скачивает выпуск, сверяет его SHA-256 с опубликованной вместе с ним суммой, копирует приложение в «Программы» и снимает отметку о загрузке с одного этого приложения. `brew install --cask vstorm-co/agenticos/agenticos` делает то же через [tap проекта](https://github.com/vstorm-co/homebrew-agenticos). Выпуски не нотаризованы Apple, поэтому `.dmg`, скачанный в браузере, всё равно попросит **Всё равно открыть** (Open Anyway). После того как проект закрепит сертификат, которым подписываются его выпуски (`scripts/macos_signing_identity.txt`), скрипт также отклоняет приложение, подписанное любым другим.
- **Windows:** откройте установщик `setup.exe`. Он следует языку системы и устанавливается для вашей учётной записи без прав администратора. Откройте AgenticOS из меню «Пуск». Для управляемых развёртываний есть также пакет `.msi`.
- **Linux:** откройте пакет `.deb` или `.rpm` в установщике приложений вашего дистрибутива. Для переносимой установки отметьте `.AppImage` как исполняемый в его свойствах и откройте его.

При первом запуске мастер проведёт вас через подключение к серверу или создание локального экземпляра. Docker нужен только для локального экземпляра; мастер находит его и предлагает скачать, если его нет. Установка не даёт доступа к экрану или микрофону.

[Почему macOS показывает это предупреждение](howto/macos-warning.md).

### Виджеты рабочего стола на macOS { #desktop-widgets-on-macos }

В macOS 14 и новее запустите установленное приложение один раз, затем щёлкните правой кнопкой по рабочему столу, выберите **Изменить виджеты** (Edit Widgets) и найдите **AgenticOS**. Маленький виджет открывает «Быстрый вопрос», средний — ещё и «Чат», «Входящие» и «Активность». Виджеты следуют оформлению системы и содержат только ярлыки, без данных учётной записи. Нажатие на виджет никогда не начинает запись или звонок.

CI выпусков собирает нативные пакеты для Mac (Apple silicon и Intel), Windows и Linux. Пакеты для macOS используют настроенный стабильный самоподписанный сертификат; подпись ad-hoc применяется только тогда, когда сертификат не закреплён. Apple эти сборки не нотаризует. Скопировав приложение в «Программы», попробуйте открыть его один раз. Если macOS блокирует его, потому что разработчик не подтверждён, выберите **Системные настройки → Конфиденциальность и безопасность → Всё равно открыть** (System Settings → Privacy & Security → Open Anyway) и подтвердите. На управляемых компьютерах это исключение может быть запрещено. См. [инструкции Apple](https://support.apple.com/en-us/102445). Загрузки обновлений по-прежнему требуют действительной подписи ключом обновлений выпуска.

После обновления с подписью ad-hoc macOS может снова запросить доступ к микрофону, записи экрана, универсальному доступу или связке ключей. Если сопряжение устройства потеряно, подключите устройство заново. Подписи обновлений подтверждают пакет, но не дают стабильной личности подписи Apple.

Когда в рабочем процессе выпуска есть стабильный самоподписанный сертификат (его создаёт `scripts/create_macos_signing_cert.sh`), macOS сохраняет разрешения на запись экрана и микрофон между обновлениями, потому что они привязаны к личности подписи. Создайте его один раз и никогда не заменяйте: новый сертификат заставит каждого пользователя подтверждать доступ заново. Самоподпись не убирает предупреждение Gatekeeper; это делают только подпись Developer ID и нотаризация.

## Нативный пакет для Arch Linux { #native-arch-linux-package }

Скачайте `agenticos-VERSION-1-x86_64.pkg.tar.zst` со страницы релиза на GitHub и установите его командой `sudo pacman -U ./agenticos-VERSION-1-x86_64.pkg.tar.zst`. Замените `VERSION` номером выпуска. Pacman разрешает объявленные системные зависимости, включая WebKitGTK 4.1. Этот пакет не содержит WebKitGTK и клиентскую библиотеку Wayland.

Скачайте `SHA256SUMS.arch` рядом с пакетом и до установки проверьте его командой `sha256sum -c SHA256SUMS.arch`. Эти пакеты выпуска не подписаны связкой ключей Arch Linux.

Чтобы обновиться, скачайте пакет новее и выполните ту же команду `pacman -U`. Удалить его можно командой `sudo pacman -R agenticos`; личные настройки останутся в вашем домашнем каталоге. **Check for Updates…** объясняет эту политику пакетного менеджера вместо загрузки AppImage. Автоматического репозитория pacman и официальной публикации в AUR нет.

Поддерживаемый рецепт — `packaging/arch/PKGBUILD.in`. `scripts/build_arch_package.sh OUTPUT_DIRECTORY` создаёт рецепт с номером версии и архив с контрольной суммой из текущего коммита Git, затем запускает makepkg от имени обычного пользователя. Собирайте в обновлённом окружении Arch x86_64 с установленными зависимостями сборки и времени выполнения из рецепта. Рабочий процесс выпуска повторяет эту сборку для каждого релиза платформы; плавающие системные зависимости разрешаются во время сборки.

CI-задача для нативного пакета Arch устанавливает пакет, повышает его ревизию, проверяет владение файлами и удаление, а затем запускает изолированную проверку отрисовки WebKit установленного исполняемого файла под Xvfb/X11 и headless Weston/Wayland. Её артефакт `arch-native` записывает пути к библиотекам, версии пакетов и журналы отрисовки. Эти проверки с программной отрисовкой не доказывают совместимость с каждым физическим GPU, версией Mesa, композитором или установкой CachyOS.

## Запуск { #running-it }

Мастер первого запуска начинается с выбора языка и вопроса: создать локальное
рабочее пространство или подключиться к серверу вашей организации. Разрешения
«Запись экрана», «Универсальный доступ» и «Микрофон» — необязательные функции,
которые предлагаются в «Готовности приложения» или при первом использовании, а не
обязательный шаг перед выбором подключения.

При подключении приложения для компьютера можно вставить исходную ссылку-приглашение, а не только адрес сервера. Приложение подключится к серверу из этой ссылки и откроет приглашение, сохранив его назначение на время входа. Само приглашение оно не принимает и не сохраняет его токен в настройках приложения. Необязательная проверка подключения ждёт, пока приглашение не будет завершено.

Стартовый экран приложения и консоль поддерживают английский, польский, немецкий,
турецкий и русский. Выбранный в приложении язык переносится в консоль; сохранённый
язык существующей учётной записи всё равно важнее. Локальная настройка спрашивает
одно название рабочего пространства; отдельное название организации — дополнительная
возможность. После проверки подключения **Начать** (Get started) открывает общий
сценарий первой задачи. Локальное рабочее пространство всё равно может отправлять
материалы удалённому ИИ-провайдеру; одна лишь локальная установка не означает работу
ИИ без сети.

Что нужно заранее: Rust из [rustup](https://rustup.rs) и webview платформы — WebKit в macOS,
WebView2 в Windows, WebKitGTK в Linux; на [странице предварительных требований](https://v2.tauri.app/start/prerequisites/)
самого Tauri есть список по платформам. Версия Tauri CLI закреплена в `desktop/package.json`,
и `make install` скачивает её вместе со всем остальным.

```bash
make desktop-dev     # opens the shell
make desktop-build   # a .app / .dmg, .msi or .deb/.AppImage for this machine
make desktop-check   # rustfmt, clippy with warnings denied, and the tests
```

При первом запуске приложение спрашивает, где будет работать AgenticOS:

- **На этом компьютере.** Приложение проверяет Docker, поднимает опубликованные
  образы с консолью и API только на loopback-адресах, создаёт вашу организацию и её
  владельца и с этого момента запускает, останавливает и обновляет этот набор
  сервисов из строки меню.
- **На сервере вашей организации.** Введите его адрес; голое имя хоста
  (`agenticos.acme.com`) открывается по HTTPS. Вы входите через собственный
  браузер (см. [Вход](#signing-in)).

!!! warning "Незашифрованный `http://` — только для этой машины"

    `localhost`, `127.0.0.1` и `::1` доступны без шифрования; любой другой хост
    отклоняется, пока не станет `https://`. Консоль отправляет пароль и получает
    токен обратно по этому же соединению, а локальная сеть — ровно то место, где
    кто-то другой может это прочитать.

Адрес, на который никто не отвечает, тоже отклоняется: оболочка открывает TCP-соединение, прежде чем направить webview по этому адресу, потому что WebKit рисует отклонённое соединение как пустое белое окно.

Настройки лежат в `server.json` в каталоге конфигурации платформы для приложения — `~/Library/Application Support/co.vstorm.agenticos/` в macOS, `%APPDATA%\\co.vstorm.agenticos\\` в Windows, `~/.config/co.vstorm.agenticos/` в Linux. Файл, который больше не разбирается, откладывается как `server.json.invalid`, и записывается новый. Сервер меняется в **Настройках…** (Settings…) (`⌘,`), из меню в области уведомлений или запуском с `--server <address>`.

**Сменить сервер…** (Change server…) находится в меню учётной записи внизу боковой панели консоли. Откройте имя своей учётной записи или аватар на свёрнутой боковой панели и выберите этот пункт, чтобы открыть форму подключения. Он остаётся доступным, даже когда Blobby скрыт.

### Docker и несколько локальных установок { #docker-and-multiple-local-instances }

Создание установки открывает отдельный шаг со сгруппированными полями рабочего пространства, владельца и провайдера. **Отмена** (Cancel) возвращает к списку установок. Blobby остаётся скрытым во время настройки и возвращается вместе с консолью, следуя сохранённой настройке видимости.

Выберите **Настроить этот компьютер** (Set up this computer), чтобы подготовить локальную среду выполнения. AgenticOS скачивает Docker Desktop 4.97.0 для вашего процессора и сверяет закреплённую контрольную сумму SHA-256. macOS проверяет установщик через Gatekeeper, подтверждает личность подписи Docker Inc и запрашивает системную авторизацию. Windows запускает подписанный установщик; недостающие компоненты WSL подготавливаются с системной авторизацией. Перезагрузите Windows, когда будет предложено, и снова откройте AgenticOS, чтобы продолжить. В x86-64 Ubuntu, Debian и Fedora используется системный установщик пакетов. Примите собственные условия первого запуска Docker.

В Linux настройка добавляет подписанный источник пакетов Docker, если его нет, и запрашивает авторизацию администратора для пакетов и доступа к KVM. Перезагрузитесь, когда будет предложено. Одна лишь проверка состояния никогда не устанавливает программы.

Перед установкой AgenticOS проверяет, что свободно 4 ГБ места; локальному набору сервисов также нужно не менее 3 ГБ памяти, видимой его движку. Это проверки запуска, а не гарантии запаса под рабочую нагрузку. Загрузка образов показывает прогресс и ограничена 30 минутами. **Повторить** (Retry) продолжает ту же установку с её существующими ключами. Для обычной работы приложения Git, Python, uv и Node.js на хосте не нужны.

Новые установки закрепляют версию платформы, поставляемую с приложением. Обновление
приложения для компьютера не подменяет версию работающей установки незаметно.
**Обновить локальное рабочее пространство** (Update local workspace) скачивает
соответствующие образы платформы, приостанавливает запись и перед применением
обновления делает резервную копию базы данных, медиафайлов и ключей экземпляра в его
частном каталоге `backups/`. Неудачная резервная копия блокирует обновление.
Резервные копии содержат персональные данные, и их нужно защищать. О неудачной
миграции сообщается; откат базы данных автоматически не выполняется.

Открытие AgenticOS автоматически перезапускает сохранённое управляемое локальное рабочее пространство, если оно остановлено, включая установленную среду выполнения для компьютера на поддерживаемых системах. Внешние серверы и неуправляемые наборы сервисов для разработки не запускаются. Приложение передаёт дочерним процессам каталоги CLI и credential helper Docker, в том числе при запуске из Finder; править конфигурацию учётных данных Docker или профиль оболочки не нужно.

Публичные образы продукта используют частную анонимную конфигурацию реестра, чтобы не вызывать запросы credential helper и связки ключей. Ваша существующая конфигурация Docker остаётся неизменной. Локальная установка отклоняет контексты, указывающие на удалённый движок.

Выберите **Новая локальная установка** (New instance), задайте ей имя и укажите её организацию и владельца. Приложение назначает свободные loopback-порты и создаёт отдельный проект Compose с собственной базой данных, томом для медиафайлов, сетью, каталогом рабочего пространства и ключами экземпляра. Cookie локального сеанса имеют пространство имён установки, поэтому переключение между установками не подменяет вход в другую. Образы фронтенда должны поддерживать это; настройка отклоняет более старый образ, прежде чем создать владельца или открыть сеанс.

Локальный экран перечисляет сохранённые установки, их адреса и то, работают ли они. **Запустить и подключиться** (Start and connect) запускает выбранную установку; **Завершить настройку** (Finish setup) повторяет прерванную установку, используя её существующие файлы и ключи. «Запустить» и «Остановить» в строке меню действуют на подключённую управляемую установку. **Обновить локальное рабочее пространство…** (Update local workspace…) открывает выбор локальной установки. Подключение к набору сервисов для разработки, запущенному извне, не делает его управляемым приложением.

Локальная установка запускает API, воркер, консоль, базу данных и Redis и никакой службы песочниц, браузерной службы или объектного хранилища. Агенты получают рабочее пространство только с файлами. В **Управление чатом → Инструменты и файлы** (Chat controls → Tools & files) выберите **Где работать → Этот компьютер** (Work on → This computer) для доступа к папкам и **Браузер → Локальный браузер** (Browser → Local browser) для работы в браузере. **Управление компьютером** (Computer use) отдельно даёт доступ к экрану, мыши и клавиатуре.

Метаданные лежат в `local-instances.json` в каталоге конфигурации; файлы новых установок находятся в `local-stacks/<id>/` в каталоге данных приложения. Существующие установки `local-stack/` сохраняют свой исходный проект Compose и данные. Пароли и ключи провайдеров передаются в начальную настройку, не сохраняясь в этих файлах и не попадая в командную строку Docker. Ключи экземпляра остаются в его частном `.env`; ключи провайдеров хранит хранилище секретов сервера. Элементы управления встроенной настройки используют нейтральный индикатор фокуса клавиатуры и не переводят фокус на кнопки выбора автоматически.

Приложение для компьютера и рабочее пространство обновляются отдельно. В главном
меню macOS выберите **AgenticOS → Обновить локальное рабочее пространство…** (Update local workspace…);
в Windows и Linux используйте меню в области уведомлений. То же действие доступно рядом с каждой
установкой в **Сменить сервер… → На этом компьютере** (Change server… → On this computer).
Окно выбора показывает версию приложения, настроенную версию каждого рабочего
пространства и целевую версию, входящую в состав приложения. У старого рабочего
пространства с незакреплённой версией версия показывается как недоступная; обновление
всё равно проверит её, прежде чем что-либо менять. Рабочее пространство новее откатить
нельзя. Текущее рабочее пространство предлагает
**Повторить обновление рабочего пространства** (Reapply workspace update), чтобы
восстановиться после прерванного перезапуска или миграции.

Выберите **Обновить локальное рабочее пространство**, затем подтвердите системное уведомление о резервной копии и перезапуске. Окно выбора сообщает о загрузке образов, резервном копировании и перезапуске, а затем позволяет подключиться снова. При сбое оно показывает ошибку и разрешает повторить; отмена оставляет рабочее пространство без изменений. **Check for Updates…** обновляет только приложение для компьютера и указывает на отдельное действие для рабочего пространства, в том числе когда приложение уже актуально. Этот путь работает, даже если подключённая консоль старее.

## Настройка подключения и готовность приложения { #connection-setup-and-app-readiness }

Меню учётной записи также открывает **Готовность приложения** (App readiness) напрямую, в том числе из настроек приложения для компьютера. Список проверок заменяет плавающий счётчик настройки, поэтому никогда не закрывает элементы управления страницы.

Проверка подключения размещена на нативном стеклянном материале, даже когда консоль
использует непрозрачный сохранённый стиль. Её строки состояния остаются
смонтированными во время проверки. «Подключение» и «Продолжить» показывают прогресс
сразу; «Обзор» загружается заранее, пока вы просматриваете настройку. Анимация
появления учитывает настройку «Уменьшить движение».

Подключение к серверу открывает **Готовность приложения**, в том числе для существующей
учётной записи. Она проверяет вход, связь с компьютером, доступного опубликованного
агента, модель ассистента, сочетания клавиш и разрешения macOS. Разрешения
запрашиваются только когда вы выбираете **Настроить** (Enable). Необязательные пункты
можно оставить незавершёнными и вернуться к ним из
**Настройки → Приложение для компьютера** (Settings → Desktop app) или из нативного
меню **Activity & Access**. Консоль помнит закрытую проверку для
каждой учётной записи, организации и сервера; явное новое подключение предлагает свежую
проверку. Ошибки состояния остаются видимыми, и проверку можно повторить. Возврат из
Системных настроек обновляет проверки разрешений.

Сбои снимков экрана и управления экраном указывают на запись экрана или универсальный доступ; сбои микрофона в «Быстром вопросе» ведут на тот же экран готовности. После выдачи разрешения на запись экрана исправление снимка снова предлагает интерактивный выбор области. macOS может потребовать перезапустить приложение, прежде чем изменённое разрешение вступит в силу.

В разделе **Настройки → Приложение для компьютера → Уведомления** (Settings → Desktop app → Notifications) настраиваются уведомления о завершённых запусках, сбоях, согласованиях, вопросах и прочих событиях. Предпросмотры скрыты по умолчанию; приватные уведомления о согласовании открывают приложение, чтобы проверить запрос, а не предлагают согласовать вслепую. Настройки чата позволяют отключить уведомления для этого диалога. Уведомление подавляется, пока его диалог в фокусе в консоли или в «Быстром вопросе». Разрешения системы на уведомления и настройки фокуса по-прежнему определяют доставку.

Меню **Activity & Access** перечисляет текущую работу и запросы, требующие внимания. Откройте запись, чтобы продолжить в консоли; кнопка **Stop** доступна, когда именно это приложение держит исходное соединение диалога. Другие запуски на сервере остаются доступны через **Open**. Здесь же можно отозвать отдельные доступы к папкам или ко всему компьютеру и вернуть себе управление экраном.

В заголовке есть **Новый чат** (New chat) (`⌘N` или `Ctrl+N`), **Продолжить в консоли** (Continue in the console) и **Закрыть** (Close). Новый чат сбрасывает выбранный диалог и контекст черновика; поле ввода остаётся под транскриптом, кнопка отправки видна.

«Быстрый вопрос» поддерживает `@mention` с теми же доступными ресурсами, что и поле ввода чата. Стрелки и Enter или Tab выбирают вариант; Escape сначала убирает подсказки. Удаление упоминания снимает привязку ресурса из следующего сообщения.

## Приложение, а не вкладка { #an-application-not-a-tab }

В macOS боковая панель консоли держит кнопки управления окном и перетаскивает окно, окно
помнит свой размер и положение, а закрытие оставляет приложение в строке меню. В строке
меню есть «Файл», «Правка», «Вид», «Переход» (`⌘1`-`⌘5`, `⌘[` и `⌘]`) и «Окно»; в
Windows и Linux то же делает меню в области уведомлений. Нативные уведомления несут «Одобрить» и
«Отклонить» для ожидающего согласования, а Dock или панель задач показывает, сколько их
ждёт. **Настройки → Приложение для компьютера** (Settings → Desktop app) открывает
приложение при входе, продолжает его работу при закрытом окне и включает или выключает
значок со счётчиком.

Вверху содержимого есть зарезервированная полоса для перетаскивания окна вне области
прокрутки, поэтому действия страницы и кнопки закрытия панелей остаются кликабельными.
Кнопка запуска «Архитектора» из веб-версии остаётся прижатой к правому краю консоли в приложении и
выезжает при наведении, оставляя угол свободным для действий карточек и нативного Blobby.

Чат заполняет область содержимого сверху, без зарезервированной полосы для перетаскивания и отступов страницы. Окно можно перетаскивать за заголовок списка диалогов; его кнопки остаются кликабельными.

**Оформление** (Appearance) в меню учётной записи предлагает и светлый или тёмный режим, и стили «Стандартный», «Стекло», «Графит», «Полночь» и «Бумага», с предпросмотром. Переключатель называет текущий стиль. Это те же варианты, что в **Настройки → Профиль → Оформление** (Settings → Profile → Appearance); смена стиля сохраняет цветовой режим и переживает перезапуск приложения.

**Закреплённые агенты** (Pinned agents): страница агента предлагает «Закрепить в Dock» (в остальных системах — «Закрепить в панели задач»). Закреплённый агент есть в меню Dock и в меню в области уведомлений — один щелчок до нового чата с ним. Файл, перетащенный на значок Dock или на Blobby, начинает чат с этим файлом во вложении.

## Blobby { #blobby }

Существо в стиле аватаров агентов, которое живёт на рабочем столе, пока консоль открыта,
свёрнута или закрыта: один из шести персонажей, лицо одного из ваших агентов или ваше
собственное лицо. Оно говорит, когда ждёт согласование, во «Входящих» что-то новое или
идут ваши запуски, и открывает это по щелчку. Перетащите его куда угодно; сожмите,
прокрутите над ним с зажатой `⌘` или используйте ползунок в настройках, чтобы изменить
размер. Его собственная вкладка в настройках выбирает персонажа, разговорчивость и то,
показывает ли он активность вообще.

Его окно прозрачное, а для этого в macOS нужен `macOSPrivateApi` в
`tauri.conf.json` — и это исключает Mac App Store, куда консоль на собственной
инфраструктуре всё равно не собиралась.

## Быстрый вопрос и голос { #quick-ask-and-voice }

**Открыть AgenticOS** (Open AgenticOS) (`⌘⇧O` в macOS, `Ctrl+Shift+O` в остальных системах) выводит консоль на передний план из любого приложения. Изменить или снять это сочетание можно в **Настройки → Сочетания клавиш** (Settings → Shortcuts). Меню в строке меню, в области уведомлений и меню Blobby показывают действующие сочетания для открытия AgenticOS, «Быстрого вопроса» и снимка экрана в новый чат и обновляются при смене привязки. Сочетание, которое не удалось зарегистрировать, в меню не показывается.

**Быстрый вопрос** (Quick ask) (`⌥Space`, сочетание можно изменить) открывает
плавающую панель, чтобы спросить любого агента откуда угодно, не выводя консоль вперёд.
В macOS он может захватить то, на что вы смотрели: текст, выделенный в другом
приложении, буфер обмена или файлы, выделенные в Finder; всё это показывается до
отправки и только после того, как вы разрешили AgenticOS читать выделенное.

Удерживайте `⌥⇧Space`, чтобы продиктовать вопрос в панель быстрого вопроса; у
голосового звонка агенту по умолчанию есть своё сочетание. **Настройки → Сочетания клавиш** меняют их все:
в сочетании нужен хотя бы один модификатор, сочетание, занятое другим приложением,
отклоняется, а старое остаётся, и **Очистить** (Clear) его отключает.

**Снимок экрана в новый чат** (Screenshot to a new chat) (`⌘⇧A`) показывает системный прицел; выбранная область попадает в новый чат уже вложением. Первое нажатие запрашивает у macOS запись экрана, которая вступает в силу после перезапуска.

«Быстрый вопрос» сохраняет полный транскрипт: ваши вопросы, прежние ответы, потоковая
активность инструментов и результаты отображаются тем же механизмом сообщений, что и в
консоли.
Запросы на согласование, уточняющие вопросы и запросы подключения можно обработать прямо
в панели. Текст, поставленный в очередь без сети, остаётся видимым, а кнопка остановки
останавливает запуск. Вложения и процитированные источники открываются в панели;
прокрутка вверх приостанавливает автоматическое следование, пока вы не вернётесь вниз.

Скрепка выбирает файлы, можно вставить изображение из буфера обмена или перетащить файлы
в «Быстрый вопрос». Вложения появляются до отправки, и каждое можно удалить отдельно.
Ограничение экземпляра на загрузку в чате действует и здесь. Отправка и начало нового чата
ждут завершения загрузок; неудачная загрузка сохраняет черновик. Файл можно отправить, не
добавляя текст.

Кнопка закрепления держит «Быстрый вопрос» поверх других приложений, когда вы щёлкаете в
другом месте. Открепите панель, чтобы вернуть автоматическое закрытие при потере фокуса.
Кнопка закрытия, Escape в поле ввода и сочетание «Быстрого вопроса» всё равно скрывают
закреплённую панель. Закрепление действует в течение текущего сеанса приложения, включая
перезагрузки страницы.

## Работа на этом компьютере { #work-on-this-computer }

Локальные файловые операции выполняются относительно открытого дескриптора одобренного каталога. Замена каталога или файла символической ссылкой не может увести запись за его пределы. Сам выданный доступ и его родительские каталоги открываются без перехода по символическим ссылкам; предпросмотры и списки файлов используют ту же границу.

Единственное, чего браузер не умеет: чат в приложении для компьютера может работать в
папке на машине, где запущено приложение, а не в облаке. Файловые инструменты агента и
инструменты оболочки — список, чтение, запись, правка, запуск — добираются до этой папки
через приложение.

**Привяжите компьютер один раз.** В настройках чата выберите
**Где работать → Этот компьютер** (Work on → This computer), чтобы привязать его
напрямую. Подтвердите в системном диалоге, затем выберите папку и режим доступа в той же
панели.
**Настройки → Приложение для компьютера → Этот компьютер → Привязать этот компьютер**
(Settings → Desktop app → This computer → Link this computer) предлагает то же действие
привязки. Приложение получает собственный сеанс для этого компьютера и держит его токен
обновления в системной связке ключей. Оно держит одно исходящее WebSocket-соединение с
хабом устройств сервера (`/api/v1/ws/device`); на компьютере ничего не слушает
порт. **Отвязать** (Unlink) завершает этот сеанс; сначала приложение спрашивает и
перечисляет, что очистит.

**Выбирайте это для каждого чата.** В приложении для компьютера настройки чата предлагают
**Где работать: «Облако» / «Этот компьютер»**. Выбор этого компьютера запрашивает папку в
системном окне выбора и то, как далеко агент может зайти в ней:

«Этот компьютер» становится выбранным только после того, как вы одобрите папку. Селектор
доступа показывает одобренный режим этой папки; его изменение снова открывает системное
окно выбора папки, чтобы подтвердить новое разрешение. Отмена сохраняет прежний выбор.
Папка и режим остаются выбранными, когда настройки закрываются и когда новый чат получает
свой ID.

| Режим           | Что агент может делать                                             | Чем это ограничено                                                                                                   |
| --------------- | ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| Только чтение   | Читать файлы; ничего не записывается и никакие команды не выполняются | Приложение отклоняет записи и команды                                                                             |
| Запись в папке  | Читать, писать внутри папки, выполнять команды                     | Команды выполняются под Seatbelt в macOS и bubblewrap в Linux, запись возможна только в папку и временные каталоги  |
| Полный доступ   | Команды выполняются от вашего имени, без песочницы                 | Каждая команда сначала показывается в системном диалоге для разрешения                                              |

Команды в папке могут читать одобренную папку и системные файлы среды выполнения, но не
посторонние файлы домашнего каталога и не унаследованные учётные данные приложений.
Инструментам, которым нужны эти файлы, требуется отдельное согласие на весь компьютер.
Прямое чтение и запись локальных файлов ограничены 10 МиБ, чтобы слишком большая передача
не отключила устройство. Более крупная запись отклоняется ещё до кодирования и отправки
байтов файла.

Windows предлагает только чтение и полный доступ. Linux предлагает запись в папке только
когда установлен `bwrap` с поддержкой `--bind-fd`. Приложение держит дескриптор каталога
без перехода по ссылкам на протяжении запуска песочницы, поэтому переименование папки или
замена её символической ссылкой не меняет одобренный каталог. В Linux переменные окружения
задачи применяются внутри песочницы, а не к процессу, который её запускает; их значения передаются через
частный дескриптор.

Корневые папки автоматизаций не должны содержать символических ссылок или точек соединения. Выбирайте в диалоге настоящую папку; при фоновом допуске ссылки в корневом пути никогда не раскрываются.

**Решает компьютер, а не сервер.** Выбранные вами папки вместе с режимами хранятся в
настройках приложения, и каждая операция называет папку и режим, которые приложение сверяет
с ними: папка, которую вы никогда не выбирали, режим шире разрешённого или путь, выходящий
за пределы папки, отклоняются на компьютере независимо от того, что запросил сервер. Выбор
запоминается для каждого диалога. Новые чаты наследуют последнюю папку и настройки
инструментов для этой учётной записи и организации; настройки проекта имеют приоритет.
Согласие на весь компьютер, данное в чате, никогда не наследуется; согласие, данное
агенту, действует для этого агента (см. «Весь компьютер»).

**Только ваши собственные запуски.** Чат добирается до вашего компьютера, только когда он
ваш, — никогда API-ключ, посетитель виджета или чужой чат, — а [триггер](triggers.md) —
только когда он действует от имени своего создателя, который указывает папку на своём
компьютере в **Где работать** триггера.

**Когда компьютер недоступен.** Интерактивный запуск чата, который запросил этот компьютер
и не нашёл приложение подключённым, ждёт его до десяти минут, и чат об этом сообщает.
Операция, которая застала приложение пропавшим посреди запуска — закрытая крышка, смена
сети, — ждёт его возвращения в том же сеансе до пяти минут, а затем продолжает. Пока
операция запуска выполняется, в области уведомлений видно, что агент работает на этом компьютере.

Сервер проверяет вход, прежде чем передать каждую локальную операцию. Отозванные или истёкшие сеансы отклоняют новую работу; сигнал активности также закрывает простаивающие соединения. Операции, которые уже выполняются, отменяются, когда сокет приложения закрывается.

В Конструкторе пункт **Песочница → Компьютер** (Sandbox → Computer) сохраняет `backend: local`
без пути и без системного согласия. Каждый человек одобряет свою цель в чате приложения. У
такого агента нет облачного рабочего пространства, поэтому **Где работать** не предлагает
для него «Облако».

Написать ему можно ещё до того, как вы что-либо разрешили: он отвечает на то, что не
требует файлов, и только когда запросу нужны ваши файлы, спрашивает, где ему работать, —
**Весь компьютер** (Whole computer) или папка. Запуск ждёт вашего выбора, затем чат сам
продолжает с файлами. Ответ запоминается для этого агента на этом компьютере, поэтому его
следующие чаты начинаются там, не спрашивая. В веб-консоли, где нечего разрешать, он
говорит, что не может добраться до ваших файлов. При создании проекта
**Песочница проекта → Компьютер · ваши файлы** (Project sandbox → Computer · your files)
открывает выбор личной папки; остальные участники сохраняют общее рабочее пространство
проекта.

**Весь компьютер.** Чат в приложении предлагает и **Весь компьютер** без выбора папки. Доступ даёт одно системное предупреждение: для агента, чьё рабочее пространство — **Компьютер**, предупреждение называет агента, и согласие действует для него во всех диалогах; в остальных случаях — только для этого диалога. Файловые инструменты могут добраться до абсолютных путей везде, куда имеет доступ ваша учётная запись, а команды выполняются от вашего имени, без отдельных системных запросов. Системные разрешения и правила согласования агента по-прежнему действуют. **Отозвать доступ ко всему компьютеру** (Revoke whole-computer access) или выбор **Облака** (Cloud) блокирует новые операции; уже выполняющиеся команды не прерываются. Согласие переживает перезапуски приложения и ограничено этим сервером и агентом или диалогом; черновик закрепляет согласие диалога на своей первой операции. Новому чату с другим агентом нужно собственное согласие. Этот режим не обходит домашний каталог и не собирает файлы во вложения автоматически.

Локальный браузер и файловые инструменты доступны в чате приложения, даже если у агента нет
привязки к «Браузеру» или «Песочнице». Выбор добавляет привязку только к этому запуску,
сохраняет существующие ограничения доменов и правила согласования и не меняет
опубликованного агента. Внутренние снимки вложений используют список файлов, а не запуск
оболочки.

## Экран { #the-screen }

[Управление компьютером](reference/capabilities.md) может управлять экраном этого
компьютера. В чате, работающем на этом компьютере, его рабочий стол `auto` — значение по
умолчанию — и есть этот экран; `local` не запрашивает ничего другого.

- **Спрашивается заранее.** Первый снимок экрана в сеансе спрашивает в системном диалоге,
  может ли агент видеть и контролировать этот экран, — на час.
- **В рамке, пока он действует.** Пока агент управляет экраном, его обводит контур.
- **Останавливается сразу.** `⌘⌥Esc` (`Ctrl+Alt+Esc` в остальных системах) забирает экран
  обратно; следующее действие отклоняется, пока вы снова его не разрешите.
- **Спрашивает и операционная система.** В macOS AgenticOS должен быть указан в разделе
  «Конфиденциальность и безопасность» (Privacy & Security) — и в «Записи экрана», и в
  «Универсальном доступе»; отказ называет их.

Каждый рабочий стол, на котором работает запуск, включая этот, показывается в реальном
времени в чате и в представлении запуска в реальном времени, где **Перехватить управление** (Take over)
передаёт его вам между шагами агента, а **Вернуть агенту** (Give back) возвращает ему.
Представление экрана этого компьютера в реальном времени доступно только вам, кто бы ещё ни
мог смотреть запуски.

## Вход { #signing-in }

Главное окно приложения резервирует полосу для перетаскивания отдельно от компактного отступа содержимого в 16px. В macOS у кнопок окна есть зарезервированная строка в 32px, поэтому логотип в боковой панели и заголовок страницы выровнены без лишнего верхнего зазора браузерной раскладки.

Консоль, Blobby и «Быстрый вопрос» используют общий именованный постоянный профиль
WebView; приватные вкладки браузера агента остаются изолированными. При переходе со
старого профиля может потребоваться один вход. В стиле «Стекло» полоса для
перетаскивания использует фон содержимого. Область прокрутки «Обзора» сглаживает
навигацию с клавиатуры и дискретные шаги колеса мыши, оставляя точный ввод трекпада
нативным; уменьшенное движение отключает сглаживание.

Консоль хранит сеанс в постоянных HttpOnly cookie, включая cookie обновления, которое
продлевается по мере использования сеанса. Повторное открытие приложения восстанавливает
этот сеанс, пока он действителен. Временный сбой сервера или лимит частоты сохраняют
учётную запись приложения и повторяют проверку сеанса, когда соединение возвращается или
окно снова получает фокус. Отклонённый или отозванный токен всё равно требует входа. Если
локально нет доступной учётной записи, недоступный сервер предлагает повторить, а не
отправляет вас на вход.

Единственный переход, который окно консоли отклоняет. Всё остальное загружается в окне;
щелчок по **Продолжить через Google** (Continue with Google) открывается в вашем браузере,
а результат возвращается в приложение (#1532).

Что происходит по порядку:

1. Собственный маршрут консоли `/api/oauth/<provider>/login` выполняется **в окне**, где
   может прочитать httpOnly-cookie с отложенным приглашением и приложить его.
2. Затем окно видит переход на `/api/v1/oauth/<provider>/login` _экземпляра_, передаёт
   его системному браузеру, добавив `client=desktop` и только что созданный
   `desktop_nonce`, и само по нему не идёт.
3. Вы входите там, в настоящем браузере, со своими паролями, своими расширениями и тем
   вторым фактором, который используете.
4. Обратный вызов экземпляра видит, что попытка была из приложения, — это записано в
   сеансе в самом _начале_ под OAuth `state` этой попытки и никогда не читается из
   возврата, — и перенаправляет на `agenticos://auth/callback?code=…` с одноразовым кодом,
   который истекает через минуту, и тем nonce, который ему передали.
5. Операционная система передаёт эту ссылку приложению. Оболочка отправляет окно консоли
   на `<your server>/auth/callback?code=…`, и тот меняет код на пару токенов при обмене
   между серверами; собственные cookie окна устанавливаются.

**Глубокую ссылку может запустить любой процесс на вашей машине**, поэтому позволено ей
здесь немногое: отправить консоль на один путь, на сервере, который настроили _вы_, с
кодом, который принимается ровно один раз — и только если она несёт nonce, созданный
этим приложением для этой попытки. В Windows и Linux блокировка единственного экземпляра
передаёт аргументы второго запуска первому. Экземпляр должен придерживаться той же схемы —
`DESKTOP_DEEP_LINK_SCHEME`, по умолчанию `agenticos`, если кто-то её не изменил, — и того же
собственного публичного адреса.

## Чего он намеренно не делает { #what-it-deliberately-does-not-do }

- **Нет защиты от переходов.** Ссылка, уводящая за пределы источника сервера, открывается
  внутри окна, потому что некоторым потокам OAuth — подключению учётной записи для
  терминала — нужно вернуться в тот же webview, чтобы их cookie установилось в этом окне. Заголовок
  окна называет любой другой хост, который оно показывает. Подключение MCP-сервера к ним
  не относится: его согласие открывается в вашем браузере, где ваши сеансы входа и ключи
  доступа, потому что обратный вызов аутентифицируется одним своим `state`. Завершите там
  и вернитесь; сервер появится в приложении, как только будет авторизован.

- **Нет постоянного доступа.** Привязка компьютера сама по себе ничего не даёт: запуск
  добирается только до одобренных папок или до отдельно одобренного диалога с доступом ко
  всему компьютеру, а до экрана — только после вашего разрешения.

## Где он находится в дереве { #where-it-sits-in-the-tree }

- `desktop/ui/` — страницы первого запуска и контур экрана, статические файлы.
- `desktop/core/` — то, о чём обе стороны должны договориться, не зависящее от среды
  выполнения: кадры протокола устройства, эндпоинты и повторные попытки с задержкой;
  тестируются отдельно.
- `desktop/src-tauri/` — оболочка: окна, меню, Blobby, «Быстрый вопрос», привязка
  устройства (`device.rs`), локальный исполнитель (`local_work.rs`) и экран
  (`screen.rs`).
- `backend/app/services/device_hub/` — серверная половина: присутствие в Redis, чтобы любой
  хост API или воркер мог добраться до компьютера, и `DeviceWorkspace` — рабочее
  пространство песочницы, которое исполняет приложение.

## Агенты для работы с кодом на этом компьютере { #coding-agents-on-this-computer }

**Настройки → Приложение для компьютера → Агенты для работы с кодом на этом компьютере**
(Settings → Desktop app → Coding agents on this computer) показывает версии и состояние
входа. **Настроить** (Set up) готовит отдельный Node.js 24.19.0 и закреплённые адаптеры для
работы с кодом из lockfile, сверяя целостность загрузок. Устанавливать инструменты
разработчика отдельно не нужно. **Войти** (Sign in) запускает собственный поток OAuth
агента в браузере; AgenticOS не читает и не копирует учётные данные. **Обновить статус**
(Refresh status) проверяет вход явно. Возврат фокуса в приложение не опрашивает хранилище
учётных данных повторно; успешный вход и настройка обновляют статус автоматически.

В **Управление чатом → Инструменты и файлы → Агент для работы с кодом**
(Chat controls → Tools & files → Coding agent) в приложении выберите **Claude Code** или
**Codex**, даже если опубликованная возможность отключена или отсутствует. Приложение готовит локальные файловые
инструменты и открывает системное окно выбора папки, если у текущей папки ещё нет доступа с
полными правами. Отмена оставляет прежние настройки без изменений. **Использовать настройку
агента** (Use agent setting) восстанавливает опубликованную конфигурацию.

Выбор относится к этому чату. Существующие правила только для чтения и правила
согласования по-прежнему действуют, а системное согласование при запуске можно запомнить
для этого агента и папки. Переход в «Облако» сбрасывает локальный выбор для работы с кодом
в диалоге. Управление чатом открывается над полем ввода. Его вкладки — **Модель** (Model),
**Инструменты и файлы** (Tools & files) (агент для работы с кодом, «Где работать»,
«Браузер», «Управление компьютером» и навыки) и **Предпочтения** (Preferences)
(согласования и уведомления).

Задайте возможность **Агент для работы с кодом** как **На этом компьютере**
(On this computer), выберите папку в разделе **Где работать** и дайте полный доступ. Системное согласование
запоминается для этого агента, папки, версии адаптера и подключения. Удаление или повторный
выбор папки сбрасывает её согласование и останавливает запущенных в ней агентов; смена
учётной записи и сервера тоже сбрасывает согласования. Адаптер работает под вашей учётной
записью операционной системы: папка задаёт его рабочий каталог, а не песочницу ОС. Доступ
ко всему компьютеру тоже запускает агента для работы с кодом — в вашем домашнем каталоге или
в папке внутри него. Согласование задачи и разрешения ОС по-прежнему действуют.

Согласование возможности действует один раз на задачу. Внутри него `edit` разрешает
запрошенные операции, а `read_only` отклоняет изменения. Режим только для чтения у Claude
отключает обход разрешений и оставляет только инструменты чтения. Режим только для чтения у
Codex выбирает его собственный режим песочницы только для чтения. Локальные агенты
используют свои настройки модели; использование подписки не тарифицируется, поэтому сообщённая
стоимость запуска — нижняя граница.

Последующие задачи возобновляют именованный сеанс (`main`, если задача не называет другой)
для этого диалога, агента, среды агента, папки, учётной записи и политики доступа;
несколько сеансов идут одновременно, до восьми на одном компьютере, каждый в папке чата или
в папке внутри неё. `fresh_session` явно начинает заново. Идентификаторы возобновления
хранятся в настройках приложения, вне вашего репозитория, и очищаются при отвязке или смене
учётной записи. Если сохранённый сеанс не загружается, задача завершается явной ошибкой; при
необходимости начните заново. Процессы останавливаются при отключении, но их сохранённую
историю среды агента можно возобновить.

Поправка, отправленная во время локальной задачи, прерывает её текущий ход ACP. После того
как адаптер подтвердит остановку, тот же сеанс продолжается с поправкой. Транскрипт
записывает применённую поправку; сообщение, пришедшее после завершения, остаётся доступным
родительскому агенту.

После выбора среды агента и одобренной папки **Модель для работы с кодом** (Coding model) и
**Уровень рассуждений** (Reasoning level) перечисляют варианты, которые сообщает
установленная среда агента. Они относятся к этому диалогу и применяются до начала новой или
возобновлённой задачи. Оставьте любое из них незаданным, чтобы сохранить собственную
настройку среды агента. Смена среды агента сбрасывает несовместимые переопределения. Обновляйте варианты
явно после смены входа или конфигурации; открытие другого окна не опрашивает учётную запись
снова. Убранный или неподдерживаемый вариант показывается и отклоняется, а не подменяется
молча. Чтение вариантов не начинает ход модели и не даёт разрешений на инструменты.

## Свои навыки и инструкции { #your-own-skills-and-instructions }

**Управление чатом → Где работать → Мои навыки и инструкции**
(Chat controls → Work on → My skills and instructions) выбирает, какие источники может
использовать диалог: `~/.agents/skills`, `~/.claude/skills` и `~/.codex/skills`. Каждый новый чат начинается с выключенными источниками.
Файлы читаются на месте, без копирования и синхронизации учётных данных или конфигурации.

Среди включённых источников конфликт имён решается в пользу `.agents`, затем `.claude`, затем
`.codex`. Счётчики отражают текущий выбор. Ссылки на одну и ту же папку навыка приложение
устраняет как дубликаты. Глобальные инструкции используют более новый из
включённых файлов `~/.codex/AGENTS.md`, `~/.claude/AGENTS.md` или `~/.claude/CLAUDE.md`,
включая символические ссылки Markdown.

`AGENTS.md` и `CLAUDE.md` одобренной рабочей папки идут после глобальных инструкций. Перед
входом в подпапку агент может вызвать `load_local_instructions`, чтобы прочитать иерархию от
одобренного корня до этого каталога. Более конкретные файлы идут после родительских. Этот
читатель никогда не поднимается выше одобренной папки и не переходит по символическим
ссылкам проекта. Файлы инструкций не могут расширить разрешения запуска.

Загруженный текст навыков и инструкций проходит через ваш сервер к настроенной модели агента.
Переключатель источников управляет этим контекстом AgenticOS; локально работающие агенты для
работы с кодом сохраняют собственную конфигурацию и поиск инструкций.

## Диагностика { #diagnostics }

**Справка → Export Diagnostics…** записывает один файл JSON в выбранное вами место, чтобы приложить его к отчёту об ошибке. В нём версия, операционная система, что разрешила macOS, установлены ли Claude Code и Codex и выполнен ли в них вход, адрес сервера (только схема, хост и порт) и последние сбои. В нём нет учётных данных, токенов, диалогов и путей внутри вашего домашнего каталога, и никуда ничего не отправляется. Сбой записывается в `crash.log` в каталоге данных приложения в момент, когда он происходит.

Если приложение 1.38.1 остаётся на **Привязан — переподключение…** (Linked — reconnecting…)
и локальные чаты говорят **Ожидание вашего компьютера** (Waiting for your computer), проверьте
указанные в экспорте места сбоев на `rustls` / `crypto/mod.rs`. Этот дефект запуска TLS в
приложении исправлен в более новом его выпуске. Установите этот выпуск и снова откройте
приложение; обновление одного сервера не заменяет клиент для компьютера. Существующее
сопряжение и доступы к папкам из-за этого исправления сбрасывать не нужно.

## Локальный браузер, модели и MCP { #local-browser-models-and-mcp }

После сопряжения приложения для компьютера выберите **Браузер → Локальный браузер** (Browser → Local browser), чтобы переопределить браузер агента для этого диалога. Выбор не зависит от **Где работать** (Work on): ему не нужен ни доступ к папке, ни возможность «Песочница», и он сохраняет облачную песочницу агента. Локальные модели и MCP-сервисы требуют одобренной папки или цели «весь компьютер»; запуск получает собственную привязку к песочнице. Мобильные приложения не вызывают команды приложения для компьютера.

Добавляйте сервисы в **Настройки → Приложение для компьютера → Локальные сервисы** (Settings → Desktop app → Local services). Каждый выданный доступ подтверждается системным диалогом. Модели используют HTTP-эндпоинт, совместимый с Ollama или OpenAI (например, `http://127.0.0.1:11434/v1`), и идентификатор установленной модели. MCP использует уже работающий сервер Streamable HTTP (например, `http://127.0.0.1:8000/mcp`).

Принимаются только loopback-эндпоинты; перенаправления и встроенные учётные данные
отклоняются. Приложение хранит адрес, а API отправляет непрозрачный идентификатор доступа.
Запросы и ответы ограничены 8 МиБ, срок службы — две минуты. MCP-серверы должны принимать
запросы без токена и возвращать конечные HTTP-ответы; отдельные подписки SSE и запуск
процессов stdio не поддерживаются. Удалите выданный доступ, чтобы отклонять последующие
вызовы. Профиль организации сохраняется для указания авторства без раскрытия её облачных
учётных данных. У локального вывода нет облачного резерва; другие возможности,
настроенные с отдельными моделями, сохраняют свои настройки.

**Локальный браузер** использует нативную страницу внутри панели браузера консоли после
согласия на сопряжённом компьютере. Щелчки, прокрутка и ввод происходят локально; страница
не передаётся снимками экрана. Его частный сеанс не импортирует личные вкладки браузера и
пароли. Текст страницы всё равно попадает в модель агента. Ручной ввод забирает управление
у агента; **Вернуть агенту** (Return to agent) возвращает его.

В широком чате браузер открывается рядом с диалогом — и для локального, и для удалённого
просмотра. Перетащите разделитель или используйте его стрелки, чтобы изменить ширину.
**Развернуть** (Maximize) занимает весь экран; **Вернуть рядом с чатом**
(Back beside the chat) возвращает панель. В узкой области чата и на телефонах автоматически используется
весь экран.

Собственная вкладка принадлежит этому компьютеру, организации, человеку, агенту и диалогу.
Она остаётся открытой между запусками; `browser_read` возобновляет работу с ней. Только один
запуск может арендовать её одновременно. Запуск автоматически продлевает аренду; если его
бэкенд останавливается, аренда снова становится доступной через две минуты.
**Закрыть вкладку** (Close tab) уничтожает её; закрытие панели только скрывает. Отключение
сопряжённого устройства закрывает все его вкладки. Хранится не более восьми вкладок, а
вкладки, простаивающие два часа, могут быть вытеснены при открытии новой.

Согласие на нативный браузинг общее для вкладок этого диалога в рамках текущего
подключения устройства. Новые вкладки и вкладки, открытые агентом заново, не спрашивают
повторно при той же политике доменов. Если вы закрываете последнюю вкладку сами, согласие
отзывается; скрытие панели — нет. Отключение устройства очищает его. Другой человек, агент,
диалог или политика доменов требуют собственного согласия.

Настройки «Управления компьютером» и веб-браузера используют карточки окружений с краткими
описаниями. Новые привязки «Управления компьютером» явно выбирают Docker / Песочницу. Вариант
«Автоматически» в окне выбора больше не предлагается; существующие автоматические
конфигурации остаются читаемыми и неизменными, пока человек не выберет окружение. Docker
Compose включает sandboxd и его среду выполнения для компьютера. Оператор может
зарегистрировать URL и ключ другого хоста песочниц в разделе
**Подключения → Песочницы** (Connections → Sandboxes), а затем выбрать его и среду
выполнения для компьютера в настройках песочницы агента.

Отключите **Использовать нативный локальный браузер** (Use the native local browser) в
возможности браузера, чтобы выбрать совместимость с Chromium. Задачи с переопределениями
зрения или языка и часового пояса тоже используют существующее изолированное окно Chromium.
Для этого пути установите Chrome, Chromium, Edge или Brave; его временный профиль
закрывается вместе с запуском. Нативные действия с DOM используют сценарный ввод, который
некоторые сайты отличают от доверенного ввода CDP в Chromium. Нативные страницы не дают
команд консоли или файлов: их единственное разрешение для оболочки — одностороннее
уведомление о том, что человек перехватил управление. Привязка с `connection: local` всё
равно требует выбора локального браузера.

## Установщики и обновления { #installers-and-updates }

Рабочий процесс **Apps** также собирает установщики для разработки и проверяет установку без автоматизации интерфейса: копирование приложения для Mac из DMG, тихую установку и удаление в Windows, установку и удаление в Debian, распаковку переносимого AppImage. Он проверяет встроенный виджет macOS и подписи, сохранение изоляции сеансов и отклонение подделанных загрузок обновлений. Эти проверки используют сборки с подписью ad-hoc или без подписи и не доказывают публичную нотаризацию или одобрение магазина.

Задачи CI для установщиков и сборок выпуска Linux тоже распаковывают AppImage и отклоняют встроенную клиентскую библиотеку Wayland (`libwayland-client.so*`), которая может конфликтовать с драйвером Mesa хоста и ронять WebKitGTK. Проверка выпуска выполняется до загрузки установщиков и подписей обновлений. Эта проверка библиотек не доказывает совместимость отрисовки на каждом композиторе Wayland или GPU.

При ручном запуске более старого тега без `scripts/build_linux_desktop_release.sh` задача для Linux собирает напрямую через Tauri и пишет в журнал предупреждение, что проверка AppImage до загрузки недоступна. Теги, содержащие обёртку, сохраняют эту проверку; сбой сборки или проверки всё равно не даёт опубликовать обновление.

Рабочий процесс **Apps** в GitHub Actions проверяет нативные крейты в macOS, Windows и
Linux и собирает отладочные APK для Android и приложение для симулятора iOS. Полные нативные
проверки идут в CI. Локальный `make desktop-check` остаётся доступным для точечного изменения.
Рабочий процесс **App release** прикрепляет установщики, подписанные артефакты обновлений,
APK для Android и cask Homebrew к уже опубликованному стабильному выпуску `v1.MINOR.PATCH`,
коммит которого есть в `main`. Он не создаёт выпуск платформы. Cask также публикуется в tap
Homebrew, когда настроен ключ развёртывания или токен. **Check for Updates…** в меню
приложения требует сборки с открытым ключом обновлений и проверяет подпись загруженного файла
перед установкой.

Сборки выпуска приложения для компьютера идут параллельно. Каждая загружает свои подписанные
пакеты; одна финальная задача проверяет все четыре нативные цели и публикует `latest.json`.
Нативный CI кэширует результаты сборки по операционной системе, архитектуре, компилятору,
цели и профилю сборки. Выпуски восстанавливают только общие загрузки зависимостей. Неудачная
сборка платформы не даёт опубликовать обновление.

Публикация мобильных приложений сейчас отключена. Задайте переменную репозитория
`AGENTICOS_MOBILE_RELEASES_ENABLED=true`, чтобы включить подписанные выпуски для Android; для
iOS нужен ещё флаг TestFlight ниже. Это не отключает обычные сборки CI. Пока распространение
не включено, следуйте [самостоятельной установке мобильного приложения](mobile.md#availability-and-self-installation).

Перед запуском выпуска настройте окружение GitHub `apps-release`:

- Стабильная подпись macOS: секреты `MACOS_SELF_SIGNED_P12`, `MACOS_SELF_SIGNED_P12_PASSWORD` и переменная `MACOS_SELF_SIGNED_IDENTITY`. Опубликуйте её открытый отпечаток в `scripts/macos_signing_identity.txt`.
- Homebrew: секрет `HOMEBREW_TAP_DEPLOY_KEY` — ключ развёртывания с правом записи, ограниченный репозиторием tap. `HOMEBREW_TAP_TOKEN` остаётся альтернативой. Временные файлы ключей удаляются и при успехе, и при сбое.
- Переменная `AGENTICOS_UPDATER_PUBLIC_KEY`; секреты `TAURI_SIGNING_PRIVATE_KEY`
  и `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` (одна постоянная пара ключей обновлений).
- Необязательная подпись Developer ID для macOS: задайте переменную репозитория
  `AGENTICOS_MACOS_SIGNING_ENABLED=true` и настройте `APPLE_CERTIFICATE`
  (P12 в base64), `APPLE_CERTIFICATE_PASSWORD`,
  `APPLE_SIGNING_IDENTITY`, `APPLE_ID`, `APPLE_PASSWORD` (специальный пароль для приложения)
  и `APPLE_TEAM_ID` для подписи Developer ID и нотаризации. Когда это включено,
  отсутствующие учётные данные останавливают сборку; запасного варианта с подписью
  ad-hoc нет. Если флаг не задан или равен false, macOS использует настроенный
  стабильный самоподписанный сертификат, а если его нет — подпись ad-hoc. Ни то, ни
  другое не нотаризуется; учётные данные Apple в этом режиме игнорируются.
- Необязательная подпись Authenticode для Windows: `WINDOWS_CERTIFICATE_BASE64` (PFX) и
  `WINDOWS_CERTIFICATE_PASSWORD`. Без них установщик не подписан.
- Android: `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`,
  `ANDROID_KEY_ALIAS` и `ANDROID_KEY_PASSWORD`. Для обновлений используйте то же
  хранилище ключей.
- TestFlight: переменная репозитория `AGENTICOS_TESTFLIGHT_ENABLED=true`; секреты
  `IOS_CERTIFICATE_BASE64`, `IOS_CERTIFICATE_PASSWORD`, `IOS_PROFILES_BASE64_JSON`
  (массив JSON из профилей base64 для приложения, виджетов и расширения «Поделиться»),
  `APP_STORE_CONNECT_KEY_P8`, `APP_STORE_CONNECT_KEY_ID`,
  `APP_STORE_CONNECT_ISSUER_ID` и `APPLE_TEAM_ID`. Сначала создайте идентификаторы
  приложения, общую группу приложений (App Group) и приложение в App Store Connect.
  Для push-уведомлений по-прежнему нужны существующие учётные данные развёртывания APNs.

Учётные данные магазинов остаются в CI; задачи выпуска удаляют временные файлы подписи. Загрузка в TestFlight остаётся отключённой, пока её явно не включат. Одобрение магазина, профили подготовки и доставка на подписанные устройства требуют учётных записей оператора и не могут быть проверены неподписанной локальной сборкой.

## Итог { #recap }

- **Консоль остаётся на сервере.** Оболочка её открывает; ничего не встроено.
- **Нативно там, где это важно.** Меню, уведомления, закреплённые агенты, Blobby,
  «Быстрый вопрос» и голос откуда угодно.
- **Ваши агенты могут работать на этом компьютере** — в папках, которые вы выбрали, в
  режимах, которые вы выбрали, в песочнице операционной системы и только для ваших
  собственных запусков.
- **И на его экране** — с предварительным разрешением, в рамке во время работы и с
  остановкой одним сочетанием клавиш.

«Быстрый вопрос» поддерживает до восьми независимых вкладок в каждом окне. Панель вкладок хранит черновики, вложения, выбранных агентов и текущие ответы раздельно. «Недавние диалоги» открывает список с поиском и переиспользует уже открытую вкладку; сохранённые чаты восстанавливают сообщения и предлагают более раннюю историю. Неактивные вкладки не перехватывают перетаскивание файлов, сочетания диктовки и фокус. «Недавние диалоги» показывает аватары агентов в компактном раскрывающемся разделе. Список занимает только нужное место и не резервирует пустую высоту окна. Новый чат — единственное действие для открытия новой вкладки. Боковая панель браузера предлагает скачать приложение; если её закрыть, напоминания приостанавливаются на 14 дней для этой учётной записи в браузере.

В «Быстром вопросе» есть кнопка микрофона для диктовки по нажатию, а не только «нажми и
говори», и те же элементы управления голосовым звонком в реальном времени, что в чате.
Звонки используют транспорт, настроенный у выбранного агента, показывают субтитры,
согласования и вопросы и сохраняют произнесённые ходы в диалоге. Отправка текста и диктовка
ждут, пока идёт звонок. Уход с вкладки или смена её агента завершает звонок и освобождает
микрофон.

## Локальные автоматизации { #local-routines }

Отказ от заменяющего компьютера не доказывает, что одобренный компьютер потерял разрешение: он мог просто быть не в сети. Владелец получает уведомление без дубликатов — переподключиться или проверить доступ, — а автоматизация и данные её событий продолжают ждать. Отказ от изначально выбранного активного сеанса всё же останавливает автоматизацию для проверки.

В Linux приложение проверяет, что установленный bubblewrap объявляет `--bind-fd`, прежде чем предложить запись в папку или запустить команду в песочнице. Отсутствующие, неподдерживаемые и неотвечающие сборки отклоняются; обновите bubblewrap, чтобы включить этот режим.

JSON-файл разрешений автоматизации сверяется с его текущим отпечатком SHA-256 в связке ключей операционной системы. Правка файла или восстановление копии, сделанной до отзыва, доступ не даёт. Недоступная связка ключей или несовпадение блокируют доступ автоматизации. **Обновление:** у старых разрешений автоматизаций нет отпечатка, и им нужно новое одобрение: явно отвяжите компьютер, привяжите его снова и проверьте его автоматизации. Тот же сброс восстанавливает прерванную запись разрешений; приложение никогда не доверяет непроверенному хранилищу автоматически.

Создайте локальную автоматизацию с **Запускать от моего имени** (Run as me), выберите её папку и отдельно отметьте доступ на чтение, запись и выполнение команд. Команды требуют доступа на запись. При сохранении сначала создаётся приостановленная автоматизация. В первый раз приложение для компьютера один раз спрашивает в системном диалоге, можно ли **всем вашим автоматизациям** в этой организации работать в этой папке и в папках внутри неё с этими операциями; для всего компьютера выберите свой домашний каталог.

Каждая следующая автоматизация в этой папке — сейчас или позже — сохраняется без вопросов, а разрешение действует после обновления приложения и после повторного входа. Отмена оставляет ту же автоматизацию приостановленной; повторная попытка завершает её настройку, не создавая ещё одну. Общий доступ к папке из чата никогда не даёт разрешения автоматизации.

**Настройки → Приложение для компьютера → Разрешения автоматизаций** (Settings → Desktop → Routine permissions) перечисляет выданные доступы текущей учётной записи и организации на этом компьютере. Отзовите нужный, чтобы остановить будущие операции. Смена сервера или учётной записи очищает их; разрешение для одной автоматизации, выданное старым приложением, тоже заканчивается вместе с его сеансом. Смена папки или расширение операций требует нового системного подтверждения. Браузер, экран, локальные модели, локальные MCP-сервисы и доступ ко всему компьютеру не входят в доступ к папке автоматизации. Опубликованный агент должен уже включать «Песочницу»; выбор локальной цели не включает возможности.

Когда именно одобренный компьютер недоступен перед выполнением, в PostgreSQL ждёт сохраняемая активация. Строка автоматизации показывает число ожидающих. Запланированные и ручные срабатывания во время ожидания объединяются; разные входящие события сохраняют собственный контекст и идентификатор активации. Существующий воркер, работающий раз в минуту, проверяет переподключение. Проверки готовности, пока компьютер не в сети, не вызывают модель и не расходуют попытки сбоя отправки. Допуск запуска фиксируется в транзакции вместе с запуском до первого вызова модели. Начатая активация никогда не воспроизводится автоматически после сбоя воркера; неопределённая файловая операция или операция оболочки никогда не превращается в новый запуск.

Пауза, смена задачи или системных прав, удаление автоматизации или её завершение отменяют старую ожидающую работу, а не переносят её в другую папку. Отозванный сеанс устройства требует проверки. Три отправки до допуска, оставшиеся без повторов или пропавшие, останавливают автоматизацию и создают инцидент у владельца; контекст неудачного события остаётся доступным в выгрузке данных владельца. Завершённые и отменённые контексты очищаются сразу. Метаданные завершённого ожидания и неудачный контекст подчиняются сроку хранения истории запусков организации; активные ожидания без сети остаются до допуска, отмены или удаления.

Развёртывайте API, воркеры и приложение для компьютера вместе и дождитесь завершения работы старых воркеров, прежде чем включать этот контракт. Старые приложения не могут подтверждать разрешения автоматизаций; унаследованные локальные автоматизации требуют явной проверки. Миграция `0272_routine_device_waits.py` добавляет ожидания, не меняя идентичность автоматизации. Перед откатом приостановите локальные автоматизации и доработайте их задачи: откат удаляет контекст ожидающих активаций и не запускает его снова. Существующие отложенные локальные запуски без снимка нативной цели требуют нового запуска.

Выбор локального доступа принадлежит выбранному агенту, а не глобальному значению по умолчанию, которое наследуют другие агенты. Отзыв папки также удаляет запомненный выбор и согласия для работы с кодом для папок внутри неё. Старые приложения для компьютера сохраняют согласие на весь компьютер в пределах одного диалога; обновите приложение, чтобы оно запоминало его между диалогами агента.

Пока идут локальные сеансы работы с кодом, запись `[session:api] Use the EU numbers` направляется в сеанс с именем `api`. При одном активном сеансе поправка без адресата попадает в него; при нескольких она остаётся у родительского агента, чтобы не изменить постороннюю задачу. Родитель записывает поправку один раз, когда продолжает работу.

 Задачи работы с кодом в песочнице в одном наборе инструментов встают в очередь, чтобы их снимки рабочего пространства не перекрывались; независимые локальные сеансы всё равно идут параллельно.
