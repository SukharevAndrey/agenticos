# Приложения { #artifacts }

**Приложение** — это страница, которую опубликовал агент: отчёт, небольшая
панель, сводка на одну страницу, которую кто-то открывает в браузере. У неё есть
ссылка, которая остаётся прежней, когда агент публикует страницу снова, поэтому
«каждый понедельник публикуй цифры недели на эту страницу» — это одна ссылка,
которую люди добавляют в закладки, а не новая каждую неделю.

Приложение — не файл. График, сгенерированный PDF-файл и файл рабочего пространства
уже живут в чате и в [рабочем пространстве](sandbox.md). Приложение — это то,
что *отдаётся*: у него есть владелец, видимость и выданные доступы, как у агента
или навыка, и ему можно дать публичную ссылку для того, у кого нет учётной записи.

## Подпись на общих страницах { #shared-page-attribution }

Публичные страницы приложений по умолчанию показывают плавающий значок с логотипом
AgenticOS и ссылкой на GitHub. Общие страницы диалогов показывают тот же значок под
диалогом. Owner или Admin может скрыть подпись для всей организации в
**Настройки организации → Бюджет и согласования → AgenticOS на публичных страницах**
(Organization settings → Governance → AgenticOS on shared pages). Следующая загрузка
страницы использует текущую настройку. Приложения, защищённые паролем, показывают
подпись только после разблокировки. Подпись принадлежит окну просмотра;
скачанные файлы и встроенное содержимое приложения не изменяются.

## Внешний вид приложения { #app-appearance }

Окно просмотра приложения для вошедших пользователей и его публичная
ссылка имеют независимые переключатели **Светлая** и **Тёмная**. Приложения
открываются со светлой темой независимо от темы консоли или операционной системы. Переключение меняет только
предпочтение `prefers-color-scheme` встроенной страницы: оно не перезагружает
приложение и не перезаписывает его HTML, CSS или сохранённые версии. Приложение с
фиксированными цветами сохраняет эти цвета; приложения, поддерживающие оба режима,
могут откликаться на выбранное предпочтение.

Контраст по-прежнему на совести страницы. В поставляемых стилях страницы
`--ao-muted` — цвет фона; вторичный текст использует `--ao-muted-fg` или класс
`.ao-muted`. Если использовать токен фона как цвет текста, он может оказаться
нечитаемым в любом режиме.

## Публикация { #publishing-one }

Включите у агента возможность **Приложения** (Apps). Она добавляет пять
инструментов: `publish_artifact`, который модель вызывает, когда результат стоит
открыть, а не прочитать один раз в чате; `read_artifact`, который читает
опубликованную страницу обратно; `list_artifacts`, который перечисляет страницы,
которые запуск может открыть; и `preview_artifact`, который рисует страницу и
говорит, что в ней пошло не так.

Страница берётся из одного из трёх мест:

- **Файл в рабочем пространстве агента**, с расширением `.html` или `.md`. Это
  обычный случай для агента с возможностью [Песочница](reference/capabilities.md#files-shell):
  он пишет `report.html`, запускает то, что его собирает, и затем публикует файл.
  Байты читаются через собственный бэкенд рабочего пространства запуска, поэтому
  это работает на любом бэкенде песочницы.
- **Страница, переданная внутри вызова** — для агента без рабочего пространства или для
  короткой страницы.
- **Правки уже опубликованной страницы** под этим именем — см. ниже.

Чат показывает карточку опубликованной страницы. Карточка ссылается на версию,
которую опубликовал *этот* запуск, поэтому, читая диалог позже, вы всё ещё видите
то, что было опубликовано в нём, а не то, что страница показывает сегодня.

### Изменение части страницы { #changing-part-of-a-page }

Из-за одного изменённого слова не нужно заново публиковать всю страницу. Агент вызывает
`read_artifact` с именем страницы, и тот возвращает текущую версию в том виде, в
каком она была написана, затем — `publish_artifact` с тем же именем и `edits`:
точные замены, применяемые по порядку. Каждая замена должна совпасть ровно с одним
местом в странице; промах или неоднозначное совпадение возвращается модели, чтобы
она его исправила. Результат — новая версия, как и любая другая.

Правки несут версию, против которой они сделаны. Если между ними публиковал другой
запуск, ничего не записывается, а модели сообщают, что страницу нужно перечитать, поэтому
отредактированная копия более старой страницы никогда не заменяет более новую.
Чтение подчиняется тому же правилу, что и открытие страницы в консоли: тот, от
чьего имени действует запуск, должен иметь право её открыть. Страница длиннее
100 000 символов возвращается обрезанной, и об этом сказано; правка всё равно может
указать текст за пределами обрезки.

### Как снова найти страницу { #finding-a-page-again }

Каждое сообщение — новый запуск, а запуск видит прошлые ходы только как текст,
поэтому модель не помнит имена, под которыми публиковала. `list_artifacts`
перечисляет страницы агента в окружении запуска, сначала новые, не более 50: у
каждой — имя, заголовок, текущая версия, формат, привязки к актуальным данным,
видимость, включена ли публичная ссылка, когда она была опубликована, ссылка на неё
в консоли и `may_edit` — обновит ли публикация под этим именем из этого запуска страницу, а
не будет отклонена. Модель проверяет его, прежде чем выбрать новое имя.

Список читается от имени того, для кого выполняется запуск, по правилу консоли: его
собственные страницы, страницы организации и те, к которым ему открыли доступ,
или все страницы для роли, которая видит все страницы. В групповом чате канал видит
только страницы, доступные всей организации: никогда — личные страницы или страницы команды
говорящего, и никогда — страницу, открытую только говорящему. Способ доступа,
при котором никто не вошёл в систему, например публичный виджет, ничего не перечисляет.

## Актуальные данные { #live-data }

Страница может показывать записи из [виртуальных таблиц](virtual-tables.md), которые
остаются актуальными, вместо копии, с которой она была опубликована. Агент передаёт
`bindings` в `publish_artifact`: каждая привязка — это имя и **запрос страницы** —
таблица, поля, которые страница из неё читает, а также, необязательно, фильтры, сортировка и
лимит. Страница вызывает `agenticos.onData(render)`, и `render(data)` выполняется с
первыми данными и снова при каждом обновлении. `agenticos.data` — это Promise первых
данных.

```js
agenticos.onData((data) => {
  // data.tickets = { status, records, fields, count, truncated, limit }
});
```

Каждая привязка приходит как `status` (`ok` или `unavailable`), `records`
(`{id, <field>: value}`), `fields` (метка, тип, варианты и состояние для каждого),
`count`, `truncated` и `limit`. Страница, не получившая ответа за 10 секунд, видит
каждую привязку как `unavailable`; обработчик, добавленный после этого, запрашивает
ещё раз.

**Все, кто открывает страницу с актуальными данными, читают одни и те же записи**, каким бы ни был
их собственный доступ к таблицам. Запрос читается с доступом
[владельца](#who-owns-a-page) страницы, и только после того, как владелец согласился
им поделиться ([согласие](#consent-the-owner-decides-who-reads-the-data)). Поэтому
страница — для данных, которые может видеть каждый, кто может её открыть. Записи
читаются, когда кто-то просматривает страницу, и никогда не хранятся в ней.

### Что замораживает привязка { #what-a-binding-freezes }

Запрос страницы — не ссылка на сохранённое представление. Агент называет `table`
или [сохранённое представление](virtual-tables.md#saved-views) по id или точному
имени, и платформа **копирует** фильтры и сортировку представления в
страницу при публикации. Правка или удаление представления позже ничего не меняет на
странице.

| В привязке | Значение |
|---|---|
| `table` или `view` | Таблица, которую читать, или представление, чьи фильтры и сортировка копируются. Не то и другое одновременно |
| `fields` | Каждое имя, которое читает страница, сопоставленное столбцу по id или метке |
| `filters` | `{column, op, value}`, и все они должны выполняться; добавляются к фильтрам представления |
| `sort` | `{by, direction}`; заменяет сортировку представления |
| `limit` | Не более 1 000, что и есть значение по умолчанию; заменяет лимит представления |

`visible_columns` и `group_by` представления игнорируются: столбцы решают `fields`
привязки. Фильтр может называть столбец, который страница не читает, и владельцу
говорят, какой. В запросе страницы нет поиска по свободному тексту, поэтому
представление, в котором есть поиск, **нельзя привязать**: публикация отклоняется, и в ответе он назван. Представление, чей фильтр называет исчезнувший столбец, отклоняется
так же.

Формулы, подстановки, сводные значения и метки связей разрешены. Они читают больше,
чем столбец, который называет страница, поэтому запрос записывает всё, до чего
доходит: входные столбцы формулы, связь и цель подстановки или сводного значения,
каждую связанную таблицу и столбец, которым каждая связанная таблица подписывает
свои записи. Спецификация агента должна давать право на чтение этой таблицы, а человек, стоящий за
запуском, должен читать каждую таблицу, до которой доходит запрос, потому что никто
не может привязать то, что не может прочитать.

Результат публикации описывает каждый запрос словами — его таблицу, фильтры,
порядок, лимит и каждое поле с тем, что оно читает (`Status (single_select)`, `Pay band:
formula over Salary, Level`). Это тот текст, на который соглашается
владелец, поэтому агент проверяет, что текст описывает именно то, что он задумал. Привязка,
перенесённая без изменений, говорит `kept`.

Имя привязки — строчные буквы, цифры и `_`. Имя поля можно записать так, как подписан
его столбец: слова из букв в любом регистре, цифры и `_`, с одиночными пробелами
между ними, например `Status` или `Created At`. Оба — не длиннее 64 символов, и
`__proto__`, `constructor` и `prototype` зарезервированы для обоих (`id` — тоже, для
поля). У страницы не более 5 привязок, у привязки — не более 50 полей.

Версия 3 [набора для страниц](#the-library-set) рисует привязку за агента:
`AO.records("#tickets", data.tickets)` внутри `agenticos.onData` рисует записи как
таблицу с шапкой из меток полей, с числами и датами по правому краю, с вариантами в
виде значков и с каждым значением, записанным как текст. До данных он показывает
строку загрузки, а привязка в состоянии `unavailable`, пустая привязка и обрезанный
список получают каждое своё сообщение. `AO.onData` в версии 3 — тот же вызов, что и
`agenticos.onData`. Связанная страница, чей скрипт так и не запрашивает свои данные,
всё равно публикуется, но с
[предупреждением](#the-page-contract-and-the-publish-warnings).

### Журнал сценария как актуальные данные { #a-workflows-log }

Привязка может также читать журнал [сценария](workflows.md) — строки, которые
записали быстрые журналы его шагов, — чтобы построить панель на странице, которая
остаётся актуальной. Дайте привязке `"kind": "workflow_log"` (привязка без `kind`
читает таблицу, как это делала каждая привязка, опубликованная до этого). Это второй
вид запроса страницы, и он подчиняется тем же правилам: он разрешается при
публикации страницы, замораживается, читается с доступом
[владельца](#who-owns-a-page) страницы и только после
[подтверждения](#consent-the-owner-decides-who-reads-the-data).

| В привязке | Значение |
|---|---|
| `workflow` | id или точное имя сценария. Он должен быть одним из тех, что привязывает возможность **Сценарии** (Workflows) агента, как для [действия](#actions), и человек, стоящий за запуском, должен иметь возможность его просматривать — а также владелец страницы, когда публикация меняет привязку |
| `step` | Необязательно: только строки этого шага — по id шага, его метке или, для шага без метки, по имени его вида, например `Send email`, когда это однозначно. Он должен быть в действующей версии или в черновике. Шаг без быстрого журнала разрешён, и результат публикации отмечает, что строк он читать не будет |
| `outcomes` | Необязательно: только строки, вышедшие через один из них — порт или `error`. Подходит любой из них, а строка, вышедшая через несколько портов и сохранённая как `a, b`, считается по каждому из них |
| `run` | Необязательно: id запуска либо 4 и более символов, с которых он начинается |
| `include_test` | Строки, записанные и тестовыми запусками. По умолчанию выключено |
| `lines` | Отдать N самых новых строк, сначала новые. До 500 в одной привязке; собственный маршрут журнала отдаёт по 100 за раз |
| `per_day` с `days` и `tz` | Вместо этого отдать количество строк по дням и исходам: `days` — 7, 30 или 90, включая сегодняшний день, а `tz` — имя IANA (по умолчанию UTC), по чьим дням идёт подсчёт |

Дайте `lines` или `per_day`, но не оба. Это фильтры и лимиты
`GET /workflows/{id}/logs` и `GET /workflows/{id}/logs/summary`, обслуживаемые одним
и тем же кодом. Сценарий и шаг разрешаются в id при публикации страницы и хранятся
вместе с фильтрами: переименование сценария или шага позже ничего не меняет на
странице. Неизвестный сценарий, тот, что агент не привязывает, или тот, что человек
не может просматривать (обо всех них говорят одинаково, чтобы отказ никогда не
подтверждал существование), неизвестный шаг, не выполняющийся фильтр или лимит
больше 500 отклоняют публикацию, и сообщение говорит, что именно.

Страница получает это через тот же вызов `agenticos.onData`. С `lines` привязка
приходит как `status`, `records` (каждая — `{id, created_at, step, outcome, status, message, run_id}`), `count`, `truncated` и `limit`, обрезанная по лимитам страницы на записи и
байты, как у таблицы. С `per_day` она приходит как `status`, `days` (каждый
день окна, сначала старые, каждый — `{day, counts: {outcome: n}}`), `total`,
`window_days` и `tz`, без лимита записей.

```js
agenticos.onData((data) => {
  const week = data.errors_per_day;
  if (week.status !== "ok") return;
  AO.chart("#errors", {
    type: "bar",
    data: {
      labels: week.days.map((d) => d.day),
      datasets: [{ label: "Errors", data: week.days.map((d) => d.counts.error ?? 0) }],
    },
  });
});
```

опубликованной с `bindings: {"errors_per_day": {"kind": "workflow_log", "workflow": "Order intake", "outcomes": ["error"], "per_day": true, "days": 30, "tz": "Europe/Warsaw"}}`.

Результат публикации и подтверждение владельца описывают это словами: какой сценарий,
какие фильтры и отдаёт ли он N самых новых строк или считает по дням за D дней.

Любое изменение привязки к журналу — сценарий, шаг, исходы, запуск, тестовые строки,
строки или подсчёт по дням, лимит, дни или часовой пояс — меняет запросы страницы,
поэтому оно снова требует подтверждения владельца, а
[проверка изменения данных](#consent-the-owner-decides-who-reads-the-data) отмечает
его как показывающий больше данных.

У журнала нет столбцов, поэтому он не может разойтись; вместо этого привязка
становится `unavailable`, когда владелец больше не может просматривать сценарий
(`creator_lost_access`) или шага в нём больше нет (`source_changed` с указанием
`step`). Два ограничения отличаются от табличных: страница, читающая журнал, **не
может иметь публичную ссылку**: публикация привязки к журналу отклоняется, пока
ссылка включена; ссылку нельзя включить или закрепить на версии, читающей журнал; и
такую версию нельзя восстановить, пока ссылка включена. Привязка к журналу никогда
не отдаётся на публичной странице.

Роли, читающие все таблицы, читают и журнал страницы без подтверждения, но только если
они видят все сценарии — а это так для каждой встроенной роли, читающей все таблицы;
та, для которой это не так, ждёт подтверждения владельца, как редактор.

### Кто что видит { #who-sees-what }

Какую версию получает читатель и читаются ли для него её данные, зависит от того, кто он.

| Кто открывает | Что получает | Его данные |
|---|---|---|
| Владелец страницы | Последнюю версию | Всегда |
| Owner, Admin, Builder и Operator, даже с доступом только на просмотр | Последнюю версию | Всегда, для ролей, которые читают каждую таблицу (`tables:view` на уровне ALL) |
| Все остальные, кто может редактировать страницу | Последнюю версию, чтобы агент редактора продолжал править актуальное | Пока действует подтверждение владельца для этой версии |
| Все остальные, кто может её открыть (**аудитория**) | Самую новую версию, на которую когда-либо дали подтверждение или которая не читает данные | Пока действует подтверждение владельца для неё |

Аудитория никогда не получает версию, которую никто не согласился открыть. Когда подтверждение данных больше не действует — редактор его отозвал или сменился владелец, — аудитория всё равно получает **всю страницу целиком**, а каждая привязка приходит со статусом `unavailable` и причиной `awaiting_consent`; страница пишет: «Данные появятся, когда владелец страницы их подтвердит.» Если ни одна версия не подтверждена и не свободна от данных, аудитория видит «Эта страница пока недоступна» и больше ничего.

Привязка также приходит со статусом `unavailable`, когда то, что она читает, изменилось после публикации страницы. Причину сообщают только тому, кто может редактировать страницу; читатель видит, сколько источников недоступно.

| Причина | Что произошло |
|---|---|
| `creator_gone` | Владелец страницы больше не активный участник |
| `creator_lost_access` | Владелец больше не может читать таблицу, до которой доходит запрос, или смотреть сценарий, журнал которого она читает |
| `source_changed` | Шаг привязки к журналу сценария больше не входит в сценарий (указан `step`), либо изменился смысл столбца (его тип, формула, цель связи или подстановки, агрегат, архивный или восстановленный вариант), либо столбец или таблицу переместили в архив, либо связанная таблица теперь подписывает записи другим столбцом. Указано текущее название столбца |
| `awaiting_consent` | Владелец не подтвердил показ данных этой версии или подтверждение отозвано |
| `public_link` | Привязку к журналу сценария запросили на публичной странице, где журнал не показывается никогда |

Если одна привязка становится `unavailable`, остальные продолжают работать. Изменение таблицы никогда не блокирует страницу: ничто не мешает изменить столбец, а привязка перестаёт отдавать данные, пока агент не опубликует страницу снова, — тогда запрос разрешается по таблице в её текущем виде. Переименование столбца не меняет привязку: страница продолжает читать его под именем, которое дал агент. Добавление варианта в список или его переименование тоже ничего не меняет.

### Подтверждение: владелец решает, кто читает данные { #consent-the-owner-decides-who-reads-the-data }

Данные страницы читаются с доступом её владельца, поэтому владелец решает, кто ещё их читает, — для каждой версии отдельно. Это решение и есть **подтверждение**: владелец просматривает запросы страницы словами — таблицу каждого запроса, условия, порядок, лимит и столбцы, каждую связанную таблицу, до которой доходит запрос, и кто будет это читать, — и подтверждает.

Проверка называет, кто увидит страницу: роли, которые видят каждую страницу (Owner, Admin, Builder и Operator), видимость страницы, люди, с которыми она открыта, и группы, включая будущих участников. Владелец может подтвердить только то, что читает сам.

Данные версии находятся в одном из состояний:

| Состояние | Значение |
|---|---|
| `not_needed` | В версии нет привязок |
| `pending` | Никто её не подтвердил. Аудитория сохраняет прежнюю версию |
| `consented` | Владелец её подтвердил, или она подтверждена автоматически |
| `declined` | Запрос на её подтверждение отклонили |
| `withdrawn` | Подтверждение больше не действует: редактор его отозвал или владелец больше не владелец страницы |

Новая версия подтверждается **автоматически**, когда её запросы страницы — и всё, до чего они доходят, — те же, которые владелец уже подтвердил. Иначе она остаётся `pending`, в том числе первая привязанная версия, если у владельца не включено [автоматическое подтверждение](#auto-consent).

Подтверждает в окне просмотра сам владелец — только он и от своего имени. Пока последняя версия ждёт, полоса под заголовком страницы сообщает об этом и предлагает **Подтвердить данные** (Confirm data): открывается то, что версия показывает и кому, а само подтверждение несёт отпечаток ровно того, что было показано. Если страницу успели опубликовать заново или её запросы изменились, подтверждение отклоняется, и владелец смотрит снова. Подтверждение также проверяет, что владелец по-прежнему может читать каждую таблицу, до которой доходит запрос.

Owner или Admin может подтвердить за владельца. В аудите это записывается как подтверждение, данное ими за владельца, и данные по-прежнему опираются на доступ владельца. Тот, у кого есть выданный доступ `edit`, этого не может: доступ на редактирование страницы не даёт власти над тем, чьи данные она читает.

**Отзыв** забирает подтверждение обратно. Любой, кто может редактировать страницу, от своего имени выбирает **Перестать показывать данные** (Stop sharing data) в меню окна просмотра. Все выданные до сих пор подтверждения аннулируются, не только последнее, и автоматическое подтверждение выключается. Каждый выданный доступ `edit_data` на странице понижается до `edit`, поэтому следующая повторная публикация редактора данных ждёт владельца, а не отменяет отзыв. Аудитория сохраняет страницу и теряет её данные, пока владелец не подтвердит снова. Отзыв только сужает круг читающих, поэтому его может выполнить любой редактор.

Когда владелец покидает организацию, его подтверждения истекают вместе с его членством. Владелец, которого удалили и пригласили снова, начинает с чистого листа. Владелец, которого деактивировали и снова активировали, возвращает свои подтверждения: повторная активация действует на всю учётную запись — во всех организациях, к которым она относится.

#### Повторная публикация { #republishing }

Когда редактор, не владелец, публикует версию, которая читает другие данные, версия остаётся `pending`, а платформа создаёт для владельца **запрос на версию** — см. [Запросы](#share-requests). Пока владелец не решит, аудитория по-прежнему видит прежнюю версию. Результат публикации сообщает: «Аудитория по-прежнему видит v2, пока Alex не подтвердит данные этой версии в консоли» (с именем владельца или «владелец страницы»).

Запуск, за которым не стоит человек, может переопубликовать привязанную страницу только без изменений — те же байты и те же запросы, для чего не нужен ни человек, ни подтверждение. Он не может подменить код, который получает записи владельца. Публикация редактора отклоняется, когда владелец страницы не может прочитать таблицу, до которой доходит запрос.

#### Автоматическое подтверждение { #auto-consent }

Владелец может включить для страницы **Автоматически показывать данные новых версий** (Share new versions automatically). По умолчанию это выключено, и включает это только сам владелец от своего имени, никогда не агент. Сначала консоль спрашивает: «Любое изменение данных этой страницы вашими запусками, включая новые таблицы и столбцы, увидят все, кто может её открыть, без вашего подтверждения. Это касается и запусков через API.» Запись в аудите хранит подтверждённый текст.

Оно распространяется только на собственные повторные публикации владельца. Повторная публикация редактора всё равно ждёт. Автоматические подтверждения записываются как автоматические, и когда одно из них показывает больше, чем версия, которую отдавали до него, полоса владельца перечисляет это: «v4 открыта автоматически и показывает больше данных: +Deals, +Salary». Выключает его владелец или Owner/Admin, а отзыв или передача страницы другому выключают его тоже.

Оно никогда не распространяется на запуск, начатый, пока администратор действовал от имени владельца, как бы поздно он ни публиковал: фоновый запуск, шаг сценария или запуск, возобновлённый после согласования, несёт это с собой, и то же касается доступа редактора данных (ниже). Повторная публикация запросов, которые владелец уже подтвердил, по-прежнему подтверждена.

#### Редакторы данных { #data-editors }

В диалоге доступа есть уровень выданного доступа выше `edit`: **Может редактировать, включая данные** (Can edit, including data; `edit_data`), только для страниц. Это постоянное подтверждение на повторные публикации этого человека, включая изменение запроса. Выдаёт его только владелец или Owner/Admin, от своего имени, после предупреждения: «Alex может менять данные, которые все видят на этой странице, включая новые таблицы и столбцы, не спрашивая вас. Это касается и его запусков через API.» Для группы предупреждение говорит: «Любой в Sales, сейчас или позже, может менять…». Выданный доступ записывается в аудит вместе с подтверждённым текстом.

Повторная публикация человека с `edit_data` подтверждается автоматически и записывается как сделанная через его доступ. Ему по-прежнему нужно читать каждую таблицу, до которой доходит запрос, — как и владельцу. Область действия роли Owner или Admin этого никогда не подразумевает. Любой, кто может редактировать страницу, понижает или снимает этот доступ, а смена владельца понижает каждый доступ `edit_data` до `edit`.

### Кто владеет страницей { #who-owns-a-page }

Владелец страницы — тот, от имени кого работал первый запуск, опубликовавший её. Он никогда не меняется сам по себе, и он единственный владелец данных страницы: человек, с чьим доступом читаются данные и с чьим подтверждением они показываются. Если владельца удалили, владельца у страницы нет. Завладеть страницей нельзя.

Владелец передаёт её другому активному участнику организации через **Сменить владельца** (Change owner) в меню окна просмотра, а Owner или Admin может переназначить любую страницу, включая ту, чей владелец пропал. Каждый делает это от своего имени, а не войдя от имени другого пользователя. Выданный доступ на редактирование страницы этого не позволяет. Инструмента для этого у агента нет.

Смена происходит сразу, без шага принятия. Данные страницы перестают доходить до аудитории, пока новый владелец их не подтвердит; все прежние подтверждения аннулируются навсегда (поэтому возврат страницы никогда не оживляет старое), автоматическое подтверждение выключается, любой ожидающий запрос аннулируется, каждый доступ `edit_data` понижается до `edit`, а старый и новый владелец получают уведомление — кроме того, кто выполнил смену. Это записывается в аудит как `artifact.owner_changed`.

Выдать странице без владельца видимость `private` — значит перехватить её, и это доступно только Owner или Admin. Действуют те же правила.

### Запросы { #share-requests }

Расширение круга тех, кто может открыть страницу, читающую данные, — более широкая видимость, новый выданный доступ или более высокий уровень, — решает владелец, а за него Owner или Admin. Сужать может любой редактор. Страница, которая не читает данные, подчиняется обычным правилам доступа.

Любой другой, кто может редактировать страницу и пытается её расширить, не получает отказа. Платформа создаёт запрос. Их три вида:

| Вид | Кто создаёт | О чём просит |
|---|---|---|
| `audience` | Редактор — в диалоге доступа или через `share_artifact` своего агента | Открыть страницу большему числу людей |
| `access` | Участник организации страницы, который открывает её ссылку без доступа | Открыть страницу; можно приложить примечание |
| `version` | Публикация другого редактора, чья версия читает другие данные | Подтвердить эту версию |

У участника может быть один ожидающий запрос `audience` и один ожидающий запрос `access` на странице, а у страницы — один ожидающий запрос `version`; более новый заменяет старый. По умолчанию запросы ограничены десятью в час на человека в организации ([`RATE_LIMIT_ARTIFACT_SHARE_REQUESTS_PER_HOUR`](configuration.md)). Запрос `version` тоже расходует лимит публикующего: сверх него повторная публикация всё равно заменяет ожидающий запрос, но владелец больше не получает уведомление.

Решает владелец страницы. Когда владельца не осталось, отклонить могут Owner и Admin; чтобы одобрить, они сначала передают страницу участнику (**Сменить владельца**), и тот подтверждает данные. Запрос аннулируется без решения, когда меняются запросы страницы, меняется владелец или страница перемещена в архив.

Владелец получает уведомление в консоли и по почте — как настроено в **Настройки → Уведомления** (Settings → Notifications) («Запросы по страницам»). Уведомление называет страницу и того, кто просит, но никогда её данные.

Ответы даются в разделе **Запросы** (Requests) диалога доступа, а кнопка **Запросы** в полосе на странице показывает, сколько их ждёт. Одобрение запроса `audience` или `access` применяет запрошенные видимость и выданные доступы — каждый только там, где он всё ещё расширяет доступ. **Данные оно никогда не подтверждает**: когда у версии, которую получает аудитория, нет действующего подтверждения, одобрение отклоняется с сообщением «Подтвердите данные страницы, прежде чем открывать к ней доступ», и владелец сначала подтверждает данные, а потом одобряет. Отклонение ничего не открывает.

Запрос `audience` или `access`, сделанный при членстве, которое уже закончилось — участника удалили и пригласили снова, — одобрить нельзя; отклоните его.

Список запросов (`GET /api/v1/artifacts/{id}/share-requests`) всегда содержит все ожидающие запросы. С `include_decided=true` он добавляет решённые и аннулированные, которые хранятся: сначала новые, по странице за раз с `skip` и `limit` (по умолчанию 50, максимум 100); `total` считает все, а диалог доступа сообщает, когда показывает только самые новые из решённых.

О решении тому, кто просил, не сообщают: ответ — страница открывается или нет. Страница, которая не читает данные, принимает обычный запрос `access`, и одобрить его может любой её редактор.

#### Запрос доступа { #requesting-access }

Участник организации, открывший ссылку страницы, которую не может открыть, видит «У вас нет доступа к этой странице», поле примечания и **Запросить доступ** (Request access). Больше ничего не раскрывается: ни заголовка, ни владельца, ни агента. Вышедший из системы посетитель или человек из другой организации получает обычное «не найдено».

#### Проверка изменённой версии { #reviewing-a-changed-version }

Запрос `version` открывает владельцу страницу в ожидающей версии, с её настоящими данными. Полоса говорит, кто изменил данные, которые показывает версия, и предлагает **Проверить изменение данных** (Review data change). Панель сравнивает запросы страницы этой версии с теми, что аудитория видит сейчас, — по каждой привязке и словами: столбцы, условия, порядок, лимит и связанные таблицы, добавленные, удалённые или изменённые, каждая помечена **Показывает больше** (Shows more), **Показывает меньше** (Shows less) или без изменений; новые привязки — с полным раскрытием, неизменённые — свёрнуты.

Переключатель **Что видят остальные** (What others see) показывает страницу такой, какой её видит аудитория. Панель называет, кто и когда опубликовал версию, и ссылается на диалог, если владелец может его открыть. **Одобрить** (Approve) подтверждает версию. **Отклонить** (Decline) оставляет аудитории прежнюю версию и помечает версию в её истории как `declined`; следующая повторная публикация спросит снова. В списке запросов запрос на версию предлагает **Проверить изменение данных**, а не «Одобрить»: подтверждение даётся из проверки.

### Открытие доступа к странице силами агента { #sharing-a-page-from-an-agent }

`share_artifact(name, visibility?, people?)` позволяет агенту попросить открыть страницу: `visibility` — это `team` или `org`, `people` — участники по полному имени или адресу почты и группы по названию, каждый запрашивается на уровне просмотра. Он **никогда ничего не открывает**. Он создаёт запрос `audience` от имени человека, для которого выполняется запуск, — включая запуск самого владельца — и отвечает: «Ждём, пока Alex одобрит это в диалоге доступа к странице». Одобряет человек в консоли, вошедший от своего имени, а не вызов инструмента.

Имя, которое никому не соответствует или соответствует нескольким людям, возвращается с сообщением, а не угадывается. Публичной ссылки он не просит: публичная ссылка настраивается только в консоли. Запуск, за которым нет человека, например от посетителя виджета, попросить не может.

### Что видит читатель { #what-the-viewer-sees }

Страница с привязками показывает значок **Данные из источников** (Live) на своей карточке, в виджете приложений на странице «Обзор» и в окне просмотра. В окне просмотра его точка пульсирует, пока приходят данные, и становится янтарной, когда часть источников недоступна этому читателю. Читатель, которому не доступен ни один источник, значка не видит — как и на старой версии.

В окне просмотра есть кнопка **Обновить** (Refresh): она читает данные заново и обновляет страницу, которая использует `agenticos.onData`, на месте, а в подсказке кнопки — когда данные читались в последний раз. Рядом меню автоматического обновления: выключено, каждую минуту, каждые 5 или 15 минут, каждый час. Каждый читатель выбирает своё, и выбор запоминается для страницы в этом браузере.

Автообновление ничего не делает, пока вкладка скрыта, и читает один раз, когда вкладка возвращается, если такт был пропущен. Оно останавливается, когда в данных отказано (страница для этого читателя пропала) и когда на странице нельзя прочитать ни один источник, — пока читатель не нажмёт **Обновить** и чтение не ответит. Сбой, который ничего не говорит о странице, например ошибка сервера, оставляет опрос включённым. Занятый ответ (429) повторяется дважды с интервалом в секунду, прежде чем читатель увидит «Сервер занят, повторите попытку через мгновение.»

Строка под полосой появляется, только когда что-то требует внимания: версия, ждущая подтверждения, запрос на проверку или источники, которые не читаются. Страница, в данных которой отказано, пишет: «Актуальные данные этой страницы вам недоступны.» Читатель, чьи источники не читаются, видит, сколько их («Вам недоступно 2 из 3 источников»). Редактор видит ещё и причину по каждому источнику, со ссылкой **Открыть таблицу** (Open the table) на привязанную таблицу.

Когда агент публикует новую версию, пока у кого-то открыта текущая, следующее чтение (обновление, ручное или автоматическое) переводит читателя на версию, которую он теперь получает: страница загружается заново, со своими данными. Читатель, выбравший версию в меню версий, остаётся на ней.

На старой версии актуальные данные не читаются. Страница пишет «Актуальные данные есть только в текущей версии.» и предлагает **Открыть текущую** (Open current), а редактору — ещё и **Восстановить** (Restore) для этой версии. Восстановление разрешает запросы данных версии по таблицам в их текущем виде, поэтому, если таблица изменилась, это новый запрос, и оно, как и любая другая повторная публикация, ждёт подтверждения.

### Как данные попадают на страницу { #how-the-data-reaches-the-page }

Открывая страницу, консоль запрашивает подписанный адрес, в котором указано, кто этот читатель. Маршрут содержимого читает каждую привязку **один раз, при загрузке**, и записывает результат в платформенный скрипт страницы, поэтому первый вызов `onData` уже имеет свои данные и никакого последующего обмена нет. [Публичная ссылка и встраивание](#live-data-on-a-public-link) записываются так же, но по более строгим правилам. Для миниатюры, карточки или версии из истории ничего не внедряется.

Обновление и автообновление продолжают использовать маршрут данных и `postMessage` из консоли, который теперь отдаёт одни и те же строки запроса страницы всем, кто получает эту версию. Маршрут никогда не кэшируется, адрес недолговечен, а содержимое записей не попадает в журналы. Привязка, которую не успели прочитать или которая упала в базе данных, внедряется как `unavailable`, и страница всё равно отрисовывается.

### Ограничения { #limits }

Каждый ответ ограничен, чтобы одна страница не уронила экземпляр:

| Ограничение | Значение |
|---|---|
| Привязок на страницу | 5 |
| Записей на привязку | 1 000 |
| Подготовленных данных на страницу | 4 МиБ, поровну между привязками |
| Один запрос | не больше 2 с |
| Одна страница | срок 5 с |
| Загрузки данных | 30 в минуту на читателя, одна загрузка одновременно на читателя и лимит на процесс |
| Чтения только причин (`rows=false`, полоса редактора) | Те же лимиты, но считаются отдельно от загрузок данных |
| Запросы на доступ | 10 в час на человека в организации (audience, access и version) |

Обрезанная привязка сообщает `truncated: true`, где `limit` равен `records` или `bytes`, а `count` — число отданных записей. `bytes` бывает и тогда, когда измеренная стоимость чтения закончилась раньше, чем подготовленные данные заполнили долю страницы.

Срок проверяется перед каждым запросом и ничего не отменяет: каждый запрос выполняется не дольше меньшего из 2 с и остатка от 5 с, а после исчерпания 5 с не начинается ни один, поэтому страница отвечает примерно за 5 с, а по часам может пройти около 7 с. Внедрённые загрузки, как и обновления, расходуют те же 30 в минуту. Сверх лимита частоты маршрут данных отвечает 429, консоль дважды повторяет занятый ответ, а страница, получившая свои данные, получает привязки со статусом `busy`. Когда Redis недоступен, нижняя граница лимита частоты и лимит одновременных чтений считаются на каждый воркер API, и лимит на процесс по-прежнему ограничивает каждый воркер.

### Кто может опубликовать привязанную страницу { #who-may-publish-a-bound-page }

Страница привязывается к таблице, только если спецификация публикующего агента даёт право на чтение этой таблицы, а человек, стоящий за запуском, читает каждую таблицу, до которой доходит запрос; это проверяется при публикации страницы или восстановлении версии. Последующий отзыв того или другого не останавливает уже опубликованные страницы; доступ владельца проверяется заново при каждой загрузке.

**Изменить** привязанную страницу может только запуск, действующий от имени участника (повторная публикация без изменений, с теми же байтами и запросами, человека не требует): участник, вошедший в систему (веб-чат, HTTP API), отправитель из привязанного канала или создатель расписания. Посетитель виджета, встраивания или размещённой страницы, отправитель из непривязанного канала и доставка события агенту (GitHub, почта, вебхук-ретранслятор) не считаются, как и запуск сценария, допущенный через публичный вход или где угодно в цепочке такого запуска.

## Действия { #actions }

Страница может запустить [сценарий](workflows.md), но только когда человек соглашается. Страница не действует: она просит, консоль показывает человеку, что произойдёт, и запуск принадлежит ему. Так страница становится небольшим приложением — форма, отправляющая заявку, кнопка, одобряющая счёт, — не имея при этом никакой собственной власти.

### Объявление действий { #declaring-actions }

Агент объявляет сценарии, которые страница может запускать, при публикации — аргументом `actions` у `publish_artifact`: до пяти записей, каждая — сценарий (его id или точное название) и **метка** — слово, которым страница его называет.

```json
{"actions": [{"workflow": "Approve invoice", "label": "Approve"}]}
```

Сценарий может быть действием, только если выполняется всё перечисленное:

- у публикующего агента он есть в [возможности «Сценарии»](reference/capabilities.md#workflows), так что то, что страница может запускать, входит в то, что проверил автор агента;
- он действующий (опубликован, не в архиве) и запускается триггером **Вручную** (Manual) или **API**;
- человек, стоящий за запуском, может его смотреть и запускать. На тот, который ему нельзя, отвечают так, будто он не привязан, поэтому отказ никогда не называет сценарий, которого человек не видит.

Метка — простой текст не длиннее 60 символов, из которого удалены управляющие и невидимые символы; пустая метка становится названием сценария. Если `actions` не указан, сохраняются действия текущей версии, а `[]` их убирает. Результат публикации перечисляет каждое объявленное действие словами или сообщает `kept`. У страницы Markdown действий быть не может. Запуск, за которым никого нет, не может добавлять или менять их и может только переопубликовать без изменений страницу, у которой они уже есть. Восстановление старой версии заново проверяет её действия по агенту в его нынешнем виде и отклоняется, если какое-то больше не выполняется.

Действия хранятся вместе с версией, поэтому новая версия заменяет весь список, а старая сохраняет свой. Последующее отвязывание сценария от агента не правит опубликованную версию; состояние самого сценария и доступ каждого читателя проверяются при каждом открытии страницы и снова при запуске.

### Кто какие действия видит { #who-sees-which-actions }

Открывая страницу, консоль перечисляет действия, которые объявляет **версия, которую получает читатель**, и которые он может запустить сейчас: каждое с настоящим названием сценария, меткой страницы и полями, которые запрашивает его триггер. То, которое читатель запустить не может, не показывается. Полоса на странице показывает **Эта страница может запускать: …** (This page can run) с названиями сценариев, и каждое — ссылка на запуски этого сценария. Если таких нет, не показывается ничего.

Страница не получает действий, а её вызов `run` сразу отклоняется, когда она показана:

- по публичной ссылке, во встраивании, в предпросмотре или в миниатюре карточки;
- как старая версия из истории или версия, которую этот читатель не получает (аудитория всё ещё ждёт подтверждения более новой);
- участнику, который не может запустить ни один из её сценариев, или сеансу, в котором вошли от имени другого пользователя.

Маршрут запуска отклоняет всё то же самое, так что страница, обошедшая консоль, ничего бы не выиграла.

### Запуск со страницы { #running-one-from-the-page }

На странице `agenticos.run(action, input)` — `AO.run` в [наборе для страниц](#the-library-set) — просит консоль запустить действие. `action` — это id сценария, метка страницы или название сценария. Консоль сначала сопоставляет id точно, затем метку, затем название, не учитывая регистр. Если на одной ступени подходят два действия, она не сопоставляется ни с чем и не передаёт поиск следующей. `input` — объект, содержащий ровно те значения, которые объявляет триггер сценария. Вызов возвращает Promise завершённого запуска, а `onRun` (`AO.onRun`) слышит каждое изменение по пути:

```js
AO.run("Approve", { invoice: "INV-204" }).then(
  (run) => show(run.status, run.output_text),
  (error) => show("not run", error.message),
);
```

Консоль ничего не запускает, пока человек не согласится. Каждый запуск, сколько бы их ни было до него, открывает диалог подтверждения:

- его заголовок — **собственное название сценария**, а метка страницы появляется только как цитата;
- он показывает каждое значение, которое отправляет страница, полностью и как текст, вместе с символами, которые ничего не рисуют или меняют порядок выводимого текста (`\u{202E}`);
- **Запустить** (Run) отключена полсекунды и никогда не получает фокус, чтобы клик, уже летящий к ней, не дал согласия; фокус — на кнопке **Отмена** (Cancel);
- одновременно открыт только один вопрос — и в диалогах запуска, и в диалогах ссылок, — а запрос, пришедший тем временем, отклоняется как `busy`;
- после **трёх отказов** на одно открытие страницы (перезагрузка фрейма счёт сохраняет) консоль перестаёт спрашивать и отклоняет дальнейшие запросы, пока страницу не откроют снова.

Запрос отклоняется без диалога, когда он слишком ранний (фрейм не загрузился), называет действие, которого страница не объявляет, не подходит под поля сценария или приходит не из собственного фрейма страницы с nonce, который консоль выпустила для этой загрузки. Сообщение из другого фрейма или от устаревшей страницы отбрасывается без ответа.

Promise отклоняется с ошибкой `Error`, чей `message` — короткий код, поэтому текст для страницы пишет она сама:

| Код | Когда |
|---|---|
| `cancelled` | Человек отклонил |
| `busy` | Был открыт другой вопрос |
| `too_many_cancels` | Три отказа; страницу больше не спрашивают, пока её не откроют снова |
| `not_ready` | Страница спросила до того, как загрузился её фрейм |
| `unknown_action` | Ни одно объявленное действие, которое читатель может запустить, не подходит |
| `invalid_input` | Значение отсутствует, неизвестно или не того типа; `error.problems` перечисляет `{field, kind}`, только когда проблему нашла консоль, и отсутствует, когда сервер ответил 422 |
| `rate_limited` | Слишком много запусков от этого человека или исчерпана квота допуска вызывающего или организации |
| `not_found`, `unavailable` | Действие исчезло, его больше нельзя запустить вручную или оно в архиве, либо страница здесь вообще не может запускать действия (публичная ссылка, встраивание, предпросмотр, история, читатель без запускаемого действия) |
| `failed` | Запуск не удалось начать или отследить |
| `page_changed` | Страница была заменена, пока вопрос был открыт |

### Что такое запуск { #what-the-run-is }

Запуск принадлежит **читателю**: он начинается с его разрешениями и расходует его бюджет, как если бы тот запустил сценарий из консоли. Его триггер — **App** (`app`), и он записывает страницу и версию, которую смотрел человек. Страница ничего не даёт; запуск отклоняется, когда человек не мог бы запустить его сам. Запуск, который ждёт согласования или того, чтобы кто-то на него посмотрел, остаётся в [истории запусков](workflows.md#running-a-workflow) сценария, а на странице появляется строка с **Открыть запуск** (Open run).

Странице никогда не отдают весь запуск. Она читает проекцию: статус, текст ответа, структурированный ответ без ссылок на файлы, первую строку ошибки (не больше 200 символов) и, пока запуск кого-то ждёт, путь к нему в консоли. Прочитать её может только тот, кто начал запуск, и только через страницу, которая его начала.

Консоль читает запуск с растущей задержкой и отправляет каждое изменение на страницу. Запуск, который кого-то ждёт, читается десять минут, пока вкладка видима. После этого promise страницы завершается последним состоянием, `paused: true` и без `finished`, и страница больше ничего не слышит; путь к запуску — это строка на странице. Перезагруженной или закрытой странице ничего не сообщается.

### Ограничения и аудит { #limits-and-audit }

| Ограничение | Значение |
|---|---|
| Действий на страницу | 5 |
| Метка | 60 символов |
| Запуски с одной страницы | 10 в минуту на человека и страницу (`RATE_LIMIT_ARTIFACT_ACTIONS_PER_MINUTE`) |
| Отклонений, после которых консоль перестаёт спрашивать | 3 на одно открытие страницы (перезагрузка фрейма счёт не сбрасывает) |
| Незавершённая работа | собственная квота допуска запусков сценариев, которая тоже отвечает `rate_limited` |

Сверх лимита человек видит сообщение, а страница получает `rate_limited`. Каждый запуск записывается в аудит как `artifact.action_started` с указанием страницы, версии, сценария и запуска — но никогда входных данных: они принадлежат человеку и находятся в самом запуске. См. [управление](governance.md#audit) и [страницу о безопасности](security.md#a-page-that-starts-workflows).

## Одно имя, одна ссылка { #one-name-one-link }

Идентичность приложения — его **имя внутри агента**: `weekly-report`, `churn-dashboard`. Публикация под тем же именем обновляет то же приложение, откуда угодно: из чата, API, [триггера](triggers.md) или сценария. Новое имя создаёт новую страницу. Имя состоит из строчных букв, цифр и дефисов, до 64 символов.

Имя также существует **внутри окружения**, из которого ответил запуск. Запуск в именованном [окружении](environments.md) — `staging`, `dev` — публикует свою страницу рядом со страницей окружения по умолчанию, поэтому проверка новой версии агента не может переопубликовать страницу, которую читатели в рабочем окружении сохранили в закладки. Окружение берётся из самого запуска, никогда из модели, и список и страница его называют.

Имя общее для всех, кто запускает агента, а страница — нет. Запуск переопубликовывает существующее приложение, только когда человек, от имени которого он действует, владеет им или имеет на него `artifacts:edit` — от роли или от выданного доступа `edit`, по тому же правилу, что и управление им в консоли. Запуску кого-либо другого сообщают, что имя занято, и он публикует под другим, поэтому коллега, попросивший у того же общего агента `weekly-report`, не может заменить страницу за вашей ссылкой.

Каждая публикация — новая **версия**. Ничего не перезаписывается, поэтому список версий на странице приложения и есть история страницы. Две вещи ограничивают эту историю:

- Публикация ровно тех байтов, что хранит текущая версия, не добавляет версию. Результат сообщает `unchanged`, и расписание, не нашедшее ничего нового, не трогает историю. Это всё равно считается публикацией, поэтому отсчёт хранения начинается заново.
- Хранятся только самые новые версии, не больше `ARTIFACT_MAX_VERSIONS` (по умолчанию 20). Старая версия удаляется, когда появляется новая, — кроме той, к которой закреплена публичная ссылка. Диалог, ссылающийся на удалённую версию, сообщает, что версия больше не хранится, и предлагает последнюю.

**Восстановить эту версию** (Restore this version) возвращает сохранённую версию. Участник, который может редактировать страницу, открывает версию и восстанавливает её; это добавляет новую версию с байтами старой, поэтому история сохраняет, что произошло, и восстановление можно отменить так же. Новое ничего не хранится. Это записывается в аудит. Новая версия сообщает, откуда она: список версий показывает `v4 · restored from v2` (в русской консоли — «v4 · восстановлена из v2»), а API отдаёт её номер `restored_from`, который публикация оставляет пустым.

## Поддерживаемые форматы { #supported-formats }

| Формат | Что хранится | Что отдаётся |
|---|---|---|
| HTML (`.html`, `.htm` или `format: html`) | Документ в том виде, в каком его написал агент | Тот же документ за коротким платформенным скриптом (см. [Как страница изолирована](#how-the-page-is-isolated)) |
| Markdown (`.md`, `.markdown` или `format: markdown`) | Исходный текст Markdown | Исходный текст, отрисованный в простую страницу, включая таблицы. Сырой HTML в нём экранируется |

Одна версия — один самодостаточный документ не больше `ARTIFACT_MAX_BYTES` (по умолчанию 5 МиБ). Наборов из нескольких файлов нет: встраивайте свои скрипты, стили и изображения (как `data:` URI) в один файл.

!!! warning "У страницы нет сети"

    Скрипты выполняются, поэтому график, нарисованный библиотекой, работает. Но страница не может ничего загрузить ниоткуда и ничего никуда отправить — скрипт с CDN, веб-шрифт по URL и вызов API одинаково не сработают. Исключения — набор библиотек ниже, который экземпляр отдаёт сам, и [актуальные данные](#live-data), которые консоль передаёт странице, объявившей привязки. Инструмент сообщает это модели. Так сделано намеренно, и [Как страница изолирована](#how-the-page-is-isolated) объясняет почему.

### Набор библиотек { #the-library-set }

Экземпляр отдаёт несколько файлов рядом с каждой страницей, чтобы модель не вставляла целую библиотеку графиков в каждую страницу. Страница загружает их по относительному адресу и продолжает работать, если позже экземпляр перенесёт своё содержимое на другой origin:

| Адрес на странице | Что это |

| `lib/d3-7.9.0.min.js` | d3 7.9.0, как `window.d3` |
| `lib/lucide-1.46.0.min.js` | Иконки Lucide 1.46.0, как `window.lucide`; это собственный набор иконок консоли |
| `lib/agenticos-3.css` | Набор для страниц: внешний вид консоли для страниц, светлый и тёмный, и компоненты `ao-`, из которых строится страница |
| `lib/agenticos-3.js` | `window.AO`: Chart.js в стиле консоли, форматирование чисел на языке страницы, иконки, вкладки, `AO.onData`, `AO.records`, а также `AO.run` и `AO.onRun` для [действий](#actions) |
| `lib/agenticos-2.css`, `lib/agenticos-2.js` | Предыдущая версия набора, сохранённая для страниц, опубликованных с ней |

| `lib/mermaid-12.1.0.min.js` | Mermaid 12.1.0, как `window.mermaid` |
| `lib/leaflet-1.9.4/leaflet.js`, `leaflet.css` | Leaflet 1.9.4, как `window.L`: рисует на [тайлах карты](#visuals) экземпляра, если они у него есть |
| `lib/agenticos-map-2.js` | `window.AOMap.itinerary`: нумерованные маркеры, показанные по порядку и опускаемые по одной по запросу, карта 16:9 ширины страницы, соединяющая их линия и карточки остановок — на тайлах карты или, без них, как контур остановок. `lib/agenticos-map-1.js`, который опускает маркеры при загрузке на одной высоте, по-прежнему отдаётся страницам, которые его называют |

Каждое имя несёт свою версию и кэшируется на год. Файлы отвечают `Access-Control-Allow-Origin: *`, потому что модульный скрипт загружается в режиме CORS, а страница в непрозрачном origin отправляет `Origin: null` — без этого three.js не импортировался бы. Обновление добавляет новый файл рядом со старым, поэтому страница, опубликованная с какой-то версией, продолжает её получать. Ничего не загружается извне экземпляра, поэтому экземпляр, отрезанный от сети, работает так же. Файлы перечислены в `backend/app/core/catalog/artifact_lib/`.

Версия 3 сохраняет каждый класс и вызов версии 2. Она также прощает небрежную разметку модели: заголовок, подзаголовок и строку метаданных, поставленные прямо в стек заголовка, а не распределённые по нему; таблица, построенная без `<thead>`, всё равно получает строку заголовков; а сообщение, записанное в обёртку таблицы, получает отступы. Она добавляет строки загрузки и примечания, строку подписи, индикатор актуальности, списки, панель инструментов с полями ввода, иконку заголовка и его действия. Иконки, которые скрипт добавляет после загрузки страницы, — как это делают записи страницы с актуальными данными, — тоже отрисовываются.

Встроенный [навык](skills.md) **`artifact-pages`** учит агента ими пользоваться: обязательный каркас, каждый класс набора, три шаблона (панель, отчёт и актуальная таблица, нарисованная через `AO.records`), фирменный стиль, иконки вместо эмодзи и то, как менять страницу через `read_artifact`. Новая организация получает его вместе с другими встроенными навыками, существующая — через `seed-skills`, а в Конструкторе его предлагает вкладка **Стиль страниц** (Page style) возможности «Приложения». Отредактируйте навык под свой бренд, и агент будет следовать ему.

### Контракт страницы и предупреждения публикации { #the-page-contract-and-the-publish-warnings }

Агент не видит страницу, которую публикует, поэтому платформа говорит ему, как страница должна выглядеть и что не так в той, которую он отправил.

Возможность «Приложения» даёт каждому агенту, у которого она есть, короткий **контракт страницы** в его инструкциях — привязан навык или нет: каркас (doctype, viewport, `lang`, таблица стилей и скрипт набора по порядку, `main.ao-page` и заголовок), закрытый список самых используемых классов набора, иконки Lucide вместо эмодзи и `AO.records` для привязанных данных.

Когда запуск агента предлагает навык `artifact-pages`, но не загрузил его, первая целая HTML-страница один раз возвращается с просьбой загрузить навык и перестроить её. Это происходит раз на запуск; каждое новое сообщение — новый запуск, поэтому на более позднем ходу это может повториться. Правка никогда не возвращается.

Затем опубликованная HTML-страница проверяется, и результат несёт `warning` с одной строкой на каждую найденную проблему. Страница публикуется в любом случае. Проверки:

- нет `<!doctype html>` первой строкой или нет meta viewport;
- класс `ao-`, в разметке или названный в скрипте, который не определяет ни версия набора, загружаемая страницей, ни её собственный `<style>`;
- таблица без `<thead>` или без класса `ao-table`;
- иконки `data-lucide` без `lib/lucide-1.46.0.min.js`;
- `AO.onData`, `AO.records`, `AO.run` или `AO.onRun` на странице, которая не загружает `lib/agenticos-3.js`;
- привязанная страница, скрипт которой ни разу не вызывает `agenticos.onData` и не читает `agenticos.data`, поэтому не показывает записей.

### Как увидеть страницу: предпросмотр { #seeing-the-page-preview }

`preview_artifact` рисует текущую версию страницы так, как увидел бы её тот, кто её открывает, шириной 1280 пикселей, и передаёт модели изображение и письменный отчёт. Отчёт приводит данные каждой привязки (записи, обрезку или недоступность с причиной), спрашивала ли страница свои данные, неперехваченные ошибки с их строкой, ошибки и предупреждения консоли браузера, то, в чём отказала политика безопасности страницы, отклонённые запросы, диалоги и предупреждения публикации выше. Изображение не выше 2400 пикселей; более длинная страница сообщает, какой она высоты. Страница, которая всё ещё выполняется через 15 секунд, сообщается как таковая, без изображения.

Данные читаются от имени человека, для которого выполняется запуск, ровно как консоль прочитала бы их для него, и расходуют лимит данных этого человека. В групповом чате предпросмотреть можно только страницу, доступную всей организации, — те же страницы, что показывает там список, — и она рисуется без данных. Так же и страница, которую предпросматривает запуск, за который никто не отвечает: начатый посторонним через вебхук, форму, сообщение в канале, письмо или событие репозитория, — кем бы он ни выполнялся. Способ доступа без вошедшего пользователя ничего не предпросматривает.

Ничто, что запрашивает страница, не выходит в сеть: API отвечает на каждый запрос страницей, [набором библиотек](#the-library-set) или отказом.

Для изображения нужен браузер, который запускает оператор, названный в [`ARTIFACT_RENDER_CDP_URL`](configuration.md#published-artifacts), и дополнительная зависимость `browser` у бэкенда. Эта настройка — только для оператора: она отделена от хостов, которыми может управлять агент с браузером, и ни один агент не может направить браузер на неё. Без того или другого инструмент всё равно возвращает отчёт, но без изображения, и сообщает, что у экземпляра нет рендерера. Отключите **Показывать модели изображение страницы** (Preview screenshot) в настройках возможности для модели, которая не читает изображения; отчёт всё равно вернётся. `agenticos cmd doctor` сообщает, отвечает ли рендерер.

Ещё три встроенных навыка строят **презентацию** как приложение: `presentation-decks` (разнообразная HTML-презентация 16:9 из `artifact-pages`, с навигацией с клавиатуры, обзором, выбором из палитры и одним слайдом на печатную страницу), `deck-storyline` (аудитория, решение и сюжетная линия утверждений до того, как появится хоть один слайд) и `deck-review` (заголовки, которые читаются как аргумент, одно сообщение на слайд, каждая цифра прослежена, читаемость издалека). Они не добавляют ни библиотеки, ни экспорта в PowerPoint.

## Визуализации { #visuals }

[Визуализация](reference/capabilities.md#visuals) — это приложение, которое не сохранили:
рисунок, который агент пишет в диалог через `draw` и который показывается под его
сообщением, пока рисуется. Это документ того же рода: визуализация `html` — это
страница, а `svg` или `mermaid` становится страницей, которая её содержит; рисуется
она с той же изоляцией.

**Фрейм.** `/api/v1/artifact-content/visual-frame` — одна фиксированная страница на
origin содержимого, отдаваемая ровно с той политикой, которую получает страница
каждого приложения. Она не содержит рисунка: консоль отправляет в неё рисунок по
мере потока, поэтому ничего не нужно хранить, прежде чем показать, а изоляция
берётся из заголовка ответа, а не из meta-тега `srcdoc`. Пока вызов идёт потоком,
фрейм преобразует разметку на месте, убирая скрипты и обработчики `on*`; когда он
завершён, он записывает весь документ, чтобы выполнились его скрипты, — ровно как
это сделает сохранённая страница. Фрейм сообщает свой размер, свои ошибки и сигнал
активности; рисунок, который перестал подавать признаки жизни, снимается, а не
оставляется занимать вкладку.

**В чате.** Рисунок находится в самом диалоге, без карточки вокруг, от левого края
текста сообщения: SVG вписывается по своему `viewBox` и уменьшается после 560
пикселей, страница раскладывается по ширине колонки и уменьшается после 900. Тихая
строка под ним называет его и говорит, рисуется ли он ещё; *Показать код*
(Show code), *Скачать* (Download; `.svg`, `.html` или исходник Mermaid),
*Копировать как изображение* (Copy as image) для SVG, *Сохранить в «Приложения»*
(Save to Apps) и *Во весь экран* (Full screen) появляются в этой строке, когда
указатель над рисунком, и всегда на сенсорном экране. Пока идёт поток, рисунок
держит высоту, объявленную его вызовом, на бледном фоне, чтобы диалог не сдвигался
под читателем. Во весь экран он показывается в собственном размере; на телефоне
предпросмотр открывается на весь экран по касанию. Масштаб находится в правом нижнем
углу рисунка, пока указатель на нём: SVG рисуется крупнее, страница масштабируется, а
рамка прокручивается, когда рисунок её перерастает. Ошибка, о которой сообщает
рисунок, сопровождается *Исправить* (Fix it), которая обращается к агенту.

**Уточнения.** Элемент управления в рисунке может вернуть выбор человека в диалог —
*Спланировать эту остановку*, *Использовать эти числа* — вызовом
`agenticos.followUp(text)`. Рисунок только просит. Консоль показывает точный текст
под рисунком с *Отправить* (Send), *Изменить* (Edit) и *Скрыть* (Dismiss), и он
становится сообщением человека, только когда тот нажимает *Отправить*, — нажатие,
которое рисунок не может сделать за него. Запрос, пришедший без пользовательского
действия за ним — при загрузке, по таймеру, — отбрасывается, как и запрос длиннее
2 000 символов, а пока один ждёт, второй его заменить не может. Уточнения
предлагаются только в чате: `agenticos.canFollowUp()` возвращает false в общем
диалоге, виджете и приложении, где `followUp` ничего не делает и возвращает `false`,
поэтому сохранённый рисунок продолжает работать.

**Карты.** Если задан [`VISUAL_MAP_TILES`](configuration.md#published-artifacts),
рисунок или приложение может рисовать на настоящих тайлах карты: экземпляр
загружает каждый тайл с того сервера и отдаёт его по собственному пути тайлов,
`agenticos.map` говорит, где, а набор карт рисует на нём маршрут с подписью сервера
внизу. Без него тот же вызов рисует контур остановок — маркеры и линию между ними, без
улиц, — и так же поступает карта, чьи тайлы не загрузились. Агент говорит об этом в
своём ответе: что сервер карт не подключён и что настоящие карты включаются этой
настройкой у администратора. Картинка карты в чате рисуется готовой, со всеми
маркерами на местах.

**Картам мира ничего не нужно.** Для всего, что о странах, — клиенты по странам,
офисы, маршрут между двумя городами, — `AOWorldMap` рисует карту в SVG по контурам
стран, которые экземпляр отдаёт сам: ни сервера тайлов, ни сети, ни лишнего
контейнера. Это значение по умолчанию для новых карт, включая маршруты между
городами. Агент загружает встроенные контуры стран и рисует маркеры и маршруты без
всякой настройки. Карты уровня улиц по-прежнему включаются администратором через
`VISUAL_MAP_TILES`; недоступный сервис тайлов должен откатываться к этой SVG-карте.

**Выбор формы.** Навык `visual-design` говорит агенту, когда рисунок вообще уместен:
текст для факта или совета, таблица Markdown для точных значений, `create_chart` для
чисел, которые надо увидеть, — так «а теперь построй график» превращает таблицу в
штатный график, — и рисунок, чтобы объяснить, как что-то движется, сделать
инструмент на один момент или проследить места на карте. Его шаблоны — схема,
объяснение с ползунками, трёхмерный самолёт с тангажом, креном и рысканием,
калькулятор и маршрут. Пустой чат с агентом, который рисует, показывает по одному
стартовому примеру для каждого шаблона. Включение «Визуализаций» в Конструкторе
привязывает и «Диаграммы».

**Скачивание.** У файла, открытого с диска, нет фрейма вокруг, поэтому загрузка несёт
то, что фрейм обеспечивал. SVG сохраняет рисунок и теряет всё, что могло бы
выполняться или обращаться наружу: скрипты, обработчики, встроенные документы и любые
ссылки за пределы файла. Страница открывается с политикой фрейма перед всем, что она
написала, и загружает свои библиотеки с origin приложений этого экземпляра.

**Сохранение как приложения.** *Сохранить в «Приложения»* (Save to Apps) принимает
заголовок и имя, оба заполненные, и публикует визуализацию как версию приложения у
агента, чей ход её нарисовал, в окружении, где шёл этот ход; владелец — тот, кто
сохраняет, и она приватна для него, пока он ею не поделится. Сервер перестраивает
визуализацию из транскрипта — с применёнными правками, — а не берёт байты из
браузера, поэтому приложение — ровно то, что нарисовал агент. Сохранение под именем,
которое у человека уже есть, добавляет версию этому приложению — так правка
сохранённого рисунка обновляет страницу, которой он был открыт. Для сохранения нужен
`artifacts:edit`.

**От агента-исполнителя.** Рисунок остаётся в запуске, который его сделал, поэтому
агент, работающий агентом-исполнителем другого, не рисует: `draw` говорит ему об
этом, и он описывает картинку в своём результате, чтобы агент, на которого он
работает, нарисовал её в диалоге.

## Кто может её открыть { #who-can-open-it }

Новое приложение **приватно** для того, от имени кого работал публикующий запуск, —
человека в чате или создателя триггера. Приватная страница также видна ролям Owner,
Admin, Builder и Operator: их `artifacts:view` имеет область `ALL`, поэтому они
открывают каждую страницу в организации независимо от её видимости и выданных
доступов (см. [области действия](permissions.md#scope)). Member или Viewer открывает
только то, что открыто ему. Эти четыре роли всегда входят в аудиторию страницы, и
каждое раскрытие их называет.

Её ссылка — та, на которую указывают карточка в чате и ответ агента, — открывает саму
страницу (из карточки в чате — в новой вкладке), заполняя окно под одной полосой с её
заголовком, версией и **Поделиться** (Share). Одна эта ссылка никого не впускает: она
открывается только вошедшему участнику, которого уже впускают правила ниже. Она
называет организацию, в которой находится приложение (`?org=`), поэтому участник
нескольких организаций попадает в нужную.

Под **Поделиться** любой, кто может ею управлять, открывает её тремя способами:

| Охват | Как | Кто |
|---|---|---|
| Отдельным людям | Выданный доступ уровня `read`, `edit` или, для страницы, `edit_data` («Может редактировать, включая данные») | Эти участники, в этой организации |
| Организации | Видимость, выставленная на всю организацию | Каждый участник, чья роль достаёт до общих приложений |
| Всем, у кого есть ссылка | **Создать публичную ссылку** (Create a public link) | Любой, у кого есть адрес, без учётной записи |

Открытие доступа и видимость используют ту же панель и те же правила, что у агентов и навыков; см.
[Разрешения](permissions.md). Управление приложением — открытие доступа, его публичная
ссылка и её настройки, восстановление версии, удаление — требует `artifacts:edit` на
этом приложении, от роли или от выданного доступа `edit`. Для открытия нужен
`artifacts:view`.

Агент не может расширить круг тех, кто читает страницу. Он публикует, а
`share_artifact` только создаёт запрос; кто её увидит, решает человек. Поэтому
возможность по умолчанию не просит согласования: первая публикация приватна, а то,
что показывает привязанная страница, ограничено
[подтверждением](#consent-the-owner-decides-who-reads-the-data) её владельца. Автор,
который хочет, чтобы человек одобрял каждую повторную публикацию уже открытой
страницы или привязанной страницы, задаёт `tool_approval` для `publish_artifact` в
спецификации. Переопубликовать привязанную страницу может только запуск, действующий
от имени участника (см. [Актуальные данные](#live-data)).

### Открытие доступа к странице с актуальными данными { #sharing-a-live-page }

Открытие [страницы с актуальными данными](#live-data) показывает её данные всем, кому
она отдаётся, прочитанные с доступом владельца, а не их собственным, поэтому
расширять круг тех, кто может её открыть, решает владелец. Владелец или Owner/Admin
за него расширяет этот круг прямо в диалоге доступа, как только данные подтверждены;
попытка любого другого редактора становится [запросом](#share-requests). Сужать может
любой редактор.

### Публичная ссылка { #the-public-link }

Публичная ссылка — это `/a/<key>` на собственном адресе консоли со случайным ключом в
192 бита — по тому же правилу, что и ключ размещённой страницы чата. Она ничего не
говорит о том, кто её опубликовал и к какой организации она относится.

**Заменить ссылку** (Replace the link) выдаёт новый ключ, и старый сразу перестаёт
что-либо открывать. **Выключить** (Turn off) удаляет её. И то и другое записывается в
аудит. Уже открытая у кого-то страница продолжает показывать то, что имеет, но
перезагрузка её или повторное открытие адреса содержимого сразу отвечает 404: адрес
называет ключ ссылки, и маршрут проверяет этот ключ при каждой загрузке. Собственное
время жизни адреса, `ARTIFACT_VIEW_TTL_SECONDS` (по умолчанию пять минут), — лишь
внешняя граница.

У удалённого участника положение прежнее: он теряет приложение при следующем запросе,
а уже открытая у него страница живёт не дольше того же окна.

Под ссылкой **Поделиться** хранит её настройки. Они сохраняются при замене ссылки, и
ссылка, выключенная и снова включённая, их сохраняет:

| Настройка | Что она делает |
|---|---|
| **Перестаёт открываться после** (Stops opening after) | Дата, после которой ссылка ничего не открывает, как будто выключена |
| **Показывать** (Shows) | Самую новую версию или одну сохранённую версию, закреплённую, чтобы новая публикация не меняла того, что люди со ссылкой уже видели. Закреплённая версия никогда не удаляется |
| **Пароль** (Password) | Спрашивается перед открытием страницы. Ссылка ничего не говорит — ни заголовка, ни даты публикации, — пока он не верен. Хранится в виде хэша и больше не показывается; каждая попытка расходует лимит частоты ссылки. Смена или удаление пароля прекращает действие адресов, открытых со старым: они не несут данных |
| **Сайты, которые могут встраивать** (Sites that may embed it) | См. ниже |

Карточка также сообщает, сколько раз ссылку открывали и когда в последний раз. Она
считает открытия, а не людей: о посетителе ничего не хранится. Каждое изменение
настроек записывается в аудит с указанием, какие настройки изменились, и никогда —
пароля.

### Встраивание на другом сайте { #embedding-it-on-another-site }

Публичную страницу можно разместить на странице интранета, в вики или на сайте клиента
через `<iframe>`. Перечислите сайты в **Сайты, которые могут встраивать** — только
схема и хост, `https://intranet.example.com`, или `https://*.example.com` для
поддоменов сайта, — и скопируйте **Код встраивания** (Embed code), который после этого
покажет «Поделиться».

Код вставляет в фрейм `/api/v1/artifact-embed/<key>` на origin содержимого: небольшой
документ самого экземпляра, который вставляет страницу в ту же песочницу, что и везде.
Его политика позволяет вставлять его в фрейм только перечисленным сайтам, а
собственная политика страницы позволяет вставлять её в фрейм только этому документу и
консоли. Если сайты не перечислены, не может никто. Страницу за паролем встроить
нельзя — встраивание предлагает вместо этого открыть её на собственной странице, — и
никто не входит в систему внутри фрейма на чужом сайте.

Встраивание несёт данные страницы на тех же условиях, что и её ссылка; см.
[Актуальные данные по публичной ссылке](#live-data-on-a-public-link). Добавление сайта
расширяет круг тех, кто читает эти данные, поэтому оно снимает подтверждение данных.

### Актуальные данные по публичной ссылке { #live-data-on-a-public-link }

Истечение срока действия публичной ссылки отклоняет и ранее выданные токены публичного
контента — ещё до того, как загрузятся байты документа. Токен, выпущенный прямо перед
истечением срока, не продлевает ссылку на время своей жизни. Токены контента для
участников по-прежнему подчиняются доступу участника и сроку жизни токена.

[Страница с привязками](#live-data) показывает свои записи по публичной ссылке и во
встраиваниях, только когда приняты два отдельных решения и при каждой загрузке
выполняется третья проверка. Без них публичная страница отдаётся в том виде, в каком
опубликована, и каждая привязка помечена `unavailable`.

1. **Организация разрешает это.** Owner или Admin включает
   **Публичные страницы с актуальными данными** (Public pages with live data) в
   настройках организации. По
   умолчанию это выключено, перед включением показывается предупреждение, а менять
   настройку можно только от своего имени — никогда от чьего-то. Это общий
   выключатель, а не сброс: когда его выключают, данные исчезают со всех публичных
   страниц и встраиваний при следующей загрузке, а подтверждения отдельных страниц
   остаются, поэтому повторное включение возвращает страницы, чьё подтверждение ещё
   в силе.
2. **Владелец страницы подтверждает это для ссылки.** В настройках ссылки в разделе
   **Поделиться** (Share) кнопка **Подтвердить данные** (Confirm data) открывает
   экран с тем, что показывает подтверждение участников: запросы страницы
   отдаваемой версии словами, все связанные таблицы, которых они достигают, — и с
   тем, кто сможет это читать: все, у кого есть ссылка, без учётной записи и без
   входа; защищена ли она паролем, когда истекает и на каких сайтах встраивается.
   Владелец — или Owner, или Admin за него — подтверждает это от своего имени;
   выданного доступа `edit` для этого недостаточно. Нужно, чтобы ссылка была
   включена, выключатель организации включён и было собственное
   [подтверждение участников](#consent-the-owner-decides-who-reads-the-data) для этой
   версии. Любой редактор может отозвать это от своего имени; Owner или Admin не
   может сделать это, войдя от имени другого пользователя.
3. **При каждой загрузке выполняются все проверки.** См.
   [что получает анонимный посетитель](#what-an-anonymous-visitor-gets).

Подтверждение относится к версии, которую отдаёт ссылка, — закреплённой, а если её
нет, той, что получает аудитория страницы, — и привязано к двум дайджестам:
отпечатку запросов страницы и дайджесту того, кого достигает ссылка (сайты
встраивания, наличие пароля, включена ли ссылка). Если что-то из этого изменилось
после того, как экран был нарисован, подтверждение отклоняется с конфликтом. Оно
записывается под членством владельца и попадает в аудит по именам таблиц и
столбцов, но никогда по строкам.

#### Что его аннулирует, а что нет { #what-voids-it-and-what-does-not }

Всё, что расширяет аудиторию или меняет, чьи это данные, снимает подтверждение — с
записью в аудите `artifact.public_data_voided` и причиной. Чтобы включить показ
снова, нужно новое подтверждение.

| Снимает подтверждение | Не трогает его |
|---|---|
| Выключение ссылки или архивирование страницы | Замена ключа ссылки: меняется адрес, а не данные |
| Удаление пароля | Смена пароля, срока действия ссылки или закреплённой версии |
| Добавление сайта встраивания | Удаление сайта встраивания |
| Передача страницы другому владельцу | Выключение выключателя организации |
| Отзыв подтверждения участников для данных | |

Другая закреплённая версия или повторная публикация, которая меняет запросы
страницы, не аннулирует подтверждение, но лишает его силы: отпечаток отдаваемой
версии больше не совпадает, поэтому публичная страница не показывает данных, пока
кто-нибудь не подтвердит их снова. Истёкшая ссылка тоже ничего не сохраняет.

Владелец и остальные редакторы видят причину в полосе над страницей: выключатель
выключен, ссылка не отдаёт ни одной версии, запросы изменились, владелец вышел или
сменился, нет подтверждения участников или срок ссылки истёк.

#### Что получает анонимный посетитель { #what-an-anonymous-visitor-gets }

Посетителю не сообщают причину. Прежде чем что-либо прочитать, каждая загрузка
проверяет, что у ссылки всё ещё тот ключ, для которого выпущен адрес; что срок не
истёк; что состояние пароля то же, при котором открывали адрес; что версия всё ещё
та, которую отдаёт ссылка; что выключатель организации включён; и что подтверждение
данных страницы и подтверждение участников в силе. Если хоть что-то не так,
страница отдаётся со всеми привязками `unavailable` и без причины.

Затем каждая привязка проверяется отдельно: владелец должен по-прежнему быть
действующим участником, который читает таблицу, а таблица не должна разойтись с
запросом. Привязка, не прошедшая эту проверку, получает `unavailable`, остальные
загружаются.

Записи вписываются в страницу при загрузке и соответствуют моменту этой загрузки. У
публичной страницы и у встраивания нет кнопки **Обновить** (Refresh) и нет маршрута
данных, и страница не может запросить больше; чтобы увидеть изменение, посетитель
перезагружает её. Заменённый или удалённый ключ даёт 404, а не страницу без данных, а
изменённый или удалённый пароль даёт старому адресу страницу без данных.

#### Кэш и потолок { #the-cache-and-the-cap }

Анонимная загрузка стоит чтений таблицы, поэтому чтения разделяются. Записи привязки
хранятся 30 секунд в памяти процесса API с ключом из версии, привязки, отпечатка
запросов и членства владельца — **никогда в Redis**, потому что это записи. Все
проверки выше выполняются до обращения к кэшу, поэтому выключенная организация,
заменённый ключ или отозванное подтверждение действуют сразу, что бы ни было
сохранено. Неудачное или недоступное чтение не сохраняется никогда.

Память ограничена: `ARTIFACT_PUBLIC_DATA_CACHE_BYTES` (по умолчанию 32 МиБ) и 64
чтения на процесс; первым вытесняется то, что дольше всего не использовалось, а
чтение больше бюджета не сохраняется. Отдельно каждая страница может читать из своих
таблиц `RATE_LIMIT_ARTIFACT_PUBLIC_DATA_PER_MINUTE` раз в минуту (60) с учётом всех
своих посетителей. Загрузка, которой нужно читать таблицы, считается один раз,
поэтому занятая страница ограничена потолком, а не числом посетителей. После
превышения — или пока процесс уже обслуживает столько загрузок данных, сколько ему
можно, — привязка, которой нужно чтение, возвращается такому посетителю как
`unavailable`.

## Как изолирована страница { #how-the-page-is-isolated }

Приложение — это HTML со скриптом, написанный моделью, которая могла прочитать
что-то враждебное. Оно отдаётся так, чтобы ничто в нём не могло добраться до
консоли или до человека, который на него смотрит:

- Байты приходят с отдельного маршрута, `/api/v1/artifact-content/<token>`,
  который не читает ни cookie, ни сеанс. Токен подписан, называет одну версию и
  истекает через минуты. Он выпускается только после того, как вызывающего
  допустили выданный доступ или публичная ссылка.
- Каждый ответ с контентом несёт `Content-Security-Policy: sandbox
  allow-scripts allow-modals`, без `allow-same-origin`. Страница выполняется в
  непрозрачном origin, поэтому не может прочитать cookie, хранилище или
  страницу консоли, а её запрос не понёс бы ничего от читателя. Это верно, даже
  если кто-то откроет адрес контента сам по себе.
- Та же политика задаёт `default-src 'none'` и `connect-src 'none'`. Единственный
  удалённый источник, который она называет, — собственный путь набора библиотек в
  origin контента, для скриптов, стилей и шрифтов, — и, в экземпляре, где задан
  `VISUAL_MAP_TILES`, изображения из его собственного пути тайлов,
  `/api/v1/artifact-content/tiles/{z}/{x}/{y}`. Этот маршрут принимает три числа,
  каждое проверяется по уровню масштабирования, на котором тайл может существовать, и сам
  загружает тайл, поэтому страница никогда не узнаёт адрес или ключ сервера
  тайлов и не может отправить ему ничего своего. `frame-ancestors` называет только
  консоль — и, для страницы с публичной ссылкой и сайтами встраивания, документ
  встраивания и эти сайты. Рамка в консоли несёт тот же список `sandbox` как
  второй замок.
- Нет `allow-popups`. `connect-src` не управляет переходами, поэтому ссылка,
  открывающая новое окно, была бы способом отправить то, что показывает страница,
  на адрес, который выбрала страница. Вместо этого каждая отданная страница
  сначала получает короткий скрипт платформы: клик по ссылке на другой сайт
  становится сообщением родителю рамки. Консоль и публичная страница показывают
  полный адрес и открывают его в новой вкладке, только когда человек согласился;
  документ встраивания делает то же в полосе под страницей. Страница могла бы
  отправить это сообщение сама, поэтому это просьба, а никогда не разрешение —
  между страницей с внедрённым промптом и адресом, куда она отправила бы свои
  числа, стоит человек, читающий адрес.
  [Уточнение](#visuals) — такая же просьба: консоль показывает текст,
  и человек отправляет его.
- Актуальные данные попадают на страницу участника двумя способами, и оба
  решаются на сервере для каждого читателя отдельно. При загрузке маршрут контента
  вписывает записи каждой привязки в скрипт платформы страницы для того участника,
  которого называет подписанный адрес; обновление приходит через `postMessage` из
  консоли, которая забирает его с маршрута данных с сеансом самого читателя. Запрос
  страницы несёт nonce, по которому консоль сопоставляет каждый ответ с нужной
  загрузкой страницы; это **соотнесение, а не управление доступом**. Публичная
  ссылка или встраивание получают данные только при загрузке, их вписывает сервер,
  и сами их не запрашивают: у них нет ни маршрута данных, ни обновления. См.
  [актуальные данные по публичной ссылке](#live-data-on-a-public-link) и
  [страницу о безопасности](security.md#a-pages-data-and-its-address).
- Страница может попросить запустить [сценарий](#actions) через тот же мост,
  вызовом `agenticos.run`, и предлагает это только окно просмотра страниц в консоли:
  адрес несёт право просить, а публичная ссылка, встраивание, предпросмотр и
  миниатюра отклоняют вызов сразу. Запрос снова **только запрос**. Консоль
  принимает его от своей собственной рамки под nonce этой загрузки, сопоставляет с
  действием, которое сервер перечислил для этого читателя и отдаваемой версии, и
  спрашивает человека в диалоге, прежде чем что-либо начнётся. Дальше запуск
  принадлежит ему, поэтому страница с внедрённым промптом может заставить человека
  прочитать вопрос, но никогда не может ответить за него.
- Один подписанный адрес загружает свою страницу не чаще нескольких раз в минуту;
  счёт идёт по адресу до того, как что-либо прочитано. Консоль и публичная
  страница выпускают новый адрес каждый раз, когда рисуют рамку, а выпуск через
  публичную ссылку сам по себе ограничен для каждой ссылки.

Список **Приложения** (Apps) рисует текущую страницу каждой карточки как живую
миниатюру через такую же рамку, со скриптом и больше ни с чем: без диалогов,
всплывающих окон и форм. Именно скрипт, чтобы панель, графики которой рисует
библиотека, не оставалась на карточке пустым холстом. Миниатюра инертна — без
событий указателя, вне порядка обхода табуляцией, скрыта от вспомогательных
технологий — и существует, только пока её карточка рядом с областью просмотра,
поэтому длинный список запускает те немногие, что читатель видит, и останавливает
страницу, которая уехала за край.

Кроме того, экземпляр может отдавать контент с
**отдельного регистрируемого домена**, задав `ARTIFACT_ORIGIN` — например
`https://agenticos-content.example.net`, направленный на тот же API. Тогда
страница оказывается совсем на другом сайте. Непрозрачный источник уже изолирует
её, так что это усиление защиты, которое может потребовать проверка безопасности,
а не требование. Задайте переменную для бэкенда и для фронтенда, который добавляет
маршрут контента этого origin в свой `frame-src`. См.
[Конфигурация](configuration.md#published-artifacts).

## Архивирование страницы { #archiving-a-page }

Архивирование убирает страницу у всех, не теряя её. Тот, кто может редактировать
страницу, выбирает **Архивировать** (Archive) в меню **Другие действия** (More
actions) над ней, и диалог говорит, что это сделает, прежде чем что-либо
изменится. Страница, её версии, её выданные доступы и её имя сохраняются. Ничто её
не отдаёт, пока её не восстановят — с той же страницы. Архивирование попадает в
аудит как `artifact.archived`, а восстановление — как `artifact.unarchived`.

Пока страница в архиве, каждый путь, который показал бы её, отвечает так, будто её
нет:

- **Консоль.** Её просмотр и её актуальные данные отклоняются, как и подписанный
  адрес, выпущенный до архивирования. Читателю, который открывает её ссылку,
  сообщают, что она недоступна. Тот, кто может её редактировать, видит, когда она
  была заархивирована, и кнопки **Восстановить** (Restore) и **Удалить** (Delete).
- **Списки.** Список приложений и виджет на странице «Обзор» её не показывают. Выберите в
  списке **Включая архивные** (Archived included), чтобы увидеть её с пометкой
  **В архиве** (Archived). Там её видят только те, кто может её редактировать.
- **Публичная ссылка и встраивание.** И то и другое не открывает ничего.
- **Агент.** `publish_artifact` отклоняет имя с сообщением, в котором назван архив,
  поэтому запуск не может завести под ним вторую страницу. `read_artifact`,
  `preview_artifact` и `list_artifacts` считают страницу отсутствующей. Запуск,
  которому нельзя редактировать страницу, слышит только, что имя не ему менять.

Архивирование выключает публичную ссылку — с записью в аудите
`artifact.public_link_disabled` — и снимает её
[подтверждение данных](#what-voids-it-and-what-does-not). Восстановление не
включает обратно ни то, ни другое. Адрес, отправленный до архивирования, остаётся
мёртвым, пока кто-нибудь не создаст новый в разделе **Поделиться** (Share). Срок
действия ссылки, закреплённая версия, пароль и сайты встраивания для этого
сохраняются.

Через API `POST /api/v1/artifacts/{id}/archive` архивирует страницу, а повторное
архивирование ничего не меняет. `POST /api/v1/artifacts/{id}/unarchive`
восстанавливает её и отвечает `400` для страницы, которая не в архиве. Оба требуют
права редактировать эту страницу, включая выданный доступ. `GET /api/v1/artifacts`
показывает архивные страницы тем, кто может их редактировать, только с
`include_archived=true`, а `archived_at` у каждой страницы говорит, когда она была
заархивирована.

## Отслеживание страницы { #following-a-page }

**Отслеживать** (Follow) на полосе страницы кладёт уведомление во «Входящие»
каждый раз, когда у неё появляется новая версия: агент опубликовал её заново с
другим содержимым или кто-то восстановил старую версию. Повторная публикация,
которая ничего не меняет, никому ничего не сообщает, поэтому расписание, не
нашедшее ничего нового, молчит. Тому, чей запуск или чьё восстановление создало
версию, о его собственном изменении не сообщают.

Отслеживание не даёт доступа. Отслеживать страницу может любой, кто может её
открыть, а тот, кто её отслеживает и теряет доступ, перестаёт получать
уведомления, ничего не отменяя. «Входящие» проверяют доступ снова при чтении,
поэтому уведомление о странице, которую вам больше нельзя открыть, исчезает вместе
с этим доступом. Уведомление может приходить и по почте; любой из двух каналов
отключается в разделе **Настройки → Уведомления → Приложение обновлено** (Settings
→ Notifications → App updated).

## Хранение и удаление { #retention-and-deletion }

У приложений свой [класс хранения](governance.md#the-classes), отсчитываемый от
**последней публикации**: отчёт, который публикуют заново каждую неделю, жив, как
бы стара ни была его первая версия. Как и любой класс, он хранит приложения вечно,
пока организация или экземпляр не задаст срок.

Удаление приложения — вручную или по сроку хранения — убирает все его версии,
сохранённые байты, выданные доступы и публичную ссылку. Страница в архиве стареет и
удаляется как любая другая. Удаление агента не удаляет его приложения: они
остаются читаемыми и просто остаются без публикующего. Удаление именованного
окружения делает то же со страницами, опубликованными из него, поэтому они никогда
не попадают на страницу с тем же именем в окружении по умолчанию. Удаление
организации убирает их. Приложения удалённого человека остаются и теряют
владельца — так же, как его агенты и навыки.

Байты лежат в [файловом хранилище](configuration.md#uploaded-files-at-rest)
экземпляра, в `artifacts/<organization>/<artifact>/`.

## Ограничения { #limitations }

- **Один самодостаточный документ на версию.** Никаких наборов файлов и никакой
  сети изнутри страницы, кроме отдаваемого набора библиотек и
  [актуальных данных](#live-data), которые ей передаёт консоль.
- **Актуальные данные ограничены.** Пять привязок, по 1 000 записей и около 5 с на
  загрузку; см. [ограничения](#limits). Данные, которые не привязаны, — это страница
  в том виде, в каком она опубликована, и они меняются, когда агент публикует её
  снова.
- **Все читают данные так, как их видит владелец.** Запрос страницы читается с
  доступом владельца, поэтому страница годится для данных, которые может видеть
  каждый, кто может её открыть. В запросе страницы нет поиска по свободному тексту,
  нет фильтра для отдельного читателя вроде «я» или «сегодня» и нет ограничения по
  строкам или столбцам сверх самого запроса.
- **Публичная ссылка или встраивание получают данные только после двух подтверждений.**
  Организация должна это разрешить, а владелец страницы —
  подтвердить для ссылки; до тех пор страница с привязками показывает там
  `unavailable`. То, что она показывает, соответствует моменту загрузки, не
  обновляется, отстаёт до 30 секунд и читается с доступом владельца для людей,
  которых владелец не знает. Экземпляр, который не может на это согласиться,
  оставляет выключатель выключенным. См.
  [актуальные данные по публичной ссылке](#live-data-on-a-public-link).
- **Страница действует только через объявленные действия.** Форме или кнопке некуда
  отправить собранное, кроме как запустить один из не более пяти сценариев,
  объявленных её публикующим, — человек подтверждает это каждый раз, и они
  выполняются от его имени. Страница не может сама вызвать API, записать запись или
  отправить сообщение и получает обратно только статус запуска и ответ. См.
  [действия](#actions).
- **Открытая страница переживает отозванный выданный доступ на время жизни одного
  подписанного адреса**, пять минут по умолчанию. Выключение публичной ссылки или
  замена её ключа прекращает это при следующей загрузке.
- **Ссылка внутри страницы сначала спрашивает.** Она открывается в новой вкладке
  после согласия человека; сама страница не может открыть окно или увести консоль.
- **Для встраивания нужна публичная ссылка и отсутствие пароля.** Участники не могут
  войти внутри рамки другого сайта.
- **Удалённые версии исчезают.** Диалог, который ссылается на версию старше
  хранимого окна, может предложить только последнюю.
- **Без рендерера агент не видит свою страницу.** Предупреждения при публикации
  читают разметку и не могут сказать, как она выглядит. С рендерером картинку даёт
  headless Chromium: шрифты и размеры могут немного отличаться от браузера читателя.
- **Визуализация рисуется только в веб-чате и в общем диалоге.** В приложении чата
  она получает картинку там, где `VISUAL_RENDER_CDP_URL` называет браузер, а иначе —
  только заголовок; виджет и встраивание на другом сайте показывают её заголовок.
- **Общий диалог показывает двенадцать самых новых визуализаций**, и все вместе они
  занимают не больше 16 МБ. Любой, у кого есть ссылка, может открывать его сколько
  угодно раз, поэтому один просмотр ограничен; ход диалога сверх любого из этих
  пределов сохраняет свой текст и не показывает рисунок.

## Кратко { #recap }

- Одна возможность, пять инструментов: `publish_artifact` — из файла рабочего
  пространства, встроенным текстом или правками; `read_artifact` — прочитать
  страницу обратно; `list_artifacts` — найти нужную; `preview_artifact` — увидеть
  её нарисованной, с её ошибками; и `share_artifact` — попросить открыть доступ к
  странице.
- Агент, окружение и имя — это и есть идентичность; повторная публикация сохраняет
  ссылку и добавляет версию, а любую сохранённую версию можно восстановить.
- По умолчанию приватная; открывает доступ к ней человек — выданными доступами, на
  организацию или публичной ссылкой. Публичная ссылка может истекать, закреплять
  версию, спрашивать пароль и встраиваться на перечисленных сайтах.
- Страница может привязаться к запросу страницы — таблица, фильтры, сортировка,
  лимит и поля — и показывать актуальные данные, которые читаются в момент просмотра
  с доступом владельца, только после того, как владелец подтвердил их показ, и они
  никогда не хранятся в странице. Любой, у кого есть право редактирования, может
  отозвать это подтверждение; расширить круг тех, кто может открыть страницу с
  привязками, может владелец — или это делается запросом. Публичная ссылка или
  встраивание показывают данные, только когда Owner или Admin разрешил это для
  организации и владелец подтвердил их для ссылки, а расширение аудитории ссылки
  снимает это подтверждение.
- Страница может объявить до пяти сценариев, привязанных у агента; её кнопки просят
  консоль запустить один из них через `AO.run`, и читатель подтверждает каждый запуск
  в диалоге, где назван настоящий сценарий и показано каждое значение. Запуск
  принадлежит читателю, у него триггер `app`, а страница получает обратно только его
  статус и ответ.
- Владелец может передать страницу другому участнику, и тот должен подтвердить её
  данные заново.
- Короткий контракт страницы в инструкциях каждого агента с возможностью
  «Приложения» и предупреждения в результате публикации о том, что выглядит
  неправильно в разметке.
- Отдаётся с маршрута без cookie в непрозрачном origin, без сети, кроме
  собственного набора библиотек экземпляра, со ссылками, которые спрашивают перед
  открытием, и, по желанию, со своим доменом.
- Архивирование сохраняет страницу и не отдаёт из неё ничего, а публичная ссылка
  выключена, пока кто-нибудь, кто может её редактировать, не восстановит её.
- Свой класс хранения, отсчитываемый от последней публикации.

## Загрузка предпросмотров и открытие доступа { #preview-loading-and-sharing }

Предпросмотры в чате резервируют своё место, пока загружается рендерер визуализаций
или миниатюра приложения. Они проявляются, только когда отрисовка или декодирование
изображения закончились; настройка уменьшенного движения отключает анимацию. Списки
приложений используют кэшированные статические миниатюры для конкретной версии, а не
запускают каждое приложение заново при возврате к списку.

Временные сбои рендерера и тайм-ауты получают не больше двух автоматических повторов
с растущими задержками. Ненастроенный рендерер и отклонённый доступ не повторяются.
Возврат к карточке или изменение её видимости не запускает исчерпанный лимит повторов
заново. Успешные изображения остаются в кэше для своей разрешённой версии.

Навык «Приложения» включает интерактивные HTML-презентации, стили печати для PDF и
примеры переиспользуемых компонентов. Экспорт в PDF требует настроенного рендерера;
предпросмотр только с проверкой не доказывает, что скрипт выполнился успешно.
Используйте настоящий отрисованный предпросмотр, чтобы проверить диаграммы, таблицы и
интерактивное содержимое. Экспорта в PowerPoint нет.

Инструмент MCP платформы `create_app_public_link` требует доступа на редактирование и
явного подтверждения того, что приложение можно открыть публично. Он переиспользует
существующую ссылку и сохраняет её пароль, срок действия и закреплённую версию.
Актуальные данные требуют отдельного подтверждения владельца. Вызов успешен, только
когда API подтвердил публичный URL.

Входящий в комплект пример презентации использует пять разных композиций:
иллюстрированная обложка, крупная метрика, сравнение, последовательность и решение.
Пример отчёта пересчитывает выбранные итоги и свою диаграмму из одних и тех же
счётчиков. Визуальный дизайн включает и процедурную продуктовую студию с фасками на
формах, отделкой материалов, местным студийным светом, разделением сборки,
