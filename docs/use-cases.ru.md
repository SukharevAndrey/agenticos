# Выберите первую задачу { #choose-a-first-task }

Начните с работы, результат которой кто-то в команде может оценить. Каждое из 30
руководств ниже даёт синтетический вход, конфигурацию, точный промпт, эталонные
проверки, обычные сбои и то, что стоит записать. Это отправные точки с эталонными
запусками, а не истории клиентов и не заявления о доле успешных запусков.

Последний столбец говорит, когда мейнтейнеры в последний раз запускали руководство на
продукте. Записанный запуск покрывает ровно то, что описывает блок примера на
странице: одну конфигурацию, одну дату и одну модель. Это не доказательство, что ваша
конфигурация проходит те же проверки. Руководство, которому нужна сторонняя учётная
запись, которую мейнтейнеры не подключали, помечено *Ещё не записано*.

## Прежде чем начать { #before-you-start }

Впервые в продукте? Сначала [соберите своего первого агента по
документам](howto/first-document-agent.md): все остальные руководства предполагают
работающий экземпляр и профиль модели.

Существующие [экраны и записи](screens.md) показывают интерфейсы продукта. Они тоже не
доказывают эти проверки. Держите свой вход, фактический вывод, запуск и ошибки вместе.

Выберите одну точку входа через [каналы](channels.md), затем назначьте ответственного
за [эксплуатацию](rollout.md). Если вы всё ещё выбираете платформу, воспользуйтесь
[сравнениями](about/comparison.md).
