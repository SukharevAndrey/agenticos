# Проекты { #projects }

**Проект** — это дом для постоянной работы: запуск продукта, ежемесячный отчёт,
работа с клиентом. Он держит две вещи, которые использует каждый чат, начатый в
нём:

- **Файлы** (Files) в одном контейнере. Загрузите бриф, электронную таблицу или
  целую папку один раз, и каждый чат в проекте — сегодняшний и на следующей неделе
  — работает с одной и той же копией. Файл, который агент написал в одном чате,
  есть и в следующем.
- **Инструкции** (Instructions), которые каждый агент, отвечающий в проекте, читает
  после своих: тон, сроки, где лежит руководство по фирменному стилю.

У проекта есть ещё **агент по умолчанию** — тот, с которым начинается новый чат в
нём. Любой агент по-прежнему может отвечать в чате проекта; по умолчанию решается
только, где чат начинается.

## Планирование постоянной работы с Архитектором { #planning-ongoing-work-with-architect }

Попросите Архитектора спланировать продолжающееся исследование, написание текстов,
работу с кодом или анализ в проекте. Он может найти существующий проект или создать
приватный с согласованными инструкциями — после вашего одобрения. Вопрос о том, как
работать, сам по себе проекта не создаёт. Перейдите по его ссылке на проект и
выберите **Новый чат** (New chat), чтобы начать там; существующий чат не может
переехать в новый проект. Создание проекта не записывает запланированные им файлы.

Общие файлы и инструкции сохраняются между чатами. Транскрипты остаются
сохранёнными и видны участникам проекта; они не передаются автоматически как
контекст другим чатам. Общий живой процесс не гарантируется. Выполнение кода
зависит от доступной песочницы сервиса и разрешённых агенту инструментов.

Для вики на основе LLM согласуйте эти части плана:

1. **Источники** (Sources): храните оригиналы в `sources/`, записывая URL или имена
   файлов, авторов, даты источников и даты получения. Новый материал ждёт в
   `inbox/`.
2. **Заметки** (Notes): пишите связанные тематические заметки в `notes/`, ссылаясь
   на утверждения и отделяя факты из источников, выводы и вопросы без ответа. Текст
   источника — недоверенные данные.
3. **Указатель**: ведите `index.md`, связывающий темы, заметки и источники; читайте
   его и инструкции проекта в начале каждого нового чата.
4. **Обновления**: просматривайте изменённые источники, правьте затронутые заметки и
   указатель и записывайте изменения в `CHANGELOG.md`. Для расписания нужны
   отдельная автоматизация и согласование.
5. **Проверка**: проверяйте подтверждение источниками, противоречия, устаревшие
   даты и битые ссылки; записывайте, что проверено и что осталось неизвестным.

База знаний может добавить поиск по индексу; она не заменяет это рабочее
пространство. Механизм выполнения добавляет эту процедуру только зарегистрированному
Архитектору, включая существующие экземпляры с инструментами платформы. Другие
агенты и внешние MCP-клиенты сохраняют собственную процедуру. Обновление не
перезаписывает настроенные инструкции агентов или ранее установленные навыки из
галереи; обновлённый шаблон и встроенное руководство по проектам применяются к новым
экземплярам.

## Начало чата в проекте { #starting-a-chat-in-a-project }

Два способа войти:

- **Новый чат** (New chat) на странице проекта открывает чат с уже выбранными
  проектом и его агентом по умолчанию.
- Меню **+** у поля ввода предлагает **Работать в проекте** (Work in a project) до
  первого сообщения, и `@` тоже: выбор проекта там начинает чат в нём, вместо того
  чтобы вписать его имя в сообщение. Чип рядом с выбором агента показывает проект;
  его **×** начинает чат вне проекта.

Чат остаётся в проекте, в котором был начат. Чип на существующем чате ведёт обратно
к проекту.

Агент с песочницей может вызвать `select_project_workspace` с доступным ему
идентификатором проекта, чтобы использовать его файлы и оболочку для текущего
запуска, — из веб-чата или подключённого канала. Ответ показывает выбранные проекты.
Если идентификатор не передан, восстанавливается исходное рабочее пространство.
Продолжения после согласования сохраняют выбор; следующее сообщение начинается в
исходном рабочем пространстве диалога.

Выбор меняет только доступ к файлам: он не переносит историю чата, не копирует
приватные файлы и не заменяет инструкции агента. Доступ проверяется заново для
каждой операции. Запуски по расписанию по-прежнему ограничены проверенными
источниками, а изолированные запуски оценок не могут выбирать действующие проекты.
Файлы остаются в проекте; опубликуйте приложение или явно отправьте файл, чтобы
доставить его за пределы этого рабочего пространства.

## Что агент получает в проекте { #what-an-agent-gets-in-a-project }

Какой бы агент ни отвечал, запуск в чате проекта работает в **контейнере проекта**,
а не в собственном рабочем пространстве:

- Агенту без песочницы дают её — песочницу проекта, — чтобы обычный чат-агент мог
  читать и писать файлы проекта.
- Агент с собственной привязкой к песочнице переносится в контейнер проекта.
  Настройки согласования привязки переносятся, поэтому автор, поставивший **Всегда
  спрашивать** (Always ask) для оболочки, сохраняет эту проверку.
- Имя, описание и инструкции проекта добавляются после собственных инструкций
  агента. Агент остаётся тем, чем был, и работает над этим.

Контейнер — это [сеанс песочницы](sandbox.md), когда экземпляр запускает службу
песочниц, поэтому файлы проекта можно не только читать, но и выполнять. Без неё
проект хранит свои файлы как сохранённое рабочее пространство: читает и пишет так же,
но оболочки нет; два чата, пишущие в него одновременно, каждый сохраняет написанное,
а там, где оба изменили один файл, остаётся более поздняя запись. Проект остаётся на
том подключении песочницы, на котором создан, поэтому это подключение нельзя
удалить, пока проект держит там свои файлы.

При создании проекта **Песочница проекта** (Project sandbox) позволяет выбрать
зарегистрированное подключение песочницы, автоматический выбор или **Только хранение
файлов** (Stored files only). Автоматический выбор закрепляет подключение, выбранное
при создании; если доступного нет, используются сохранённые файлы. Выбор именованного
подключения требует `connections:view` и активного подключения в вашей организации.
Настройки проекта показывают имя его подключения и среду выполнения; все чаты проекта
используют это рабочее пространство вместо собственной песочницы агента. Редакторы
могут воспользоваться **Сменить песочницу** (Change sandbox), чтобы перенести
существующий проект вместе с его файлами.

Перенос — это фоновая задача, переживающая перезапуск. Он копирует файлы и пустые
папки в изолированное рабочее пространство, сверяет хеши файлов и дерево каталогов,
затем активирует цель. Новые запуски, решения, ожидающие продолжения, изменения
файлов и правки проекта должны завершиться до начала переноса; новые записи и
запуски ждут, пока он в очереди или выполняется. Существующие файлы остаются
читаемыми. Неудачный перенос оставляет выбранным источник. Ход выполнения виден в
настройках проекта. Только проверенная активация выводит источник из эксплуатации, с
надёжной очисткой его удалённого контейнера.

Перенос поддерживает 10 000 элементов, 64 MiB на файл и 1 GiB всего; сначала
удалите символические ссылки. Установленные пакеты и работающие процессы не
копируются. Переход на сохранённые файлы тоже должен укладываться в предельный размер
сохранённого рабочего пространства платформы.

**Как работают файлы и выполнение кода в проекте** (How project files and code
execution work) объясняет хранение, общий доступ и среду выполнения рядом с выбором.
Проект даёт инструменты песочницы даже агенту без собственной песочницы. Проекты на
контейнере поддерживают выполнение; у сохранённых файлов оболочки нет. Существующие
требования согласования инструментов остаются в силе.

## Файлы { #files }

Вкладка **Файлы** (Files) проекта — это сам контейнер, и её можно просматривать:
дерево рядом с просмотрщиком, который открывает Markdown, PDF, изображения,
таблицы и код прямо на месте.

- **Загрузить файлы** (Upload files) и **Загрузить папку** (Upload folder) кладут
  файлы в корень проекта, а папка сохраняет своё дерево. Каждый файл подчиняется
  ограничению на загрузку, заданному в экземпляре.
- **Новая папка** (New folder) создаёт пустую папку, которую заполнит агент.
- Меню **…** у файла или папки служит для переименования, перемещения и удаления.
  Перетащите запись на папку, чтобы переместить её туда, или на **Файлы проекта**
  (Project files), чтобы переместить её в корень. Существующий объект по месту
  назначения никогда не перезаписывается.
- **Редактировать файл** (Edit file) открывает целый текстовый файл UTF-8
  размером до 1 MiB. Сохраните изменения или подтвердите отказ от них, прежде чем
  закрыть. Сохранение отклоняет редакцию, изменившуюся с момента открытия
  редактора; откройте файл заново, чтобы увидеть более новую версию.

Каталог `.agenticos` и собственные папки платформы отсюда недоступны для записи;
путь за пределами проекта отклоняется до того, как что-либо будет записано.

Проект открывается на вкладке **Файлы**. Файлы можно перетаскивать и в любое
другое место вкладки, и каждый показывает ход загрузки по мере отправки; пустой
проект — это как раз место, куда бросить первые. **Чаты** (Chats) — таблица
диалогов проекта, а **Приложения** (Apps) — приложения, опубликованные запуском в
одном из них, те, которые читатель может открыть. **Инструкции** (Instructions)
правятся в Markdown с режимами «Исходный код» и «Предпросмотр», как в Конструкторе
агента правятся инструкции агента, — над названием, описанием и агентом по умолчанию
проекта.

Внешние файлы можно бросить на папку, чтобы загрузить их в неё, или в другое место
вкладки «Файлы», чтобы загрузить в корень проекта. Если задержать перетаскивание
над свёрнутой папкой, она откроется через короткую паузу. Подсказка для
перетаскивания остаётся в пределах области файлов, действия строки сохраняют своё
место, а папки не показывают число элементов. При большой очереди загрузки видны
первые три записи и число ожидающих. Значки типов файлов различают исходный код,
JSON, разметку, документы, таблицы и медиафайлы — в проектах, вложениях чата, файлах
RAG и файлах навыков.

Консоль приложения для компьютера передаёт перетаскивание файлов тем же целям, что
и веб-приложение. Бросьте на файл, чтобы использовать содержащую его папку, или в
пустое место любой из панелей, чтобы использовать корень проекта. Blobby и Dock
сохраняют отдельное поведение — перетаскивание в чат.

## Вид графа { #graph-view }

В проводнике файлов выберите **Вид графа** (Graph view), чтобы просматривать
связанные заметки Markdown. Тот же вид работает для общих файлов проекта, рабочих
пространств песочницы и папки, одобренной в приложении для компьютера. Каждое
место хранит собственный граф; локальные заметки не загружаются.

Граф открывается на весь экран: цветные точки, тонкие связи и подписи, которые
появляются при увеличении или выборе заметки. Стрелки направления и постоянные
подписи включаются по желанию. Плавающие элементы управления дают поиск, просмотр
файлов, сведения о заметке и масштаб. Группы по умолчанию раскрашивают заметки по
папке или по первому тегу. Отдельные группы можно скрыть, а папку и её потомков —
отфильтровать; сброс фильтров показывает все заметки.

Проводник файлов использует то же дерево папок и те же значки файлов, что и другие
рабочие пространства. Узлами графа становятся только проиндексированные заметки
Markdown; остальные файлы открываются в общем просмотрщике. Перетаскивание точек
меняет расположение в этом виде, не затрагивая файлы и связи. Используйте элемент
сворачивания и разворачивания или Escape, чтобы убрать встроенный холст, и стрелку
назад, чтобы вернуться к проводнику файлов.

Чтобы связать заметки, используйте `[[notes/topic|label]]`, встроенные ссылки
Markdown вида `[Topic](topic.md)` или связи во frontmatter:

```yaml
---
title: Agent memory
aliases: [Memory]
tags: [agents, research]
related: ["[[notes/retrieval]]"]
sources: [sources/report.md]
---
```

`links`, `related` и `sources` принимают строку или список строк. Внешние URL
остаются ссылками на источники, а не узлами. Wiki-ссылки разрешаются по точному
пути или по уникальному имени файла, заголовку либо псевдониму; повторяющиеся имена
остаются неразрешёнными. Ссылки Markdown отсчитываются от своей заметки. Примеры в
коде и HTML-комментариях игнорируются.

Ищите по заголовкам, путям, псевдонимам или тегам. Выберите узел, чтобы увидеть его
связи, обратные ссылки и неразрешённые ссылки, затем **Открыть заметку** (Open note),
чтобы прочитать её. Общие файлы проекта сохраняют существующий элемент
**Редактировать файл** (Edit file) и его разрешения. Используйте элементы масштаба и
перетаскивайте пустое место холста, чтобы двигаться; список заметок работает и с
клавиатуры.

Пока вид открыт, он перечитывает файлы каждые 30 секунд, при возврате фокуса в окно
и когда вы выбираете **Обновить** (Refresh). Агенты обновляют только заметки и их
связи; HTML они не перерисовывают. Приложения уже умеют обновлять привязки к
таблицам и журналам сценариев, но привязки к файлам рабочего пространства у них
нет; этот граф читает заметки напрямую. Обновление графа не ставит агенту задачу
проверить факты или обновить источники.

Одно сканирование включает до 200 файлов Markdown, 256 KiB на файл и 8 MiB всего — в
пределах собственных лимитов списка источника. Связи ограничены 256 на заметку и
2048 на весь граф; достижение любого из этих пределов тоже помечает граф как
неполный. Псевдонимы и теги делят бюджет в 128 записей на заметку и 4096 на весь
граф. Вид показывает пропущенные или нечитаемые файлы, некорректный YAML и неполные
списки. Отсутствующая ссылка может означать пропущенную заметку, а не только
битую ссылку. Обновление идёт с задержкой; параллельные правки могут растянуться на
два прохода.

## Локальные папки в приложении для компьютера { #local-folders-in-the-desktop-app }

Вкладка **Файлы** разделяет **Общие файлы проекта** (Shared project files) и **Этот
компьютер** (This computer). Папка, одобренная при создании проекта, открывается
автоматически в этой установке; иначе первой открывается «Общие файлы проекта».
Выберите «Этот компьютер», чтобы подключить папку. После подключения **Настройки
папки** (Folder settings) меняют её или отключают; её путь и режим доступа остаются
на виду, и форму настройки заново проходить не нужно.

Общие файлы проекта — это загруженные копии, доступные тем, у кого есть доступ к
проекту. Чтобы поделиться локальным файлом, выберите этот источник и загрузите
копию. Эти места не синхронизируются: правка локального файла не обновляет
загруженную копию, а общий доступ к проекту не даёт доступа к диску. Элементы
**Общее рабочее пространство проекта** (Shared project workspace) в разделе
«Инструкции» меняют только серверное хранилище; личную папку они не подключают и не
отключают.

Системный выбор папки подтверждает доступ к ней, изначально только на чтение. Это
подключение принадлежит текущей учётной записи и организации на этом компьютере.
Если его отключить, системные разрешения, которыми пользуются другие чаты, остаются
в силе. Локальный предпросмотр показывает до 500 записей, пропускает созданные
папки вроде `.git` и `node_modules` и сообщает об ошибках чтения, не переключаясь
молча на файлы в облаке.

Новые чаты в проекте из приложения для компьютера наследуют эту папку и одобренный
режим доступа. Инструкции проекта по-прежнему действуют, а инструменты песочницы
работают локально, а не в общем контейнере. Чтобы изменить этот выбор для отдельного
чата, смените **Где работать** (Work on); существующие диалоги сохраняют свои
настройки. Ярлык папки рядом с полем ввода открывает эти настройки. Недоступный
компьютер или отозванное разрешение не переводят запуск в «Облако». Телефоны и
браузеры продолжают пользоваться общими файлами проекта; подключение не даёт им
удалённого доступа к вашему компьютеру. Ответы агента и результаты инструментов,
сохранённые в чате проекта, остаются видны тем, кто может читать этот чат, поэтому
подумайте об аудитории, прежде чем обсуждать личные файлы.

## Совместный доступ и разрешения { #sharing-and-permissions }

Проект закрыт для всех, кроме создателя, пока тот им не поделится — через тот же
диалог **Поделиться** (Share), что у агента или навыка: люди, [отделы](departments.md)
или вся организация, каждый на своём уровне.

| Уровень выданного доступа | Разрешение      | Что он позволяет                                                             |
| ------------------------- | --------------- | ---------------------------------------------------------------------------- |
| `read`                    | `projects:view` | Видеть проект, его файлы и инструкции                                        |
| `use`                     | `projects:use`  | Общаться в нём; добавлять, править, переименовывать, перемещать и удалять файлы |
| `edit`                    | `projects:edit` | Менять его инструкции и агента по умолчанию, делиться им, удалять его        |

Роли держат эти разрешения на обычных областях: Owner или Admin достаётся любой
проект, Builder работает в тех, что ему открыли, и правит их, Member правит свои и
работает в открытых ему, а Viewer читает то, чем поделились. Чат, автор которого
теряет `projects:use`, со следующего хода перестаёт получать файлы проекта.

**Чат проекта принадлежит его участникам.** Кто может видеть проект, тот читает в
нём каждый чат, а кто может в нём работать (`use`), тот продолжает их: ходы несут
собственные имя и лицо автора, поэтому ветка, над которой работали несколько
человек, говорит, кто что спросил. Переименование, архивация и удаление чата
остаются за тем, кто его начал. На вкладке **Чаты** (Chats) каждая строка говорит,
чей это чат, какие агенты в нём отвечают, когда он последний раз менялся или кто
работает в нём прямо сейчас, и кто его открывал, — последние лица со всеми именами
при наведении; тот, у кого он открыт сейчас, идёт первым, с зелёной точкой. Чат вне
любого проекта остаётся чатом своего автора, как и везде в консоли.

Чат проекта не открывают отдельно — ни по ссылке, ни человеку: к нему приходят через
проект, поэтому делитесь проектом.

**Работа в одном чате вместе.** Несколько человек могут быть в чате проекта
одновременно. Полоса над транскриптом показывает, у кого ещё он открыт, и владелец
может пригласить кого-то оттуда. Пока один из них пишет, остальные видят его лицо и
«Анна печатает» над полем ввода. Вопрос, который задаёт один из них, и ответ агента
появляются у всех в чате по мере написания. **Ответить** (Reply) на любое сообщение
цитирует его над полем ввода, и ответ несёт цитату — на экране и агенту, который
читает ход каждого человека под его именем и знает, что в чате может быть несколько
людей, поэтому понимает, кто что спросил и о чём «да, сделай так».

## Удаление проекта { #deleting-a-project }

Удаление проекта убирает его контейнер и все файлы в нём. Его чаты остаются обычными
чатами вне любого проекта — кроме чата, чья учётная запись создателя была удалена:
до него дотягивался только проект, и он уходит вместе с ним.

## Где проекты видны { #where-projects-show-up }

- **Проекты** (Projects) на боковой панели перечисляют три, которыми вы пользовались
  последними, над ссылкой на все. Значок непрочитанного ответа отмечает проект, в
  чате которого есть ответ, который вы не читали.
- Список чатов складывает каждый чат из видимых вам проектов — ваших и ваших коллег
  — под именем проекта, выше чатов вне любого проекта.
- Карточка **Проекты** на странице «Обзор» показывает их списком, с чатами в
  каждом.
- `GET /api/v1/projects` и его подмаршруты входят в публичный API, поэтому скрипт
  может создать проект и наполнить его файлами. См. [API](api.md).

## Держите проект под контролем { #keep-a-project-on-track }

Выберите **Держите проект под контролем** (Keep project on track) на странице
проекта. Выберите опубликованного агента, которого можете править, просмотрите его
ресурсы и подключённые учётные записи, назовите нового агента и таблицу задач,
выберите ритм и явно одобрите **Опубликовать и запустить** (Publish and start). Так
создаётся личная копия этого агента, таблица задач (личная, если вы не выберете
видимость для организации), сохранённые виды «All tasks», «Board», «Open tasks» и
«Blocked», а также автоматизация, закреплённая за новой версией. Исходный агент не
меняется.

Автоматизация работает от вашего имени внутри этого проекта и отчитывается в
диалоге проекта. Она читает состояние задач, проверяет прогресс по проверенным
источникам, обновляет следующие действия и отмечает блокировки и сроки. Отправка
сообщения вовне по-прежнему требует обычного разрешения. Новые
источники, согласие учётной записи или замена рабочего пространства требуют новой
проверки источников. Потеря доступа к проекту останавливает последующие
инструменты; поставленные в очередь уведомления проекта заново проверяют текущий
доступ получателя к проекту. Повторная попытка с теми же настройками использует уже
созданные ресурсы. Ритмом и проверкой источников управляют в разделе
«Автоматизации»; таблица открывается со страницы проекта.

Диалог по расписанию без владельца в проекте может переименовать, архивировать или
удалить тот, у кого есть право править этот проект. Чаты, начатые другим человеком,
остаются под управлением этого человека.

Удаление проекта также стирает его утверждения памяти и производные общие копии и
пытается снять зарегистрированные вебхуки провайдеров, прежде чем каскадно удалить
его автоматизации. Недоступный провайдер записывается в журнал; удалению это не
мешает.
