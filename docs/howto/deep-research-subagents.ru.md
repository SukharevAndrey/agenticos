# Исследуйте вопрос с субагентами и опубликуйте отчёт { #research-a-question-with-subagents-and-publish-a-report }

Создайте агента, который разбивает вопрос на независимые части, отдаёт каждую
своему специалисту и пишет отчёт по тому, что вернулось. Образец — сравнение
трёх лицензий с открытым исходным кодом: устойчивая публичная тема, где каждое
утверждение можно сверить с самим текстом лицензии. Это процедура, которую
нужно выполнить; один записанный запуск приведён как образец.

## Что понадобится { #what-you-need }

- Работающий [экземпляр AgenticOS](../install.md) с профилем модели.
- Веб-поиск: метод по умолчанию — DuckDuckGo, учётная запись и ключ не нужны.
- Песочница, коллекция знаний и подключение по MCP не нужны.

## Подготовьте входные данные { #prepare-the-input }

Вопрос распадается на три независимых подвопроса, по одному на лицензию.
Спросите:

```text
Compare the MIT licence, the Apache License 2.0 and the GPLv3 on one question:
when you distribute software that includes code under that licence, what are
you obligated to do - include the licence text, state changes you made, or
disclose or release your own source code?
```

Опора для сверки, чтобы проверить отчёт агента вручную:

| Лицензия | Включить текст лицензии | Указать изменения | Открыть свой исходный код |
| --- | --- | --- | --- |
| MIT | Да | Нет | Нет |
| Apache-2.0 | Да, плюс файл `NOTICE` | Да, по каждому файлу | Нет |
| GPLv3 | Да | Да, по каждому файлу | Да, для всей составной работы, при распространении |

Обязательство GPLv3 по исходному коду возникает при распространении, а не при
изменении: организация, которая лишь запускает изменённую копию внутри себя,
никому не обязана раскрывать код.

## Создайте агента { #build-the-agent }

1. Создайте агента в **Агенты → Новый агент** (Agents → New agent) и выберите
   свой профиль модели.
2. В **Инструменты** (Toolbox) включите **Делегирование** (Delegation). Включите
   `allow_dynamic` — настройку, которая позволяет модели придумать специалиста
   на один раз для подвопроса, под которого никто не писал специалиста заранее.
   Поставьте режим **Асинхр.** (Async), чтобы три подвопроса выполнялись сразу,
   а не один за другим, и оставьте предел одновременных делегирований равным 3.
   Для `delegate` поставьте **Всегда спрашивать** (Always ask), чтобы вы
   прочитали каждого специалиста, которого пишет модель, до его запуска.
3. Там же, в блоке **Делегирование**, включите **Поделиться поиском в интернете с
   исполнителями** (Share Web search with delegates) и **Поделиться чтением
   веб-страниц с исполнителями** (Share Web fetch with delegates). Придуманный
   моделью специалист не получает собственных возможностей
   [по замыслу](../reference/capabilities.md#delegation): до него доходит только
   то, чем родитель явно поделился, поэтому без этого шага каждый придуманный
   специалист мог бы поручать, но не искать.
4. Включите **Поиск в интернете** (Web search) с методом DuckDuckGo и **Чтение
   веб-страниц** (Read web pages) у самого родителя: общий доступ доводит до
   исполнителя только то, к чему привязан родитель.
5. Включите **Планирование** (Planning) и **Приложения** (Apps).
6. Задайте бюджет и лимит шагов для проверки. В записанном запуске ушло
   40 шагов и около 0,43 USD.
7. Задайте инструкции ниже, затем нажмите **Опубликовать** (Publish).

```text
You research a question that splits into independent sub-questions.
Write a plan naming each sub-question as its own step.
For each sub-question, call delegate to create a one-off specialist with
mode="async": give it a narrow instruction (research exactly this one
sub-question, using web search and web fetch, and answer with a short sourced
summary), a clear name, and no capabilities argument.
After firing all the sub-questions, call wait_tasks for all of them before
writing anything.
Every claim in your final report must carry the source URL it came from.
State plainly where the sources disagree or where you could not find an answer.
Publish the finished report with publish_artifact under the name
licence-comparison.
Do not answer from your own training knowledge without a source URL next to it.
```

## Запустите его { #run-it }

Откройте новый чат с агентом и отправьте вопрос из раздела *Подготовьте входные
данные*.

Модель вызывает `delegate` трижды, по разу на лицензию: это три отдельных
делегирования, а не один вызов на все три. **Вы поставили согласование на
`delegate`**, поэтому все три останавливаются на согласовании вместе: один шаг
модели может остановить несколько вызовов сразу. Просмотрите трёх предложенных
специалистов, затем нажмите **Одобрить** (Approve). Запуск продолжается,
поднимает трёх специалистов в фоне и вызывает `wait_tasks`, чтобы собрать их,
прежде чем писать отчёт.

## Проверьте результат { #check-the-result }

| Проверка | Образец |
| --- | --- |
| Число делегирований | Три, по одному на лицензию, каждое — своя строка в разделе **Активность** под родительским запуском |
| Обязательство MIT | Включить текст лицензии и уведомление об авторских правах; больше ничего |
| Обязательство Apache-2.0 | Текст лицензии, файл `NOTICE` и указание изменений по каждому файлу |
| Обязательство GPLv3 | Текст лицензии, изменения по каждому файлу и полный исходный код при распространении |
| Каждое утверждение | Рядом с ним URL источника, а не общий список в конце |
| Разногласие или пробел | Отчёт прямо говорит об этом или сообщает, что их не было |
| Приложение | В **Приложения** (Apps) есть `licence-comparison`, доступное только вам |
| Вопрос из двух частей, где настоящий источник только один (например, о лицензии, которой не существует) | Отчёт говорит, что не смог подтвердить эту часть, а не выдумывает ответ |

!!! example "Записано на v0.0.504, 25 сентября 2026"

    Модель: Claude Sonnet 4.6 через OpenRouter. Агент написал план из четырёх
    шагов, затем вызвал `delegate` трижды за один ход — `mit-licence-research`,
    `apache2-licence-research`, `gplv3-licence-research` — все в асинхронном
    режиме. Все три остановились на согласовании одним шагом; после одобрения
    запуск вызвал `wait_tasks` и получил `3/3 finished`. Отчёт в точности совпал
    с опорной таблицей, сослался на страницы OSI, Apache.org, GNU.org и FAQ FSF
    и завершился словами «No source disagreements found», перечислив источники,
    которые совпали. Он опубликовал `licence-comparison` как HTML-приложение.
    Общая стоимость: 0,43 USD, включая все три делегирования; отдельной строки
    `agent_runs` для динамического специалиста не существует, так как он не
    опубликованный агент.

## Когда что-то идёт не так { #when-it-goes-wrong }

- **Делегирование отклоняется сразу, а не останавливается на согласовании.**
  Делегирование выключено, или `allow_dynamic` выключен, а модель всё равно
  попробовала `delegate` или `create_agent`: при отсутствии обоих
  делегированию предлагается только `task`.
- **Специалист сообщает, что у него нет инструмента поиска.** Не задан
  `share_with_delegates` или в нём названа возможность, к которой сам родитель
  не привязан; публикация отклоняет второй случай, поэтому обычно это первый.
- **Три подвопроса идут один за другим, а не вместе.** Режим `sync`, или модель
  выбрала `mode="sync"` в собственных вызовах `delegate`, несмотря на
  инструкции.
- **Появляется только одно делегирование, охватывающее всё.** Модель сочла
  вопрос из трёх частей одной задачей, а не разбила его: ужесточите инструкции,
  чтобы в них было сказано поручать каждую часть отдельно, а не только
  исследовать её.
- **Запуск останавливается с сообщением «reached the fan-out ceiling».** За один
  ход запущено делегирований больше, чем `max_fanout`; три подвопроса
  укладываются в значение по умолчанию 3, а четвёртый — нет.

## Зафиксируйте проверку { #record-the-trial }

Сохраните вопрос, план, который написал агент, имя и результат каждого
делегирования, процитированные источники, приложение и его версию, а также
стоимость из раздела **Активность**. Человек по-прежнему сверяет приложение с
опорными фактами, прежде чем доверять ему, решает, кому можно его читать, и
судит, честен ли раздел «не удалось подтвердить» или скрывает поиск, который
стоило повторить.

## Что дальше { #next-steps }

Когда это заработает на теме с известным ответом, направьте агента на вопрос без
фиксированной опоры и полагайтесь на инструкцию «указывать, где источники
расходятся», а не на таблицу, которую вы и так знаете. Чтобы отчёт оставался
актуальным, перейдите к странице
[«Запланируйте еженедельный отчёт»](scheduled-report.md).
