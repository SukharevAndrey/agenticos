# Извлеките данные счетов в таблицу { #extract-invoice-data-into-a-spreadsheet }

Создайте агента, который читает партию счетов и записывает один CSV с
одинаковыми столбцами для каждой строки. Образец — три небольших синтетических
счёта, у одного из них нет даты, поэтому главная проверка в том, сообщает ли
агент о пробеле вместо того, чтобы придумать правдоподобный. Это процедура,
которую нужно выполнить; один записанный запуск приведён как образец.

## Что понадобится { #what-you-need }

- Работающий [экземпляр AgenticOS](../install.md) с профилем модели и
  зарегистрированное [подключение песочницы](../sandbox.md), предоставляющее
  среду выполнения `workbench`: в ней есть `liteparse` (`lit`) и `pdftotext` для
  чтения PDF и окружение Python для записи CSV.
- Знания и диаграммы не нужны.

## Подготовьте входные данные { #prepare-the-input }

Три коротких счёта, сгенерированных как PDF, чтобы образец был похож на
настоящую загрузку. Сохраните этот скрипт как `make_invoices.py` во временном
каталоге:

```python
from reportlab.lib.pagesizes import A4
from reportlab.lib.units import mm
from reportlab.pdfgen import canvas

def draw_invoice(path, number, date, vendor, lines, tax_rate, include_date=True):
    c = canvas.Canvas(path, pagesize=A4)
    width, height = A4
    y = height - 30 * mm
    c.setFont("Helvetica-Bold", 16)
    c.drawString(20 * mm, y, "INVOICE")
    y -= 10 * mm
    c.setFont("Helvetica", 11)
    c.drawString(20 * mm, y, f"Invoice number: {number}")
    y -= 6 * mm
    if include_date:
        c.drawString(20 * mm, y, f"Date: {date}")
        y -= 6 * mm
    c.drawString(20 * mm, y, f"Vendor: {vendor}")
    y -= 6 * mm
    c.drawString(20 * mm, y, "Bill to: Meridian Analytics BV")
    y -= 12 * mm

    c.setFont("Helvetica-Bold", 11)
    c.drawString(20 * mm, y, "Description")
    c.drawString(130 * mm, y, "Qty")
    c.drawString(150 * mm, y, "Amount")
    y -= 6 * mm
    c.setFont("Helvetica", 11)
    subtotal = 0.0
    for desc, qty, amount in lines:
        c.drawString(20 * mm, y, desc)
        c.drawString(130 * mm, y, str(qty))
        c.drawString(150 * mm, y, f"{amount:.2f}")
        subtotal += amount
        y -= 6 * mm
    y -= 4 * mm

    tax = round(subtotal * tax_rate, 2)
    total = round(subtotal + tax, 2)
    c.drawString(120 * mm, y, "Subtotal:")
    c.drawString(150 * mm, y, f"{subtotal:.2f} EUR")
    y -= 6 * mm
    c.drawString(120 * mm, y, f"Tax ({int(tax_rate*100)}%):")
    c.drawString(150 * mm, y, f"{tax:.2f} EUR")
    y -= 6 * mm
    c.setFont("Helvetica-Bold", 11)
    c.drawString(120 * mm, y, "Total:")
    c.drawString(150 * mm, y, f"{total:.2f} EUR")
    c.showPage()
    c.save()
    return subtotal, tax, total

s1 = draw_invoice("INV-1001.pdf", "INV-1001", "2027-01-15", "Nordic Office Supplies",
                   [("Desk chairs, ergonomic", 3, 420.00), ("Standing desks", 2, 260.00)], 0.21)
print("INV-1001", s1)

s2 = draw_invoice("INV-1002.pdf", "INV-1002", "2027-01-22", "Blue Ridge Logistics",
                   [("Freight, Rotterdam-Warsaw", 1, 780.00), ("Customs handling", 1, 195.00)], 0.21)
print("INV-1002", s2)

s3 = draw_invoice("INV-1003.pdf", "INV-1003", None, "Summit Cleaning Services",
                   [("Monthly office cleaning, January", 1, 227.27)], 0.21, include_date=False)
print("INV-1003", s3)
```

Затем запустите его там же. Он запишет `INV-1001.pdf`, `INV-1002.pdf` и
`INV-1003.pdf` рядом с собой:

```bash
uv run --with reportlab python make_invoices.py
```

`make_invoices.py` рисует каждый счёт с помощью `reportlab`: номер счёта,
поставщик, таблица позиций, промежуточный итог, налог 21% и итог. `INV-1001` и
`INV-1002` полные, а в `INV-1003` строки с датой нет вовсе — намеренно.

Опорные значения для сверки извлечения:

| Счёт | Дата | Поставщик | Промежуточный итог | Налог | Итог |
| --- | --- | --- | --- | --- | --- |
| INV-1001 | 2027-01-15 | Nordic Office Supplies | 680.00 | 142.80 | 822.80 |
| INV-1002 | 2027-01-22 | Blue Ridge Logistics | 975.00 | 204.75 | 1179.75 |
| INV-1003 | *(отсутствует)* | Summit Cleaning Services | 227.27 | 47.73 | 275.00 |

Каждый итог — это промежуточный итог плюс налог 21%, поэтому неверный итог можно
проверить вручную.

## Создайте агента { #build-the-agent }

1. Создайте агента в **Агенты → Новый агент** (Agents → New agent) и выберите
   свой профиль модели.
2. В **Инструменты** (Toolbox) включите **Песочница** (Sandbox). Выберите
   **Контейнер** (Container), укажите своё подключение песочницы и среду
   выполнения `workbench`.
3. Задайте бюджет и лимит шагов: чтение трёх коротких PDF и запись одного CSV —
   это несколько вызовов инструментов.
4. Задайте инструкции ниже, затем нажмите **Опубликовать** (Publish).

```text
You extract structured data from attached invoices.
Read each invoice from the workspace before extracting anything - use lit
or pdftotext to get its text; do not guess from the filename.
Write invoices.csv in the workspace with exactly these columns: invoice_number,
date, vendor, subtotal, tax, total, currency.
If a field is not present on an invoice, leave that cell empty and name the
invoice and the missing field in your reply. Never invent a value that is
not on the document.
Check that subtotal plus tax equals total for each invoice, and say so if one
does not.
```

## Запустите его { #run-it }

Приложите `INV-1001.pdf`, `INV-1002.pdf` и `INV-1003.pdf` к новому диалогу и
отправьте:

```text
Extract the invoice data from these three files into invoices.csv, with one row per invoice.
```

Чтение текста PDF в среде выполнения `workbench` запускает `lit` или `pdftotext`
через `execute`, а он запрашивает согласование так же, как команда оболочки на
странице [«Превратите CSV в диаграмму, которую можно проверить»](csv-chart.md#run-it).
Прочитайте команду, затем нажмите **Одобрить** (Approve); сама запись CSV
согласования не требует. Агент может несколько раз за
один ход остановиться на `execute`: первая попытка, которая записывает вывод
`lit` в файл вне рабочего пространства, и вторая, которая печатает прямо в вывод
команды, — одна из возможных форм. См. записанный запуск ниже.

## Проверьте результат { #check-the-result }

| Проверка | Образец |
| --- | --- |
| Строки `invoices.csv` | Три, по одной на счёт, те же семь столбцов в том же порядке |
| INV-1001 и INV-1002 | Каждое поле в точности совпадает с опорной таблицей |
| Ячейка даты в INV-1003 | Пустая, а не угаданная или придуманная дата |
| Ответ | Называет `INV-1003` и «date» как пропущенные, а не просто оставляет ячейку пустой |
| Итоги | Промежуточный итог плюс налог равен итогу в каждой строке; агент говорит об этом, если проверял и в одной строке не сходится |
| Четвёртый файл, вовсе не счёт | Агент говорит, что не смог извлечь из него поля счёта, а не придумывает строку |

Откройте `invoices.csv` из рабочего пространства и проверьте его напрямую:
ответ, который перечисляет правильные числа текстом, тогда как в файле лежит
другое, — это пробел, который показывает только сам файл.

!!! example "Записано на v0.0.504, 25 сентября 2026"

    Модель: Claude Sonnet 4.6 через OpenRouter, среда выполнения `workbench`.
    Первый вызов `execute` у агента запустил `lit parse <file> -o /tmp/inv*.md`
    для всех трёх PDF, затем он попробовал `read_file` для `/tmp/inv1001.md` и
    двух других — все три не удались, потому что `/tmp` находится вне рабочего
    пространства, до которого дотягивается `read_file`, хотя сам `execute` может
    туда писать. Агент справился сам: второй вызов `execute` заново выполнил
    `lit parse` для всех трёх файлов без `-o`, напечатав прямо в вывод команды,
    откуда он затем прочитал результат инструмента. Оба вызова
    `execute` потребовали отдельных согласований в одном и том же ходе.

    `invoices.csv` получился со всеми тремя строками и опорными столбцами, каждое
    поле INV-1001 и INV-1002 в точности совпало с исходными PDF, а ячейка
    `date` у INV-1003 осталась пустой. В ответе пропущенным полем названо
    «`INV-1003` — `date`». Перед завершением агент прогнал собственную проверку
    арифметики отдельным `execute` — `python3 -c "..."`, который прочитал CSV
    обратно и сравнил промежуточный итог плюс налог с итогом, — и сообщил, что
    все три строки сходятся. Общая стоимость запуска: 0,1302 USD при 37 246
    входных и 1 233 выходных токенах.

## Когда что-то идёт не так { #when-it-goes-wrong }

- **Агент угадывает дату для INV-1003.** Инструкции велят оставить ячейку
  пустой и назвать пробел; если он всё равно её заполняет, добавьте «не выводи
  дату из контекста» и проверьте снова на том же файле.
- **Запуск останавливается после чтения файлов.** Он ждёт согласования
  `execute` для `lit` или `pdftotext`. Откройте чат или **Согласования**
  (Approvals) в разделе **Активность** (Activity). Он может остановиться дважды
  за один ход — см. записанный запуск выше.
- **`read_file` не срабатывает на пути, который только что записал `lit`.**
  `execute` может писать где угодно в контейнере, в том числе вне `/workspace`,
  а `read_file` ограничен рабочим пространством. Пусть агент разбирает прямо в
  вывод команды или пишет файл `lit` с ключом `-o` внутри рабочего
  пространства, а не в `/tmp`.
- **Итог отличается на сумму налога.** Проверьте, прочитал ли агент напечатанный
  в счёте итог или пересчитал его: образцу такого размера пересчёт не нужен
  никогда, и расхождение обычно означает неверно прочитанную позицию.
- **Столбцы CSV каждый раз разные.** Инструкции называют их точно; если модель
  всё равно меняет порядок или добавляет столбец, перечислите их буквальной
  строкой заголовка, а не прозой.
- **PDF с отсканированной страницей читается как пустой.** `lit` распознаёт
  лишь страницы, у которых нет текстового слоя, а распознавание стоит несколько
  секунд на страницу; см. [что есть в среде выполнения, а чего в ней намеренно
  нет](../sandbox.md#what-is-in-it-and-what-is-deliberately-not), прежде чем
  направлять этого агента на сканы счетов вместо сгенерированных файлов.

## Зафиксируйте проверку { #record-the-trial }

Сохраните три исходных PDF, точный промпт, версию агента, одобренные вызовы
`execute` из раздела **Активность** и получившийся `invoices.csv` — а не только
ответ в чате. Человек по-прежнему сверяет отчёт о пропущенных полях с исходным
PDF и решает, что делать с пробелом: задача агента — показать его, а не
устранить.
