# Управляйте AgenticOS с помощью ИИ-клиента { #operate-agenticos-with-an-ai-client }

[Плагин AgenticOS](https://github.com/vstorm-co/agenticos/tree/main/plugins/agenticos)
добавляет к инструментам MCP платформы процедуры: выбор пути развёртывания,
настройку зависимостей, сборку решений и выпуск проверенных агентов. Он действует
с правами подключённого участника в одной организации. Для установки нужен
терминал или CI-раннер.

## Установите и подключите { #install-and-connect }

```bash
claude plugin marketplace add vstorm-co/agenticos
claude plugin install agenticos@agenticos
claude mcp add --transport http agenticos https://<api-host>/mcp
```

Завершите OAuth в браузере и выберите нужную организацию и области доступа.
**Настройки → MCP-клиенты** (Settings → MCP clients) перечисляет команды
подключения для конкретных клиентов. В плагине нет фиксированного адреса
сервера. Правила доступа и согласования см. в разделе [MCP](../mcp.md).

Базовая версия плагина проверена на 1.82.2. Новые инструменты зависимостей,
качества и пакетов используют контракт MCP 1, который объявляет
`get_platform_context`. Сервер без него по-прежнему может пользоваться своими
существующими инструментами. Клиент должен обнаружить возможности и области
доступа; одни лишь номера версий доступ не дают. Маршруты, доступные только
ИИ-клиенту, требуют OAuth, а обычные ключи организации сохраняют свою границу
публичного API.

## Соберите и выпустите решение { #build-and-release-a-solution }

Опишите результат, пользователей, источники и разрешённые эффекты своими словами.
Прежде чем проектировать решение, клиент обнаруживает возможности, узлы
сценариев, подключения и существующие ресурсы. Пакеты для поддержки, работы с
репозиторием и вводного обучения — это примеры, а не предел поддерживаемых
задач.

Профили моделей могут ссылаться на существующие идентификаторы в хранилище
секретов. `list_secret_references` показывает только доступные имена,
идентификаторы, виды и назначения; значения и подсказки он опускает. Поиск
эндпоинтов эмбеддингов определяет локальные сервисы. `get_setup_link` передаёт ввод
учётных данных и согласие OAuth обратно в сессию консоли самого человека.
Никогда не вставляйте учётные данные или адрес обратного вызова OAuth в диалог
или в пакет.

`plan_solution` проверяет манифест и возвращает его хеш и требуемые разрешения.
`install_solution` нужны этот хеш, точный манифест и ключ установки. Он создаёт
приватные ресурсы и свою квитанцию в одной транзакции базы данных, ничего не
публикуя, не выполняя, не индексируя и не ставя в расписание. Повтор с тем же
содержимым возвращает ту же квитанцию; изменённый манифест для того же
вызывающего, организации и ключа отклоняется. Другая копия требует другого ключа
и не конфликтующих имён ресурсов.

Логические ссылки пакета привязывают агентов к их новым файлам контекста,
навыкам и знаниям. Подготовка сценария может включать таблицу и её
заполнитель. Внешние ссылки на модели, эмбеддинги и подключения остаются
явными идентификаторами, специфичными для экземпляра. Перечитайте ресурсы после
установки: квитанция — это история, а не доказательство того, что их с тех пор не
правили и не удаляли. Правьте установленные ресурсы обычными операциями;
установка не перезаписывает их, как обновление пакета.

Для выпуска создайте набор данных с кейсами, у которых настроена оценка, оцените
стоимость и запустите оценки, изучите результат, затем опубликуйте версию
и переведите её в окружение. Закрепите версию в продакшене до публикации, если
продакшен следует за последней версией, а вам нужен поэтапный выпуск. Действуют
существующие тестовые подключения, защитные проверки и ограничения на обход
проверок. Для отката перенаправьте окружение на существующую версию, сохранив
историю. См. [Окружения](../environments.md).

## Проверьте развёртывание или ответвление { #verify-a-deployment-or-fork }

Навык развёртывания использует существующую [процедуру для одного
хоста](../deploy.md), команды bootstrap и doctor. Навык разработки поддерживает
собственный префикс образов ответвления и пул-реквесты обновления из upstream. MCP
платформы не даёт прав SSH или прав в облаке.

Для одноразовой локальной проверки инфраструктуры из рабочей копии:

```bash
uv run --directory backend python ../scripts/agenticos_smoke.py --version 1.84.0
# Выполните показанный план, сохранив отчёт вне одноразового стека:
uv run --directory backend python ../scripts/agenticos_smoke.py --version 1.84.0 --run --report /tmp/agenticos-smoke.json
```

Проверка использует опубликованные образы, изолированный проект Compose,
сгенерированные локальные учётные данные и детерминированную локальную модель.
Она создаёт организацию, проверяет консоль и API и доводит запуск агента до конца
через настоящий MCP-клиент. После этого она удаляет свои контейнеры и тома. Это
проверяет инфраструктуру платформы, а не качество модели, платного провайдера,
внешний DNS или TLS в продакшене.
