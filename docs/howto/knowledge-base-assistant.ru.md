# Отвечайте на вопросы по библиотеке документов со ссылками на источники { #answer-questions-across-a-document-library-with-citations }

Создайте агента, который отвечает по небольшой библиотеке кадровых политик, а не
по одному файлу. В примере четыре коротких документа в одной коллекции: на один
вопрос отвечает один документ, для другого нужно объединить два, а третий не
покрыт вовсе. Проверка ответа по нескольким документам означает чтение обоих
исходных фрагментов, а не только ответа. Это процедура, которую нужно выполнить;
один записанный запуск приведён как образец.

Если документ один и коллекцией управлять не нужно, начните с [вашего первого
агента по документам](first-document-agent.md). Эта страница — следующий шаг:
несколько документов и ответ, который должен ссылаться на нужный.

## Что понадобится { #what-you-need }

- Работающий [экземпляр AgenticOS](../install.md) с профилем модели.
- Провайдер эмбеддингов и ключ в хранилище секретов для него — в записанном
  запуске использовался `text-embedding-3-small` от OpenRouter. [Настройка базы
  знаний](set-up-knowledge-base.md) полностью разбирает диалог создания.
- Песочница и другие возможности не нужны.

## Подготовьте входные данные { #prepare-the-input }

Четыре коротких файла Markdown, загружаемых по отдельности. Пример вымышлен, и
две политики намеренно содержат одно и то же число, чтобы для одного вопроса
понадобились обе.

`expense-policy.md`:

```text
Employees may claim reimbursement for client meals up to 40 EUR per person.
Travel booked more than 14 days in advance must use economy class for flights
under 6 hours. Mileage for a personal car used on company business is
reimbursed at 0.35 EUR per kilometre. Receipts are required for any claim over
15 EUR. Claims must be submitted within 30 days of the expense.
```

`remote-work-policy.md`:

```text
Employees may work remotely up to 3 days per week without prior approval.
A fully remote arrangement needs sign-off from the department head and HR.
Remote employees must be reachable during core hours, 10:00 to 16:00 in their
local time zone. Equipment for a home office is reimbursed once per employee,
up to 400 EUR, on the same 15 EUR receipt threshold as the expense policy.
```

`onboarding-checklist.md`:

```text
A new employee's manager requests a laptop and accounts in the first week.
IT provisions access within 2 business days of the request. The employee
completes the compliance training module within 30 days of their start date.
The 400 EUR home-office equipment allowance from the remote work policy is
requested through the same IT ticket as the laptop.
```

`travel-booking-guide.md`:

```text
Book flights and hotels through the corporate travel portal. Economy class is
the default for flights under 6 hours, matching the expense policy's advance-
booking rule. Hotel stays are capped at 180 EUR per night in tier-1 cities and
120 EUR elsewhere. A trip that combines client meetings and a conference needs
the sponsoring manager's approval before booking.
```

Контрольные факты: на деловой обед с клиентом можно потратить не больше 40 EUR
(только из политики расходов). Лимит на оборудование для домашнего офиса —
400 EUR, и он запрашивается через ту же ИТ-заявку, что и ноутбук: одно число из
политики удалённой работы, один шаг из чек-листа адаптации. Срок уведомления при
увольнении здесь нигде не указан.

## Создайте агента { #build-the-agent }

1. В **Знания → Новая база знаний** (Knowledge → New) назовите коллекцию,
   разверните **Эмбеддинги** (Embeddings) и выберите провайдера и модель,
   которые работают с вашим ключом: в записанном запуске использовались
   OpenRouter и `text-embedding-3-small`. Этот выбор фиксируется, как только
   коллекция создана.
2. Создайте коллекцию и загрузите четыре файла. Дождитесь, пока каждый перейдёт
   в `done`, прежде чем продолжать.
3. Создайте агента в **Агенты → Новый агент** (Agents → New agent) и выберите
   свой профиль модели.
4. В **Инструменты** (Toolbox) включите **Поиск по знаниям** (Knowledge search)
   и привяжите только что наполненную коллекцию. Оставьте `default_top_k` по
   умолчанию: четырём коротким документам больше не нужно.
5. Задайте инструкции ниже, затем нажмите **Опубликовать** (Publish).

```text
Answer questions from the bound HR policy collection.
Cite the document you used for each fact.
If the answer draws on more than one document, name each one.
If the collection does not cover the question, say so rather than guessing.
```

!!! info "Две настройки, которые стоит знать, прежде чем масштабировать это"

    `self_query_enabled` (по умолчанию выключена) заставляет модель выводить
    фильтры — например, по источнику, типу документа или диапазону дат — из
    вопроса вроде «политики, обновлённые в прошлом квартале»: полезно, когда
    документы несут такие метаданные, и не нужно для четырёх файлов без них.
    `parent_context` (по умолчанию выключена) возвращает текст вокруг найденного
    фрагмента, а не только сам фрагмент, что помогает, когда ответ находится на
    краю фрагмента. Обе настройки читаются из явных фильтров, которые задаёт сама
    модель, и никогда в них не записываются, и ни одна не расширяет коллекции или
    организацию, к которым агент может получить доступ. См. [справочник по
    возможностям](../reference/capabilities.md#knowledge-search).

## Запустите его { #run-it }

Задавайте каждый вопрос в новом диалоге, чтобы более ранний ответ не просочился
в следующий.

```text
How much can I claim for a client meal?
```

```text
I am fully remote. How much is the home-office equipment allowance, and how do I request it?
```

```text
What is the notice period if I want to resign?
```

## Проверьте результат { #check-the-result }

| Проверка | Образец |
| --- | --- |
| Ответ про обед с клиентом | 40 EUR, со ссылкой на `expense-policy.md` |
| Ответ про домашний офис | 400 EUR, со ссылкой на `remote-work-policy.md`, а шаг запроса — со ссылкой на `onboarding-checklist.md` |
| Вопрос об увольнении | Говорит, что коллекция это не покрывает, и не выдумывает цифру |
| Найденные фрагменты на странице **Активность** (Activity) | Лучшее совпадение в запуске про обед с клиентом — `expense-policy.md`; среди совпадений в запуске про домашний офис есть оба исходных документа |
| Вопрос о командировках за прошлую неделю | Отвечен по `travel-booking-guide.md`, а не смешан с остальными тремя |

Читайте найденные фрагменты на странице **Активность**, а не только ответ. Ссылка
на правильный файл с неправильным числом или правильное число из неправильного
файла — и то и другое в чате выглядит правильно.

!!! example "Записано на v0.0.504, 25 сентября 2026"

    Модель: Claude Sonnet 4.6 через OpenRouter, `default_top_k` равно 5. Вопрос
    про обед с клиентом вызвал `search_documents` один раз и получил ответ «до
    40 € на человека» со ссылкой на `expense-policy.md`, стоимость 0,0133 USD.
    Вопрос про домашний офис нашёл три документа и получил ответ «до 400 €» со
    ссылкой на `remote-work-policy.md` для суммы и на `onboarding-checklist.md`
    для «той же ИТ-заявки, через которую запрашивается ноутбук», стоимость
    0,0181 USD. Вопрос об увольнении нашёл три наименее подходящих документа,
    ничего в них не обнаружил и ответил «похоже, здесь нет документа о сроках
    уведомления при увольнении», стоимость 0,0135 USD.

    При первой попытке к спецификации этого агента не была привязана ни одна
    коллекция — ошибка в подготовке проверки, а не в продукте — и модель
    ответила из собственного обучения, вместо того чтобы признать, что ей
    ничего не привязали. `search_documents` не вызывался ни разу. Привязка
    коллекции и повторная публикация это исправили; различие между «вызова
    инструмента не было» и «инструмент отработал и ничего не нашёл» — первое,
    что нужно проверить, когда ответ выглядит уверенным, а источника нет.

## Когда что-то идёт не так { #when-it-goes-wrong }

- **Агент отвечает гладко, но без ссылки.** Проверьте на странице **Активность**,
  вызывался ли `search_documents` вообще. Возможность знаний, к которой не
  привязана ни одна коллекция, молча не даёт ничего, вместо того чтобы давать
  инструмент, который всегда падает.
- **Документ отсутствует в ответе, где он должен быть.** Проверьте статус
  документа в коллекции. Документ в состоянии `processing` или с ошибкой невидим
  для поиска, как бы ясно его ни мог прочитать человек.
- **На вопрос об увольнении приходит уверенный, но неверный ответ.** Именно
  последняя строка инструкций — «скажите об этом, а не гадайте» — превращает
  молчание в отказ. Проверьте это намеренно, как это делает третий вопрос здесь.
- **Два документа, которые должны объединяться, всегда дают ответ только по
  одному.** Увеличьте `default_top_k` или проверьте, не отдаёт ли формулировка
  вопроса предпочтение словарю одного документа перед другим.
- **Коллекцию должна наполнять синхронизируемая папка, а не ручная загрузка.**
  См. [настройку источников синхронизации](configure-sync-sources.md): одна
  коллекция может сочетать загрузки и синхронизацию по расписанию.

## Зафиксируйте проверку { #record-the-trial }

Сохраните четыре файла, вопросы, версию агента, профили модели и эмбеддингов, а
также найденные фрагменты со страницы **Активность** для каждого запуска — не
только ответы. Человек по-прежнему судит, действительно ли ссылка подтверждает
сказанное агентом и было ли «не покрыто» верным решением, а не ленивым.

## Что дальше { #next-steps }

Когда поиск уверенно работает по нескольким документам, поставьте агента перед
людьми: [Slack](slack-handbook-assistant.md) — тот же шаблон, только перед ним
появляется канал. Если корпус слишком велик для ручной загрузки, вместо этого
[настройте источники синхронизации](configure-sync-sources.md).
