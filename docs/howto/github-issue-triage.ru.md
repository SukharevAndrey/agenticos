# Разбирайте новые задачи на GitHub автоматически { #triage-new-github-issues-automatically }

Подключите [триггер по событию](../triggers.md) к вебхуку `issues` репозитория,
чтобы новая задача попадала к агенту в момент открытия, и пусть агент предложит
приоритет, метки и проверку на дубликат по тексту доставки. Эта страница
проверяет только половину с триггером: она подписывает синтетическую доставку и
отправляет её прямо в вебхук — учётная запись GitHub не используется. Это
процедура, которую нужно выполнить; один записанный запуск приведён как образец
для этой половины. Чтобы ставить метки или отвечать комментарием в задаче, нужно
подключение GitHub, которого в этой среде нет, и здесь это не выполняется.

## Что понадобится { #what-you-need }

- Работающий [экземпляр AgenticOS](../install.md) с профилем модели.
- Чтобы запускать это по-настоящему, нужен репозиторий, в который можно добавить
  вебхук (источник **GitHub** в варианте OAuth App), или приложение GitHub,
  зарегистрированное для вашей организации (**GitHub (App)**), — см. [два
  способа подключить
  GitHub](../triggers.md#two-ways-to-connect-github-and-how-to-tell-which-you-are-running).
  Для проверки ниже не настроено ни то, ни другое.
- Чтобы агент действительно ставил метки или комментировал, нужно [подключение
  MCP к GitHub](../mcp.md#development) (аутентификация по токену) или собственные
  права на запись приложения GitHub, привязанные к агенту, — это здесь тоже не
  настроено.

## Подготовьте входные данные { #prepare-the-input }

Сокращённая, но реалистичная полезная нагрузка вебхука `issues` для вымышленного
репозитория — достаточно малая, чтобы проверить разбор вручную:

```json
{
  "action": "opened",
  "issue": {
    "number": 42,
    "title": "Export button does nothing on Safari",
    "html_url": "https://github.com/acme/widgets/issues/42",
    "body": "Steps to reproduce:\n1. Open the reports page in Safari 18\n2. Click Export as CSV\n3. Nothing happens, no download, no error in the console\n\nWorks fine in Chrome. This is blocking our weekly export for finance."
  },
  "repository": {"full_name": "acme/widgets"}
}
```

Здесь нет ни настоящего репозитория, ни настоящего отчёта.

## Создайте агента { #build-the-agent }

1. Создайте агента в **Агенты → Новый агент** (Agents → New agent) и выберите
   свой профиль модели.
2. Для этой проверки оставьте **Инструменты** (Toolbox) пустыми: агенту нужно
   только прочитать доставку и порассуждать о ней. **Дата и время** (Date and
   time) достаточно, если хотите, чтобы разбор ссылался на сегодняшнюю дату.
3. Задайте инструкции, совпадающие с промптом готового шаблона, затем нажмите
   **Опубликовать** (Publish):

```text
You triage new GitHub issues from the delivery described in the task message.
Suggest a priority (low, medium, high) and one or two labels.
Say whether it looks like a duplicate of an existing issue, using only what the message gives you.
Flag immediately, in the first line, if it looks like a security report.
End with a short comment-ready summary a maintainer could paste onto the issue.
You have no tool to read the repository or post the comment yourself - say so if asked to do either.
```

Это промпт шаблона **Triage the new issue** в шаблонах триггеров
(`GET /trigger-templates`), который подставляет ровно его в новый триггер по
событию **GitHub**.

## Настройте триггер { #set-up-the-trigger }

В **Автоматизации → Новый триггер по событию → GitHub** (Routines → New event
trigger → GitHub) выберите этого агента, оставьте фильтр по умолчанию
(срабатывает только на `opened`) и вставьте полученные URL вебхука и секрет
подписи в раздел репозитория **Settings → Webhooks → Add webhook** с типом
содержимого `application/json` — точные поля см. в [рецепте для
GitHub](../triggers.md#a-github-recipe-5-minutes). Этот шаг требует репозитория,
которого в этой проверке нет.

## Запустите его { #run-it }

Раз доставлять из репозитория нечего, подпишите синтетическую доставку сами —
ровно так, как описано в разделе [подпись доставки
самостоятельно](../triggers.md#signing-a-delivery-yourself) для универсального
источника: собственные доставки GitHub используют ту же схему `HMAC-SHA256`,
меняется только имя заголовка:

```python
import hashlib, hmac, json, httpx

secret = b"<the trigger's signing secret>"
body = json.dumps(payload).encode()  # the fixture above
signature = "sha256=" + hmac.new(secret, body, hashlib.sha256).hexdigest()

httpx.post(
    f"{BASE}/api/v1/webhooks/triggers/github/{trigger_id}",
    content=body,
    headers={
        "Content-Type": "application/json",
        "X-Hub-Signature-256": signature,
        "X-GitHub-Event": "issues",
    },
)
```

## Проверьте результат { #check-the-result }

| Проверка | Образец |
| --- | --- |
| Подписанный POST | `202`, сразу |
| Запуск на странице **Активность** (Activity) | Способ запуска `schedule` (триггер по событию срабатывает так же, как расписание), статус completed |
| Разбор | Называет приоритет и одну-две метки, отвечает на вопрос о дубликате и не помечен как отчёт об уязвимости |
| Последняя строка ответа | Короткая сводка, готовая для комментария |
| Вызовы инструментов | Нет — у этого агента нет инструмента GitHub, поэтому он рассуждает только по доставленному тексту |
| Просьба самому поставить метку в диалоге того же запуска | Говорит, что у него нет такого инструмента, а не выдумывает его |
| Та же полезная нагрузка, подписанная неверным секретом | `403`, ещё до того, как запуск вообще будет рассмотрен |
| Доставка с `"action": "edited"` | `202` и никакого нового запуска — фильтр по умолчанию срабатывает только на `opened` |

!!! example "Записано на v0.0.504, 25 сентября 2026"

    Модель: Claude Sonnet 4.6 через OpenRouter. Подписанная доставка ответила
    `202`; примерно через десять секунд на странице **Активность** появился запуск
    со способом запуска `schedule`, стоимость 0,003861 USD, с сообщением, которое
    дописал триггер: «В acme/widgets открыта задача GitHub. Задача №42: кнопка
    Export ничего не делает в Safari …».

    Ответ: «**Это не отчёт об уязвимости.** Приоритет: High. Метки: `bug`,
    `browser-compatibility`. Проверка на дубликат: ничто в предоставленных
    сведениях не указывает на дубликат …» — и в конце абзац, готовый для
    комментария, с шагами воспроизведения и советом мейнтейнеру проверить
    обработку `Blob`/`<a download>` в Safari. Вызовов инструментов не было.
    Доставка, подписанная неверным секретом, вернула `403` с сообщением
    `"Webhook signature did not verify"`; та же полезная нагрузка с
    `"action": "edited"` вернула `202` без нового запуска.

## Когда что-то идёт не так { #when-it-goes-wrong }

- **`403` на каждую доставку, настоящую или синтетическую.** Секрет не совпадает
  или тип содержимого не `application/json`: при доставке в кодировке формы
  подписываются не те байты, что отправил GitHub. Вкладка **Recent Deliveries**
  самого вебхука в GitHub показывает точный запрос и ответ для настоящего
  репозитория.
- **`202`, а в «Активности» ничего нет.** `202` означает «принято», а
  не «выполнено», и ещё означает «ни с чем не совпало»: неактивный триггер или
  отфильтрованное действие отвечают точно так же. Прежде чем считать это ошибкой,
  проверьте фильтр триггера.
- **У триггера `GitHub (App)` нет вебхука в настройках репозитория.** Это
  ожидаемо: приложение доставляет на один общий URL на установку, а не на URL для
  каждого триггера. См. [когда приходит
  доставка](../triggers.md#when-a-delivery-arrives).
- **Агент пытается комментировать и не может.** У агента в этой проверке
  намеренно нет инструмента GitHub. Добавление его — отдельный осознанный шаг,
  см. далее.

## Зафиксируйте проверку { #record-the-trial }

Сохраните подписанную полезную нагрузку, фильтр триггера, запуск на странице
**Активность** и его ответ. Это доказывает только триггер и промпт; это не
доказывает проставление меток или комментирование, для которых нужна своя
возможность и своя проверка.

## Что дальше { #next-steps }

Чтобы агент действовал, а не только предлагал, привяжите [подключение MCP к
GitHub](../mcp.md#development) или права на запись приложения GitHub и решите,
кто проверяет метку или комментарий до публикации: у инструментов MCP нет
собственного согласования для каждого инструмента, поэтому такая проверка должна
исходить от человека, наблюдающего за запуском, или от режима чата **Спрашивать
обо всём** (Ask about everything), как и при [превращении заметок о встрече в
задачи](meeting-to-tasks.md). Триггер всегда работает от имени [участника,
который его создал](../concepts.md#it-runs-as-a-person), поэтому назначьте эту
роль тому, кто должен отвечать за ошибочно срабатывающий триггер, а не тому,
кто случайно его настроил.
