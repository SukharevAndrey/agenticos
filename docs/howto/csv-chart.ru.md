# Превратите CSV в диаграмму, которую можно проверить { #turn-a-csv-into-a-chart-you-can-check }

Дайте агенту небольшой файл продаж и попросите итоги по месяцам, диаграмму и
скрипт, который их построил. Образец настолько мал, что суммы можно сложить
вручную, поэтому каждое число в ответе агента можно сверить с исходными
строками. Это процедура, которую нужно выполнить; один записанный запуск
приведён как образец. Она не измеряет точность на ваших данных.

## Подготовьте входные данные { #prepare-the-input }

Понадобится [работающий экземпляр AgenticOS](../install.md) с профилем модели.
Сохраните это как `sales.csv`:

```csv
month,product,revenue_eur
2026-01,A,120
2026-01,B,80
2026-02,A,150
2026-02,B,100
2026-03,A,90
2026-03,B,110
```

Цифры придуманы. Опора для сверки: январь — 200 EUR, февраль — 250, март —
200; всего 650 из шести строк данных.

## Проверьте песочницу { #check-the-sandbox }

Агент читает файл и запускает скрипт в контейнере. Для этого нужны служба
песочницы и зарегистрированное подключение:

- `make dev` и профиль `sandbox` в Docker Compose запускают службу. См.
  [установку](../install.md).
- **Песочницы → Добавить подключение** (Sandboxes → Add connection)
  регистрирует подключение для организации. Подключение предоставляет среду
  выполнения `workbench`, в которой есть `pandas` и `matplotlib`. См.
  [песочницу](../sandbox.md#which-environments-an-agent-may-ask-for).
- `agenticos cmd doctor` показывает, отвечает ли каждое зарегистрированное
  подключение какой-либо средой выполнения.

Первый сеанс собирает образ `workbench`, около 2 ГБ. На первом ходе диалога на
новом хосте заложите минуту-другую.

## Создайте агента { #build-the-agent }

1. Создайте агента в **Агенты → Новый агент** (Agents → New agent) и выберите
   свой профиль модели.
2. В **Инструменты** (Toolbox) включите **Песочница** (Sandbox). Выберите
   **Контейнер** (Container), а не **Файлы** (Files): в рабочем пространстве
   «Файлы» нет оболочки, поэтому агент не сможет запустить скрипт. Укажите
   подключение и среду выполнения `workbench`, а область оставьте «Этот диалог».
3. Включите **Диаграммы** (Charts). Они рисуют числа, которые у агента уже
   есть, поэтому диаграмма показывает то, что посчитал скрипт.
4. Задайте бюджет и лимит шагов для проверки. В записанном запуске ушло
   25 шагов и около 0,11 USD.
5. Задайте инструкции ниже, затем нажмите **Опубликовать** (Publish).

```text
You analyse CSV files the user attaches.
Read the file from the workspace before calculating anything.
Show the totals as a table and state the number of rows you read.
Draw charts with create_chart from numbers you computed.
Save any code and output files in the workspace and give their paths.
Do not fetch data from the internet.
```

## Запустите его { #run-it }

Откройте новый чат с агентом, приложите `sales.csv` и отправьте:

```text
Sum revenue_eur by month. Return the totals as a table, draw a bar chart of them, and save the calculation script and a PNG of the chart in the workspace.
```

Вложение записывается в рабочее пространство в папку `uploads/`, и сообщение
говорит агенту, где его искать. [Обработка файлов](../file-processing.md)
описывает, как это устроено.

Когда агент захочет запустить скрипт, в чате появится **Требуется согласование
инструмента** (Tool approval required). Запуск команды оболочки — побочный
эффект, поэтому по умолчанию его одобряет человек. Прочитайте команду, затем
нажмите **Одобрить** (Approve). Запуск продолжится с того места, где
остановился. Чтобы пропустить это для доверенного тестового агента, измените
настройку согласования для `execute` в Конструкторе. См.
[согласования](../governance.md#approvals).

## Проверьте результат { #check-the-result }

| Проверка | Образец |
| --- | --- |
| Итоги по месяцам в ответе, выводе скрипта и на диаграмме | 200, 250 и 200 EUR в порядке месяцев |
| Общий итог | 650 EUR |
| Прочитано строк | 6 |
| Диаграмма | Столбцы начинаются от нуля, на оси указана единица |
| Рабочее пространство | Скрипт и PNG существуют и открываются |
| То же сообщение без приложенного файла | Агент говорит, что файла нет, и не выдумывает данные |

Сверяйте каждое число с исходными строками, а не с итогами в самом ответе.
Затем откройте рабочее пространство из панели файлов чата. Откройте сам PNG и
прочитайте скрипт. Путь в ответе не доказывает, что файл существует.

!!! example "Записано на v0.0.504, 25 сентября 2026"

    Модель: Claude Sonnet 4.6 через OpenRouter. Агент вызвал `read_file` для
    загруженного файла, `write_file` для `analysis/revenue_by_month.py`, затем
    `execute`, который остановился в ожидании согласования. После одобрения
    скрипт вывел три итога, `Total rows read : 6` и
    `Grand total (€) : 650`. `create_chart` нарисовал 200, 250 и 200. В рабочем
    пространстве лежали скрипт и PNG 1050×600. Стоимость: 0,115 USD.

    В финальном ответе итоги приведены словами и перечислены сохранённые файлы,
    но таблица и число строк не повторены. Они были в выводе скрипта. Без файла
    агент показал пустое рабочее пространство и попросил CSV.

## Когда что-то идёт не так { #when-it-goes-wrong }

- **Агент говорит, что у него нет оболочки.** В возможности выбраны **Файлы**
  вместо **Контейнера**.
- **Первый ход длится долго.** Собирается образ `workbench`. Следующие сеансы
  используют его повторно.
- **Запуск останавливается после того, как агент написал скрипт.** Он ждёт
  согласования `execute`. Откройте чат или вкладку **Согласования** (Approvals)
  в разделе **Активность** (Activity).
- **Ошибка подключения упоминает песочницу.** Запустите
  `agenticos cmd doctor`, затем проверьте подключение в разделе **Песочницы**
  (Sandboxes).
- **Итог неверен.** Прочитайте скрипт, прежде чем менять промпт. Ошибка в
  расчёте и отсутствующая среда выполнения — разные проблемы, и результаты
  инструментов в разделе **Активность** показывают, какая из них случилась.

## Зафиксируйте проверку { #record-the-trial }

Сохраните точный CSV, промпт, версию агента, профиль модели, запуск в разделе
**Активность**, скрипт и PNG. Сохраняйте и неудачные запуски. Если публикуете
результат, скажите, что данные синтетические, и покажите столько таблицы, чтобы
диаграмму можно было проверить.

Человек одобряет команду, сверяет итоги с исходными данными и открывает файлы. Агент
эту проверку не заменяет. Он даёт всё, чтобы сделать её быстро.

Когда это заработает, добавляйте трудности по одной: пропущенное значение,
повторяющийся месяц или вторая валюта. Каждая показывает, как агент обходится с
данными, которые не сходятся аккуратно. Чтобы повторять отчёт по расписанию,
перейдите к странице
[«Запланируйте еженедельный отчёт»](scheduled-report.md).
