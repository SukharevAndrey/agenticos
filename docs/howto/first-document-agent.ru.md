# Соберите своего первого агента по документам { #build-your-first-document-agent }

Соберите помощника, который отвечает на вопросы о политике выдачи оборудования
по одному документу. Этот синтетический пример даёт факт для проверки и
намеренный пробел в информации. Это процедура, которую нужно выполнить; один
записанный запуск приведён как образец.

## Подготовьте источник { #prepare-the-source }

Используйте работающий [экземпляр AgenticOS](../install.md) и настроенную модель.
Настройку учётных данных провайдера и модели см. в разделе [ваш первый
агент](../first-agent.md). Затраты зависят от выбранного провайдера и
конфигурации.

Сохраните этот текст как `equipment-handbook.md`:

```text
Equipment requests go to the office manager.
Include the item, reason and delivery location.
```

Это выдуманные факты политики. Лимит расходов не указан.

## Создайте и опубликуйте { #build-and-publish }

1. В **Знания → Коллекции** (Knowledge → Collections) откройте диалог создания и
   разверните **Эмбеддинги** (Embeddings). Выберите совместимого провайдера и
   модель эмбеддингов, а также учётные данные для них в хранилище секретов или
   локальный эндпоинт, затем создайте коллекцию и загрузите файл. Одной
   чат-модели недостаточно. Дождитесь обработки и проверьте статус документа.
2. Создайте агента в **Агенты → Новый агент** (Agents → New agent) и выберите
   свой профиль модели.
3. В **Инструменты** (Toolbox) включите **Знания** (Knowledge) и привяжите только
   тестовую коллекцию. Задайте инструкции ниже.
4. Задайте бюджет и лимит шагов, подходящие для проверки, затем **Опубликуйте**
   (Publish) версию, которую будете тестировать.

```text
Answer equipment-policy questions from the bound handbook.
Cite the document you used.
If it does not contain the answer, say what is missing.
Do not invent policies or submit equipment requests.
```

## Проверьте результат { #check-the-result }

| Вопрос | Контрольная проверка |
| --- | --- |
| Кто занимается заявкой на оборудование? | Называет офис-менеджера, и это подтверждается источником |
| Какие сведения нужно указать? | Предмет, причина и место доставки |
| Сколько я могу потратить? | Говорит, что лимита в источнике нет |

Спрашивайте в новом тестовом диалоге. Проверьте ответ и найденный материал на
странице [**Активность**](../governance.md). Сохраняйте не только удачные ответы,
но и неверные или неполные. Если поиск ничего не находит, проверьте привязку
коллекции, разрешения и обработку, прежде чем менять промпт.

Измените в тестовом файле ответственного на службу эксплуатации. В [списке
документов коллекции](../file-processing.md) удалите исходный тестовый документ и
дождитесь завершения удаления, прежде чем загружать отредактированный файл.
Загрузка файла с тем же именем сама по себе не заменяет старые векторы.
Дождитесь обработки и повторите в новом диалоге. Убедитесь, что устаревший
материал больше не извлекается.

!!! example "Записано на v0.0.504, 25 сентября 2026"

    Модель: Claude Sonnet 4.6 через OpenRouter, поиск по знаниям привязан к
    единственной коллекции. Вопрос «Кто занимается заявкой на оборудование?»
    вызвал `search_documents` один раз и получил ответ «заявки на оборудование
    направляются офис-менеджеру» с тремя сведениями и ссылкой на
    `equipment-handbook.md`. Вопрос «Сколько я могу потратить?» вызвал
    `search_documents` дважды и получил ответ, что в справочнике «нет никакой
    информации о лимитах расходов или порогах согласования покупок». Стоимость
    по трём вопросам и одной повторной попытке ниже: 0,043 USD.

    Вопрос «Какие сведения нужно указать?» сначала вернул уточняющий вопрос
    («уточните, о чём идёт речь?») вместо поиска: заданная отдельно в новом
    диалоге, эта фраза не несёт темы заявки на оборудование. Вторая попытка с
    тем же вопросом вызвала `search_documents` и ответила правильно.
    Формулируйте вопрос с явно названной темой, если хотите, чтобы поиск
    сработал с первого раза.

    После удаления исходного документа, проверки, что список пуст, и загрузки
    отредактированного файла тот же первый вопрос в новом диалоге получил ответ
    «заявки на оборудование направляются в службу эксплуатации» без упоминания
    офис-менеджера. Общая стоимость за пять ходов: 0,055 USD.

## Перейдите к следующему шагу { #share-the-next-step }

Проверив результат, поместите агента [в Slack](slack-handbook-assistant.md) или
выберите [другую точку входа](../channels.md). Размещённая страница доступна по
ссылке публично: используйте там публичный или синтетический материал. Выбор
канала не задаёт правила доступа к документам.

Перед пилотом в команде назначьте [ответственного за
эксплуатацию](../rollout.md). Если какой-то шаг не удаётся, укажите в [запросе
помощи](../help.md) версию, конфигурацию и воспроизведение с вырезанными
секретами.
