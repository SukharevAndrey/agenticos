# Почему macOS показывает предупреждение { #why-macos-shows-a-warning }

Вручную скачанный DMG-файл AgenticOS может показать **Apple не удалось проверить
это приложение** (Apple could not verify this app). Это проверка издателя в
Gatekeeper. Релиз по умолчанию использует стабильный самоподписанный сертификат:
он сохраняет идентичность подписи приложения, но это не нотаризация Apple
Developer ID. Это сообщение не означает, что приложению предоставлен доступ к
экрану или микрофону.

## Установите релиз { #install-a-release }

Скачивайте только со страницы [релизов
AgenticOS](https://github.com/vstorm-co/agenticos/releases/latest). Переместите
приложение в «Программы» (Applications), попробуйте открыть его один раз, затем
воспользуйтесь **Системные настройки → Конфиденциальность и безопасность → Всё
равно открыть** (System Settings → Privacy & Security → Open Anyway), если ваша
организация это разрешает. Следуйте [инструкциям
Apple](https://support.apple.com/en-us/102445). Не отключайте Gatekeeper
глобально.

Либо используйте `brew install --cask vstorm-co/agenticos/agenticos` или
[установщик
проекта](https://github.com/vstorm-co/agenticos/blob/main/scripts/install_macos.sh).
Они устанавливают релиз и снимают карантин только для этого приложения. Скрипт
проверяет контрольную сумму релиза и зафиксированный в репозитории отпечаток
издателя. Он останавливается, если ответ с закреплением отпечатка отсутствует или
искажён, подпись не совпадает или контрольная сумма не сошлась. Перед публикацией
контрольной суммы Homebrew рабочий процесс релиза монтирует оба образа Mac и
проверяет каждое приложение по зафиксированному отпечатку издателя. Отсутствующее
закрепление, недействительная подпись или другой подписант останавливают
публикацию.

## Сохраняйте разрешения между обновлениями { #keep-permissions-across-updates }

Разрешения **Запись экрана** (Screen Recording) и **Микрофон** (Microphone)
привязаны к идентичности подписи приложения. Сохраняйте один сертификат релиза
между версиями. Более старая
ad-hoc сборка или изменённый сертификат могут потребовать повторной выдачи
разрешений; одни лишь обновлённые подписи не сохраняют выданные операционной
системой разрешения. Включайте только те разрешения, которые нужны, в настройке
приложения или в настройках macOS.

## Настройте подпись релизов { #configure-release-signing }

Мейнтейнеры создают постоянный сертификат с помощью
`scripts/create_macos_signing_cert.sh`. Храните `MACOS_SELF_SIGNED_P12` и
`MACOS_SELF_SIGNED_P12_PASSWORD` как секреты, а `MACOS_SELF_SIGNED_IDENTITY` — как
переменную в `apps-release`. Коммитьте только открытый отпечаток сертификата SHA-1
в `scripts/macos_signing_identity.txt` и никогда не коммитьте P12 или его
пароль. После публикации закрепления установщик требует релизы, подписанные этим
сертификатом.

Подпись Developer ID и нотаризация остаются необязательным режимом релиза,
требующим учётной записи Apple и учётных данных мейнтейнера. Они перечислены в
[конфигурации релиза приложения для
компьютера](../desktop.md#installers-and-updates). Самоподписанный релиз не
заявляет о нотаризации.
