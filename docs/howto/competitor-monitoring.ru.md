# Следите за изменениями веб-страниц по расписанию { #watch-web-pages-for-changes-on-a-schedule }

Создайте агента, который загружает небольшой набор страниц, хранит краткую
сводку увиденного и при следующем запуске говорит, что изменилось, — или что
не изменилось ничего. В примере используются две страницы, которые вам не
принадлежат, но меняются редко: страница релизов проекта на GitHub и
`example.com`. Это процедура, которую нужно выполнить; два записанных
срабатывания приведены как образец.

Два срабатывания доказывают две разные вещи. **Запустить сейчас** (Run now)
доказывает, что логика сравнения работает. Оно не доказывает, что когда-либо
будет поймано *настоящее* изменение: это показывает только срабатывание,
пришедшее после того, как страница действительно изменилась, а записать такое
по команде эта страница не может.

## Что понадобится { #what-you-need }

- Работающий [экземпляр AgenticOS](../install.md) с профилем модели.
- Ни коллекции знаний, ни подключения MCP, ни подключения песочницы: рабочему
  пространству из этого рецепта ничего такого не нужно. См. ниже.

## Почему не файлы памяти { #why-not-memory-files }

Очевидная возможность для «запомнить, что я видел в прошлый раз» — [файлы
памяти](../reference/capabilities.md#memory-files). Здесь она не работает, и
причину стоит знать, прежде чем тянуться к ней по расписанию.

Срабатывание триггера выполняется с ролью и выданными доступами своего
создателя, но не от его имени в отношении памяти: *аудитория* запуска — кто
услышит ответ — на способе доступа `schedule` намеренно пуста, поэтому запуск
без участия человека не может читать или писать личные заметки создателя.
`write_memory` и `read_memory` оба отвечают:

```text
This conversation has no memory. It has no identified person and is not a
group chat, so a note would have to land somewhere other people read. Answer
from what you have rather than saving.
```

Тот же агент, которому задали тот же вопрос в обычном чате, сохраняет заметку
без труда: хранилище там есть, потому что слушает настоящий человек. По
расписанию не слушает никто.

## Что использовать вместо этого { #what-to-use-instead }

Рабочее пространство [песочницы](../sandbox.md) с областью **Диалог**
(conversation) сохраняется между всеми срабатываниями одного триггера: триггер
открывает один диалог на всё время своей жизни и дописывает в него каждое
срабатывание, — а `conversation_id`, по которому рабочее пространство ведёт
учёт, не зависит от того, кто слушает. Хранилище `state` не требует подключения
песочницы: это небольшое хранилище в собственной базе данных этого экземпляра,
без оболочки и без контейнера.

## Создайте агента { #build-the-agent }

1. Создайте агента в **Агенты → Новый агент** (Agents → New agent) и выберите
   свой профиль модели.
2. На вкладке **Инструменты** (Toolbox) включите **Чтение веб-страниц** (Read web
   pages). Ограничьте `allowed_domains` значениями `github.com` и `example.com`,
   чтобы агента нельзя было попросить загрузить что-либо ещё.
3. Включите **Песочница** (Sandbox). Оставьте поле **Где хранятся файлы** (Where
   files live) на **Файлы** (Files) — это хранилище `state`, без оболочки и без
   подключения песочницы — и область на **Этот диалог** (This conversation):
   значения по умолчанию — ровно то, что нужно этому рецепту.
4. Задайте бюджет и лимит шагов для пробы. Каждое записанное срабатывание
   стоило около 0,07–0,14 USD.
5. Задайте инструкции ниже, затем нажмите **Опубликовать** (Publish).

```text
You watch two pages for changes, once per run:
- https://github.com/vstorm-co/agenticos/releases
- https://example.com/

Each run:

1. Fetch both pages with web_fetch.
2. For the GitHub page, keep only the latest (topmost) release: its tag and
   title. For example.com, keep its heading and first paragraph. Ignore
   everything else on each page - star counts, timestamps, navigation.
3. Look for a file named watch-state.txt in your workspace.
4. If it does not exist, write it now with today's two summaries, one line
   per page, and report that you recorded a baseline - not a change.
5. If it exists, read it and compare each page's new summary to the line
   stored for it. Report, page by page, either the old and new value or
   "no change". Then overwrite watch-state.txt with the new summaries.
Never say a page changed unless the two lines you compared actually differ.
```

## Создайте расписание { #create-the-schedule }

Откройте **Автоматизации → Новое расписание** (Routines → New schedule) или
вкладку **Доступность** (Availability) агента, выберите агента и задайте
ежедневную периодичность. В промпте достаточно назвать задачу:

```text
Run today's page check.
```

## Запустите его { #run-it }

Нажмите **Запустить сейчас** (Run now) у расписания дважды с промежутком в
несколько минут. Первое срабатывание не находит `watch-state.txt` и записывает
базовый результат. Второе читает его обратно и сравнивает.

!!! warning "Публикация исправления не переводит работающее расписание на него"

    Публикация создаёт версию, но не перенаправляет [окружение](../environments.md),
    из которого читает расписание, если только это окружение не следит за
    последней версией, — а `production` по умолчанию не следит. Если вы
    отредактировали агента после создания триггера, переведите новую версию в это
    окружение (**Перевести v2 в…** (Promote v2 to…), с вашим номером версии) до
    следующего **Запустить сейчас**, иначе срабатывание всё ещё выполнит версию,
    которую вы только что заменили.

## Проверьте результат { #check-the-result }

| Проверка | Образец |
| --- | --- |
| Первое **Запустить сейчас** | Сообщает о базовом результате, а не об изменении, и ни про одну страницу не сказано, что она отличается |
| `watch-state.txt` после первого срабатывания | Существует, по одной строке на страницу |
| Второе **Запустить сейчас** | Читает тот же файл обратно и сообщает «без изменений» про обе страницы |
| Страница, которую вы отредактировали между двумя срабатываниями | Сообщает старое и новое значение только для этой страницы |
| Способ запуска в разделе «Активность» | `schedule` для обоих срабатываний, тот же триггер, тот же диалог журнала запусков |
| Запуск с `web_fetch`, направленным на третий домен | Отклоняется — `allowed_domains` его не включает |

!!! example "Записано на v0.0.504, 25 сентября 2026"

    Модель: Claude Sonnet 4.6 через OpenRouter. Первое **Запустить сейчас**
    вызвало `web_fetch` для обеих страниц, затем `read_file` для
    `watch-state.txt`, и этот вызов завершился ошибкой, потому что файла ещё не
    было, затем `write_file`. Оно сообщило последний релиз страницы GitHub как
    `v0.0.504`, заголовок и абзац example.com и сказало, что это базовый
    результат. Стоимость: 0,13 USD. Второе **Запустить сейчас** примерно через
    минуту прочитало тот же файл обратно, сопоставило обе сводки и сообщило
    «Без изменений» про обе страницы, а затем перезаписало файл тем же
    содержимым. Стоимость: 0,14 USD.

    Первая попытка использовала `memory_files` вместо песочницы — ровно то, от
    чего эта страница предостерегает: оба срабатывания вызвали `read_memory` и
    получили приведённый выше отказ «нет памяти», и агент правильно сказал
    человеку, читающему отчёт, что не смог сохранить базовый результат, вместо
    того чтобы утверждать, что сохранил.

## Когда что-то идёт не так { #when-it-goes-wrong }

- **Каждое срабатывание говорит «нет предыдущего состояния» и никогда не
  сравнивает.** Рабочее пространство не сохраняется. Проверьте, что область —
  **Этот диалог** (This conversation), а не **Никто** (Nobody): область `run`
  открывает новое пустое рабочее пространство при каждом срабатывании.
- **В транскрипте вообще появляются `read_memory` или `write_memory`.** Файлы
  памяти всё ещё привязаны. Уберите их; по расписанию они эту работу выполнить
  не могут.
- **Настоящее изменение страницы не обнаружено.** Его поймает только
  срабатывание, которое произойдёт после изменения и после срабатывания,
  записавшего предыдущее состояние. Проверьте в разделе «Активность» два
  срабатывания по обе стороны изменения, а не только последнее.
- **Каждое срабатывание сообщает об изменении, даже когда ничего не
  менялось.** Сводка слишком широка: необработанная загрузка страницы включает
  число звёзд, относительные отметки времени или меняющийся nonce, который
  отличается при каждой загрузке. Сократите в инструкциях то, что сохраняется,
  до одного важного факта.
- **Срабатывание всё ещё ведёт себя как старая версия после повторной
  публикации.** См. предупреждение об окружении выше.

## Зафиксируйте проверку { #record-the-trial }

Сохраните два URL страниц, инструкции, версию агента, `watch-state.txt` после
каждого срабатывания и каждый запуск в разделе «Активность» с его способом
запуска и стоимостью. По-прежнему человек решает, что считать изменением, на
которое стоит реагировать, и следит за первым срабатыванием, пришедшим после
настоящей правки, чтобы подтвердить, что сравнение его ловит: пара `Run now`
доказывает только логику, но никогда — само срабатывание.
