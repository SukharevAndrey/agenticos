# Соберите отчёт Excel и презентацию из данных { #build-an-excel-report-and-a-slide-deck-from-data }

Дайте агенту песочницу и небольшой CSV с продажами, и пусть он соберёт книгу с
листом сводки, построенным на формулах, и диаграммой, а затем презентацию из трёх
слайдов с теми же числами. Данных достаточно мало, чтобы просуммировать их
вручную, поэтому каждую ячейку можно сверить с исходными строками. Это
процедура, которую нужно выполнить; один записанный запуск приведён как образец.
Если нужен только отчёт, начните с [превращения CSV в диаграмму, которую можно
проверить](csv-chart.md) — эта страница добавляет к этому шаблону полную книгу и
презентацию.

## Что понадобится { #what-you-need }

- Работающий [экземпляр AgenticOS](../install.md) с профилем модели и
  зарегистрированным [подключением песочницы](../sandbox.md), у которого среда
  выполнения по умолчанию — `workbench`: в ней есть `openpyxl` и `python-pptx`,
  поэтому шаг установки пакетов не нужен.
- Синтетический CSV ниже — достаточно малый, чтобы проверить его вручную.

## Подготовьте входные данные { #prepare-the-input }

Сохраните это как `sales.csv`. Четыре квартала, четыре региона, шестнадцать
строк.

```csv
quarter,region,revenue_usd,units
Q1,North,12000,300
Q1,South,9000,250
Q1,East,15000,320
Q1,West,8000,200
Q2,North,13000,310
Q2,South,9500,260
Q2,East,16000,330
Q2,West,8500,210
Q3,North,14000,320
Q3,South,10000,270
Q3,East,17000,340
Q3,West,9000,220
Q4,North,15000,330
Q4,South,10500,280
Q4,East,18000,350
Q4,West,9500,230
```

Контрольные суммы, вычисленные вручную: по регионам — North 54 000, South
39 000, East 66 000, West 35 000; по кварталам — Q1 44 000, Q2 47 000, Q3
50 000, Q4 53 000; итого 194 000.

## Создайте агента { #build-the-agent }

1. Создайте агента в **Агенты → Новый агент** (Agents → New agent) и выберите
   свой профиль модели.
2. В **Инструменты** (Toolbox) включите **Песочница** (Sandbox). Выберите
   **Контейнер** (Container), укажите своё подключение песочницы и среду
   выполнения `workbench`, а область оставьте «Этот диалог».
3. Задайте бюджет для проверки, затем задайте инструкции ниже и нажмите
   **Опубликовать** (Publish).

```text
You build spreadsheets and slide decks in your workspace from data the user
attaches.
Read the attached file before calculating anything.
Use openpyxl to build the workbook and python-pptx to build the deck.
Save every output file in the workspace and give its path.
Do not fetch data from the internet.
```

## Запустите его { #run-it }

Откройте новый чат с агентом, прикрепите `sales.csv` и отправьте:

```text
Using the attached CSV, build report.xlsx with a summary sheet totalling
revenue by region and by quarter (use SUM formulas over a raw-data sheet, not
hand-typed numbers) plus a bar chart of revenue by region. Then build a
3-slide summary.pptx: a title slide, a slide with the totals table, and a
slide with the chart or its key numbers. Save both files in the workspace.
```

Когда агент запускает свой скрипт, в чате появляется **Требуется согласование
инструмента** (Tool approval required). Прочитайте команду и нажмите
**Одобрить** (Approve). См. [согласования](../governance.md#approvals).

## Проверьте результат { #check-the-result }

| Проверка | Образец |
| --- | --- |
| Суммы по регионам | North 54 000, South 39 000, East 66 000, West 35 000 |
| Суммы по кварталам | Q1 44 000, Q2 47 000, Q3 50 000, Q4 53 000 |
| Итог | 194 000 |
| Лист сводки использует формулы | Нажмите на ячейку с итогом и увидите `=SUM(...)`, а не введённое число |
| Диаграмма | Столбцы по регионам, ось подписана валютой |
| Презентация | Три слайда: титульный, таблица сумм, диаграмма или ключевые числа |
| Числа совпадают в книге и презентации | Суммы в презентации равны суммам в книге, а не округлены отдельно |

Откройте `report.xlsx` и `summary.pptx` на панели файлов чата и проверьте их
сами: путь в ответе не доказывает, что файл существует или что его формулы
вычисляют правильное число.

!!! example "Записано на v0.0.504, 25 сентября 2026"

    Модель: Claude Sonnet 4.6 через OpenRouter. Агент прочитал CSV, написал
    скрипт сборки на 460 строк и запустил его — один вызов `execute`, одобрен.
    Затем он сделал ещё три вызова `execute`, чтобы конвертировать презентацию
    через LibreOffice в PNG по слайдам и посмотреть на собственную работу;
    каждый был одобрен по очереди.

    В `report.xlsx` был лист `Raw Data` со всеми 16 строками и лист `Summary`,
    где каждая ячейка по региону и кварталу была настоящей формулой
    `SUMPRODUCT` по `Raw Data`, с итогами строк и столбцов через `SUM` и
    кластеризованной гистограммой — ни одного введённого вручную числа. Если
    вычислить эти формулы по исходным данным, получаются North 54 000, South
    39 000, East 66 000, West 35 000 и 44 000/47 000/50 000/53 000 по
    кварталам, 194 000 в целом — в точности контрольные суммы.

    В `summary.pptx` было три слайда: титульный с общим итогом, полная таблица
    «регион × квартал», совпадающая с книгой ячейка в ячейку, и слайд с
    диаграммой и ключевыми показателями, повторяющий четыре региональные
    суммы. Стоимость: 0,37 USD за четыре круга согласования.

## Когда что-то идёт не так { #when-it-goes-wrong }

- **Агент говорит, что у него нет оболочки.** Возможность использует **Файлы**
  (Files) вместо **Контейнер** (Container) — переключитесь на «Контейнер» и
  выберите среду выполнения `workbench`.
- **Итог — введённое число, а не формула.** Попросите собрать лист сводки заново
  с формулами `SUM` или `SUMPRODUCT`, ссылающимися на лист исходных данных:
  введённое вручную число не обновится, если строка изменится.
- **Рабочее пространство ненадолго отклоняет любую запись.** Это один раз
  случилось при проверке, когда хост песочницы потерял разрешение на сокет
  Docker; каждый `write_file` завершался ошибкой, и агент вместо запуска вывел
  скрипт текстом. `agenticos cmd doctor` и статус подключения в разделе
  **Песочницы** (Sandboxes) показывают, может ли служба действительно запустить
  сеанс.
- **Числа в презентации не совпадают с книгой.** Возможно, агент ввёл суммы
  презентации отдельно вручную; попросите его вычислять числа презентации из тех
  же значений, которые дают формулы книги.
- **Первый ход медленный.** Собирается образ `workbench`; последующие сеансы
  используют его повторно.

## Зафиксируйте проверку { #record-the-trial }

Сохраните CSV, промпт, версию агента, запуск на странице **Активность**
(Activity) и оба выходных файла. Прежде чем доверять итогу, откройте формулы
книги, а не только отображаемые числа.

Человек проверяет, что формулы — настоящие формулы, что ось диаграммы означает
то, что на ней написано, и что презентацию действительно не стыдно передать
другому. Агент даёт вам файлы, но не заменяет их открытие.

## Что дальше { #next-steps }
