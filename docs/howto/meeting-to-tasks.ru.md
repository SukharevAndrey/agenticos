# Превратите пункты действий из встречи в задачи с согласованием { #turn-meeting-action-items-into-tasks-with-approval }

Дайте агенту пункты действий из транскрипта встречи и
[MCP-подключение к Linear или Jira](../mcp.md#project-management) — и пусть он
предложит по одной задаче на каждый пункт, а не создаёт что-либо без участия
человека. Человек, читающий предложения, правит их или отклоняет, прежде чем в
трекер попадёт хотя бы одна задача. Эту страницу здесь нельзя пройти от начала
до конца: в этом окружении нет подключения к Linear или Jira, поэтому
записанного запуска ниже нет.

## Что понадобится { #what-you-need }

- Работающий [экземпляр AgenticOS](../install.md) с профилем модели.
- Разрешение `connections:manage`, чтобы добавить Linear или Jira как
  MCP-подключение для всей организации, либо обычная учётная запись участника,
  чтобы подключить такое для себя в **MCP-серверы → Вы** (MCP servers → You).
- Транскрипт встречи, с которым работать. [Краткое изложение
  встречи](meeting-summary.md) рассказывает, как проверить решения и пункты
  действий в нём, прежде чем что-то из них станет задачей.

## Подготовьте входные данные { #prepare-the-input }

Небольшой выдуманный транскрипт с одним ясным пунктом действий, одним пунктом
действий без срока и одной поднятой проблемой, за которую на самом деле никто не
отвечает — последнее и есть тот крайний случай, который стоит проверить:

```text
Weekly ops sync - 24 September 2026
Attendees: Priya, Tom, Sana

- Priya will update the onboarding doc with the new pricing tiers by Friday.
- Tom will follow up with the vendor about the delayed shipment.
- Sana raised that the support queue is growing, but nobody was assigned to look into it.
```

Образец: два настоящих пункта действий (Priya, срок — пятница; Tom, срок не
указан) и один открытый вопрос без владельца, который пунктом действий не
является.

## Подключите трекер { #connect-the-tracker }

Linear есть в каталоге с типом **oauth**, `https://mcp.linear.app/sse`; Jira и
Confluence делят одну запись, тоже **oauth**, по адресу
`https://mcp.atlassian.com/v1/sse` (см. [каталог](../mcp.md#project-management)).
Для трекера, в который пишет вся команда, подключите его в
**MCP-серверы → Организация** (MCP servers → Organization), чтобы каждый
привязанный агент создавал задачи под одной и той же учётной записью интеграции;
привязывайте вместо этого [учётную запись каждого
человека](../mcp.md#whose-account-a-binding-speaks-through) только если ваш
трекер ожидает, что задачи будут создаваться от имени того, кто о них попросил.

В самом подключении сузьте `allowed_tools` до инструмента создания и
комментирования, который нужен этому процессу, если сервер предлагает ещё и
инструменты, правящие или удаляющие существующие задачи: привязка может только
сужать то, что подключение уже разрешает, и никогда не возвращает то, что оно
исключает.

## Создайте агента { #build-the-agent }

1. Создайте агента в **Агенты → Новый агент** (Agents → New agent) и выберите свой
   профиль модели.
2. В **Инструменты** (Toolbox) добавьте трекер в **MCP-серверы** (MCP servers).
3. Задайте инструкции ниже, затем нажмите **Опубликовать** (Publish).

```text
You turn meeting notes into tracker tasks.
Propose one task per real action item: a title, the assignee named in the notes, a due date only if one was actually stated, and a one-line description.
Do not invent an assignee, a due date or a priority that the notes do not state.
If something was raised but nobody was assigned to it, say so as an open question rather than proposing a task for it.
Create each proposed task with its own tool call, one at a time, so each can be reviewed on its own.
```

## Запустите его { #run-it }

Прежде чем просить агента что-либо создать, откройте **Управление чатом → Режим
согласования** (Chat controls → Approval mode) и выберите **Спрашивать обо всём**
(Ask about everything). Здесь это важно по той же причине, что и при [дописывании
в Notion](notion-agent.md#workflow-append-meeting-notes-with-a-person-deciding):
инструмент создания в трекере обнаруживается из MCP-подключения во время
выполнения, поэтому согласование, объявленное для отдельного инструмента в
спецификации, до него никогда не доходит — единственная проверка, которую
получает вызов создания, — это режим согласования самого сеанса.

```text
Turn the action items in this transcript into tasks:

Weekly ops sync - 24 September 2026
Attendees: Priya, Tom, Sana

- Priya will update the onboarding doc with the new pricing tiers by Friday.
- Tom will follow up with the vendor about the delayed shipment.
- Sana raised that the support queue is growing, but nobody was assigned to look into it.
```

Каждый вызов создания встаёт на согласование отдельно: модель, которая предлагает
две задачи за один шаг, ставит на согласование две отдельные строки, и по каждой
решение принимается независимо. Прочитайте точное название, исполнителя и срок в
каждой, прежде чем выбрать **Одобрить** (Approve) или отклонить её; отклонённый
вызов передаётся агенту обратно как отказ, на который он может отреагировать, а не
как сбой.

## Проверьте результат { #check-the-result }

| Проверка | Образец |
| --- | --- |
| Число предложенных задач | Две — по одной на каждый настоящий пункт действий |
| Задача Priya | Исполнитель Priya, срок — пятница |
| Задача Tom | Исполнитель Tom, срок не выдуман |
| Пункт Sana | Не предложен как задача; назван открытым вопросом без владельца |
| Отклонение одной предложенной задачи | В трекер она не попадает; в итоговом ответе агента сказано, какая пропущена |
| Одобрение остальных | В трекер попадают ровно одобренные задачи, и ничего сверх них |
| Тот же транскрипт при выключенном **Спрашивать обо всём** | Каждая предложенная задача создаётся сразу, и проверить нечего |
| Транскрипт вообще без пунктов действий | Говорит, что превращать в задачу нечего, а не выдумывает её |

## Когда что-то идёт не так { #when-it-goes-wrong }

- **Задача создана раньше, чем кто-либо её проверил.** Сначала проверьте
  **Режим согласования** этого диалога: `required` у возможности никогда не
  доходит до инструмента MCP, поэтому проверка зависит от того, что сеанс
  переключён на **Спрашивать обо всём**, каждый раз.
- **Агент выдумывает срок или исполнителя.** Ужесточайте инструкции, а не
  подключение: это ошибка промпта, и транскрипт уже должен был сказать агенту,
  чего он не знает.
- **Поднятая проблема всё равно становится задачей.** Проверьте, что инструкции
  различают «назначено кому-то» и «упомянуто»: открытый вопрос в образце
  существует именно для того, чтобы это поймать.
- **Два разных агента предлагают задачу по одному и тому же пункту.** Источник
  истины здесь — сам трекер, а не история запусков этой платформы: проверьте
  трекер на дубликат, прежде чем считать, что агент ошибся.

## Зафиксируйте проверку { #record-the-trial }

Сохраните транскрипт, каждую предложенную задачу, какие из них одобрены или
отклонены, и состояние самого трекера после этого: журнал согласований AgenticOS
записывает, что было предложено и кто решил, а не то, как трекер выглядит позже.
Человек по-прежнему читает каждое предложение, исправляет неверного исполнителя
до одобрения, а не после, и решает, кому вообще можно привязывать к агенту
подключение к трекеру с правом создания.
