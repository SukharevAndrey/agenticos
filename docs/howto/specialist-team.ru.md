# Направляйте запросы команде агентов-специалистов { #route-requests-to-a-team-of-specialist-agents }

Соберите три агента: специалиста по счетам, технического специалиста и
приёмную, которая направляет вопрос тому, кому он принадлежит, — или спрашивает,
когда это неясно. Каждый специалист публикуется отдельно, поэтому его проверяют,
версионируют и могут переиспользовать другие приёмные. Это
процедура, которую нужно выполнить; три записанных вопроса приведены как
образец.

## Что понадобится { #what-you-need }

- [Работающий экземпляр](../install.md) с профилем модели для всех трёх агентов.
- `agents:run` на обоих специалистов, чтобы закрепить их в приёмной, — то же
  разрешение, которое проверяет упоминание в канале или любая проверка поручения
  в продукте. См.
  [разрешения](../permissions.md#delegation-is-not-a-privilege-boundary).
- Для этого тестового образца не нужны ни коллекция знаний, ни песочница, ни
  подключение MCP.

## Подготовьте входные данные { #prepare-the-input }

Небольшой синтетический продукт, чтобы факты специалистов можно было проверить:

**Факты о счетах** — тариф Basic 9 USD в месяц, Pro 29 USD в месяц, оба
списываются ежемесячно. Полный возврат в течение 14 дней после списания, без
объяснения причины; после — нет. Счета приходят по почте в дату списания и
всегда доступны на странице **Оплата** (Billing) учётной записи.

**Технические факты** — API-ключ находится в разделе **Настройки → API-ключи**
(Settings → API keys); пересоздание ключа немедленно отзывает старый. Лимит частоты
— 60 запросов в минуту на ключ; ответ `429` называет число секунд ожидания.
Состояние и история инцидентов публикуются на странице статуса.

## Соберите двух специалистов { #build-the-two-specialists }

Опубликуйте каждого как отдельного агента, без возможностей: каждый отвечает
только по фактам, которые вы ему дали.

1. **uc-billing-specialist** — инструкции: изложите факты о счетах выше и
   скажите, что вопрос за их пределами этот агент не покрывает.
2. **uc-tech-specialist** — инструкции: изложите технические факты выше, с тем
   же отказом для всего остального.

Опубликуйте обоих до сборки приёмной: агент-исполнитель должен быть
опубликованным агентом, который вы можете запускать, и на него ссылаются по
`slug`.

## Соберите приёмную { #build-the-front-desk }

1. Создайте третьего агента, **uc-front-desk**, и выберите профиль модели.
2. В **Инструменты** (Toolbox) включите **Субагенты** (Delegation). Оставьте
   `allow_dynamic` выключенным: этот агент вызывает только двух названных вами
   специалистов и никогда — придуманного.
3. В разделе **Агенты-исполнители** (Delegates) добавьте обоих опубликованных
   специалистов, закреплённых на текущей версии.
4. Задайте бюджет и лимит шагов для проверки.
5. Задайте инструкции ниже, затем нажмите **Опубликовать** (Publish).

```text
You are the front desk for this product's support. You never answer a billing
or technical question yourself.
Route a billing question (pricing, refunds, invoices, charges) to the billing
specialist with task(description=..., subagent_type="uc-billing-specialist").
Route a technical question (the API, keys, rate limits, uptime) to the
technical specialist with task(description=..., subagent_type="uc-tech-specialist").
If a question could be either, or names neither, ask the user one short
question to tell which team it belongs to before delegating anything.
Relay the specialist's answer; do not add facts of your own.
```

Ни одно из этих поручений не требует согласования — ни один инструмент не просит
его, пока так не решит автор инструмента, — а одобрять человек будет инструменты
самого специалиста, по спецификации самого специалиста.

## Кто платит и что видит пользователь { #who-pays-and-what-the-user-sees }

Запуск приёмной оплачивает весь обмен: единый журнал расходов охватывает
родителя и каждого вызванного специалиста, а посреди диалога применяется бюджет
приёмной. У каждого специалиста всё равно есть своя строка в разделе
«Активность» с `parent_run_id`, указывающим на запуск приёмной, — поэтому у
вопроса «сколько в этом месяце стоил специалист по счетам» есть ответ, который
не удваивает счёт организации. См.
[что записывается как поручённый запуск](../governance.md#what-a-delegated-run-is-recorded-as).

Тот, кто спрашивает, видит один непрерывный ответ. Приёмная передаёт то, что
сказал специалист; в транскрипте ничто не выглядит как передача, если только не
открыть запуск в разделе «Активность» и не увидеть под ним поручение.

## Согласование внутри поручения { #an-approval-inside-a-delegation }

Ни у одного из специалистов здесь нет инструмента, требующего согласования,
поэтому ничего не приостанавливается. Если бы был — скажем, возможность
`send_email` у специалиста по счетам, — согласование всё равно пришло бы в ту
же очередь, за которой следит тот, кто вызвал приёмную, с указанием, **какой
агент-исполнитель** предложил вызов, а не только инструмента. Одобрение
возобновляет работу этого специалиста с того места, где он остановился, а не
поручает заново с нуля. См.
[согласование внутри поручения](../governance.md#an-approval-inside-a-delegation).

## Запустите его { #run-it }

Задайте приёмной три вопроса в отдельных диалогах:

```text
I was charged twice this month, can I get a refund on the extra charge?
```

```text
My integration keeps getting 429s, what's the limit and where do I check status?
```

```text
Something changed and now it doesn't work like before.
```

## Проверьте результат { #check-the-result }

| Проверка | Образец |
| --- | --- |
| Вопрос о счетах | Поручает `uc-billing-specialist`; в ответе названо правило возврата 14 дней |
| Технический вопрос | Поручает `uc-tech-specialist`; в ответе названы лимит 60 в минуту и страница статуса |
| Неясный вопрос | Поручения нет; приёмная спрашивает, какой команде он принадлежит |
| Активность, запуск по счетам | Дочерний запуск под запуском приёмной, `parent_run_id` задан, собственная стоимость |
| Активность, технический запуск | Та же форма, под `uc-tech-specialist` |
| Вопрос, не называющий ни одну команду и отказывающийся уточнять | Приёмная всё равно спрашивает, а не угадывает, какого специалиста вызвать |

!!! example "Записано на v0.0.504, 25 сентября 2026"

    Модель: Claude Sonnet 4.6 через OpenRouter, у всех трёх агентов. Вопрос о
    возврате вызвал один вызов `task` к `uc-billing-specialist` (стоимость
    запуска приёмной — 0,0236 USD, включая агента-исполнителя); в ответе были
    названы срок 14 дней и страница «Оплата». Вопрос об ограничении вызвал один
    вызов `task` к `uc-tech-specialist` (0,0227 USD); в ответе были названы
    60 запросов в минуту и страница статуса. Неясное сообщение не вызвало
    никакого поручения: «Не могли бы вы рассказать чуть подробнее, что
    изменилось, — это связано с оплатой… или что-то техническое…?»
    (0,0066 USD). Собственная строка запуска специалиста по счетам записала
    0,0057 USD как дочерний запуск под запуском приёмной, что подтверждает
    описанную выше форму с общим журналом расходов и отдельными строками.

## Когда что-то идёт не так { #when-it-goes-wrong }

- **Приёмная отвечает сама, без поручения.** Инструкции не соблюдены или
  `subagents` не привязан — прежде чем перечитывать промпт, проверьте
  **Инструменты**.
- **Публикация приёмной отклоняется с указанием агента-исполнителя.** Любой из
  специалистов не опубликован, или вы не можете его запускать: закрепление
  проверяет `agents:run` на строке этого специалиста.
- **Приёмная спрашивает всегда, даже при явном вопросе о счетах.** Правило
  маршрутизации в инструкциях слишком строгое, или модель слишком широко понимает
  «может быть и то и другое», — сузьте примеры в промпте.
- **Специалист отвечает на вопрос за пределами своих фактов вместо отказа.** В
  его собственных инструкциях не сказано отказываться; добавьте явную строку
  отказа, использованную выше.
- **Версия агента-исполнителя сдвинулась без вашей просьбы.** Нет — закрепление
  сдвигается, только когда спецификацию приёмной публикуют заново против новой
  версии. См.
  [закреплённый агент-исполнитель не сдвигается сам](../governance.md#a-pinned-delegate-does-not-move-on-its-own).

## Зафиксируйте проверку { #record-the-trial }

Сохраните каждый вопрос, кто из специалистов отвечал, ответ, дочерний запуск в
разделе «Активность» с его собственной стоимостью и итог приёмной. Человек
по-прежнему решает, что считать достаточно неясным, чтобы спросить, проверяет
факты каждого специалиста до публикации и судит, действительно ли переданный
ответ отражает то, что сказал специалист.

## Что дальше { #next-steps }

Добавьте третьего специалиста и посмотрите, как инструкции маршрутизации
приёмной всё труднее держать однозначными, — хороший признак того,
что команда перерастает маршрутизацию, написанную вручную. `allow_questions`
позволяет специалисту посреди ответа задать вопрос тому же человеку, с которым
говорит приёмная, вместо того чтобы угадывать; см.
[поручение](../reference/capabilities.md#delegation).
