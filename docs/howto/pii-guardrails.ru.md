# Не допускайте персональные данные в промпты и ответы агента { #keep-personal-data-out-of-an-agents-prompts-and-answers }

Включите [возможность защитных проверок](../reference/capabilities.md#guardrails) на
небольшом тестовом агенте и отправьте ему вымышленные персональные данные. Нужно
найти два разных текста: то, что транскрипт запуска показывает модели, и то, что
запуск на самом деле оплатил провайдеру для чтения. Это процедура, которую
нужно выполнить, с одним записанным запуском как образцом.

## Что понадобится { #what-you-need }

Работающий [экземпляр AgenticOS](../install.md) с профилем модели. Ни песочница, ни
модель эмбеддингов не нужны. Возможность не добавляет инструментов, поэтому в
**Инструменты** (Toolbox) нужны только **Защитные проверки** (Guardrails).

## Подготовьте входные данные { #prepare-the-input }

На этот раз файла нет — входные данные — это само сообщение в чате. Возьмите эту
строку, в ней по одному виду персональных данных из тех, что распознаёт
возможность:

```text
My email is jane.doe@example.com, my card number is 4111 1111 1111 1111,
my SSN is 123-45-6789, and my phone number is 415-555-0132.
```

Справочные факты: `redact_pii_*` вычищает адрес эл. почты, IBAN, номер банковской
карты (с проверкой Луна), SSN США и телефонный номер. Телефонный номер сверяется с
планом нумерации своей страны: записанный с `+` ловится для любой страны,
национальный, вроде `415-555-0132`, — только для стран из **phone_regions**, где по
умолчанию `US, GB, DE, PL`.

## Создайте агента { #build-the-agent }

1. Создайте агента в **Агенты → Новый агент** (Agents → New agent) и выберите свой
   профиль модели.
2. В **Инструменты** (Toolbox) включите **Защитные проверки** (Guardrails). Она не
   даёт ни одного инструмента: здесь человеку нечего одобрять, есть только
   проверка текста.
3. В настройках возможности включите **Вырезать API-ключи и токены из промпта
   пользователя** (Redact API keys and tokens from the user's prompt), **Вырезать
   адреса эл. почты, телефоны, IBAN, номера карт и SSN из промпта** (Redact
   emails, phone numbers, IBANs, cards and SSNs from the prompt), **Вырезать
   API-ключи и токены из ответа агента** (Redact API keys and tokens from the
   agent's answer) и **Вырезать адреса эл. почты, телефоны, IBAN, номера карт и
   SSN из ответа** (Redact emails, phone numbers, IBANs, cards and SSNs from the
   answer). Оставьте **phone_regions** по умолчанию, где есть `US`. А полю
   **Блокировать запуск, если промпт содержит любой из этих терминов (через
   запятую или с новой строки)** (Block the run if the prompt contains any of
   these terms (comma or newline separated)) задайте значение `wire transfer`.
4. Задайте инструкции ниже, затем нажмите **Опубликовать** (Publish).

```text
You are a signup-support assistant.
When the user gives you account details, confirm receipt by repeating them back in a bulleted list.
End every answer with a new line reading exactly: Reference key: sk-live-51ABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789
```

Просьба повторить данные обратно даёт проверке на входе материал: то, что дошло до
модели вырезанным, повторить можно только вырезанным. Фиксированный опорный ключ
нужен, чтобы проверке на выходе было что поймать детерминированно: заставлять
модель придумать собственный секрет ненадёжно.

## Запустите его { #run-it }

Отправьте образцовое сообщение в новом тестовом диалоге, затем отправьте второе, не
связанное с ним сообщение:

```text
I need to send a wire transfer today, can you help?
```

## Проверьте результат { #check-the-result }

| Проверка | Образец |
| --- | --- |
| Ответ | Не повторяет адрес эл. почты, номер карты, SSN или телефон в открытом виде |
| Телефон в ответе | Отсутствует или возвращён как `[redacted:phone]` |
| Строка `Reference key:` в ответе | Читается как `Reference key: [redacted:openai_key]`, а не настоящее значение |
| Транскрипт запуска («Активность») для собственного хода пользователя | Показывает исходное, невырезанное сообщение, которое вы набрали, вместе с телефоном |
| Сообщение про банковский перевод | Статус запуска — `guardrail_blocked`, стоимость `0`, ответ не создаётся |
| То же сообщение про банковский перевод без ключевого слова | Выполняется нормально — блокирует ключевое слово, а не тема |

Вторая строка таблицы — та, над которой стоит посидеть: номер телефона
национальный, поэтому он ловится только потому, что `US` есть в **phone_regions**;
уберите `US`, и он дойдёт до модели точно так, как набран. Четвёртая строка —
про другое: человек, который смотрит «Активность», чтобы узнать, «что произошло»,
видит настоящие входные данные посетителя, потому что защитная проверка
переписывает то, что читает *модель*, и никогда — сохранённый ход диалога.

Транскрипт для человека остаётся исходной записью аудита. Отдельная просеянная
копия, включая любую сводку вложения, хранится для воспроизведения модели и цитат.
Последующие ходы сохраняют эту копию, даже если вырезание на входе потом отключат.
Воспроизведение старых запусков просеивается до управления контекстом запуска;
заблокированные ходы по-прежнему используют маркер отказа.

!!! example "Записано на v0.0.504, 25 сентября 2026, до вырезания телефонов"

    Модель: Claude Sonnet 4.6 через OpenRouter. Первый ответ: *«некоторые из ваших
    данных были автоматически вырезаны для вашей безопасности, прежде чем дошли до
    меня, поэтому я не смог увидеть ваш адрес эл. почты, номер карты или SSN»*,
    затем `Phone Number: 415-555-0132`, возвращённый без изменений, и `Reference key:
    [redacted:openai_key]`. Стоимость 0,003 USD. Тот запуск предшествует
    детектору телефонов
    ([#1901](https://github.com/vstorm-co/agenticos/issues/1901)); с ним номер
    доходит до модели как `[redacted:phone]`.

    Транскрипт запуска сохранил ход пользователя как
    `My email is jane.doe@example.com, my card number is 4111 1111 1111 1111,
    my SSN is 123-45-6789, and my phone number is 415-555-0132.` — полный,
    исходный текст, невырезанный, — а сохранённый ход ассистента уже нёс
    `[redacted:openai_key]`.

    Ещё одно проявилось только в потоке: кадры `text_delta` WebSocket передавали
    настоящий опорный ключ символ за символом, прежде чем кадр `final_result`
    заменил весь ответ вырезанной версией. Вырезание работает по готовому ответу, а
    не по каждому переданному токену, — `widget.js` перезаписывает свой
    отрисованный текст из `final_result.output` именно поэтому, но клиент, который
    только дописывает дельты, показывал бы секрет ту секунду-две до замены. С
    [#1900](https://github.com/vstorm-co/agenticos/issues/1900) агент с проверкой на
    выходе придерживает каждую часть, пока её не просеют, поэтому дельты больше не
    несут ключ.

    Сообщение о переводе: `error` — *«Этот запрос был заблокирован защитной
    проверкой на входе»* — и ни одного кадра `complete` после него. Запуск записал
    статус `guardrail_blocked`, `0` входных и выходных токенов, стоимость
    `0.000000`.

## Когда что-то идёт не так { #when-it-goes-wrong }

- **Значение, которое вы ждали вырезанным, проходит нетронутым.** Сверьте его с
  пятью детекторами: адрес эл. почты, IBAN, банковская карта (с проверкой
  контрольной суммы), SSN США и телефонный номер. Национальному номеру нужна его
  страна в **phone_regions**, а номер, недействительный в плане нумерации своей
  страны, не трогают. Физический адрес и имя не покрыты: это слой шаблонов, а не
  модель, понимающая, что такое персональные данные.
- **Потоковый клиент на мгновение показывает секрет.** При любой включённой
  проверке на выходе текст и рассуждения придерживаются по частям и выдаются уже
  просеянными, поэтому собственный ответ агента так делать не должен. Два
  потоковых пути пока не просеиваются: аргументы вызова инструмента и собственный
  ответ агента-исполнителя на панели делегирования
  ([#2000](https://github.com/vstorm-co/agenticos/issues/2000)). Если секрет пришёл
  одним из них, отрисовывайте текст `final_result`, а не только дописывайте дельты.
- **Блокировка не сработала.** `blocked_keywords_*` совпадает с литеральной
  подстрокой без учёта регистра. Для блокировки нужен ещё и собственный
  переключатель этой проверки: список ключевых слов на выходе ничего не делает для
  входа.
- **Транскрипт всё ещё показывает исходное значение.** На входе так и должно
  быть: переписывается только то, что доходит до модели, а не сохранённый ход,
  который человек проверяет позже. Вырезание до сохранения — отдельная функция, и
  эта не она.
- **Запуск показывает `guardrail_blocked`, которого вы не хотели.** Прочитайте
  поле `error` запуска — оно называет место проверки (`input`, `output` или
  `tool_result`), но по устройству никогда не называет совпавший текст, так что проверьте сам список
  ключевых слов. `error`, который начинается с *«It holds more than ... digits»* или
  *«It is longer than ... characters»*, пришёл вместо этого от вырезания
  персональных данных: оно читает не больше этого объёма одного текста, и чем
  больше стран перечислено в `phone_regions`, тем меньше этот объём; остальное оно
  отклоняет, а не передаёт дальше номера, которых не прочитало.
- **Просеивание результатов инструментов кажется неиспользуемым.** Оно важно
  только когда у агента есть инструмент, читающий недоверенное содержимое, —
  загруженная страница, файл, ответ MCP. В этой проверке такого нет, поэтому
  проверка на результатах инструментов была настроена, но ни разу не задействована.

## Зафиксируйте проверку { #record-the-trial }

Сохраните точное сообщение, версию агента, какие проверки и ключевые слова были
настроены, транскрипт запуска для обоих ходов, а также `status` запуска и его
стоимость из «Активности». Человек решает, достаточно ли этих пяти детекторов
для конкретного агента, какие страны должны быть в его **phone_regions**, и нужно
ли включать просеивание результатов инструментов до того, как появится инструмент,
читающий внешний мир.

## Что дальше { #next-steps }

[Справочник по защитным проверкам](../reference/capabilities.md#guardrails)
