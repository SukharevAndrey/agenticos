# Разберите почту и подготовьте черновики ответов { #triage-your-inbox-and-draft-replies }

Подключите почтовый ящик Gmail как [триггер по
событию](../triggers.md#gmail-1-minute-and-no-secret-anywhere), и пусть агент
читает каждое новое письмо и готовит черновик ответа или список задач. Это
процедура, которую нужно выполнить, а не отчёт об измеренном развёртывании: для
неё нужны настоящая учётная запись Gmail и клиент Google OAuth, которого в этом
экземпляре нет, поэтому ничто на этой странице не запускалось против живого
почтового ящика.

## Что агент может и чего не может делать с почтой { #what-the-agent-can-and-cannot-do-with-mail }

Прочитайте это до того, как что-либо подключать: от этого зависит, стоит ли ради
страницы ниже давать согласие OAuth.

**Он умеет читать.** Триггер Gmail опрашивает подключённый ящик каждую минуту —
или так часто, как задано в настройке **Проверять новую почту каждые** (Check
for new mail every), — и передаёт агенту тему, отправителя и тело нового письма.
Экземпляр запрашивает у Google только область `gmail.readonly` — на экране
согласия не запрашивается ничего больше, поэтому нет более широкого доступа, на
который можно случайно понадеяться.

**Он не умеет отправлять и не может создать настоящий черновик Gmail.** У
агента, собранного по этой странице, нет инструмента, который вызывает API
отправки или API черновиков Gmail. То, что шаблоны ниже называют «черновиком», —
это текст ответа агента, записанный в запуск, который сработал: он попадает на
страницу **Активность** (Activity), в диалог этого запуска, как сообщение,
которое человеку всё ещё нужно прочитать и самому вставить в исходящее письмо.
От вашего имени ничего не отправляется, и в почтовый ящик ничего не
записывается. Чтобы ответ записывался в ветку ящика — черновиком или отправленным
письмом — после того, как человек его одобрит, используйте сценарий
[ответ на письмо с одобренным
черновиком](answer-mail-with-approved-draft.md).

## Что понадобится { #what-you-need }

- Работающий [экземпляр AgenticOS](../install.md) с профилем модели.
- Клиент Google OAuth, зарегистрированный оператором экземпляра
  (`GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`, с включённым API Gmail) — это
  *предварительное условие экземпляра*, а не то, что каждая организация
  настраивает для себя. Без него карточка подключения Gmail говорит об этом
  вместо кнопки, которая могла бы только завершиться ошибкой.
- Разрешение `mcp:manage`, чтобы подключить почтовый ящик.

## Создайте агента { #build-the-agent }

1. Откройте **Автоматизации → Новый триггер по событию → Gmail → Подключить
   учётную запись** (Routines → New event trigger → Gmail → Connect account).
   Согласие даёт доступ к ящику только на чтение; подключение ничего не
   запускает и ничего не теряет — позиция ящика фиксируется в момент завершения
   согласия.
2. Выберите, что его запускает: любое новое письмо, только входящие или
   помеченные как важные. Сузьте дальше с помощью **Тема содержит** (Subject
   contains), **Отправитель содержит** (Sender contains) или метки Gmail — все
   три необязательные фильтры по подстроке, и незаполненный означает, что
   срабатывает каждое письмо в пределах области.
3. Начните с шаблона, а не с пустого промпта. `GET /trigger-templates`
   перечисляет два для этого источника:

   | Шаблон | Что делает |
   | --- | --- |
   | **Draft a reply to the email** | Кратко, одной строкой, излагает, что нужно отправителю, затем готовит черновик ответа для проверки |
   | **Turn the email into action items** | Извлекает каждую задачу, её владельца и любой срок |

4. Создайте агента, которого будет запускать этот триггер, с профилем модели и
   опубликуйте его. Ни песочница, ни коллекция знаний, ни какая-либо другая
   возможность для этих шаблонов не нужны.
5. Привяжите триггер к опубликованному агенту и включите его.

Промпт шаблона **Draft a reply to the email**, дословно:

```text
An email just arrived - its subject, sender and body are in this message.
Summarise in one line what the sender needs, then draft a reply I can review and
send. Match the sender's tone, answer every question they asked, and keep it
brief.
```

## Что здесь означает «Запустите его» { #what-run-it-means-here }

Здесь нет подписанной доставки, которую можно отправить вручную: Gmail
опрашивается, а не присылает данные сам, поэтому нет ни URL, ни секрета. Есть два
способа увидеть, как работает агент, до прихода настоящего письма:

- **Запустить сейчас** (Run now) на триггере запускает **базовый промпт агента
  без контекста доставки** — без письма, без отправителя, без чего-либо, на что
  можно ответить черновиком. Это доказывает, что агент, его бюджет и его
  состояние публикации в порядке, но не проверяет разбор: в этом запуске нет
  письма, к которому могли бы примениться инструкции шаблона.
- **Настоящее письмо, пришедшее в подключённый ящик**, — единственный способ
  увидеть настоящий черновик. Сигнал активности (heartbeat) читает то, что
  пришло с момента последней проверки, с интервалом проверки ящика (по умолчанию
  минута), до 25 писем за проверку: поэтому задержка в худшем случае равна этому
  интервалу, а всплеск рассылки не превращается в сотни запусков.

## Проверьте результат { #check-the-result }

Когда настоящее письмо запустило триггер, применяются общие проверки:

| Проверка | Образец |
| --- | --- |
| Письмо, подходящее под фильтр | Срабатывает один раз, и в диалоге запуска лежит черновик ответа или список задач, но никогда — отправленное письмо |
| Письмо, **не** подходящее под тему, отправителя или метку | Не срабатывает вовсе |
| Письмо без ясного вопроса или задачи | Шаблон задач прямо говорит, что работы к выполнению нет, а не выдумывает её |
| Собственный статус подключения Gmail | Показывается на триггере; неудачный опрос отражается там, а не только в журнале контейнера |
| Почта, пришедшая до подключения ящика | Никогда не срабатывает — курсор начинается с момента завершения согласия |

## Когда что-то идёт не так { #when-it-goes-wrong }

- **Ничего не срабатывает.** Сначала проверьте статус подключения Gmail: сбойный
  опрос отражается на триггере. Затем проверьте фильтр: пустые **Тема содержит**
  или **Отправитель содержит** совпадают со всем, поэтому узкий фильтр, который
  на бумаге выглядит правильно, всё равно может исключить письмо, отправленное
  вами для проверки.
- **Вы ждёте отправленного ответа, а получаете сообщение в чате.** Таков весь
  замысел, а не ошибка — см. *Что агент может и чего не может делать с почтой*
  выше. Скопируйте черновик в свой почтовый клиент вручную.
- **Пропущенные письма после простоя.** Google хранит историю примерно за неделю;
  курсор старше этого синхронизируется заново до текущего момента, а не
  проигрывает всё, что накопилось, поэтому у ящика, простаивавшего дольше
  недели, образуется пробел, который ничто не заполняет.
- **Запустить сейчас выглядит так, будто сработало, но ничего полезного не
  вернулось.** Он запустил агента без прикреплённого письма — это ожидаемо, и это
  не способ проверить сам разбор. Дождитесь настоящей доставки или отправьте себе
  подходящее тестовое письмо.

## Зафиксируйте проверку { #record-the-trial }

Когда получится прогнать это на настоящем ящике, сохраните заданный фильтр,
использованный шаблон или промпт, несколько сработавших запусков и их черновики,
а также сведения о том, кто читает эти черновики до отправки. Каждый ответ
отправляет человек, и каждую задачу заводит человек — агент только готовит текст.
