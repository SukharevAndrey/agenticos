# Запланируйте еженедельный отчёт { #schedule-a-weekly-report }

Соберите агента, который пишет короткий отчёт по данным из своей задачи и
публикует его как [приложение](../artifacts.md) по постоянной ссылке. Затем
поставьте его на еженедельное расписание. В тестовом образце есть строка,
которую нельзя использовать, так что можно проверить, что агент сообщает о ней,
а не скрывает её. Это процедура, которую нужно выполнить; один записанный запуск
приведён как образец.

Страница разделяет два вопроса. Отчёт получается правильным? Это проверяет
**Запустить сейчас** (Run now). Расписание его доставляет? На это отвечает
только срабатывание по расписанию.

## Создайте агента { #build-the-agent }

Нужен [работающий экземпляр](../install.md) с профилем модели. Песочница и
модель эмбеддингов не требуются.

1. Создайте агента в **Агенты → Новый агент** (Agents → New agent) и выберите
   профиль модели.
2. В **Инструменты** (Toolbox) включите **Диаграммы** (Charts) и
   **Приложения** (Apps).
3. Задайте бюджет и лимит шагов для проверки. В записанных запусках было
   по 15 шагов, и каждый стоил около 0,05 USD.
4. Задайте инструкции ниже, затем нажмите **Опубликовать** (Publish).

```text
You write short reports from data given in the task.
Use only the rows in the task. Report totals per category and name any row you could not use.
Label the report as synthetic when the task says the data is synthetic.
Publish the finished report with publish_artifact under the name weekly-report.
```

Имя приложения — это его идентичность. Каждый запуск этого агента, публикующий
`weekly-report`, обновляет то же приложение, поэтому ссылка, которой вы
поделились, остаётся той же. Запуск добавляет версию, только если страница
изменилась. Идентичное содержимое получает в ответ `unchanged` и оставляет
последнюю версию.

## Создайте расписание { #create-the-schedule }

Откройте **Автоматизации → Новое расписание** (Routines → New schedule) или
вкладку **Доступность** (Availability) агента и выберите агента. Поместите данные
в сообщение, чтобы более поздний запуск не зависел от файла, который кто-то
загрузил в предыдущий чат:

```text
Create a report for the synthetic period Demo Week.
Use only these CSV rows:
category,amount
Supplies,20
Supplies,30
Travel,15
Travel,abc
Report totals by category in a fictional demo currency and draw a bar chart.
Label the report synthetic and name any row you could not use.
```

Для частоты выберите **Еженедельно** (Weekly) в поле **Как часто** (How often),
отметьте **Пн** (Mon) и задайте **Время** (Time) — 09:00 UTC. Эквивалентное
cron-выражение — `0 9 * * 1`. Планировщик работает в UTC, поэтому пересчитайте из
своего местного времени. Сохраните и проверьте следующее время срабатывания, которое
показывает расписание.

Расписание работает от имени участника, который его создал, с его доступом, а
его запуски, как и любые другие, списываются с бюджета агента.
[Основные понятия](../concepts.md#trigger) объясняют почему.

## Запустите сейчас { #run-it-now }

Нажмите **Запустить сейчас** (Run now) у расписания. Оно срабатывает ещё один
раз и не меняет еженедельный ритм. Запрос возвращается, как только воркер
принимает срабатывание. Затем запуск появляется в собственном диалоге
расписания, в разделе **Автоматизации** (Routines) на боковой панели чата.

| Проверка | Образец |
| --- | --- |
| Итоги | Supplies 50, Travel 15 |
| Строка `Travel,abc` | Названа непригодной и не учтена |
| Метка | В отчёте сказано, что данные синтетические |
| Приложение | В разделе **Приложения** (Apps) есть `weekly-report`, приватное для вас |
| Запуск в разделе «Активность» | Способ запуска `schedule`, статус completed |
| Повторное нажатие «Запустить сейчас» | То же приложение и та же ссылка: новая версия, если страница изменилась, или `unchanged`, если содержимое идентично |

Откройте страницу приложения и прочитайте отчёт там, а не только ответ в чате.
Люди будут открывать именно страницу. Она остаётся приватной, пока вы ею не
поделитесь или не создадите публичную ссылку.

!!! example "Записано на v0.0.504, 25 сентября 2026"

    Модель: Claude Sonnet 4.6 через OpenRouter. Расписание показало следующее
    срабатывание — понедельник 28 сентября, 09:00 UTC. «Запустить сейчас» было
    принято с `202`, и примерно через 30 секунд запуск завершился на способе
    запуска `schedule`, стоимость 0,044 USD.

    Агент вызвал `publish_artifact` с именем `weekly-report` и получил версию 1,
    приватную. Затем он вызвал `create_chart`. Приложение показало Supplies 50 и
    Travel 15, метку о синтетических данных и «Исключённые строки (не удалось
    использовать): Travel, abc». Второе нажатие «Запустить сейчас» добавило версию 2 тому же
    приложению и той же ссылке.

    Диаграмма появилась в диалоге запуска, а не в приложении. У страницы
    приложения нет доступа к сети, и агент написал отчёт без встроенной
    диаграммы.

## Что расписание не решает за вас { #what-the-schedule-does-not-decide-for-you }

- **Откуда берутся данные.** В этом тестовом образце они закреплены в сообщении.
  Настоящему отчёту нужен источник, который агент сможет получить при каждом
  запуске: [коллекция знаний](set-up-knowledge-base.md),
  [подключение MCP](../mcp.md) или рабочее пространство песочницы. Расписание не
  может угадать, какой новый загруженный файл заменяет прошлонедельный.
- **Период отчёта.** Назовите его в сообщении или пусть агент прочитает дату.
  Файл с именем «weekly» не говорит модели, какие даты включать.
- **Кто его читает.** Новое приложение приватно для того, от имени кого шёл
  запуск. Поделитесь им или создайте публичную ссылку на странице приложения.
  [Приложения](../artifacts.md) описывают видимость и выданные доступы.
- **Согласования.** Ни один из инструментов здесь их не требует. Если вы
  добавите инструмент, которому согласование нужно, запуск по расписанию
  приостановится, пока кто-нибудь не решит, поэтому назовите того, кто следит за
  [очередью согласований](../governance.md#approvals).

## Понаблюдайте за настоящим срабатыванием { #watch-a-real-fire }

«Запустить сейчас» доказывает работу задачи, а не расписания. После
первого понедельника в 09:00 UTC проверьте, что новый запуск появился в разделе
«Активность» сам, что у приложения прибавилась версия и что те, кому положено его
читать, могут его открыть. Карточка **Автоматизации** (Routines) на странице
«Обзор» показывает последний исход каждой автоматизации, поэтому расписание,
которое начинает сбоить, видно.

Расписание, создатель которого больше не может запускать агента, отключается и
записывает причину. См. [основные понятия](../concepts.md#it-runs-as-a-person).

## Когда что-то идёт не так { #when-it-goes-wrong }

- **При нажатии «Запустить сейчас» ничего не происходит.** Расписание
  приостановлено или фоновый воркер не работает. Воркер выполняет каждое
  срабатывание — и по расписанию, и по кнопке.
- **У отчёта нет приложения.** Проверьте, что включена возможность
  **Приложения** (Apps) и что в инструкциях названо `weekly-report`. Вызовы
  инструментов запуска в разделе «Активность» показывают, вызывался ли
  `publish_artifact` и что он вернул.
- **Каждый запуск создаёт новое приложение.** Имя изменилось между запусками.
  Держите его неизменным в инструкциях.
- **Итог неверен или плохая строка исчезла.** Уточните инструкции, прежде чем
  что-то ставить на расписание. Расписание повторяет ошибку каждую неделю.

## Зафиксируйте проверку { #record-the-trial }

Сохраните сообщение, версию агента, профиль модели, выражение cron, каждый
запуск в разделе «Активность» и каждую версию приложения. Запишите, какие
срабатывания были по кнопке, а какие по расписанию. Человек проверяет итоги,
решает, кому можно читать приложение, и следит за первым настоящим
срабатыванием.
