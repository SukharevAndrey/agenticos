# Соберите личного помощника, который вас помнит { #build-a-personal-assistant-that-remembers-you }

Соберите помощника, который ведёт собственные заметки о собеседнике и сохраняет их
между диалогами — без единого подключения и без внешней учётной записи. Назовите
несколько вымышленных предпочтений, откройте новый диалог и проверьте, что
помощник ими пользуется, затем попросите его забыть одно. Это процедура, которую
нужно выполнить, с одним записанным запуском как образцом.

## Что понадобится { #what-you-need }

- Работающий [экземпляр AgenticOS](../install.md) с профилем модели.
- Ни песочница, ни модель эмбеддингов, ни MCP-подключение не нужны:
  [Память](../reference/capabilities.md#memory-files) работает без всяких привязок.

## Подготовьте входные данные { #prepare-the-input }

Это вымышленные факты о вымышленном человеке, достаточно мелкие, чтобы сверить их
с ответами самого помощника:

```text
Timezone: Europe/Warsaw
Meeting-free day: Friday
Summary format: short bullet points, not paragraphs
```

## Создайте агента { #build-the-agent }

1. Создайте агента в **Агенты → Новый агент** (Agents → New agent) и выберите свой
   профиль модели.
2. В **Инструменты** (Toolbox) включите **Память** (Memory), **Дата и время**
   (Date and time) и **Прошлые диалоги** (Past conversations). Добавьте
   **Поиск в интернете** (Web search), если хотите, чтобы сводка ниже что-нибудь
   искала; здешним проверкам это не нужно.
3. Задайте бюджет и лимит шагов для проверки. В записанных запусках было 5–15
   шагов, и каждый стоил около 0,01–0,04 USD.
4. Задайте инструкции ниже, затем нажмите **Опубликовать** (Publish).

```text
You are a personal assistant that remembers what this person tells you about themselves.
When the person states a preference or a standing fact (timezone, working hours, meeting-free days, how they like summaries formatted), save it with write_memory under a short name, then read MEMORY.md and add or update a one-line entry for it with edit_memory (or write_memory if MEMORY.md does not exist yet).
When asked for a plan, a summary or a morning brief, apply every preference currently in your notes: check MEMORY.md, read any note it lists that is relevant, and follow it without being asked again.
When asked to forget something, delete the matching note with delete_memory, remove its line from MEMORY.md with edit_memory, and confirm in one sentence what you forgot.
Never save something the person has not actually told you.
```

`write_memory`, `edit_memory` и `delete_memory` выполняются без согласования, как
любой инструмент, пока его автор не поставит проверку. Это пошаговое руководство
её ставит: включите **Всегда спрашивать** (Always ask) для всех трёх в
Конструкторе, чтобы каждое сохранение или забывание останавливалось с отметкой
**Требуется согласование инструмента** (Tool approval required). Одобрите его, чтобы
продолжить.

## Запустите его { #run-it }

**Диалог 1** — назовите предпочтения:

```text
A few things about me: I'm in the Europe/Warsaw timezone, I keep Fridays meeting-free, and I prefer summaries as short bullet points rather than paragraphs.
```

**Диалог 2** — новый диалог с тем же агентом, где вы просите применить то, что он
узнал:

```text
Give me a plan for tomorrow. I have three things to fit in: a client call, writing a proposal, and a team sync.
```

**Диалог 3** — попросите забыть одно из трёх:

```text
Forget my meeting-free Fridays preference.
```

Расписание может читать инструкции этого агента, но не заметки его владельца — см.
[что расписание прочитать не может](#what-a-schedule-cannot-read), прежде чем
привязывать к нему утреннюю сводку.

## Проверьте результат { #check-the-result }

| Проверка | Образец |
| --- | --- |
| Ответ в диалоге 1 | Подтверждает все три предпочтения после одобрения трёх вызовов `write_memory` и одного, который пишет `MEMORY.md` |
| `MEMORY.md` после диалога 1 | Перечисляет `timezone`, `meeting_free_days` и `summary_format` |
| План в диалоге 2 | Использует Europe/Warsaw, в основном состоит из пунктов списка и не применяет правило пятницы к дню, который пятницей не является |
| Ответ в диалоге 3 | Называет в одном предложении, что забыл |
| **Настройки → Память** (Settings → Memory) или `GET /memory/mine` после диалога 3 | `meeting_free_days` исчезла полностью; две другие заметки не изменились |
| Собственный **Запустить сейчас** (Run now) утренней сводки, до того как ей вообще что-либо сказали в чате | Говорит, что ничего не записано, а не гадает — см. ниже |

Откройте «Активность» для каждого запуска и проверьте вызовы инструментов, а не
только ответ: `write_memory`, который модель вызвала, но никто не одобрил, так и
не произошёл.

!!! example "Записано на v0.0.504, 25 сентября 2026"

    Модель: Claude Sonnet 4.6 через OpenRouter. В диалоге 1 `write_memory`
    вызывался три раза, затем, после одобрения, `MEMORY.md` был записан как
    `- timezone [preference] — …`, `- meeting_free_days [preference] — …`,
    `- summary_format [preference] — …`. Стоимость 0,039 USD.

    Диалог 2 вызвал `read_memory` по всем трём заметкам и `search_conversations`
    (который ничего не нашёл, и правильно: о завтрашнем дне ещё ничего не
    говорили), затем ответил расписанием в виде пунктов списка по времени
    Europe/Warsaw и отметил, что завтра суббота, поэтому правило про свободную
    пятницу не применяется. Стоимость 0,026 USD.

    Диалог 3 вызвал `delete_memory` для `meeting_free_days`, затем, после
    одобрения, `read_memory` и `edit_memory` для `MEMORY.md`, чтобы убрать её
    строку, и ответил: «Готово — я забыл ваше предпочтение о свободных пятницах и
    убрал его из своего индекса». `GET /memory/mine` после этого перечислил только
    `timezone` и `summary_format`. Стоимость 0,043 USD.

## Что расписание прочитать не может { #what-a-schedule-cannot-read }

Срабатывание по расписанию или по событию выполняется с ролью и выданными
доступами создателя, но это ничей диалог с точки зрения памяти: `list_memory` при
**Запустить сейчас** (Run now) утренней сводки ответил: «У этого диалога нет
памяти. У него нет опознанного человека, и это не групповой чат, поэтому заметка
должна была бы лежать там, где её читают другие» — тот же отказ, который получает
анонимный посетитель виджета, хотя создатель расписания — настоящий, известный
участник. Если сводке по расписанию нужно предпочтение, назовите его в собственном
промпте расписания — так же, как [отчёт по расписанию](scheduled-report.md)
называет свои данные в сообщении, а не полагается на память или на файл, который
никто не подаёт заново.

## Кто это может читать { #who-can-read-this }

Никто не читает ваши заметки по роли в организации — ни Owner, ни Admin, ни тот, у
кого есть выданный доступ на редактирование этого агента. До собственных заметок
вы добираетесь в **Настройки → Память** (Settings → Memory, `GET /memory/mine`),
где можно перестать использовать заметку, снова её использовать или удалить
совсем; «перестать использовать» оставляет её на странице для вас, но она больше
не доходит ни до одной модели. Читать чужие может только администратор экземпляра,
по одному человеку за раз, и это чтение записывается в журнал аудита с действующим
лицом, субъектом и причиной — но никогда с содержимым. См. [чьи это заметки и кто
их может слышать](../reference/capabilities.md#whose-notes-and-who-may-hear-them) и
[как их прочитать и стереть](../reference/capabilities.md#reading-it-and-erasing-it).

В групповом чате правило меняется: заметки принадлежат комнате, и их читают все в
ней, а сказанное помощнику наедине там не читается. Эта проверка
использовала только личный чат в веб-интерфейсе, где хранилище принадлежит только
вам.

## Когда что-то идёт не так { #when-it-goes-wrong }

- **Сохранение или забывание не происходит.** Когда `write_memory`, `edit_memory` и
  `delete_memory` закрыты проверкой, поищите на странице «Активность» в разделе
  **Согласования** (Approvals) вызов, который ожидает согласования, прежде чем
  считать, что модель проигнорировала инструкцию.
- **Следующий диалог не знает сохранённого предпочтения.** Проверьте сам
  `MEMORY.md`: заметка, которую агент сохранил, но не проиндексировал, невидима,
  пока модель не вызовет `list_memory`, а более лёгкая модель может этого не
  сделать без подсказки.
- **Сводка по расписанию гадает вместо того, чтобы использовать ваши заметки.**
  Так и должно быть — см. [что расписание прочитать не
  может](#what-a-schedule-cannot-read) выше. Впишите факт в промпт расписания.
- **Удаление заметки не убирает её везде.** `delete_memory` удаляет саму заметку;
  если строку в `MEMORY.md`, которая её называет, тоже не переписать через
  `edit_memory`, индекс всё ещё описывает то, чего больше нет.

## Зафиксируйте проверку { #record-the-trial }

Сохраните каждый диалог, версию агента, какие вызовы `write_memory`/`delete_memory`
были одобрены, и `GET /memory/mine` до и после просьбы забыть. Человек по-прежнему
одобряет каждое сохранение и удаление, решает, остаётся ли для этого агента
включённым **Хранить личные заметки о каждом человеке** (Allow personal memory), и
судит, отражает ли план то, что было сказано: помощник себя не проверяет.

## Что дальше { #next-steps }

Чтобы добраться до этого помощника из расписания, а не из веб-чата, сначала
прочитайте [что расписание прочитать не может](#what-a-schedule-cannot-read), затем
[запланируйте еженедельный отчёт](scheduled-report.md) — там описана механика
периодичности и диалога, в котором виден журнал запусков. Чтобы он искал по тому,
что действительно было сказано в прошлых диалогах, а не только по тому, что решил
сохранить, см. [поиск по диалогам](../reference/capabilities.md#conversation-search).
