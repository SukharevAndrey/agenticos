# Напишите инструкции для агента { #write-an-agents-instructions }

!!! danger "Инструкции — это данные, а не код"

    Здесь нет `prompts.py`, который можно править, и нет константы
    `DEFAULT_SYSTEM_PROMPT`, которую можно переопределить. Поведение агента
    задаёт поле `instructions` его [спецификации](../reference/spec.md): его
    правят в Конструкторе, версионируют при публикации и экспортируют как YAML в
    собственный репозиторий клиента. Правка Python, чтобы изменить, что говорит
    агент, — самое распространённое неверное предположение об этой кодовой базе.

## Где хранится текст { #where-the-text-lives }

| | Где | Кто правит |
|---|---|---|
| Инструкции одного агента | `AgentSpec.instructions`, правятся в Конструкторе | Тот, кому разрешено править агента |
| Инструкции встроенного специалиста | `InlineSpecialistSpec.instructions`, в той же спецификации | Тот же |
| Начальный текст нового агента | Шаблон AgenticOS, `backend/app/core/catalog/agent_templates/general/agenticos/AGENT.md` | Тот, кто разворачивает экземпляр: это представление о помощнике, принятое при развёртывании |
| Что агенту сообщают о том, что он может и чего не может | Собирается из его возможностей при каждом запуске, в разделе **Your setup** | Никто — включение возможности меняет это |
| Что агенту сообщают о человеке | Его язык, часовой пояс, роль и работа из его учётной записи; добавляются после инструкций при каждом запуске | Сам человек, в **Настройки → Профиль** (Settings → Profile) |
| Процедура, общая для многих агентов | [Навык](../skills.md), строка в базе данных | Руководитель поддержки во вторник днём, без развёртывания |

Последняя строка — та, к которой стоит прибегать в первую очередь. Двадцать
процедур в одном поле `instructions` значат, что каждый запуск платит за все
двадцать; двадцать навыков стоят почти ничего, потому что модель видит имена и
загружает только нужное.

## Что писать в инструкциях { #what-belongs-in-instructions }

Прочитайте инструкции шаблона AgenticOS, прежде чем писать свои: новый агент
начинает с них, так что это разобранный пример. Они начинаются с собственного
имени агента в `{{agent_name}}`, ведут человека шаг за шагом, предлагают один
следующий шаг после задачи и не называют ни одного инструмента, которого не даёт
какая-либо возможность. Большую часть качества решают два выбора:

- **Пишите с расчётом на отказы.** Своё место заслуживают те абзацы, которые
  говорят не выдумывать факты, указывать, из какого источника пришёл ответ, и
  остановиться и спросить, а не гадать там, где можно что-то разрушить. «Будь
  полезным» — украшение: модель и так старается быть полезной, а нужно ей знать,
  где проходят границы.
- **Ставьте в начало то, что относится именно к *этому* агенту.** Кто откроет
  текст следующим, перепишет первый абзац, а остальное оставит.

```text
You are a customer support agent for Acme.

Answer questions about our products, help people troubleshoot, and escalate
anything involving a refund over £500 — the refund-policy skill has the rule.

Never quote a price you have not read from the knowledge base. If a question
needs an account change, say what you would do and ask them to confirm.
```

!!! warning "Не перечисляйте инструменты агента в его инструкциях"

    Агент получает возможности из своей спецификации, а инструменты несут
    собственные описания из библиотеки. Промпт, который их перечисляет,
    становится неверным в тот момент, когда кто-то переключает одну
    возможность, — и сбой выглядит так: агент уверенно отказывается делать то,
    что теперь умеет.

!!! tip "Не пересказывайте и правила самой возможности"

    Возможность, которой нужно, чтобы модель вела себя определённым образом,
    сама это и добавляет. Формат ссылок при поиске по знаниям, как пользоваться
    песочницей, когда спрашивать человека, — всё это приходит вместе с
    возможностью, в каждом агенте, который её включает.

## Знания, навыки и файлы контекста { #knowledge-skills-and-context-files }

Три способа дать агенту текст, которого у него не было, и они не
взаимозаменяемы:

| | Для чего | Откуда берётся |
|---|---|---|
| `collection_ids` — [знания](../file-processing.md) | Тысячи документов: что мы знаем | Семантический поиск, со ссылками на источник |
| `skill_ids` — [навыки](../skills.md) | Десятки процедур: как мы это делаем | Модель выбирает имя, затем загружает тело |
| `context_ids` — файлы контекста | Несколько файлов, достаточно маленьких, чтобы всегда быть на месте | Подставляются в инструкции, без поиска |

Все три проверяются по доступу **публикующего** в момент публикации, а не во
время запуска. См. [Разрешения](../permissions.md).

## Дорабатывайте его { #iterating-on-it }

- **Черновик работает только как тест.** Везде, где агент доступен, он отвечает
  опубликованной версией; тестовая панель Конструктора — и
  `POST /agents/{id}/run` с `"draft": true`, который вызывает `test_agent_draft`
  Архитектора, — отвечают как неопубликованный черновик, в тестовом запуске.
  Публикация намеренно дешёвая, а откат — это перевод в окружение, а не
  восстановление. Дорабатывайте в `dev`-[окружении](../concepts.md#version),
  которое следует за каждой публикацией, а `production` оставьте ждать, когда
  на него переведут версию.
- **Проверяйте на настоящих запросах, а не на идеальных.**
- **Держите текст таким коротким, каким позволяет поведение.** За длинный промпт
  платят на каждом ходе каждого запуска, и он раньше выталкивает диалог за
  пределы окна.
- **Публикуйте, когда всё верно.** Публикация замораживает версию, поэтому «что
  этот агент делал в прошлый вторник» остаётся отвечаемым и после дюжины
  правок — а откат публикует *новую* версию, скопированную со старой, а не
  удаляет историю.
- **Температура и остальное — это `model_settings`**, для каждого агента и
  каждого специалиста, поверх профиля модели. Не переменная окружения.
