# Отвечайте на вопросы новых сотрудников с помощью файлов контекста и навыков { #answer-new-hire-questions-with-context-files-and-skills }

Создайте справочную службу для новых сотрудников, которая всегда знает несколько
небольших, стабильных фактов и берётся за прописанную процедуру, только когда
вопрос действительно этого требует. За этим стоят две возможности —
[файлы контекста](../context.md) и [навыки](../skills.md), — и эта страница
существует потому, что неверный выбор из них — обычная причина, по которой агент
либо игнорирует то, что ему сказали, либо так и не открывает то, что ему
понадобилось. Это процедура, которую нужно выполнить, с одним записанным запуском
как образцом.

## Что подходит { #which-one-fits }

| | Что хранит | Что видит модель |
| --- | --- | --- |
| **Файл контекста** (Context file) | Постоянные факты, небольшие и стабильные — когда выплачивают зарплату, ИТ-канал | Всегда (`inject`) или по требованию (`link`) |
| **Навык** (Skill) | Процедура для одного вида задач — как запросить доступ | Только когда модель решит, что происходит именно эта задача |
| **Коллекция знаний** (Knowledge collection) | Корпус, слишком большой, чтобы прочитать его целиком — весь справочник, все PDF с политиками | Только фрагменты, которые вернёт поиск |

Приведённое ниже вводное руководство короткое и всегда уместно, поэтому это файл
контекста. «Как получить доступ к системе» — процедура с шагами и исключением,
поэтому это навык. Если ваш вводный материал — это справочник на пятьдесят
страниц, привяжите его как [коллекцию знаний](set-up-knowledge-base.md), а приём с
этой страницы оставьте только для коротких постоянных фактов. См. [навыки или
знания?](../skills.md#skills-or-knowledge) о том же различии со стороны навыков.

## Что понадобится { #what-you-need }

Работающий [экземпляр AgenticOS](../install.md) с профилем модели. Ни песочницы,
ни модели эмбеддингов не нужно: оба файла здесь достаточно малы, чтобы вставить
или загрузить их целиком.

## Подготовьте входные данные { #prepare-the-input }

Файл контекста с постоянными фактами:

```markdown
# Acme Robotics — new-hire quick facts

- Payroll runs on the last business day of the month.
- The standard laptop is a MacBook Pro; loaner laptops are requested from IT, not HR.
- The internal help channel for IT questions is #it-help.
- Health insurance enrollment is open during your first 30 days; after that, only
  during the November open-enrollment window.
```

Навык для одной процедуры, о которой новые сотрудники спрашивают чаще всего:

```markdown
# Requesting access

Most access requests go through the #it-help channel, not a person directly.

1. Post in #it-help naming the system and the reason you need it.
2. IT grants standard tools (chat, email, laptop) within one business day.
3. Anything touching customer data (the CRM, production databases) needs your
   manager's written approval first - tag them in the same thread.
4. Access to the payroll system is never granted through chat; email
   payroll@acme-example.com instead.
```

Acme Robotics вымышлена. Образцовые факты: зарплата в последний рабочий день,
MacBook Pro по умолчанию и доступ к CRM, для которого сначала нужно одобрение
руководителя.

## Создайте агента { #build-the-agent }

1. В **Контекст → Новый файл контекста** (Context → New) создайте файл с
   названием `onboarding-guide`, вставьте факты выше, поставьте **Режим** (Mode)
   `inject` и дайте описание, которое человек потом узнает.
2. В **Навыки → Новый файл** (Skills → New) создайте `request-access` с
   процедурой выше и описанием, написанным для модели: *«Когда кто-то спрашивает,
   как получить доступ к инструменту, репозиторию или системе, или не уверен, кто
   его выдаёт».* — связанный навык выбирается по названию и этой одной строке.
3. Создайте агента в **Агенты → Новый агент** (Agents → New agent) и выберите
   свой профиль модели.
4. В **Инструменты** (Toolbox) включите **Контекст** (Context) и привяжите
   `onboarding-guide`. Включите **Навыки** (Skills) и привяжите `request-access`.
5. Задайте инструкции ниже, затем нажмите **Опубликовать** (Publish).

```text
You are Acme Robotics' new-hire helpdesk assistant.
Answer from the standing facts you were given, and use a bound skill's
procedure when a question is about how to do something.
If you are not sure, say so rather than guessing.
```

## Запустите его { #run-it }

Сначала спросите о постоянном факте, затем задайте вопрос о процедуре:

```text
When does payroll run, and what laptop will I get?
```

```text
How do I get access to the CRM?
```

## Проверьте результат { #check-the-result }

| Проверка | Образец |
| --- | --- |
| Вопрос о зарплате и ноутбуке | Отвечает сразу, без вызова инструмента — файл контекста уже в промпте |
| Вопрос о доступе к CRM | Перед ответом вызывает `read_skill` для `request-access` |
| Ответ про CRM | Называет письменное одобрение руководителя первым шагом, а не только «напишите в #it-help» |
| Вопрос, который файл контекста не покрывает (например, «какой у вас дресс-код?») | Говорит, что не знает, а не выдумывает политику |
| Правка файла контекста после этого | Следующий запуск отражает правку, хотя на агенте ничего не публиковали |

Первые две строки — та проверка, которая важна: один ответ берётся из текста,
лежащего в каждом промпте, другой — из вызова инструмента, который модель решила
сделать. Если что-то из этого происходит наоборот, выбрана не та возможность.

!!! example "Записано на v0.0.504, 25 сентября 2026"

    Модель: Claude Sonnet 4.6 через OpenRouter. Вопрос о зарплате и ноутбуке
    израсходовал 914 входных токенов **без вызова инструмента** и получил ответ:
    *«Зарплата выплачивается в последний рабочий день месяца… Стандартный ноутбук
    — MacBook Pro»*. Стоимость 0,004 USD.

    Вопрос о CRM вызвал `read_skill` с `{"id": "request-access"}`, получил полное
    тело навыка и ответил: *«Поскольку CRM затрагивает данные клиентов, есть
    отдельный процесс… Сначала получите письменное одобрение руководителя…
    Напишите в #it-help. Отметьте руководителя в той же ветке»*. Стоимость
    0,009 USD.

## Когда что-то идёт не так { #when-it-goes-wrong }

- **В ответе нет постоянного факта.** Проверьте **Режим** файла контекста. Файл в
  режиме `link` вообще не попадает в промпт, пока модель не решит его прочитать:
  для фактов, которые нельзя упускать, используйте `inject`.
- **Навык не загружается никогда.** Модель выбирает его только по названию и
  описанию; описание, которое читается как заголовок («Запросы доступа»), говорит
  ей меньше, чем написанное в духе *когда за него браться*.
- **Агент пересказывает навык на каждый вопрос.** Описание навыка слишком широкое,
  или инструкции недостаточно чётко различают «постоянный факт» и «процедуру»,
  чтобы модель поняла, что это за вопрос.
- **Отредактированный файл контекста не меняет ответ.** Убедитесь, что вы правили
  файл организации, а не копию: файлы контекста привязываются по `id`, и
  отдельного ответвления для агента у них нет.
- **Вместо прямого ответа появляется предложение изменить навык.** Агент может
  попытаться *улучшить* навык посреди диалога; это предложение для человека с
  `skills:edit`: применить его или отклонить, а не то, что запуск применяет сам.
  См. [навыки](../skills.md#an-agent-can-propose-a-change-a-person-makes-it).

## Зафиксируйте проверку { #record-the-trial }

Сохраните содержимое и `id` обоих файлов, версию агента, оба вопроса и ответа и то,
использовал ли каждый вызов инструмента. Человек по-прежнему пишет и правит
постоянные факты и процедуру — этот приём решает только, где лежит каждый кусок
текста, а не кто прав насчёт дат зарплаты.

## Что дальше { #next-steps }

Того же агента можно привязать к боту Slack для канала команды вместо консоли —
см. [ответ на вопрос по справочнику в Slack](slack-handbook-assistant.md), где
разобраны привязка, связывание учётных записей и проверка того, какой запуск кому
принадлежит. Если вводный материал вырастает за пару страниц, перенесите его в
[коллекцию знаний](set-up-knowledge-base.md), а не растягивайте встроенный файл
контекста.
