# Соберите вики на LLM, которую ведёт агент { #build-an-llm-wiki-the-agent-maintains }

Andrej Karpathy описал этот шаблон в апреле 2026 года: держите исходные материалы
нетронутыми в одном месте, пусть агент компилирует их в небольшую перекрёстно
связанную вики на Markdown в другом, и запишите схему, чтобы любой последующий
сеанс мог сверить себя с ней, а не угадывать раскладку заново. Здесь это
строится на рабочем пространстве, которое живёт дольше одного диалога, с двумя
синтетическими источниками, добавленными с разницей в один сеанс. Это процедура,
которую нужно выполнить; один записанный запуск приведён как образец: два диалога
добавления ниже выполнены полностью, а до вопроса и шага проверки в том запуске
не дошли, и это отмечено.

## Что понадобится { #what-you-need }

- Работающий [экземпляр AgenticOS](../install.md) с профилем модели и
  зарегистрированным [подключением песочницы](../sandbox.md), которое
  предоставляет среду выполнения `workbench`.
- Других возможностей не нужно. Вики целиком живёт в рабочем пространстве
  агента.

## Подготовьте входные данные { #prepare-the-input }

Две короткие заметки, на вид не связанные, но на деле содержащие один и тот же
факт, — чтобы у вики был повод связать их перекрёстно.

Источник один, вставленный в первом диалоге:

```text
Meeting notes, 3 March. The team adopts a weekly on-call rotation starting
Monday. Alice is on-call first, then Bob, then Carol, rotating every Monday
at 9am. Escalation rule: if the on-call person does not respond within 15
minutes, page the backup, who is always the previous week's on-call person.
```

Источник два, вставленный во втором, отдельном диалоге:

```text
Incident report, 11 March. A database outage occurred on Tuesday. Alice was
on-call and responded within 5 minutes; the backup escalation was not
needed. Root cause: a migration script left a lock unreleased. Fix: the
migration now acquires the lock with a timeout.
```

Контрольный факт, который страница вики должна собрать из обеих заметок: Alice
была дежурной во время сбоя из-за графика, установленного 3 марта, а правило
резервного дежурного из того же графика не сработало.

## Создайте агента { #build-the-agent }

1. Создайте агента в **Агенты → Новый агент** (Agents → New agent) и выберите
   свой профиль модели.
2. В **Инструменты** (Toolbox) включите **Песочница** (Sandbox). Выберите
   **Контейнер** (Container), укажите своё подключение песочницы и среду
   выполнения `workbench`.
3. Задайте **область сеанса `user`**, а не `conversation` по умолчанию. Рабочее
   пространство с областью диалога начинается пустым в следующем чате — ровно
   тот сбой «вики всё забывает», который проверяет эта страница; рабочее
   пространство с областью агента делится между всеми в организации, кто говорит
   с этим агентом, а это неправильная модель совместного доступа для личной
   вики. `user` хранит одно рабочее пространство для человека во всех диалогах и
   на всех способах доступа, через которые он обращается к агенту, и ни для кого
   больше. О том, чем делится каждая область, см.
   [Песочница](../reference/capabilities.md#files-shell).
4. Задайте бюджет и лимит шагов для проверки.
5. Задайте инструкции ниже, затем нажмите **Опубликовать** (Publish).

```text
You maintain a small personal LLM wiki in your workspace: raw sources
compiled into a cross-linked Markdown wiki, following this schema.

Layout:
raw/<slug>.md - one file per ingested source, saved verbatim, append-only.
Never edit a raw file once written.
wiki/index.md - one line per wiki page, each a Markdown link to it.
wiki/<topic>.md - one page per topic, written in your own words from the raw
sources. Link related pages with a relative Markdown link.
schema.md - this layout, written once on your first turn if it does not
exist, so any later session can check itself against it.

When asked to ingest a source: read schema.md first, writing it if it is
missing; list wiki/ so you know what exists; save the source verbatim to
raw/<slug>.md; update an existing wiki page if the source is about it, or
create a new one only for a genuinely new topic; cross-link pages that refer
to each other; update wiki/index.md; report which files you touched.

When asked a question, read the relevant wiki page(s) - not the raw sources,
unless a page is missing something the question needs - and answer citing
the page you used by name.

When asked to lint the wiki: list every file, read wiki/index.md and every
page it links to, then report broken links, orphan pages nothing links to,
and any two pages that state different facts about the same thing. Do not
fix anything unless asked; only report.
```

Здесь схема живёт в инструкциях, потому что она короткая. Схема, которая
вырастает больше абзаца-двух, лучше подходит для [файла контекста](../context.md)
в режиме `link`: он читается один раз и общий для каждого агента, который ведёт
вики таким образом, вместо того чтобы вставляться в инструкции каждому.

## Запустите его { #run-it }

В первом, новом диалоге:

```text
Ingest this source: [paste source one]
```

Начните **второй, новый диалог** с тем же агентом — не ответ в первом — и
попросите его добавить второй источник, затем задайте вопрос:

```text
Ingest this source: [paste source two]
```

```text
Who was on-call during the outage, and what is the backup escalation rule?
```

В третьем ходе или третьем диалоге запросите проверку, вокруг которой построен
шаблон:

```text
Lint the wiki.
```

## Проверьте результат { #check-the-result }

| Проверка | Образец |
| --- | --- |
| `schema.md` после первого диалога | Существует и совпадает с раскладкой в инструкциях |
| Рабочее пространство в начале второго диалога | Уже содержит `schema.md`, `raw/`, `wiki/` из первого — ничего не создаётся заново |
| Страницы вики после обоих источников | Упоминают Alice, порядок дежурств и сбой; две темы ссылаются друг на друга, а не лежат как две несвязанные страницы |
| Ответ на вопрос | Называет Alice, ссылается на страницы вики и говорит, что правило резервного дежурного не сработало |
| Отчёт проверки | Правдиво называет любую сломанную ссылку или страницу-сироту — в том числе «не найдено» — а не общее «всё хорошо» |
| Третий диалог с вопросом, когда ещё ничего не добавлено | Читает существующую вики и всё равно отвечает, потому что рабочее пространство принадлежит человеку, а не диалогу |

Читайте сами файлы через панель файлов диалога, а не только ответ. Модель,
которая описывает, как обновляет перекрёстную ссылку, и модель, которая
действительно её записала, в прозе выглядят одинаково.

!!! example "Записано на v0.0.504, 25 сентября 2026"

    Модель: Claude Sonnet 4.6 через OpenRouter, среда выполнения `workbench`,
    `session_scope: user`. Первый диалог не нашёл ни `schema.md`, ни `wiki/`,
    создал и то и другое по раскладке из инструкций, сохранил заметку о
    дежурствах в `raw/meeting-notes-2024-03-03.md` и создал
    `wiki/on-call-rotation.md` и `wiki/index.md` — без вызова `execute`, поэтому
    согласование не потребовалось. Стоимость: 0,1022 USD.

    Второй, отдельный диалог с тем же агентом начался с чтения `schema.md` и
    перечисления `wiki/` и обнаружил, что и то и другое уже на месте: рабочее
    пространство сохранилось. Он сохранил отчёт об инциденте в
    `raw/incident-report-11-march.md`, создал `wiki/database-incidents.md` с
    упоминанием Alice, пятиминутного отклика и первопричины, затем использовал
    `edit_file` для `wiki/on-call-rotation.md`, чтобы добавить раздел
    «Incidents» со ссылкой на новую страницу, и обновил `wiki/index.md`, чтобы
    перечислить обе страницы: настоящая двусторонняя перекрёстная ссылка, а не
    две страницы, стоящие рядом. Стоимость: 0,1250 USD.

    Сбой инфраструктуры, не связанный с агентом или песочницей, остановил
    проверку на этом месте. Вопрос («Кто был дежурным во время сбоя…») и шаг
    проверки выполнены не были, поэтому соответствующие строки в таблице выше —
    ожидаемый образец, а не наблюдаемый результат. Подтверждено то, ради чего
    эта страница существует: рабочее пространство пережило полностью отдельный
    диалог, а две темы связались друг с другом, а не продублировали содержимое.

## Когда что-то идёт не так { #when-it-goes-wrong }

- **Второй диалог начинается с пустого рабочего пространства.** Область имеет
  значение `conversation` или `agent`, запуск привязан к подключению по
  умолчанию, отличному от того, что использовал первый, или между ними
  изменились подключение либо бэкенд — любое из этого создаёт новое рабочее
  пространство, а не возвращается к старому.
- **Две страницы повторяют друг друга вместо перекрёстных ссылок.** Модель не
  прочитала `wiki/index.md` перед записью. Ужесточите инструкции, чтобы они
  каждый раз требовали сначала перечислить вики.
- **Отчёт проверки всегда говорит, что всё в порядке.** Попросите проверить
  вики, в которой вы знаете о проблеме, — сначала переименуйте связанный файл, —
  чтобы убедиться, что отчёт читает файлы, а не предполагает.
- **`schema.md` перезаписывается в каждом диалоге.** Инструкции велят создавать
  его, только если он отсутствует; если модель всё равно его перезаписывает,
  скажите ей явно: читать до того, как что-либо писать.
- **Коллега видит заметки, которые вы считали личными.** Проверьте область
  сеанса. `agent` делит одно рабочее пространство со всеми, кто говорит с этим
  агентом, и Конструктор предупреждает об этом у самого поля именно поэтому.

## Зафиксируйте проверку { #record-the-trial }

Сохраните оба исходных источника, точные промпты, версию агента и список файлов
рабочего пространства после каждого диалога — не только ответы. Человек
по-прежнему судит, полезна ли перекрёстная ссылка на самом деле или она просто
есть, и поймал ли отчёт проверки что-то настоящее.

## Вики или поиск по знаниям? { #wiki-or-knowledge-search }

Они отвечают на разные потребности. [Поиск по
знаниям](../reference/capabilities.md#knowledge-search) находит фрагменты в
документах, которые никто не переписывает, — подписанный договор, PDF с
политикой — и ссылается на исходный фрагмент. Этот шаблон — для материала,
который начинается с беспорядка и малого объёма и стоит времени агента на
*компиляцию*: заметки, транскрипты, недописанные тексты, которым полезно
превратиться в небольшое число поддерживаемых страниц вместо растущей груды
исходных файлов. Как только скомпилированная вики сама становится слишком
велика, чтобы её вставлять в промпт или читать целиком, естественный следующий
шаг — искать по ней как по любой другой коллекции, а не хранить её файлом в
рабочем пространстве.

## Что дальше { #next-steps }

Попробуйте намеренно добавить источник, противоречащий более раннему, и
проверьте, что шаг проверки называет обе страницы, а не молча выбирает сторону.

Для командной вики используйте [проект](../projects.md): несколько агентов делят
его файлы и инструкции в рамках членства в проекте. Для личного хранилища заметок
в приложении для компьютера подключите одобренную локальную папку; она не
синхронизируется с общими файлами проекта.

Откройте [вид графа](../projects.md#graph-view) в проводнике файлов, чтобы
просматривать ссылки и обратные ссылки. Он автоматически перечитывает заметки
Markdown; агент только ведёт заметки и их ссылки, не пересоздавая
HTML-приложение. Обновление графа не выполняет фактические проверки, описанные в
этом руководстве.
