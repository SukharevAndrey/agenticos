# Получите помощь и внесите вклад { #get-help-and-contribute }

О воспроизводимой ошибке сообщайте через [шаблоны для сообщений о проблемах](https://github.com/vstorm-co/agenticos/issues/new/choose). Сначала поищите среди уже открытых проблем. Укажите выпуск или коммит, тип развёртывания, относящуюся к делу конфигурацию модели и инструментов, ожидаемый результат, фактический результат и минимальный синтетический ввод.

Не прикладывайте учётные данные и приватные документы. При подозрении на уязвимость следуйте инструкциям по приватному сообщению из [SECURITY.md](https://github.com/vstorm-co/agenticos/blob/main/SECURITY.md), а не открывайте публичное воспроизведение.

## Прежде чем сообщать о проблеме с установкой { #before-reporting-an-installation-problem }

Проверьте [установку](install.md) и выбранную [конфигурацию развёртывания](deployment.md). Запишите команду, которая завершилась с ошибкой, и ошибку с вырезанными секретами. Для ответа по документу проверьте обработку источника, привязку коллекции и разрешения. При сбое инструмента сохраните ошибку инструмента и статус запуска. Проверка подключения — не доказательство того, что задача выполнена.

## Внесите вклад или оговорите помощь с реализацией { #contribute-or-scope-implementation-help }

Прочитайте [CONTRIBUTING.md](https://github.com/vstorm-co/agenticos/blob/main/CONTRIBUTING.md), [архитектуру](architecture.md) и соответствующее руководство, прежде чем менять поведение. Точечное исправление документации или воспроизводимая проблема — полезный вклад. Крупные изменения согласуйте с мейнтейнерами через репозиторий.

По развёртыванию на вашей инфраструктуре, документации, созданию процессов или доработке под заказ обращайтесь в [Vstorm](https://vstorm.co/) или к Kacper. Обязательства по поддержке определяются отдельно. Сообщения о проблемах от сообщества не подпадают под договорный срок ответа.
