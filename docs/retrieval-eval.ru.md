# Оценка поиска { #retrieval-evaluation }

Агент со знаниями хорош ровно настолько, насколько хорошо то, что его поиск передаёт
модели. Изменение разбиения на фрагменты, `top_k` или расширения запроса сдвигает это,
а хорошо читающийся ответ ничего не говорит о том, попала ли в выдачу нужная страница.
Поэтому есть набор вопросов с известными ответами по этой документации и стенд, который
измеряет на нём поиск, — в `evals/retrieval/`. Эта страница о том, что он измеряет, как
его запустить и во сколько обходится запуск.

Всё началось с одного вопроса ([#2482](https://github.com/vstorm-co/agenticos/issues/2482)).
На вопрос *«Поддерживает ли AgenticOS единый вход SAML?»* агент по документации нашёл
только страницу сравнения с Dify и ответил, что в документации об этом не сказано.
[Вход через каталог](directory.md) прямо говорит, что SAML нет, и как вместо этого
попасть в AgenticOS через Keycloak.

## Набор вопросов { #the-question-set }

`evals/retrieval/docs_questions.yaml` содержит 34 вопроса в трёх категориях:

| Категория | Что проверяет | Пример |
|---|---|---|
| `factual` | Заданную настройку, значение по умолчанию или имя | «Если я никогда не задавал мастер-ключ хранилища, чем платформа шифрует учётные данные?» |
| `negative` | Вопрос «поддерживаете ли вы X», на который документация отвечает прямым нет | «Поддерживает ли AgenticOS единый вход SAML?» |
| `cross_language` | Польский вопрос, отвечаемый только по английским страницам, или английский вопрос — только по польским | «Czy da się logować do AgenticOS przez SAML?» |

Каждый вопрос называет ожидаемые страницы и, для проверки ответа, факты, которые
содержит правильный ответ. Запись выглядит так:

```yaml
- id: saml-single-sign-on
  category: negative
  language: en
  question: Does AgenticOS support SAML single sign-on?
  expected_pages: [directory.md]
  expected_facts:
    - ["no", "not", "nie"]
    - [Keycloak*]
  evidence: "directory.md: **No SAML.** A SAML-only identity provider can reach AgenticOS through Keycloak"
```

Страница называется без языка: `directory.md` — это и `directory.pl.md`, поэтому фрагмент
из любого перевода считается попаданием. Вопрос `cross_language` добавляет
`search_locales` — единственный язык, по которому его поиск может читать, и он никогда не
совпадает с языком самого вопроса. Файл версионируется, а изменение смысла поля
увеличивает `version`. Загрузчик отклоняет ожидаемую страницу, которой нет или которая
не опубликована, поэтому переименование страницы приводит к сбою модульных тестов, а не становится
промахом в запуске, за который кто-то заплатил.

## Что измеряет запуск { #what-a-run-measures }

Корпус — это опубликованный сайт: каждая страница Markdown в `docs/`, кроме того, что
исключает `mkdocs.yml` (`plans/`, `design/`, `audits/`, дорожная карта), и кроме этой
страницы, где приведены вопросы и ответы. Каждый язык индексируется в свою коллекцию,
названную по модели эмбеддингов и дайджесту настроек эмбеддингов и индексации, поэтому
запуск, который меняет размер фрагмента или модель, индексирует заново. Следующий запуск
использует коллекцию, пока в ней лежит каждая страница в её нынешнем виде, и строит её
заново, если страницу добавили, удалили, переименовали или изменили. Обычный вопрос ищет
по всем им сразу, как это делает агент, привязанный к нескольким коллекциям.

Каждая конфигурация — это один проход по всем 34 вопросам. Поиск идёт собственным путём
инструмента знаний: запрос расширяется согласно `query_analysis_mode`, каждый запрос
выполняется, а результаты объединяются и обрезаются до `top_k`. Расширенные запросы
вопроса генерируются один раз на режим и переиспользуются для каждого `top_k`, поэтому
два значения `top_k` сравниваются на одних и тех же переформулировках. По категориям
запуск сообщает:

| Число | Значение |
|---|---|
| hit@k | Доля вопросов, у которых среди выданных `top_k` есть хотя бы один фрагмент с ожидаемой страницы |
| recall@k | Доля ожидаемых страниц каждого вопроса, до которых дошли, усреднённая |
| MRR | Среднее значение 1/ранга первого фрагмента с ожидаемой страницы; 0, если ни одного не выдано |
| Ответы верны | С `--answers`: сколько ответов содержат каждый ожидаемый факт |

После каждой таблицы запуск перечисляет вопросы, которые промахнулись, и страницы,
которые получились вместо них, — именно там и лежит полезная информация.

Проверка ответа сопоставляет факты как целые слова без учёта регистра. Вариант,
оканчивающийся на `*`, совпадает по префиксу (`Keycloak*` совпадает с «Keycloaka»).
Маркеры ссылок вроде `[5]` не дают числовых фактов. Повторы вопроса игнорируются после
нормализации регистра, пунктуации и пробелов.

Распознанные английские и польские оговорки о незнании исключаются до сопоставления:
`not` в «the documentation does not state» не даёт отрицательного ответа. Отдельные ясные
утверждения по-прежнему считаются. Отрицательные кейсы, начинающиеся с «yes» или «tak»,
не проходят, а простое «no» всё ещё требует задокументированной альтернативы. Это
остаётся сигналом на уровне слов: нераспознанные запасные варианты или путаные ответы,
использующие ожидаемые слова, всё ещё требуют ручной проверки.

Подстановочному знаку нужен непустой корень: одиночная `*` отклоняется до индексации,
потому что она совпала бы с каждым ответом.

`--json` записывает найденные страницы и ответ по каждому вопросу для тех, кто хочет их
прочитать, и запросы, с которыми искал режим `multi_query` или `hyde`. Файл также
фиксирует, чем был сделан запуск: когда он начался, SHA-256 набора вопросов, модель
эмбеддингов и её размерность, настройки фрагментов и парсеры, а также дайджест, который
несут имена коллекций.

`corpus` также записывает число страниц и отпечаток исходников каждого языка, снятые до
индексации. `corpus_fingerprint_algorithm` — это `sha256-path-content-v1`: SHA-256 от
компактного UTF-8 JSON (`ensure_ascii=False`), содержащего отсортированные пары
`[relative POSIX path, SHA-256(source bytes)]`. Абсолютные пути рабочей копии исключены.
Это отличает изменённые исходные страницы, даже когда вопросы и настройки индексации
остаются прежними. Не меняйте рабочую копию во время запуска.

## Как запустить { #running-it }

Для запуска нужна база с применёнными миграциями и pgvector (`make dev` даёт такую),
эндпоинт эмбеддингов и, для `multi_query`, `hyde` и `--answers`, модель. Используйте базу
разработки, а не экземпляра. Стенд удаляет и перестраивает собственные коллекции и
отказывается стартовать, когда база знаний уже использует одно из их имён.

!!! warning "Каждый вызов — настоящий, оплачиваемый вызов"
    Стенд строит эмбеддинги корпуса и каждого запроса на указанном вами эндпоинте и
    вызывает названную вами модель. Ничего не кэшируется и не подделывается. Прочитайте
    [Стоимость](#cost) перед первым запуском.

```bash
export OPENAI_API_KEY=sk-...
make eval-retrieval EVAL_ARGS="--top-k 5 --top-k 10 --mode off --mode multi_query --mode hyde \
    --llm-model openai:gpt-4.1-mini --answers --json /tmp/retrieval.json"
```

Параметры:

| Параметр | По умолчанию | |
|---|---|---|
| `--collection-prefix` | `retrieval_eval` | Начинается со строчной буквы; далее строчные буквы, цифры или подчёркивания. Сгенерированные имена должны укладываться в ограничение длины имени коллекции в хранилище |
| `--top-k` | `5` | Можно повторять, 1–50. Фрагментов на поиск, `default_top_k` возможности знаний |
| `--mode` | `off` | Можно повторять. `off`, `multi_query` или `hyde`, `query_analysis_mode` возможности |
| `--chunk-size` | `2500` | Символов на фрагмент, как задают настройки индексации коллекции |
| `--chunk-overlap` | `200` | Символов, которые фрагмент повторяет из предыдущего. Должно быть меньше `--chunk-size` |
| `--chunking-strategy` | `recursive` | `recursive`, `markdown` или `fixed` |
| `--max-variants` | `3` | Переформулировок, которые может добавить `multi_query`, 1–5 |
| `--locale` | `en`, `pl` | Можно повторять. Индексируемые языки; должны включать язык каждого вопроса `cross_language` |
| `--embedding-model` | `text-embedding-3-small` | Любая модель из каталога эмбеддингов или другая с `--embedding-dim` |
| `--embedding-dim` | из каталога моделей | Обязательная положительная размерность для модели вне каталога; для моделей из каталога отклоняется |
| `--embedding-base-url` | `https://api.openai.com/v1` | Любой совместимый с OpenAI эндпоинт `/v1/embeddings` |
| `--embedding-api-key-env` | `OPENAI_API_KEY` | Переменная, из которой читается ключ |
| `--keyless` | выкл. | Эндпоинт не принимает ключ |
| `--llm-model` | нет | Имя модели Pydantic AI. Её провайдер читает свою переменную с ключом. `openai:` использует Responses API OpenAI; о других эндпоинтах см. ниже |
| `--answers` | выкл. | Ещё и отвечать на каждый вопрос по найденному и проверять факты |
| `--reingest` | выкл. | Удаляет коллекции и индексирует корпус заново. Запуск делает это сам, когда изменилась страница или настройка фрагментов; передавайте этот параметр после изменения кода парсера |
| `--json` | нет | Ещё и записывать результаты по вопросам в этот файл |

Требуемые агенты расширения запросов и ответов готовятся до индексации, поэтому неверная
конфигурация LLM останавливает работу ещё до эмбеддингов. Если задан только `--mode off`
и нет `--answers`, переданный `--llm-model` не используется и LLM-агент не создаётся.

Параллельные замеры резервируют имена своих коллекций сеансовыми рекомендательными
блокировками PostgreSQL — от проверки владения до индексации и измерения. Если какое-то
имя занято, новый запуск останавливается до вызовов эмбеддингов или поиска. Дождитесь
другого запуска или выберите другой `--collection-prefix`. Успех, сбой и прерывание
освобождают все резервирования.

Параметры фрагментов проверяются так же, как настройки индексации базы знаний, а все
остальные настройки индексации — значения по умолчанию из той формы. Корпус — Markdown,
который встроенное средство чтения разбирает независимо от выбранного парсера PDF,
поэтому параметра парсера нет. Стенд не читает переменные окружения для этих настроек.

Набор вопросов, который отклоняет загрузчик, останавливает запуск до какой-либо
индексации, одним сообщением, где назван каждый элемент и его проблема.

Отчёт идёт в стандартный вывод, а ход работы — в стандартный поток ошибок, поэтому
`> results.md` оставляет только отчёт. Первая страница, которая не проиндексировалась,
немедленно останавливает запуск и удаляет неполную коллекцию, не пробуя другие страницы.
Прерванная коллекция тоже удаляется: корпус с пробелами измеряет пробелы.

Место для `--json` проверяется до индексации или оплачиваемых вызовов. Его родительский
каталог должен уже существовать, а файл — быть записываемым. Проверка создаёт новый
пустой файл; существующий отчёт остаётся цел, если оценка сорвалась. Успешная оценка
заменяет файл полным JSON-отчётом.

### Без платного ключа { #without-a-paid-key }

Для эмбеддингов подойдёт совместимый с OpenAI сервер на вашей машине. С
[Ollama](https://ollama.com), после `ollama pull bge-m3`:

```bash
make eval-retrieval EVAL_ARGS="--embedding-base-url http://localhost:11434/v1 \
    --embedding-model bge-m3 --keyless"
```

`bge-m3` многоязычна, что важно для вопросов `cross_language`. Числа описывают эту
модель, а не ту, что используют коллекции экземпляра, поэтому сравнивайте только запуски
с одной и той же моделью эмбеддингов.

Локальной модели для `multi_query`, `hyde` и `--answers` нужен префикс `openai-chat:`,
потому что `openai:` вызывает Responses API, которого нет у большинства совместимых с
OpenAI серверов. `OPENAI_BASE_URL` направляет провайдера на сервер. Задавайте её для
одной команды, как ниже: экспортированная, она отправила бы на локальный сервер все
последующие вызовы `openai:` и ключ, который к ним прилагается. Без `OPENAI_API_KEY`
провайдер отправляет ключ-заглушку. После `ollama pull qwen3:8b`:

```bash
OPENAI_BASE_URL=http://localhost:11434/v1 make eval-retrieval EVAL_ARGS="\
    --embedding-base-url http://localhost:11434/v1 --embedding-model bge-m3 --keyless \
    --mode multi_query --llm-model openai-chat:qwen3:8b"
```

То же относится к любому эндпоинту, который предлагает только chat completions.

## Стоимость { #cost }

Опубликованный корпус — около 0,6 млн токенов на английском и 1,0 млн на польском,
измерено токенизатором `cl100k_base`, который используют модели эмбеддингов OpenAI. При
перекрытии фрагментов в 200 символов индексация обоих языков — около 1,7 млн токенов.
Платится один раз и ещё раз за язык, когда меняется одна из его страниц или при
`--reingest`.

| Часть | Токенов за запуск | По прайс-листу |
|---|---|---|
| Индексация, `text-embedding-3-small` | ~1,7 млн, один раз | ~$0,03 |
| Индексация, `text-embedding-3-large` | ~1,7 млн, один раз | ~$0,22 |
| Эмбеддинги вопросов | меньше 10 тыс. на конфигурацию | меньше $0,01 |
| `multi_query` или `hyde`, `gpt-4.1-mini` | ~34 вызова, ~10 тыс. токенов на конфигурацию | меньше $0,01 |
| `--answers` при `top_k` 5, `gpt-4.1-mini` | ~34 вызова, ~150 тыс. входных и ~5 тыс. выходных токенов | ~$0,07 |
| `--answers` при `top_k` 10, `gpt-4.1-mini` | ~300 тыс. входных и ~5 тыс. выходных токенов | ~$0,13 |

Цены — прайс-листовые за миллион токенов на момент написания: `text-embedding-3-small`
$0,02, `text-embedding-3-large` $0,13, `gpt-4.1-mini` $0,40 за вход и $1,60 за выход.
Проверяйте текущие цены своего провайдера. При этих ценах полная матрица из двух значений
`top_k`, трёх режимов и ответов стоит меньше доллара. В конце запуск печатает сделанные
вызовы модели и их токены.

## Измеренное сравнение { #measured-comparison }

10 ноября 2026 года настоящий запуск использовал существующее подключение GPT-6 Luna через
OpenRouter: `openai/gpt-6-luna` для расширения и ответов и
`openai/text-embedding-3-small` размерностью 1536 для эмбеддингов. Ревизия `e8e782562`
дала 128 английских страниц (1452 фрагмента) и 128 польских (1553 фрагмента) при
рекурсивном разбиении, размере 2500 и перекрытии 200. Все 34 вопроса прошли в каждой
конфигурации, разделяя сгенерированные запросы между разными глубинами поиска.

Проверка исправила формулировки ответов и добавила документированные страницы-ответы для
таймаутов, файлов контекста, парсера по умолчанию и поведения окружения и версии. «Три
дня» теперь тоже считается как 72 часа. Модуль оценки теперь нормализует повторы вопроса
и исключает распознанные оговорки о незнании и утвердительные ответы на отрицательные
кейсы.

Таблица применяет эти пересмотренные эталоны к сохранённым рангам и ответам. Ни один
вызов поиска, эмбеддингов или модели не повторялся. Расширенные списки ожидаемых страниц
меняют hit@k, recall@k и MRR; сами результаты поиска не изменились. Исходные итоги
проверки ответов остаются рядом с пересмотренными итогами.

| `top_k` | Режим | Пересмотренный hit@k | Пересмотренный recall@k | Пересмотренный MRR | Исходные проверки фактов | Пересмотренные проверки фактов |
|---|---|---|---|---|---|---|
| 5 | `off` | 91.2% | 79.4% | 0.676 | 23/34 | 27/34 |
| 5 | `multi_query` | 91.2% | 80.9% | 0.667 | 25/34 | 27/34 |
| 5 | `hyde` | 97.1% | 85.3% | 0.772 | 25/34 | 29/34 |
| 10 | `off` | 97.1% | 89.7% | 0.682 | 28/34 | 29/34 |
| 10 | `multi_query` | 94.1% | 85.3% | 0.709 | 24/34 | 29/34 |
| 10 | `hyde` | 100.0% | 94.1% | 0.775 | 27/34 | 31/34 |

Оба вопроса про SAML находят и цитируют страницу про каталог и отвечают, что прямой SAML
не поддерживается, а мост — Keycloak, во всех шести конфигурациях. `10/hyde` доходит до
ожидаемой страницы по всем 34 вопросам, включая все десять кросс-языковых кейсов, и
проходит 31 из 34 проверок фактов. `10/off` доходит до ожидаемой страницы по 33 из 34
вопросов и проходит 29 из 34 проверок фактов без вызовов расширения.

Для агентов по документации на этом снимке выбирайте `default_top_k: 10` с
`query_analysis_mode: hyde`, когда в приоритете полнота охвата. Используйте `off`, чтобы
избежать дополнительных вызовов расширения. Оставляйте умолчания платформы
`default_top_k: 5` и `query_analysis_mode: off`: один корпус и одна модель не оправдывают
глобального роста контекста или затрат.

Неизменный [исходный запуск](https://github.com/vstorm-co/agenticos/blob/main/evals/retrieval/results/2026-11-10-openrouter-gpt6-luna.json)
хранит каждый ответ, найденную страницу, запрос, хеш корпуса и настройки окружения. Он
сделал 272 запроса к модели, израсходовав 872 567 входных и 41 553 выходных токена, плюс
эмбеддинги. [Первое пересчитывание](https://github.com/vstorm-co/agenticos/blob/main/evals/retrieval/results/2026-11-10-openrouter-gpt6-luna-rescored.json)
сохраняет исправления формулировок ответов; [второе
пересчитывание](https://github.com/vstorm-co/agenticos/blob/main/evals/retrieval/results/2026-11-10-openrouter-gpt6-luna-rescored-v2.json)
фиксирует пересмотренные списки страниц-ответов и модуль оценки, с хешами исходников,
набора и модуля оценки, оценками по категориям и новыми вердиктами по поиску и ответу для
каждого вопроса. Оба прохода пересчитывания сделали ноль запросов к провайдеру.

[Исправление про Redis](https://github.com/vstorm-co/agenticos/blob/main/evals/retrieval/results/2026-11-10-openrouter-gpt6-luna-rescored-v3.json)
тоже принимает «managed Redis instance» как альтернативу без кластера. Оно поднимает
`10/hyde` с 30 из 34 до 31 из 34 проверок фактов; все остальные вердикты по ответам и
метрики поиска не изменились. Это исправление фиксирует хеши исходников и предыдущего
результата, изменённую группу фактов и вердикт, а также сводку по каждой категории. Оно
делает ноль вызовов провайдера и сохраняет все три предыдущих файла.

Это измерения по одному запуску. Попадание называет ожидаемую страницу; выданный фрагмент
всё равно может не содержать отвечающего предложения. Три ответа `10/hyde` всё ещё не
проходят проверки фактов, а совпадение слов не гарантирует смысловой правильности.
Читайте ответы и повторяйте на своём корпусе, прежде чем широко принимать настройку.

Чтобы повторить настройки модели и поиска со своим авторизованным ключом:

```bash
OPENAI_BASE_URL=https://openrouter.ai/api/v1 make eval-retrieval EVAL_ARGS="\
    --embedding-base-url https://openrouter.ai/api/v1 \
    --embedding-model openai/text-embedding-3-small --embedding-dim 1536 \
    --llm-model openai-chat:openai/gpt-6-luna \
    --top-k 5 --top-k 10 --mode off --mode multi_query --mode hyde \
    --answers --json /tmp/retrieval.json"
```

## Что он не решает { #what-it-does-not-decide }

Стенд никогда не меняет настройки агента. Рекомендация выше относится к измеренному
корпусу документации; оцените свой корпус, прежде чем менять агента. Этот набор проверок
также не тестирует разрешения. Его коллекции не принадлежат ни одной организации, и поиск
по ним идёт без ограничения области, как это делает `rag-search`. Страницы [обработка
файлов](file-processing.md) и [возможность
знаний](reference/capabilities.md#query-analysis-and-expansion) описывают поиск с
ограничением области.
