# Обучение { #learn }

Разделы ниже — рекомендуемый порядок изучения AgenticOS. Читайте их как курс:
каждый предполагает предыдущие, и ни один не предполагает, что вы читали исходный
код.

## Начало работы { #get-started }

Вам нужен работающий стек и один агент, который вам отвечает. Около двадцати
минут.

<div class="grid cards" markdown>

- :material-download:{ .lg .middle } **[Установка](../install.md)**

    Docker Compose или сервисы вручную. Пять минут до стека, который можно
    открыть в браузере.

- :material-rocket-launch:{ .lg .middle } **[Ваш первый агент](../first-agent.md)**

    Ключ провайдера, агент, опубликованная версия, запуск, который чего-то стоил.

- :material-lightbulb:{ .lg .middle } **[Понятия](../concepts.md)**

    Спецификация, версия, способ доступа, триггер, запуск. Пять существительных.
    Всё остальное строится из них, поэтому эту страницу стоит перечитать, когда
    что-то удивляет.

</div>

!!! tip

    Читайте **Понятия**, даже если спешите. Большая часть путаницы с этой
    платформой — это одно из тех пяти существительных, принятое за другое:
    *спецификация* вместо *версии*, *способ доступа* вместо *триггера*.

!!! tip "Заблудились в консоли?"

    [Консоль](../console.md) — карта всех областей: для чего каждая и какая
    страница её объясняет.

## Создание агента { #build-the-agent }

Теперь сделайте его хорошим. Каждая страница здесь — это одна вещь, которую вы
даёте агенту, и они независимы: берите те, что нужны вашему агенту.

<div class="grid cards" markdown>

- :material-compass-outline:{ .lg .middle } **[Выбор модели](../choosing-models.md)**

    Какую модель выбрать этому агенту — открытые веса или закрытая, что формирует
    счёт и как потом передумать.

- :material-brain:{ .lg .middle } **[Модели и провайдеры](../models.md)**

    28 провайдеров, профили моделей, резервные модели и сколько на самом деле
    стоит токен.

- :material-school:{ .lg .middle } **[Навыки](../skills.md)**

    Записанные практические знания, которые агент загружает, только когда сочтёт
    их уместными.

- :material-text-box-outline:{ .lg .middle } **[Файлы контекста](../context.md)**

    Постоянные знания, написанные один раз и привязанные к многим агентам:
    глоссарий, руководство по тону, матрица эскалации.

- :material-file-document-multiple:{ .lg .middle } **[Знания](../file-processing.md)**

    Загрузка, разбор, разбиение на фрагменты, эмбеддинги. Коллекции и
    синхронизация папки Drive или бакета в коллекцию.

- :material-connection:{ .lg .middle } **[Подключения MCP](../mcp.md)**

    Любой MCP-сервер по URL и 59 в списке выбора с уже настроенным OAuth.

- :material-console:{ .lg .middle } **[Песочница](../sandbox.md)**

    Файлы и оболочка, изолированные, со своим сроком жизни.

- :material-clock-outline:{ .lg .middle } **[Триггеры](../triggers.md)**

    Запуск по расписанию или по событию, когда никто ничего не печатает.

</div>

## Доступ для людей { #put-it-in-front-of-people }

Агент, до которого никто не может дотянуться, — черновик. Вот как он покидает
консоль.

<div class="grid cards" markdown>

- :material-source-branch:{ .lg .middle } **[Окружения](../environments.md)**

    `staging` и `production` как имена, закреплённые за версиями, поэтому
    публикация и выпуск — два разных решения.

- :material-forum:{ .lg .middle } **[Способы доступа](../channels.md)**

    Веб-чат, размещённая страница, виджет для встраивания, HTTP API, Slack,
    Telegram и Mattermost — за всеми ими один механизм выполнения.

- :material-server:{ .lg .middle } **[Сам экземпляр](../deployment.md)**

    Его идентичность, политика регистрации, его правовые уведомления. То, что
    относится к установке, а не к агенту.

- :material-cloud-upload:{ .lg .middle } **[Развёртывание](../deploy.md)**

    Как поместить платформу на хост.

- :material-account-group:{ .lg .middle } **[Внедрение](../rollout.md)**

    Кто что делает, реалистичные первые девяносто дней, сколько это стоит и какие
    вопросы задаст ваша проверка безопасности.

</div>

## Контроль { #keep-it-under-control }

Та часть, которую большинство фреймворков для агентов оставляют вам. Прочитайте
её, прежде чем дать агенту инструмент, который тратит деньги или что-то записывает.

<div class="grid cards" markdown>

- :material-account-key:{ .lg .middle } **[Разрешения](../permissions.md)**

    Три слоя: что позволяет роль, что расширяет выданный доступ и что позволяет
    инструменту его область действия.

- :material-shield-check:{ .lg .middle } **[Управление](../governance.md)**

    Бюджеты, проверяемые до запроса, согласования, решаемые один раз, оповещения и
    журнал аудита, в котором остаётся значение, а не строка.

- :material-lock:{ .lg .middle } **[Секреты и хранилище секретов](../secrets.md)**

    Один механизм для всех учётных данных в состоянии покоя — и намеренно никакого
    второго.

</div>
