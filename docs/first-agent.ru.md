# Ваш первый агент { #your-first-agent }

Здесь весь путь проходится один раз: ключ провайдера, модель, агент, который
отвечает, опубликованная версия и запуск, у которого есть стоимость.

Пятнадцать минут и примерно цент токенов.

Сначала нужен запущенный стек — см. [Установка](install.md).

!!! tip "Продукт проведёт вас по этому пути тоже"

    При первом входе любого человека на странице «Обзор» открывается экскурсия, и
    в конце она предлагает собрать первого агента *вместе* с вами, работая с
    настоящими диалогами.

    Ручной путь всё равно стоит прочитать один раз — это и есть эта страница.
    Экскурсия описана [в конце](#the-guided-walkthrough).

## 1. Сохраните ключ провайдера { #1-store-a-provider-key }

**Настройки → Секреты → Добавить ключ** (Settings → Vault → Add credential).

Выберите провайдера, вставьте ключ, дайте ему метку. Значение запечатывается
сразу, и нет эндпоинта, который его вернёт, — обратно приходят метка и последние
четыре символа.

!!! info "Почему хранилище секретов, а не файл конфигурации"

    Ключ в окружении принадлежит экземпляру. Ключ в хранилище секретов
    принадлежит **организации**, и именно это позволяет одному экземпляру
    обслуживать несколько организаций, не давая ни одной из них тратить бюджет
    другой.

    Шифротекст привязан к организации, которая его сохранила, и для другой не
    расшифровывается.

## 2. Добавьте модель { #2-add-a-model }

**Агенты → любой агент → Конструктор → Модель** (Agents → any agent →
Build → Model).

Выберите провайдера, затем модель, затем то, какой сохранённый ключ за неё
платит.

Список моделей берётся у провайдера там, где он его публикует, и из встроенного
короткого списка там, где нет. Это подсказка, а не ограничение: провайдер
выпускает модель утром после того, как любой каталог был прогрет, поэтому
принимается всё, что вы введёте.

То, что вы только что создали, — это **профиль модели**: названная модель, за
которой стоит названный ключ.

Смысл именно в названии. Оно позволяет сменить ключ или перенаправить всех
агентов на новую модель, не трогая ни одного агента.

## 3. Соберите агента { #3-build-the-agent }

**Агенты → Новый агент** (Agents → New agent).

!!! tip "Или начните с шаблона"

    **Агенты → Шаблоны агентов** (Agents → Agent templates) — здесь двадцать
    девять готовых агентов: двадцать восемь сгруппированы по отраслям, а
    **AgenticOS** — в разделе *Общее назначение*: агент для любой задачи,
    который работает в рабочем пространстве, планирует, поручает специалистам и
    исследует интернет. Каждый приходит с написанными инструкциями, включёнными
    возможностями и установленными рядом навыками, которые ему нужны.

    Один приходит **черновиком**, а не опубликованным, и намеренно: шаблон не
    может выбрать вашу модель и никогда не видел вашу коллекцию знаний.
    Остальное на этой странице — то, что вы делаете дальше в любом случае.

Введённое имя становится именем для упоминаний, по которому к агенту обращаются
из Slack и API, и оно фиксируется при создании: `Support Copilot` становится
`@support-copilot`.

Вкладка **Конструктор** (Build) — это инструкции и модель, и инструкции — это всё
поведение агента:

```markdown
You are Support Copilot.

Answer from the product wiki and cite the document you used.
If the wiki does not cover it, say so rather than guessing.
Never quote a price - route those to sales.
```

Пишите их в Markdown. Модель читает структуру, а заголовки и списки — то, что
позволяет ей следовать длинному промпту.

!!! note "Кнопки сохранения нет"

    Черновик сохраняется по мере ввода. Конструктор с кнопкой сохранения — это
    Конструктор, где вкладку закрыли на двадцати минутах инструкций.

## 4. Дайте ему возможности { #4-give-it-capabilities }

**Инструменты** (Toolbox).

Каждая возможность показывает ровно то, что она добавляет, — каждый инструмент,
его описание и аргументы, которые модель должна заполнить, — *до* того, как вы её
включите. Прочитать возможность — не значит её выдать.

Здесь стоит знать две вещи:

- **Имя и описание инструмента — это промпт.** К `search_refund_policy`
  обращаются в вопросах, в которых `search_documents` пропускают. И то и другое
  редактируется для каждого агента.
- Ничего не просит согласования, пока вы не скажете. Включите **Всегда
  спрашивать** (Always ask) для возможности или для одного инструмента, который
  человек должен увидеть до его запуска.

## 5. Дайте ему что почитать { #5-give-it-something-to-read }

**Знания → Коллекции** (Knowledge → Collections) — для документов. **Навыки**
(Skills) — для записанных знаний.

Разница важна:

| | |
|---|---|
| **Коллекцию** *ищут* | Модель сама выбирает, что искать, и никогда не может расширить то, где ищет |
| **Навык** *читают* | Агент загружает его, только когда решит, что навык уместен, поэтому двадцать навыков почти ничего не стоят в контексте |

У каждой коллекции сказано, сколько в ней документов, потому что привязка пустой
даёт агента, который ищет, ничего не находит и говорит об этом, — а это читается
как сломанный агент, а не как пустая коллекция.

## 6. Задайте лимит и скажите, кого уведомлять { #6-set-a-limit-and-say-who-is-told }

**Лимиты** (Limits). Месячный лимит в долларах, лимит шагов и кто об этом узнаёт.

Лимит шагов — тот, о котором забывают. Он ловит другой вид неконтролируемого
расхода: цикл инструментов, дешёвый за вызов и никогда не заканчивающийся.
Бюджет только выставляет счёт за это; лимит шагов его останавливает.

В разделе **Оповещения** (Alerts) решите, кого уведомлять, когда этот агент
останавливается на своём пределе или встаёт на согласование. По умолчанию о
бюджете узнают администраторы и владелец агента, а о согласованиях — тот, кто
начал этот запуск, и администраторы, поэтому запуск, начатый расписанием, не
встаёт без присмотра.

О том, как сочетаются бюджеты, согласования и оповещения, — в разделе
[Управление](governance.md).

## 7. Опубликуйте { #7-publish }

**Опубликовать** (Publish) сначала проверяет черновик, поэтому здесь же вы
узнаёте, что спецификация ссылается на коллекцию, которую кто-то удалил.

!!! success "Спецификация, ссылающаяся на отсутствующее, отклоняется здесь, а не во время выполнения"

    В этом и весь смысл проверки при публикации: кто-то смотрит на форму и может
    это исправить, вместо того чтобы узнать три недели спустя в запуске, который
    начался по расписанию.

Публикация фиксирует **версию**. Запуски записывают, какая версия выполнялась,
поэтому что агент делал в прошлый вторник, остаётся выяснимым и после десятка
правок.

## 8. Запустите его { #8-run-it }

**Проверка** (Test) в заголовке открывает чат с опубликованным агентом. Спросите
его о чём-нибудь.

Затем посмотрите на **Активность** (Activity): запуск, версию, которую он
выполнил, модель, которая была выбрана, токены и сколько это стоило. Если
инструменту нужно было согласование, оно в очереди там.

## 9. Разместите его где-нибудь { #9-put-it-somewhere }

**Доступность** (Availability) — там, где агент перестаёт быть вещью в
Конструкторе:

| | |
|---|---|
| **Способы доступа** (Exposures) | Кто может его запускать и как — API-ключи, публичные ссылки |
| **Боты каналов** (Channel bots) | Slack и Telegram. `@support-copilot` в канале работает как *отправитель*, никогда как бот |
| **Встраивание** (Embeds) | Виджет для ваших собственных страниц |
| **Окружения** (Environments) | Именованные указатели на версии, чтобы staging и production могли различаться |

## Экспортируйте его { #export-it }

**Скачать** (Download) даёт вам спецификацию в виде YAML.

Она содержит ссылки — профиль модели, коллекцию, секрет — и никогда значения, и
именно поэтому её можно безопасно закоммитить в свой репозиторий и проверять как
код.

```yaml
name: Support Copilot
instructions: |
  You are Support Copilot.
  Answer from the product wiki and cite the document you used.
model_profile_id: 8f1c...
capabilities:
  - id: knowledge
    config: { default_top_k: 8 }
collection_ids: [b2a9...]
budget:
  monthly_usd: 50
```

## Итог { #recap }

Девять шагов, и их форма — это форма платформы:

1. Запечатали **ключ** в хранилище секретов, для каждой организации.
2. Назвали **профиль модели**, чтобы ключ и модель могли меняться, не меняя
   агента.
3. Написали **инструкции**.
4. Включили **возможности** и выбрали, какие из них запрашивают согласование.
5. Привязали **знания** для поиска и **навыки** для чтения.
6. Задали **бюджет** и **лимит шагов** и сказали, кого уведомлять.
7. **Опубликовали** — это зафиксировало версию и проверило спецификацию.
8. **Запустили** его и увидели, сколько это стоило.
9. Сделали его **доступным** откуда-то ещё, кроме Конструктора.

Всё, что дальше, — это ещё шаги 4, 5 и 9.

## Экскурсия по продукту { #the-guided-walkthrough }

Продукт учит сам себя, и стоит знать как: экскурсия — это ещё и то, как научится
любой, кому вы его передадите.

**Она показывается один раз, а «?» позволяет её повторить.** Завершение, пропуск
или закрытие запоминается для учётной записи, а не для браузера, поэтому на
следующем устройстве она не вернётся. **«?»** в заголовке любой страницы с
экскурсией повторяет подсказки этой страницы в любой момент.

Она предлагается только там, где есть что повторять. В разделе без остановок — на
страницах администратора экземпляра — **«?» нет вообще**, вместо кнопки, которая
открывает пустую экскурсию. При выходе из экскурсии так и говорится, чтобы никто
не натыкался на **«?»** случайно или не находил его вовсе.

**В конце она предлагает собрать первого агента вместе.** Это интерактивный
сценарий, а не подсветка: он указывает на настоящие элементы управления, вы
работаете с настоящими диалогами, и он идёт дальше в тот момент, когда вещь
действительно создана.

Пока она идёт, страница **заморожена**: всё приглушено, кроме одного элемента
управления, о котором говорит шаг, поэтому нельзя уйти с середины сценария и
оставить шаг экскурсии не на той странице. Заморозка сама отступает, когда
открывается диалог или список выбора, так что элемент, на который указывает шаг,
всегда доступен.

Она адаптивна. Она проходит путь выше, проверяет, что уже есть в организации, и
останавливается только там, где чего-то не хватает: объясняет рабочему пространству
без модели, как её добавить, или говорит тому, кто собирает агента, но не имеет
разрешения на добавление, об этом — вместо того чтобы молча довести его до
публикации, которая отклонит агента без модели.

**Знания, навыки и MCP — то, где она делает больше всего.** Если что-то уже есть,
сценарий просто указывает, куда это подключается. Если ничего нет, он сначала
переходит на собственный экран этого раздела и *спрашивает там* — «базы знаний
пока нет, создать?» — чтобы вопрос прозвучал там, где происходит ответ.

Ответ «да» ведёт создание на месте, и не просто до кнопки: экскурсия заходит
вместе с вами в сам диалог, по очереди обводя каждое поле и объясняя, что в него
вписать, — имя навыка, по которому его вызывает модель, описание, решающее, когда
его читать, переключение на **Источник** (Source), где записаны сами знания, — и
идёт дальше, когда вещь действительно создана.

Потом она ведёт вас обратно, *указывая*: на **Агенты** (Agents) в боковой панели,
на карандаш редактирования у того самого агента, которого вы только что собрали,
на вкладку **Знания** (Knowledge), где подключается новая база. Обратный путь
ждёт вашего щелчка, а не переходит за вас, поэтому он учит дороге через приложение,
а не проходит её вместо вас. Пропуск сам возвращает в Конструктор.

С MCP развилка та же, но она остаётся в Конструкторе. Сервер подключается встроенным
диалогом прямо в «Инструментах», поэтому «да» указывает на эту кнопку, а сценарий
подхватывает с того момента, как подключение установлено, — без похода на другую
страницу и обратно.

**Она не заканчивается публикацией.** После публикации сценарий переносит вас в
чат, просит выбрать только что собранного агента и закрывается только после того,
как вы отправите ему первое сообщение. Первый агент, которого никто не запускал,
— это экскурсия, остановившаяся в шаге от смысла.

**У каждого другого раздела она своя.** Отказ никого не ведёт, и предложение
возвращается в конце экскурсии по **«?»** в разделе «Агенты». «?»
любого другого раздела заканчивается так же — предложением создать ресурс этого
раздела: навык, базу знаний, подключение MCP, организацию, автоматизацию.

Две из них устроены иначе намеренно:

- **Автоматизации** (Routines) заканчиваются *за* созданием. Расписание, которое
  просто ждёт часов, ничему не учит, поэтому последняя остановка экскурсии —
  **Запустить сейчас** (Run now) в только что созданной строке, и первое
  срабатывание попадает в журнал запусков у вас на глазах.
- **Чат** (Chat) предлагает экскурсию по самому интерфейсу чата: как начать
  диалог, переключить отвечающего агента, изменить модель или глубину
  рассуждений для одного чата. Чат может говорить только с *опубликованным*
  агентом, поэтому без него экскурсия начинается с предложения сначала собрать
  агента и сразу передаёт управление сценарию агента. Дальше она ничего не
  создаёт, поэтому идёт вперёд по кнопке **Далее** (Next).

!!! tip "Повторите «?» на странице «Обзор» один раз"

    Её остановка настройки объясняет весь редактор: добавление карточек из
    каталога (одну и ту же карточку можно добавить несколько раз, если она нужна
    по каждому агенту), перетаскивание между секциями, изменение размера,
    скрытие, переименование и раскрашивание самих секций, именованные раскладки
    и сброс.

    Каждое расположение личное, поэтому эксперименты не сдвигают страницу ни у
    кого другого.

## Что вы уже умеете { #what-you-can-already-do }

Четыре вещи, которые люди ищут и не находят сами:

- **Разместить его на сайте, на размещённой странице, в WebSocket или в публичном
  API** — вкладка **Доступность** (Availability) агента. Конструктор указывает
  туда после первой публикации.
- **Подключить инструмент со своей учётной записью** — у каждого свой GitHub,
  Gmail или Notion — с карточки сервера в разделе **MCP-серверы** (MCP servers).
  См. [MCP](mcp.md#personal-or-organization-wide).
- **Найти файлы, которые сохранил агент** — что прикрепляли люди и что писали
  агенты, лежит в разделе **Документы** (Documents).
- **Поделиться им как документом** — **Поделиться** (Share) в заголовке
  Конструктора добавляет человека или группу и задаёт, кто ещё его найдёт. См.
  [Разрешения](permissions.md).

**Архитектор** (Architect) в углу каждой страницы отвечает на те же вопросы и даёт
ссылку на нужный элемент управления.
