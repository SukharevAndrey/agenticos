# Спецификация агента { #the-agent-spec }

Важнейший тип платформы: Конструктор его редактирует, база данных версионирует, фабрика
создаёт по нему объект, а клиенты экспортируют его в свои репозитории git как YAML.

Сгенерировано из исходников, потому что обоснование живёт в docstring-строках.

::: app.agents.spec.AgentSpec

## Переменные { #variables }

`{{name}}` в `instructions` подставляется при старте каждого запуска: системная
переменная, которую знает платформа (дата и время, кто вошёл в систему и его
[группы](../departments.md), организация, агент, канал), или одна из собственных
`variables` агента. `time_zone` решает, по каким часам читается `{{current_time}}`.
Публикация отклоняет имя, которое не является ни тем, ни другим.

::: app.agents.spec.PromptVariableSpec

## Поручение { #delegation }

Две формы, и [Понятия](../concepts.md#delegate-vs-inline-specialist) объясняют, какую
выбрать. `subagents` хранит первую; вторая живёт в собственной конфигурации
[возможности `subagents`](capabilities.md#delegation).

::: app.agents.spec.SubagentRef

которых [поручение](capabilities.md#remote-agents) вызывает наравне с этими.

## Речь в текст { #speech-to-text }

Провайдер, модель, ключ и язык, которыми расшифровываются диктовка агента и
унаследованные голосовые заметки каналов, если они отличаются от настроек организации.
Ключ — это id секрета из хранилища секретов, а не сам ключ. Порядок, в котором они
определяются, — в разделе
[ML-сервисы](../ml-services.md#which-engine-a-recording-reaches). Спецификацию с этим
блоком нельзя импортировать в экземпляр старше блока: спецификация того экземпляра
отклоняет поля, которых не знает.

::: app.agents.spec.SpeechToTextSpec

## Голос { #voice }

Как агент ведёт [голосовой разговор](../voice.md): модель в реальном времени, ключ из
хранилища секретов, голос и собственные ограничения звонка. Блок необязательный, и
полностью пустой блок читается как отсутствие блока, поэтому спецификации, написанные
до него, загружаются без изменений и `SPEC_VERSION` не сдвинулся. Как и блок «Речь в
текст», спецификацию с ним нельзя импортировать в экземпляр старше блока.

| Поле | Что содержит |
|---|---|
| `provider` | Провайдер из каталога реального времени: `openai`, `azure`, `google` или `xai` |
| `model` | Модель реального времени этого провайдера. Для Azure оставьте пустым и используйте два поля ниже |
| `deployment` | Только Azure: имя развёртывания, на которое идут звонки |
| `base_model` | Только Azure: модель каталога, которую запускает это развёртывание; она определяет его голоса и его цену |
| `secret_id` | Ключ из хранилища секретов, которым держат звонки, — id, а не сам ключ |
| `voice` | Один из голосов модели; пусто — голос модели по умолчанию |
| `language` | Код ISO-639-1, на котором говорит агент; пусто — следует за звонящим |
| `max_call_seconds` | Самый долгий звонок, от 60 до 3000; пусто — 600 (10 минут) |
| `voice_note` | До 1000 символов, добавленных к инструкциям агента только в звонках |

Каждое правило, охватывающее несколько полей, проверяется при публикации версии, а не
при сохранении черновика, потому что Конструктор автоматически сохраняет между выбором
провайдера и выбором его модели. Публикация отклоняется с указанием раздела голоса,
когда:

- провайдер не указан или в каталоге этого экземпляра нет такого провайдера;
- модель не указана или не является моделью реального времени, которую каталог
  предлагает для этого провайдера (для Azure — базовая модель), либо раздел Azure не
  называет развёртывания;
- голос не один из голосов модели;
- ключ не выбран или не проходит общую проверку: его назначение — не этот провайдер,
  его тип — не тип провайдера (`api_key`, а для Azure — `azure_openai`), он принадлежит
  другой организации либо публикующий его не видит;
- язык не является кодом, который принимают звонки.

Возможности, которые звонок запустить не может, не блокируют публикацию; их просто нет
в звонках, и Конструктор их перечисляет.

::: app.agents.spec.VoiceSpec

## Системные агенты { #system-agents }

К [системному агенту](../concepts.md#system-agent-spec) — судье, генератору кейсов,
составителю или классификатору пробелов, помощнику по редактированию — требования выше.
Сохранение его черновика отклоняет то, что он не может использовать никогда; публикация
вдобавок отклоняет пустые инструкции и `max_tokens` ниже минимума для его типа. Он
работает только с тем, что допускает его версия, и ищет в тех базах знаний, к
которым относится его запуск.

::: app.agents.system_agents.unusable_parts

::: app.agents.system_agents.incomplete_parts

::: app.agents.system_agents.for_the_platform
