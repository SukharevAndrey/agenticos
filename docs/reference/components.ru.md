# Перечень компонентов { #the-component-inventory }

Из чего состоит экземпляр AgenticOS: части, которые пишет этот проект, сторонние
пакеты, от которых эти части зависят, образы, в которых они работают, ресурсы,
которые они поставляют, и модели с сервисами, которые оператор подключает потом. Это
читаемая половина SBOM выпуска и ответ на вопрос «что в нём есть», когда вопрос
приходит из проверки безопасности, а не из системы сборки.

!!! abstract "Что охватывает эта страница и где она останавливается"

    Всё до раздела *Комплектные ресурсы* ниже поставляется этим проектом и
    перечислено точно — по файлам блокировки и Dockerfile. Всё после него — модели,
    провайдеры, MCP-серверы, базы данных, на которые оператор направляет экземпляр, —
    выбирается для каждого экземпляра, здесь не поставляется и может быть перечислено
    только тем экземпляром, который это выбрал. Последний раздел — о том, как записать
    эту половину; эта страница не может написать её за вас.

Машиночитаемый перечень приложен к каждому выпуску в виде шести документов
[CycloneDX](https://cyclonedx.org/) — по одному на образ **на каждую архитектуру**,
потому что опубликованный тег — это список манифестов, а два варианта содержат разные
пакеты. Доказательства лицензий для каждого компонента — в
[`THIRD_PARTY_NOTICES.md`](https://github.com/vstorm-co/agenticos/blob/main/THIRD_PARTY_NOTICES.md),
а разбор того, к чему обязывают эти лицензии, — в разделе
[Лицензии и уведомления о сторонних компонентах](../licenses.md).

## Выпуск, который описывает этот перечень { #the-release-this-inventory-describes }

Перечень без версии не описывает ничего. У каждого выпуска своя: документы SBOM в
релизе GitHub для тега `vX.Y.Z`, созданные по образам, опубликованным под этим тегом,
и эта страница в том виде, в каком она была в дереве этого тега. Читая перечень для
версии, которую экземпляр запускает, берите и то и другое из одного тега, а не из
`main`.

| Артефакт | Где он | Что задаёт его версию |
|---|---|---|
| `sbom-api-amd64.cdx.json`, `sbom-api-arm64.cdx.json` | ресурсы релиза на GitHub | тег `v*`, к которому они приложены |
| `sbom-frontend-amd64.cdx.json`, `sbom-frontend-arm64.cdx.json` | ресурсы релиза на GitHub | тот же |
| `sbom-browser-amd64.cdx.json`, `sbom-browser-arm64.cdx.json` | ресурсы релиза на GitHub | тот же |
| `ghcr.io/vstorm-co/agenticos-backend` | GHCR | `<version>`, `latest`, `edge`, `sha-<short>` |
| `ghcr.io/vstorm-co/agenticos-frontend` | GHCR | те же |
| `ghcr.io/vstorm-co/agenticos-browser` | GHCR | те же |
| `THIRD_PARTY_NOTICES.md` | репозиторий, на этом теге | файлы блокировки на этом коммите |

## Компоненты, которые пишет этот проект { #components-this-project-writes }

Собственная разработка под Apache-2.0 в этом репозитории. Здесь нет сторонних
компонентов, и ни один из них не попадает в уведомления о сторонних компонентах.

| Компонент | Где | Что это | Входит в |
|---|---|---|---|
| API и платформа | `backend/app` | Приложение FastAPI: маршруты, сервисы, репозитории, механизм выполнения агентов, реестр возможностей | `agenticos-backend` |
| Фоновый воркер | `backend/app/worker` | Забирает задачи из очереди PostgreSQL — запуски агентов, индексацию, синхронизации, обходы — и запускает расписания экземпляра (`python -m app.worker`) | `agenticos-backend` |
| Миграции | `backend/alembic` | Цепочка схемы, применяется сервисом миграций до запуска API | `agenticos-backend` |
| Командная строка | `backend/app/commands` | `agenticos cmd …` — начальная настройка, doctor, команды RAG | `agenticos-backend` |
| Консоль | `frontend/src` | Приложение Next.js, с которым встречаются оператор и пользователь | `agenticos-frontend` |
| Оболочка для компьютера | `desktop/` | Окно Tauri вокруг консоли экземпляра, собирается под каждую платформу | не образ; см. [приложение для компьютера](../desktop.md) |
| Сайт документации | `docs/`, `mkdocs.yml` | Этот сайт | не входит ни в один образ |

## Сторонние зависимости { #third-party-dependencies }

Разрешены по файлам блокировки, а не по тому, что оказалось установленным на машине.
Счётчики меняются с каждым изменением зависимостей, поэтому доверять стоит цифре в
файле уведомлений того выпуска, который вы читаете.

| Набор | Файл блокировки | Для чего разрешён | В уведомлениях |
|---|---|---|---|
| Python-дистрибутивы бэкенда | `backend/uv.lock` | Linux, обе архитектуры, `--no-dev` | Да |
| npm-пакеты фронтенда | `frontend/bun.lock` | полный набор производственных зависимостей `frontend/package.json` | Да |
| Инструменты разработки и документации бэкенда | `backend/uv.lock`, группы `dev` и `docs` | машина участника | Нет: их нет ни в одном образе |
| `devDependencies` фронтенда | `frontend/bun.lock` | машина участника | Нет: их нет в образе |
| Rust-крейты для компьютера | `desktop/src-tauri/Cargo.lock` | платформа, под которую собирается оболочка | Нет: их нет ни в одном образе |

Два аудита читают эти файлы блокировки на каждом пул-реквесте. `make audit` разрешает
`backend/uv.lock` и сверяет его с базой уязвимостей; `make audit-frontend` запускает
`bun audit --audit-level=high` по `frontend/bun.lock`. Оба входят в задание
`Security Scan` и в `make check`.

## Образы среды выполнения { #runtime-images }

| Образ | База | Содержит | Собирается из |
|---|---|---|---|
| `agenticos-backend` | образ Python на базе Debian | API, воркер, миграции, CLI, полный набор зависимостей бэкенда, тексты лицензий | `backend/Dockerfile` |
| `agenticos-frontend` | образ Node на базе Debian | автономную сборку консоли, её полный набор производственных зависимостей, шрифты, уведомления по пакетам | `frontend/Dockerfile` |
| `agenticos-browser` | `debian:bookworm-slim` | Chromium с окном под Xvfb, шрифты для рабочего стола и `socat` для доступа к его DevTools — то, что запускает профиль compose `browser` для возможности «Веб-браузер» | `docker/browser/Dockerfile` |

Все три собираются для `amd64` и `arm64`, публикуются в GHCR и после публикации
сканируются Trivy. Пакеты Debian, которые устанавливает каждый образ, записаны в
`licenses/components.toml` вместе с их положением в лицензиях и попадают в документы
CycloneDX, потому что генератор читает опубликованный образ, а не дерево исходников.

Сервисы, которые экземпляр запускает рядом с этими тремя, — PostgreSQL с pgvector,
Redis, обратный прокси, прокси исходящего трафика Squid для браузера, — оператор
забирает у их собственных издателей. Они названы в файлах compose, здесь не собираются
и в SBOM этого проекта не входят.

## Модели, провайдеры и сервисы: половина экземпляра { #models-providers-and-services-the-deployments-half }

Ничто из перечисленного ниже не входит в выпуск, и ни один созданный здесь SBOM не
может это перечислить. Каждый из них — компонент работающей системы и должен быть в
собственном перечне экземпляра.

- **Провайдеры моделей.** Тот из Anthropic, OpenAI, Google, Groq, xAI, Cohere,
  OpenAI-совместимого эндпоинта или локальной среды выполнения, который настроил
  экземпляр, с идентификаторами моделей, которые он закрепил. См.
  [модели](../models.md).
- **Веса моделей.** Локальная среда выполнения скачивает их; их лицензии — на
  рассмотрение оператора, и [обзор лицензий](../licenses.md) объясняет почему.
- **MCP-серверы.** Сторонние процессы или размещённые эндпоинты, подключённые для
  каждой организации. Каталог называет кандидатов; компонент — конкретная установка.
- **Источники знаний и коннекторы.** Google Drive, S3 и остальные, каждый — сторонний
  сервис, до которого доходят с учётными данными из хранилища секретов.
- **Каналы.** Рабочие пространства Slack, Telegram и Mattermost, в которых
  зарегистрирован экземпляр.
- **Хранилища данных и инфраструктура.** PostgreSQL, Redis, объектное хранилище,
  обратный прокси, хост и любой эндпоинт наблюдаемости, который получает
  трассировки.

!!! warning "SBOM образа — не перечень системы"

    Документы CycloneDX описывают три образа. Экземпляр, который подключает
    размещённую модель, три MCP-сервера и объектное хранилище, работает с компонентами,
    которых не увидит ни одно сканирование этих образов. Считать SBOM выпуска всем
    перечнем — и есть тот пробел, который назван в этом разделе.

## Как перечень создаётся и поддерживается { #how-the-inventory-is-produced-and-kept-current }

| Артефакт | Чем создаётся | Когда |
|---|---|---|
| Шесть SBOM выпуска | заданием `sbom` в `.github/workflows/images.yml`, по одному на образ на архитектуру, из опубликованных манифестов | при каждой публикации; прикладываются к релизу по тегу `v*`, иначе хранятся как артефакт запуска |
| `THIRD_PARTY_NOTICES.md` | `make licenses` | при каждом изменении файла блокировки; `make licenses-check` останавливает сборку, когда он устарел |
| Эта страница | вручную | при каждом добавлении, удалении или переносе компонента между наборами выше |

`make sbom` пишет другое, и имена это показывают: `sbom-source-api.cdx.json` и
`sbom-source-frontend.cdx.json` — перечни того, что **объявляет дерево исходников**, а
не того, что содержит образ. Они несут группы зависимостей разработки и документации,
если те установлены, и ни одного из слоёв под ними — ни базового образа, ни пакетов
Debian, ни собранных артефактов. Полезны, чтобы прочитать набор зависимостей, не
вытягивая два образа; бесполезны как доказательство того, что поставляет выпуск, — а
для этого и нужны шесть документов выше. Для запуска нужен установленный
[syft](https://github.com/anchore/syft), и он намеренно не входит в `make check`.

Чтобы расширить перечень для экземпляра, возьмите SBOM выпуска той версии, которую
запускаете, добавьте компоненты из раздела выше с версией и провайдером каждого и
держите его рядом с собственной конфигурацией экземпляра.
[Проверка безопасности](../rollout.md) — место, где проверяющий заказчика её
запрашивает, а [защита данных](../data-protection.md) — где записано, каких данных
касается каждый из этих компонентов.
