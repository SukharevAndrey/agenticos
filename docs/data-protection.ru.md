# Защита данных { #data-protection }

Где в экземпляре живут персональные данные, что из него уходит и при какой
конфигурации, какие средства контроля существуют в коде и подкреплены тестом, а
какие остаются открытыми вопросами. Написано для того, кто отвечает на проверку
защиты данных в одном экземпляре, — для DPO, специалиста по безопасности или
оператора, — и честно показывает разницу между тем, что умеет программа, и тем,
что экземпляр действительно решил.

!!! warning "Страница не доказывает соответствие требованиям"

    Ничто здесь не доказывает, что экземпляр соответствует GDPR. Кодовую базу
    можно развернуть в среде, соответствующей требованиям; соответствует ли
    конкретная среда *сама*, зависит от настроенных провайдеров, выбранных сроков
    хранения, подписанных соглашений и оператора, который её запускает. Каждое
    такое условие ниже названо тем, что нужно получить и проверить, а не
    предполагать.

Перечень возможностей также включает выбираемое для отдельного диалога
переопределение агента для работы с кодом на компьютере, даже когда в
опубликованной спецификации нет привязки агента для работы с кодом или
используется песочница. Эта строка описывает возможный маршрут, а не
доказательство того, что он использовался.

Выгрузки персональных данных включают имена файлов и патчи задач работы с кодом
из диалогов в выгрузке; их полезная нагрузка JSON учитывается в лимите размера,
проверяемом перед выгрузкой. Прекращение членства в организации удаляет
подключения этого человека к работе с кодом в той же транзакции. Повторное
присоединение требует нового подключения и нового согласия; оно не может
возродить прежний выданный доступ.

Выгрузки персональных данных также включают личные доски задач, значения их
записей, сохранённую историю изменений и схемы столбцов, а также заранее данные
согласия на действия автоматизаций. Эти полезные нагрузки JSON учитываются в
лимите размера, проверяемом перед выгрузкой. Общие таблицы задач проектов, групп
и организации не включаются только потому, что человек создал в них задачу.

## Что уходит по умолчанию { #nothing-leaves-by-default }

Новый экземпляр хранит всё в собственном PostgreSQL и на собственном диске или в
объектном хранилище, с которым настроен. Он никуда не отправляет промпты, диалоги
и документы. Каждый внешний переход — это строка или настройка, которую кто-то
добавляет позже: профиль модели, называющий провайдера, коллекция, выбирающая
парсер или удалённого провайдера эмбеддингов (который затем получает фрагменты
документов), метод поиска в спецификации, токен Logfire, MCP-сервер, бот канала.
Уберите строку — и перехода нет.

Один отчёт включён по умолчанию и не несёт содержимого:
[диагностика экземпляра](#deployment-diagnostics) отправляет коллектору состояние
установки, грубые счётчики использования, счётчики неудачных запусков, задач
и индексаций по закрытым категориям и псевдонимный сигнал активности. Экземпляр,
который хочет **никаких исходящих обращений вообще**, задаёт
`DIAGNOSTICS_ENABLED=false`.

Поэтому экземпляр, которому **не нужны никакие третьи стороны в цепочке**,
настраивает себя так, и программа это поддерживает:

| Аспект | Локальный ответ |
| --- | --- |
| Модель чата | Профиль `ollama` или `litellm` — без ключа, указывает на эндпоинт, который размещаете вы. Любой из 28 провайдеров с `base_url` тоже принимает ваш шлюз |
| Разбор документов | `pymupdf` по умолчанию работает в воркере. OCR LiteParse тоже работает в воркере или на OCR-сервере, который вы регистрируете как локальный сервис. LlamaParse — выбор для отдельной коллекции, которому нужен ключ в хранилище секретов; без него ничего не разбирается у внешнего поставщика |
| Эмбеддинги | Ollama, который размещаете вы, зарегистрированный как локальный сервис в разделе **Знания → Интеграции** (Knowledge → Integrations) и выбранный для каждой коллекции как провайдер `ollama`. Без ключа и единственный провайдер, которого может использовать коллекция уровня экземпляра |
| Трассировки | Оставьте `LOGFIRE_TOKEN` незаданным и не привязывайте токен `observability` к спецификации или окружению. Запуски всё равно записывают идентификатор трассировки локально |
| Поиск, браузер, память, инструменты | Не привязывайте секрет `search`, возможность `web_fetch` или `browser_use`, подключение MCP. Веб-браузер может остаться, если каждый сайт, который он может открыть, входит в `allowed_domains`, а его шаги идут в модель, которую размещаете вы |
| Почта | Ваш собственный SMTP-релей |
| Речь, изображения и видео | Для речи в текст — никакого провайдера: держите диктовку на `off` или `browser`, а ботов каналов выключенными, поскольку самостоятельно размещаемый сервер распознавания речи пока нельзя указать (запланировано на будущее). Для синтеза речи и видео — никакой возможности `text_to_speech` или `video_generation`. Для изображений — профиль на провайдере, который размещаете вы, или никакого такого профиля |

Включая эмбеддинги: каталог называет OpenRouter и OpenAI, до которых коллекция
доходит с ключом из хранилища секретов, и `ollama`, до которого коллекция доходит
через локальный сервис — строку, называющую сервер, который запускает организация
или экземпляр. Коллекция на `ollama` отправляет свои фрагменты и запросы только
этому хосту и никому не платит. Экземпляр, который должен держать документы на
собственном оборудовании, создаёт там каждую коллекцию.

## Кто за что отвечает { #who-is-responsible-for-what }

| Сторона | Роль | Что это значит здесь |
| --- | --- | --- |
| Организация, которая его разворачивает (город, компания) | **Контролёр** | Решает цели, сроки хранения и то, к каким провайдерам может обращаться агент, и подписывает с ними соглашения |
| Vstorm как автор программы | **Ни то ни другое**, для самостоятельно размещаемого экземпляра | Код работает на вашей инфраструктуре. Vstorm никогда не видит ваши промпты, диалоги или документы. Пока используется коллектор по умолчанию, который Vstorm эксплуатирует, он получает [диагностику экземпляра](#deployment-diagnostics); при `DIAGNOSTICS_ENABLED=false` или вашем собственном коллекторе — ничего |
| Vstorm, если он эксплуатирует экземпляр за вас | **Обработчик** | Соглашение об обработке данных — это договор между нами, а не настройка. Оно должно существовать до публикации первого агента |
| Провайдер моделей, эмбеддингов, разбора, поиска или наблюдаемости | **Субобработчик**, выбираемый конфигурацией | Платформа записывает, _какого_ провайдера и _какой_ эндпоинт использует каждый агент. Их местоположение, сроки хранения и условия обучения — их собственные и проверяются для каждого экземпляра |

Платформа ничего не обучает и не дообучает. Она отправляет промпты, документы и
результаты инструментов провайдерам, которых настроил экземпляр, и сохраняет то,
что приходит в ответ. Использует ли провайдер трафик API для обучения — свойство
его учётной записи и условий, и контрольный список в конце требует заявления об
этом, а не предполагает его.

## Где живут персональные данные { #where-personal-data-lives }

Всё ниже находится в собственном PostgreSQL экземпляра, на его собственном диске
или в сервисе, который выбрал экземпляр. Каждая таблица, принадлежащая
организации, несёт `organization_id`; дочерняя строка — сообщение, вложение,
оценка — ограничена диалогом или пользователем, к которому относится, а её чтение
проходит проверку родителя.

### База данных { #the-database }

Совокупный предел проверяется внутри точки сохранения изменения, под блокировкой
организации, до коммита. Запись сверх лимита откатывает свою строку и каждую
сохранённую копию, включая строку пакета; остальные строки пакета сообщаются как
отклонённые. Повтор квитанции, записи без изменений, чтение и удаление остаются
доступны и после снижения лимита. Удаление по срокам хранения освобождает те
байты, которые убирает.
Считаются байты полезной нагрузки JSONB в PostgreSQL на организацию по записям,
истории, квитанциям и очереди исходящих; физические накладные расходы таблиц и
индексов — отдельно.

| Хранилище | Что содержит | Персональные данные в нём | Назначение |
| --- | --- | --- | --- |
| `users`, `sessions`, `organization_members` | Учётные записи и входы | Адрес электронной почты, имя, аватар, хеш пароля или идентификатор учётной записи Google, хеш токена обновления, IP-адрес и заголовок User-Agent каждого сеанса; то, что человек рассказал агентам о себе, — язык консоли, часовой пояс, роль, чем он занимается, рабочие часы, — и первые сообщения, написанные для его пустого чата | Аутентификация и авторизация; то, что каждый агент знает о человеке |
| `browser_sign_ins` | Сохранённые человеком входы на сайты для веб-браузера | Сайт, организация, когда вход использовался в последний раз, и сам сеанс (cookies и `localStorage` сайта), запечатанный через хранилище секретов в области самого человека | Запуск более позднего просмотра, который действует от его имени уже с выполненным входом. Экспорт персональных данных перечисляет сайты и никогда — сам сеанс |
| `coding_accounts` | Личные подключения Claude Code/Codex | Организация, владелец, метка учётной записи, версия согласия и запечатанные пользователем API-ключ или пара токенов ChatGPT | Экспорт метаданных только для владельца; один одноразовый контейнер на задачу; отключение снимает доступ платформы, а не доступ у провайдера |
| `conversations`, `messages`, `tool_calls` | Каждый чат через любой способ доступа | Текст, который написали люди, ответы и рассуждения модели, аргументы и результаты инструментов, скользящее резюме длинных диалогов | Основная функция продукта; история, к которой человек возвращается |
| `coding_task_changes` | Задача агента для работы с кодом в режиме `edit` в диалоге | Изменённые файлы, отображаемый патч и сохранённая без потерь копия ограниченного патча в base64 (до 256 КиБ до кодирования), отпечатки файлов, ссылка на исходное рабочее пространство, изоляция захвата, резервирование задачи отката, время попытки, пути сбоя и время успеха | Разница задачи и безопасный откат; чтение — с доступом к диалогу, откат — с текущим доступом на редактирование |
| `voice_calls` | Каждое подключение [голосового звонка](voice.md) | Идентификатор пользователя-звонящего (нет для посетителя), агент, запуск, диалог и встраивание, к которым звонок относился, провайдер и модель, идентификатор звонка у провайдера, идентификатор ключа хранилища секретов, которым звонок держали, воркер, который его держит, его сигнал активности, время начала, окончания и завершения звонка, его стоимость, секунды и число срабатываний защитных проверок. **Ни аудио, ни транскрипта** — слова звонка лежат обычными строками в `messages`, каждая помечена `turn_id` и, если звонящий перебил, `interrupted` | Завершение звонка, процесс которого умер, и подсчёт ежемесячных минут звонков организации |
| `chat_files` | Вложения к сообщению | Имя файла, тип, размер, извлечённый текст (`parsed_content`) и путь к байтам на диске | Ответ на вопрос о файле |
| `generated_media` | Одна строка на изображение, речевой фрагмент или видео, созданные агентом | Организация, диалог, в котором это создано, если у запуска он был, имя файла, путь в хранилище и размер — **не содержимое**, которое лежит файлом в `MEDIA_DIR` | Подсчёт созданных медиа каждой организации против её квоты и их удаление вместе с диалогом или по истечении срока хранения |
| `context_files` | Постоянные знания, которые автор написал для агентов | Всё, что автор туда положил, — и это дословно попадает в промпт. См. [Файлы контекста](context.md) | Инструкции и факты, которые агент должен знать всегда |
| `datasets`, `dataset_cases` | Тестовые кейсы для оценок | Вопросы и ответы, скопированные из диалогов, когда кто-то выбрал «Добавить в набор данных», комментарий к ответу с отрицательной оценкой как примечание кейса и всё, что содержал импортированный файл. Учётные данные вырезаются до сохранения кейса. Каждый кейс также записывает, чьи слова он хранит, — кто спросил, кто написал каждый более ранний ход, чей комментарий стал его примечанием, — и это никогда не показывается и не экспортируется, а переживает диалог. Удаление человека, который спросил, обезличивает кейс во всех версиях, где он есть; удаление любого другого, чей ход или комментарий кейс сохранил, заменяет этот ход и ответ агента на него и очищает это примечание. См. [Наборы данных](datasets.md#personal-data) | Проверка, стал ли агент лучше |
| `spec_proposal_hunks`, `skill_proposals`, `context_proposals`, `authoring_requests` | Предложенные изменения помощника по редактированию и его отчёты | Цитаты, до 600 символов каждая, из прочитанных им запусков: что спрашивали люди, что отвечал агент и какие комментарии оставили вместе с оценкой. Удаление человека убирает цитаты его запусков и цитаты его комментариев к чужим запускам. См. [Помощник по редактированию](authoring.md#every-quote-is-checked) | Показ, почему помощник предложил изменение |
| `skill_improvement_runs` | Сеанс, который улучшает общий навык | То, что нашло собственное «Улучшение» агента, когда передавало навык дальше: проблемы и цитаты из прочитанных им запусков. Удаление человека убирает все переданные цитаты сеанса, если они ссылаются на запуски этого человека | Запуск «Улучшения» навыка из того, что нашло «Улучшение» агента |
| `knowledge_searches`, `knowledge_gap_topics`, `knowledge_gap_members` | Каждый поиск по знаниям, который агент сделал в запуске, и промахи, сгруппированные в темы | Запрос, который агент сформулировал из чьего-то вопроса, базы знаний, где он искал, и то, насколько близок был ближайший фрагмент. Поиск хранится, найден он или нет, столько же, сколько его запуск, так что класс запусков в [правилах хранения](governance.md#retention) до него достаёт. Тема не копирует ни одного вопроса: она хранит векторное среднее своих вопросов и всё остальное читает из поисков. Единственный её текст — черновик, который для неё написали модель или человек, проверенный на персональные данные и на числа, повторённые из вопросов, прежде чем его можно добавить в базу знаний; тема записывает, кто её добавил и с каким документом. Документ, добавленный из темы, остаётся в базе знаний, когда человека, чей вопрос её сформировал, удаляют, потому что человек подтвердил то, что в нём сказано. См. [Пробелы в знаниях](knowledge-gaps.md#personal-data) | Показ, на какие вопросы база знаний не смогла ответить |
| `knowledge_gap_classifications` | Каждый ответ, который модель прочитала для пробелов в знаниях, вместе с её вердиктом | Какой ответ, для какой базы знаний, вердикт, причина классификатора в одно предложение и его запуск. Строка идёт вместе с диалогом ответа; причина очищается, когда удаляют человека, который спросил, если только запуск ответа уже не удалён. Вопрос, прочитанный из ответа как пробел, — это строка `knowledge_searches`, хранящая вопрос человека. См. [Пробелы в знаниях](knowledge-gaps.md#answers-and-comments) | Чтобы не платить дважды за чтение одного и того же ответа |
| `run_skill_uses` | Какие навыки использовал каждый запуск и каким агентом | Текста нет: идентификаторы запуска, агента, навыка и версии навыка и то, как навык использовался (открыт, прочитаны файлы, назван путь в его папке рабочего пространства). Строка идёт вместе со своим запуском, так что класс запусков в [правилах хранения](governance.md#retention) на неё распространяется. См. [Навыки](skills.md#which-skills-an-answer-used) | Показ, какие агенты используют навык, и чтение доказательств навыка |
| `case_scores` | Что оценка выяснила об ответе одного запуска на один кейс | Копия ответа, который оценивали, до 8000 символов; причины судьи и цитаты, которых он не нашёл в ответе; решение и примечание человека при проверке и кто их дал. Решения, которые дал человек, и ответы, сохранённые из его запусков, возвращаются в его экспорте (`GET /me/data/export`); удаление человека очищает эти ответы вместе с причинами и цитатами, которые могут их повторять. Ответ посетителя через способ доступа, который человек опубликовал, принадлежит не ему: он не попадает в его экспорт и не удаляется вместе с ним. CSV/JSONL. Отсутствующий источник остаётся замаскированным. Читатель не может
изменить замаскированный текст; правка метаданных его не открывает. Оценки
по-прежнему выполняют полную сохранённую ревизию.

Ответы на проверку, примечания проверяющего и доказательства оценки требуют
`runs:view` и доступа к агенту, который отвечал. Без того или другого итог и статус
остаются видны, а текст ответа, причины, правила и цитаты убираются. Прежде чем
«Добавить в набор данных» скопирует чужой личный диалог, окно называет его
владельца и предупреждает, что читатели набора данных, которым можно читать
запуски, увидят его текст.
`workflow_node_spend` сохраняет прямые расходы на решения и эмбеддинги после
удаления истории выполнения: организация, UUID попытки, стоимость, признак
частичной стоимости и отметки времени. Промптов, результатов, файлов и личности
участника в ней нет. Расходы агента остаются в `agent_runs` и не считаются дважды.
Историческое использование, которое никогда не записывалось, восстановить нельзя.

`messages.search_vector` — полнотекстовый индекс по тому же содержимому, а
`conversations.summary_messages` — его сжатие, написанное моделью. И то и другое —
копии чата и уходят вместе с ним.

### Созданные медиа { #generated-media }

Изображение, речевой фрагмент или видео, которые создал агент, — это файл под
`generated_<org>/` и строка `generated_media`, называющая его. Строка записывает
организацию, диалог, в котором это было сделано, если у запуска он был, и размер —
поэтому сумма по организации ограничена `GENERATED_MEDIA_QUOTA_MB` (5120), которая
проверяется перед каждым платным вызовом генерации. Считается каждый файл, включая
сделанный без диалога: предпросмотр или тестовый запуск, реплика `/btw` в канале,
запуск через API, не называющий диалога, или файл, чей диалог был удалён путём,
который его оставил.

Файл удаляется вместе со своим диалогом, вместе с учётной записью, чьим был диалог,
ежедневной задачей `sweep-generated-media`, когда он старше
`GENERATED_MEDIA_RETENTION_DAYS` (90), даже если его диалог ещё на месте, и по
префиксу вместе со своей организацией. 0 отключает любую из этих границ. Файл без
диалога — это то, что участник не может удалить, чтобы освободить место, поэтому та
же задача удаляет его через 7 дней, каким бы ни был `GENERATED_MEDIA_RETENTION_DAYS`,
включая 0. Ссылка на него — в ответе канала или в ответе API — с этого момента
перестаёт работать.

Удаление диалога, учётной записи или организации убирает строки в своей собственной
транзакции и ставит в очередь отвязку байтов как фоновую задачу в той же
транзакции, так что байты уходят, только если ушли строки, и перезапуск после
коммита не теряет отвязку. Эта задача повторяет попытку для префикса, который
хранилище не удаляет целиком, — префикса организации, — и для отдельного файла
удалённого диалога или учётной записи, который хранилище отклоняет, потому что
больше ничто не смогло бы найти эти байты снова. Файл, который хранилище всё ещё
отклоняет после последней попытки задачи, остаётся под `generated_<org>/` без
строки, пока не уйдёт его организация, и отчёт ниже его считает.

Очистка удаляет сначала файл и только после его исчезновения — строку; файл,
который хранилище отклоняет, сохраняет свою строку, и следующая очистка пробует
снова.

Файлы, созданные до появления таблицы, не имеют строки. Их всё ещё отдают, но они
не считаются против квоты, и очистка их не видит: они уходят вместе со своей
организацией или вручную, а отчёт о защите данных считает их среди файлов без
строки.

## Данные таблиц, показанные на странице { #table-data-on-a-page }

Опубликованная [страница](artifacts.md#live-data) может показывать записи таблицы, а
эти записи могут быть персональными данными. Это **поток внутри экземпляра, от
владельца страницы ко всем, кто может открыть страницу**, а не получатель вне его,
но он обходит собственный контроль доступа таблицы, поэтому перечислен здесь.

- **Что течёт.** Только столбцы, которые называет запрос страницы, и строки, которые
  выбирают её фильтры, до 1 000 на привязку. Фильтр может использовать столбец,
  которого страница не показывает, и владельцу сообщают, какой. Формулы,
  подстановки, сводные значения и метки связей тоже несут данные из связанных
  таблиц, и согласие называет эти таблицы.
- **По чьему решению.** Владельца страницы. Каждому зрителю отдают одни и те же
  записи, каким бы ни был его собственный доступ к таблице. Данные покидают таблицу
  только после того, как владелец подтвердил это, прочитав запросы словами и
  увидев, кто может открыть страницу сейчас и позже (роли, которые открывают любую
  страницу, видимость, людей и группы). Данные читаются заново при каждой загрузке
  и никогда не сохраняются в странице. Чтения для участников не кэшируются; чтения
  для публичной страницы кэшируются, как описано ниже.
- **Что об этом хранится.** Для каждой версии страницы: кто её опубликовал, отпечаток
  её запросов, согласился ли владелец, когда и при каком членстве. Запросы на
  совместный доступ хранят просителя, вид, необязательное примечание, решение и кто
  его принял. Журнал аудита записывает согласие, отзыв, автоматическое согласие,
  выданные доступы `edit_data`, смену владельца и запросы — с текстом, который
  подтвердил человек.
- **Что никогда не записывается.** Значения записей, значения фильтров и адрес
  содержимого страницы, отданной вместе с её данными. Записи аудита и уведомления
  называют страницу и людей, никогда — строку.
- **Что до неё не доходит.** Согласие удалённого участника истекает вместе с его
  членством, а страница, чей владелец ушёл, не отдаёт данных, пока другой владелец
  их не подтвердит.

### Людям без учётной записи { #table-data-on-a-public-page }

Это единственный поток здесь, который **выходит за круг людей, у которых есть
учётная запись**. [Публичная ссылка страницы и её встраивания](artifacts.md#live-data-on-a-public-link)
могут записать те же записи в страницу для любого, кто откроет адрес, и для каждого
сайта, который её встраивает, без входа. Его открывают два решения, и экземпляр,
которому поток не нужен, оставляет первое выключенным.

- **По умолчанию выключено, для всей организации.** `public_live_data` — переключатель,
  который меняют только Owner или Admin и только от своего имени. Когда он выключен,
  ни одна страница не показывает данные ни по ссылке, ни во встраивании, что бы ни
  подтвердил её владелец.
- **Затем для каждой страницы.** Владелец страницы или Owner либо Admin вместо него
  подтверждает это после экрана, который называет таблицы и столбцы и говорит, кто
  может их читать, — любой, у кого есть ссылка, её пароль и срок действия, каждый
  сайт встраивания. Согласие привязано к запросам страницы и к этой аудитории.
  Добавление сайта, снятие пароля, выключение ссылки, архивирование страницы, новый
  владелец и отозванное согласие участника его очищают.
- **Что хранится.** В странице: отпечаток запросов, к которым дано согласие, кто его
  подтвердил, членство владельца и когда. Строка организации хранит переключатель.
  Журнал аудита записывает `organization.public_live_data_changed`,
  `artifact.public_data_consented`, `artifact.public_data_withdrawn` и
  `artifact.public_data_voided` — с именами таблиц и столбцов, сайтами встраивания,
  сведениями, задан ли пароль, и причиной, — никогда со строкой, значением или
  посетителем.
- **Кэш.** Записи привязки держатся 30 секунд в памяти процесса API, чтобы популярная
  страница не читала свою таблицу на каждого посетителя. Они **никогда не пишутся в
  Redis**, базу данных или файл, память ограничена по байтам
  (`ARTIFACT_PUBLIC_DATA_CACHE_BYTES`) и исчезает при остановке процесса. Все проверки
  доступа выполняются до чтения кэша, поэтому выключение переключателя или смена
  ссылки прекращают поток при следующей загрузке; то, что посетитель уже загрузил,
  остаётся в его браузере.
- **Что никогда не записывается.** Значения записей, значения фильтров, ключ ссылки и
  адрес содержимого страницы, загруженной вместе с её данными, держатся вне журналов,
  трасс и записей аудита. Ни один посетитель не записывается: ссылка считает
  открытия, а не людей. Только ключ лимита частоты хранит IP посетителя — в
  Redis, на минуты.
- **Никому не говорят почему.** Посетитель, чья загрузка не прошла проверку, видит
  страницу без её данных и без причины, так что страница не выдаёт, что хранит
  таблица и почему это скрыто.
- **Что видит сайт, который встраивает страницу.** Сайт встраивания показывает
  страницу во фрейме; страница работает в непрозрачном источнике без сети, поэтому
  сайт не может прочитать записи из фрейма, но тот, кто открывает сайт, их читает.

Записи, показанные любому, у кого есть ссылка, может скопировать каждый, кто их
видит. Привязывайте публичную страницу только к тем столбцам, которые и должны быть
публичными.

Экземпляр, которому нужно скрыть строки таблицы от части своих участников, не должен
привязывать к ней страницу, которую эти участники могут открыть; подтверждение
называет, кто они.

стоит задача, — это пробел, и он так и назван.

### Трассы { #traces }

`instrument_pydantic_ai()` работает с настройкой по умолчанию из библиотеки,
поэтому спан хранит сообщение пользователя, ответ модели и каждый аргумент и
результат инструмента. Если `LOGFIRE_TOKEN` не задан, ни в одной спецификации нет
токена `observability`, а в окружениях нет `logfire_token_secret_id`, ничего не
отправляется, а id трассы всё равно записывается локально. Экземпляр, которому
нужны трассы без содержимого, ставит агенту `observability.content` в `none` —
тогда записываются время, токены, стоимость и имена инструментов, но не текст
сообщений; этот режим наследует специалист этого агента, независимо от того,
задал ли его автор явно или его придумала модель запуска.

Третьего режима между ними нет. Выгрузка, вычищенная фильтром персональных
данных, — гарантия, которую никто не может проверить: один пропущенный фильтром
идентификатор уже ушёл, а оператор считает, что нет. Поэтому выбор сознательно
таков: всё содержимое или ничего
([#1616](https://github.com/vstorm-co/agenticos/issues/1616)).

### Что удаление затрагивает { #what-deletion-reaches }

Удаление — это то, что продукт делает сегодня, когда его просят; хранение по
расписанию — [#1420](https://github.com/vstorm-co/agenticos/issues/1420).

| Действие | Что удаляет | Что оставляет |
| --- | --- | --- |
| `DELETE /conversations/{id}` (владелец) | Диалог, его сообщения, вызовы инструментов, оценки, доступы, открытые другим, строки `chat_files` и поиски по знаниям, сделанные в нём, каскадом — среди них транскрипт голосового звонка, поскольку его ходы — это сообщения; байты вложений в `MEDIA_DIR`, собранные до удаления и отвязанные после коммита; медиаобъекты диалога, выгруженные по префиксу; рабочее пространство контейнера через `purge_for_conversation`; сгенерированные черновики наборов данных, взятые из него и всё ещё ожидающие решения. Сгенерированные изображения, речь и видео в этих диалогах удаляются вместе с их строками; задача, поставленная в очередь в той же транзакции, удаляет их файлы. | Строки запусков и манифесты, называвшие диалог, сохраняют свою копию промпта; строка `voice_calls` сохраняет время и стоимость, а ссылка на диалог очищается. Скопированные из него кейсы наборов данных сохраняют текст, а все ссылки назад на диалог, его запуск и его сообщения очищаются — текст может по-прежнему содержать персональные данные, которые кто-то написал, и уходит, когда этого человека стирают. Результаты оценок, уже полученные по этим кейсам, сохраняют ответы и вызовы, которые они записали. Ответвления, сделанные из него, сохраняют скопированные сообщения и вызовы инструментов, а ссылка на диалог очищается, и сгенерированные изображения в них перестают загружаться; срок хранения ответвления отсчитывается с момента его создания |
| `DELETE /projects/{id}` (`projects:edit`) | Контейнер проекта и каждый файл в нём; чаты, учётная запись автора которых удалена и до которых добирался только проект, вместе с тем, что удаляет удаление диалога; сгенерированные черновики наборов данных, взятые из этих чатов и всё ещё ожидающие решения | Его остальные чаты, сохранённые как обычные чаты вне любого проекта. Кейсы наборов данных, скопированные из удалённого им чата, сохраняют текст, а все ссылки назад на чат, его запуск и его сообщения очищаются |
| `DELETE /memory/person/{user_id}` (сам человек или `members:manage`) | Каждую строку `agent_memory_files` с ключом этого человека у всех агентов организации, каждое записанное утверждение в области человека и копии, розданные из этих утверждений; текст диалогов, факты, заметки и запросы в манифестах запусков обслуживания памяти и ежедневных сводок, сделанных для человека. Запуск, начавшийся до стирания — включая тот, что ждёт согласования, — или во время того, как стирание ещё фиксировалось, больше ничего не пишет в память человека, а более поздняя ежедневная сводка читает только запросы, сделанные после него. Защита порядком фиксации работает и без доступа к управляющим данным PostgreSQL. После перезапуска или восстановления базы начните новый запуск, прежде чем писать в память; более старые снимки не могут разрешить запись. Запуски, предшествующие записи снимков, блокируются после любого относящегося к делу стирания. Он также удаляет первые сообщения и предложения, которые ежедневные сводки написали для человека в организации; результаты наблюдений остаются | Заметки с ключом группового чата, в котором человек говорил |
| `DELETE /users/{id}` | Учётную запись, её сеансы, её личную организацию и личные коллекции с их векторными таблицами и файлами — явной очисткой; диалоги вне любого проекта и файлы чата — каскадом; их байты, отвязанные после коммита; и то, до чего не доходит каскад, — заметки и утверждения, которые записали о человеке агенты (`owner_key` — строка, а не внешний ключ), и текст диалогов, факты, заметки и запросы в манифестах запусков обслуживания памяти и ежедневных сводок, сделанных для человека, его идентичности на платформах, его рабочие пространства уровня пользователя, поиски по знаниям каждого запуска, который он начал, включая поиски из чата проекта, копию ответа, которую оценка сохранила из одного из его запусков, сгенерированные черновики наборов данных, взятые из набранных им вопросов, его диалогов или его запусков и всё ещё ожидающие решения; текст кейсов наборов данных, вопрос которых он задал, во всех версиях, найденный даже после того, как диалог исчез, вместе с ответами и вызовами, которые записали для этих кейсов запуски оценок, сообщениями в манифестах запусков агента и судьи, ответивших на них, и аргументами вызовов, которые эти запуски придержали; его ходы в более ранней истории чужих кейсов вместе с ответами агента на них; его комментарии, сохранённые как заметка кейса; цитаты о нём помощника по редактированию; и черновики тем пробелов в знаниях, содержащие его поиски. Сгенерированные изображения, речь и видео в этих диалогах удаляются вместе с их строками; задача, поставленная в очередь в той же транзакции, удаляет их файлы. | Записи аудита, называющие id действующего лица и для некоторых действий адрес электронной почты, — сохранены намеренно, потому что запись с удалённым действующим лицом хуже записи, называющей удалённую учётную запись. Сообщения в диалогах, которыми владеет кто-то другой, и чаты проектов, которые он начал, сохранены для команды без автора; его ходы там отрисованы как ходы бывшего участника. Кейсы наборов данных, скопированные из его диалогов или запусков, сохранены с пометкой «Обезличено после удаления» и всеми ссылками назад очищенными, чтобы их куратор мог переписать или удалить их; запуск оценки не берёт их до тех пор. Кейс, записанный до того, как кейсы стали хранить, кто спрашивал, и чей диалог был удалён раньше этого, сохраняет свой текст. Кейс из чужого запуска, который человек только оценил, сохраняет свой вопрос и ответ. Сгенерированные медиафайлы без диалога не связываются с человеком и истекают через семь дней. |
| Удаление документа или коллекции | Строки, векторную таблицу (или только фрагменты коллекции, если таблицу сохраняют другая коллекция или фрагменты, не принадлежащие ни одной коллекции) и сохранённый файл — надёжным процессом после коммита; копию для разбора в `_rag_tmp` — когда документ удалён или в следующий раз запускается его задача индексации, а иначе — часовой уборкой, как только копии исполнится час, то есть примерно в течение двух часов после загрузки. Копия хранится, пока её документ ещё обрабатывается | Ничего, когда процесс отработал, кроме старых фрагментов без записанной коллекции, которые могут оставаться, пока таблицу не удалят, если её сохраняет другая коллекция или содержимое оператора; счётчики `sync_logs` остаются |
| Удаление организации | Всё, что относится к ней, той же отложенной очисткой — её сгенерированные медиафайлы по префиксу, включая файлы, записанные до того, как их начали учитывать | Личные коллекции, которые лишь несли этот id |

Сообщения каналов хранят только текст отправителя. Метки автора разрешаются из
идентичностей каналов непосредственно перед передачей модели, вне системных
инструкций. Консоль и действия копирования, закрепления и ярлыков получают
простой текст. Сохранённые истории и приостановленные запуски хранят непрозрачные
ссылки на идентичности, а манифесты опускают внедрённые части со ссылками канала.
Удаление учётной записи удаляет её идентичности каналов, поэтому будущие запросы
не могут разрешить метки этого человека на платформах; общие тела сообщений
остаются.

Ничто из этого не достигает резервной копии. Восстановление возвращает стёртое,
поэтому срок хранения резервных копий — часть политики хранения и записывается
вместе с ней.

## Что экземпляр должен решить и получить { #what-a-deployment-has-to-decide-and-obtain }

Программа не может предоставить ничего из этого. Каждый пункт — доказательство,
которое запросит проверка, отдельное от технической возможности, которая его
делает возможным.

- **Соглашение об обработке с каждым настроенным субпроцессором** — каждый
  провайдер, названный строкой `model_profiles` или `organization_secrets`,
  провайдер эмбеддингов, LlamaCloud, если его использует коллекция, поисковый
  поставщик, названный `method` агента, Logfire, SMTP-ретранслятор и Google, если
  включён вход.
- **Заявление о месте хранения данных по каждому провайдеру**, сверенное с
  `base_url`, который действительно использует каждый профиль. Провайдер с эндпоинтом
  в ЕС находится в ЕС, только если профиль так говорит.
- **Исключение из обучения по каждому провайдеру**: настройка учётной записи или
  условие договора, по которому данные API не используются для обучения.
  Собственное положение платформы — одно предложение: она ничего не обучает, —
  а остальное за ними.
- **Соглашение об обработке с Vstorm** — только если Vstorm эксплуатирует
  экземпляр.
- **Расписание хранения** для диалогов, файлов, памяти, документов, запусков и
  аудита и рядом — срок хранения резервных копий. Пока
  [#1420](https://github.com/vstorm-co/agenticos/issues/1420) не начнёт его
  соблюдать, хранение — это удаление вручную.
- **Шифрование диска или тома** на хосте базы данных, томе медиафайлов и хосте
  песочницы, поскольку приложение само содержимое не шифрует, — и правило
  исходящего трафика на хосте песочницы, если агенты могут выполнять команды.
- **Правовые страницы**, на которые ссылается экземпляр, и кто отвечает на запрос
  о доступе или стирании. Механизмы здесь — `GET /me/data/export` и удаление
  учётной записи; но кто получает запрос и в какой срок, должен указать
  контролёр.

## Проверка одного экземпляра { #verifying-one-deployment }

Воспроизводимые проверки с хоста против работающего экземпляра. Каждая печатает
факты, которые проверка может приложить; ни одна не печатает учётные данные или
данные человека. Из рабочей копии исходников запускайте эти команды из `backend/`
с конфигурацией экземпляра:

```bash
# 1. Может ли он работать и зашифрованы ли соединения с хранилищами?
#    `postgres` сообщает состояние TLS соединения, которое установил сам doctor.
uv run agenticos cmd doctor

# 2. Каждые запечатанные учётные данные всё ещё открываются настроенными
#    мастер-ключами.
uv run agenticos cmd vault-rotate --dry-run

# 3. Хеш-цепочки журнала аудита и их контрольные точки, пересчитанные.
#    Завершается с ненулевым кодом, если какая-либо цепочка изменена.
uv run agenticos cmd audit-verify

# 4. Всё, что этот экземпляр действительно настроил: параметры, решающие, что
#    уходит наружу, каждый провайдер и эндпоинт, до которых может дотянуться агент,
#    учётные данные по назначению, коллекции и кто строит их эмбеддинги, серверы
#    в вашей собственной сети, MCP-серверы, порталы триггеров, источники
#    синхронизации и боты каналов, возможности, обращающиеся по собственному
#    адресу, где трассируются запуски и сколько содержимого несёт спан, до какой
#    части каждого хранилища дотянется срок хранения, и файлы в `MEDIA_DIR`, на
#    которые больше не указывает ни одна строка.
uv run agenticos cmd data-protection-report --older-than 365
```

Для экземпляра на Compose используйте установленный CLI напрямую; образ среды
выполнения не включает `uv`. Запускайте из каталога экземпляра с теми же файлами
Compose, файлом окружения и параметрами проекта, что и у работающего стека:

```bash
docker compose exec app agenticos cmd doctor
docker compose exec app agenticos cmd vault-rotate --dry-run
docker compose exec app agenticos cmd audit-verify
docker compose exec app agenticos cmd data-protection-report --older-than 365
```

Приложить стоит пункт 4. Он печатает конфигурацию и количества и никогда
содержимое: ни текста сообщений, ни документа, ни значения секрета и ни намёка на
него; параметр, содержащий учётные данные, сообщается как заданный или
незаданный, а не печатается. `--older-than` — рассматриваемый срок хранения в
днях, и последний столбец его таблицы хранения показывает, что этот срок уже
удалил бы.

Его последний раздел считает байты, на которые больше не указывает ни одна
строка. Удаление диалога или учётной записи теперь отвязывает их вложения после
коммита, поэтому этот путь больше не пополняет его; что он всё ещё находит — то,
что старше этих удалений, плюс отвязку, которую не довела до конца уборка по мере
возможности.

Временный каталог для разбора исключён, поскольку у него по замыслу нет
строки; часовая задача `sweep-rag-scratch` удаляет копию, чей документ исчез или
больше не обрабатывается.

Сгенерированные медиафайлы учитываются с тех пор, как `generated_media`
записывает каждый файл, поэтому то, что обнаруживается в каталоге
`generated_<org>`, — в основном файл, созданный до появления этой таблицы и
уходящий только вместе со своей организацией. Это может быть и файл, чья отвязка
не удалась после удаления его строки, или файл, который ещё сохраняется до записи
его строки. Всё остальное, что там посчитано, — байты, которые продукт больше не
может найти и не может удалить. Он сообщает каталог и количество, а не имя файла,
потому что сохранённый путь хранит имя, под которым файл загрузили.

Два раздела читаются с того, что работает, а не с таблицы. **Назначения
возможностей** (Capability destinations) перечисляют возможности, к которым
привязан агент и которые обращаются по собственному адресу, — `web_research`
ищет через DuckDuckGo без учётных данных и поэтому не даёт строки нигде больше в
отчёте, — а **Трассировка** (Tracing) читается с каждой исполняемой версии: версии
по умолчанию и той, которую закрепляет каждое именованное
[окружение](environments.md), потому что запуск через это окружение использует
observability той версии, а не версии по умолчанию.

Чего не может выдать ни одна команда, — это вторая половина этой страницы:
соглашения, места хранения и исключения из обучения из предыдущего раздела.
Приложите их рядом с выводом.

## Открытые условия для первого внедрения { #open-conditions-for-a-first-rollout }

Сформулированы для экземпляра, под который писалась эта страница, и верны для
любого экземпляра, пока каждое условие не закрыто.

**В коде, и это сохраняется:**

- Трассы несут полное содержимое, если агент не поставит `observability.content`
  в `none`. Отфильтрованной середины нет и не будет: частично вычищенная выгрузка
  — гарантия, которую никто не может проверить
  ([#1616](https://github.com/vstorm-co/agenticos/issues/1616)).
- **Содержимое в состоянии покоя — забота оператора.** Тела сообщений, документы
  и их векторы, а также рабочие пространства песочницы — это столбцы и файлы
  открытым текстом; хранилище секретов запечатывает учётные данные, а не
  содержимое. Загруженные файлы могут попадать в S3-совместимое хранилище,
  которое шифрует их на стороне сервера, но база данных и том медиафайлов
  защищены шифрованием диска или тома — или никак.

**Закрыто, и ответ выше, а не здесь:** доказательства защиты журнала аудита от
подмены (#1622, #1648), режим содержимого трасс для каждого агента и его
наследование специалистами (#1413, #1699), трассировка в процессе, который
выполняет агента, запущенного по триггеру (#1700), матрица мер HIPAA и SOC 2 в
[Безопасности](security.md#controls-matrix) (#1412), стирание и выгрузка данных
одного человека (#1421), бэкенд S3 с шифрованием на стороне сервера (#1423) и
общий вход OIDC (#1419). У трасс нет отфильтрованной середины, и не появится
([#1616](https://github.com/vstorm-co/agenticos/issues/1616)); `none` — ответ для
экземпляра, которому нельзя выгружать содержимое.

**В экземпляре — решает его оператор:** соглашения, места хранения, исключения из
обучения, расписание хранения, срок хранения резервных копий, шифрование диска,
исходящий трафик песочницы и правовые страницы из предыдущего раздела. Каждый из
них — тот вид доказательства, который `data-protection-report` намеренно не может
выдать.

Проверка, которая находит каждую строку выше либо закрытой, либо принятой в
письменном виде, получает всё, что может дать эта страница. Остальное — за
экземпляром.

## Диагностика экземпляра { #deployment-diagnostics }

Сборщик получает состояние работоспособности установки, грубые корзины
использования, сгруппированные количества сбоев (компонент, закрытый код ошибки и
количество, никогда текст исключения) и псевдонимное присутствие на переднем
плане, которое каждый вошедший браузер или приложение отправляет ему
напрямую.
Отправка включена по умолчанию, в том числе при обновлениях со старыми файлами
`.env`, а сборщик по умолчанию — удалённый адрес
`https://analytics-agenticos.testapp.ovh`. См. [настройку
диагностики](configuration.md#diagnostics): точные поля, хранение, как направить
её на собственный сборщик и как отключить её через `DIAGNOSTICS_ENABLED=false`.

## Данные моста iMessage { #imessage-bridge-data }

Необязательный канал iMessage отправляет текст сообщений и явно приложенные файлы
через настроенные в организации Mac с BlueBubbles и Apple Messages. Этот Mac и его
учётная запись Apple — дополнительные места, где могут оставаться копии.
AgenticOS хранит связанные адреса, диалоги канала, запуски и загрузки по
действующим правилам хранения и стирания для каналов; удаление их здесь не
удаляет копии на Mac или в Messages. Личные уведомления требуют явного маршрута;
групповые диалоги никогда не наследуют память личного профиля.

Пароль сервера и отдельные учётные данные обратного вызова запечатаны в
хранилище секретов. HTTP-клиент не выносит свой пароль в URL запросов, видимые
клиенту; сам мост всё равно получает обязательные для него учётные данные в
строке запроса, поэтому его оператор должен защитить собственные журналы и сеть.
