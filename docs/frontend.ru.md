# Код консоли { #the-consoles-code }

[Архитектура](architecture.md) — это бэкенд. Здесь другая половина: приложение
Next.js в `frontend/`, для того, кто собирается его менять.

**Стек.** Next.js 15 (App Router) · React 19 · TypeScript strict · Tailwind ·
`next-intl` · TanStack Query · Zustand · vitest и Testing Library · Playwright.
Менеджер пакетов и среда запуска: **bun**.

## Что где лежит { #where-things-live }

| Путь | |
|---|---|
| `src/app/[locale]/(dashboard)/…` | Продукт. Маршруты **начинаются с локали** |
| `src/app/api/…` | Обработчики маршрутов, проксирующие запросы к бэкенду |
| `src/lib/` | Типизированные API-клиенты, `query-keys.ts` и реестры, описанные ниже |
| `src/hooks/` | По одному на ресурс — `use-agents`, `use-permissions`, … |
| `src/stores/` | Zustand, по одному на каждую область |
| `src/components/<domain>/` | Интерфейс по доменам; примитивы в `ui/`, пустые и ошибочные состояния в `states/` |

Серверные компоненты используются по умолчанию. `"use client"` — для состояния,
эффектов и обработчиков, а не по привычке.

## Оформление консоли { #console-presentation }

Компактные заголовки и действия делайте через `PageHeader`. Сеточные каталоги
используют `ListCard layout="grid"`, чтобы не обводить карточки панелью;
таблицы панель сохраняют. Кнопки действий используют нейтральные токены
`action`, независимо от цвета `primary`, которым отмечены выбранные элементы
управления и метки. Фокус и границы полей ввода должны оставаться
видимыми.

Элементы форм берутся из `components/ui`: `Input`, `Textarea`, `SelectTrigger`, `NativeSelect`, `Button`, `Checkbox` и `Switch`. Для нестандартных триггеров комбобокса переиспользуйте `control-styles.ts`. Заливка полей, мягкие границы в 2px, фокус с клавиатуры, состояния невалидности и недоступности берутся из действующего оформления; не переопределяйте в стилях страницы все вложенные поля ввода сразу. Стандартные поля и действия на компьютере имеют высоту 40px, с явными компактным и крупным вариантами и областями касания 44px. Вход и регистрация следуют выбранной теме и оформлению. Сравнивайте все пять оформлений в светлой и тёмной теме в галерее компонентов для разработки.

Люди и организации используют `EntityAvatar`: загруженные фотографии обрезаются
в круги, а запасным вариантом служат устойчивые цвета и инициалы. Агенты
сохраняют сгенерированные лица. Описания в галерее занимают две строки; при
открытии элемента показывается полное описание.

Асинхронные действия используют `Button loading`, чтобы сохранить подпись и размер и не допустить повторной отправки. Держите это состояние, пока не завершится каждый шаг, включая загрузку файлов. Кнопки-ссылки сохраняют единственный дочерний элемент и блокируют срабатывание, пока недоступны. Элементы управления единообразно показывают фокус с клавиатуры и компактные размеры на компьютере, с областями касания 44px там, где хватает места. Оверлеи анимируются от своей привязки; подсказки переносятся в пределах окна просмотра. Заголовки календаря следуют языку консоли, а индикатор прогресса сообщает вспомогательным технологиям своё фактическое значение и максимум. Анимация подчиняется персональной настройке движения.

## Браузер никогда не обращается к бэкенду { #the-browser-never-calls-the-backend }

Каждый запрос идёт на `/api/*` этого приложения, а оно пересылает его в FastAPI с
токеном доступа из **HttpOnly cookie**. Именно поэтому токен не попадает в
JavaScript, а URL бэкенда — в клиентский бандл.

Пересылает всё один модуль — `src/lib/platform-proxy.ts`, — а не отдельный
самодельный файл маршрута на каждый эндпоинт с повторением одних и тех же
двенадцати строк.

!!! warning "Отсутствие `Cache-Control` не означает, что ответ никто не кеширует"

    Прокси ставит `no-store` на всё, что бэкенд оставил без пометки. Каждый ответ
    здесь зависит от cookie, набора разрешений и заголовка организации, а список,
    запрошенный заново после записи, обязан дойти до сервера.

    Самодельный файл маршрута обязан выставить тот же заголовок — прокси
    остаётся единственным местом, где он ставится за вас.

## Данные и где живёт состояние { #data-and-where-state-lives }

**Весь доступ к API идёт через клиент в `src/lib/`, который используется через
хук.** Никакого `fetch` в компоненте.

Серверные данные живут в слое запросов; **хранилища держат только состояние
интерфейса и временное состояние**. Регистрируйте каждый ключ запроса в
`query-keys.ts`, чтобы инвалидация после записи оставалась согласованной.

## История чата и потоковые обновления { #chat-history-and-streamed-updates }

Консоль открывает последнюю страницу транскрипта и подгружает более ранние
сообщения по требованию. Плашки проектов читают `/conversations/{id}/metadata`,
где действуют те же проверки читателя и организации, но без загрузки сообщений.
Чтение из репозитория не отдаёт сохранённое моделью резюме, если реконструкция
истории модели явно его не запросила.

Сокеты чата отдают пакеты раз в кадр анимации, с запасным вариантом каждые 50 мс
для скрытых вкладок и пределом очереди в 256 кадров. Соседние дельты текста или
рассуждения объединяются; границы управляющих событий, инструментов и частей
сохраняют порядок. Смена диалога, учётной записи или организации сбрасывает
буферизованные кадры.

Неизменённый Markdown и вывод инструментов переиспользуются. Прокрутка следует за
измеренным приростом содержимого. Готовые рисунки монтируются рядом с областью
просмотра и размонтируются за её пределами, сохраняя измеренное место; их скрипты
перезапускаются при возвращении. Рисунки, которые ещё рисуются, остаются живыми, а
полноэкранный режим приостанавливает встроенную копию.

## Разрешения — это решение при отрисовке { #permissions-are-a-rendering-decision }

`use-permissions.ts` отдаёт действующий набор разрешений для активной
организации. **Элемент управления, которым вызывающий не вправе пользоваться, не
отрисовывается** — его не отрисовывают, а потом отвечают 403.

Две ловушки, и обе уже случались здесь:

- **Какие роли предлагает список выбора — это арифметика, а не перечень.**
  `assignableRoles` повторяет серверное правило по каталогу разрешений: роль
  предлагается, только если роль самого вызывающего строго её выше. Жёстко
  зашитое «любая роль, кроме владельца» и предложило Admin вариант Admin, а затем
  ответило 403 уже после того, как ввели адрес электронной почты.
- **Страница, которая называет организацию в своём URL, *и есть* эта
  организация.** API-клиент ставит `X-Organization-Id` из *активной*
  организации, поэтому страница, которая работает с организацией из своего пути,
  а разрешения читает для активной, определяет состав участников Acme по вашей
  роли в Globex. Подхват живёт в `ActiveOrgGuard`, в одном месте.

## Каждая строка для пользователя проходит через `next-intl` { #every-user-facing-string-goes-through-next-intl }

`make lint` следит за этим в обе стороны: читаемая строка прямо в компоненте не
проходит проверку, как и ключ в каталоге, который не читает ни один компонент.

Три правила, на которых спотыкаются:

- **Число — это `plural` из ICU, а не тернарный оператор.**
  `{n} file{n === 1 ? "" : "s"}` — предложение, которое так строит только
  английский.
- **Существительное, с которым согласуется предложение, — не параметр.**
  `{matched} of {total}
  {noun}` по-польски даёт `3 of 40 skills`. Существительное идёт внутрь
  `plural` или `select`.
- **В каталоге лежат тексты, и только тексты.** Ложное срабатывание получает
  `i18n-exempt` с причиной; оно никогда не получает ключ. Ответ на такое
  срабатывание переносом списка классов Tailwind в `en.json` — это то, как
  однажды перевод строки лишил компонент его стилей.

Английский — исходный язык, и он подмешивается под каждую локаль, поэтому при
отсутствующем переводе показывается английский текст, а не ключ.

!!! info "Собственные существительные продукта остаются английскими"

    agent, spec, capability, skill, embed, budget, run, prompt, provider, token,
    vault, workspace, sandbox, MCP. Они называют вещи, с которыми клиент
    встречается ещё и в документации, в API и в экспортируемом YAML: перевести их
    в интерфейсе и нигде больше — значит завести два словаря для одного продукта.
    Склоняйте их, но не заменяйте.

    Исключение — русский язык: латинское существительное не принимает русских
    окончаний, поэтому `ru.json` и русские страницы пишут кириллический термин,
    который приводит [Перевод страницы](howto/translate.md#russian-writes-them-in-cyrillic).

## Четыре реестра и никакого второго источника { #four-registries-and-no-second-source }

Каждый из них — одна таблица, которую читают несколько частей интерфейса. Добавить
строку в таблицу — это и есть вся правка; завести второй источник — это ошибка.

| | Что хранит | Как добавить |
|---|---|---|
| `lib/tool-catalog.ts` | Значок, подпись во время работы, имя по завершении и отрисовщик для каждого инструмента, который регистрирует бэкенд | Строку с ключом по id инструмента возможности. Тест бэкенда сверяет обе стороны в обоих направлениях |
| `lib/brand-glyphs.generated.ts` | Знак каждого сервиса, коннектора и провайдера, в виде исходных данных пути | Строку в `scripts/gen-brand-icons.ts`, затем `bun run gen:brand-icons`. Никогда импорт из пакета значков |
| `lib/dashboard/registry.ts` | Виджеты «Обзора» и разрешение, которым закрыт каждый | Пять правок, перечисленных на странице ниже |
| `lib/dialog-sizes.ts` | Один токен ширины и один токен формы на диалог | Выбор токена, никогда самодельная высота |

## Две вещи, которыми обязан новый экран { #two-things-a-new-surface-owes }

Обе — реестры с одинаковым режимом отказа: страница, добавленная где-то ещё,
просто отсутствует, ничего не падает, и функция выходит невидимой.

**Остановка экскурсии.** `lib/onboarding/tour.ts` — это пассивная экскурсия,
которую повторяет «?» страницы, а `flows.ts` — управляемое создание, которое она
предлагает в конце. Страница без остановок не рисует **вообще никакого «?»**,
поэтому новая страница, в заголовке которой нет кнопки помощи, не зарегистрирована.
Закройте шаг разрешением, которое несёт его элемент управления, помечайте его
`optional`, когда элементу нужно, чтобы данные уже существовали, и привязывайте
его к чему-то ограниченному.

**Виджет «Обзора»**, если функция создаёт состояние, которое кому-то захочется
видеть с одного взгляда. Пять правок: id и определение в `dashboard/registry.ts`,
компонент в `components/dashboard/widgets/`, размещение в `layouts.ts`, id,
продублированный в `backend/app/schemas/dashboard_layout.py` (тест падает, когда
эти два расходятся), и текст в `en.json` и в каждом переводе рядом с ним.

## Проверка { #verify }

Из `frontend/`. В корне репозитория vitest не находит конфигурацию, сообщает
примерно о 164 фантомных ошибках и оставляет лишний каталог кеша.

```bash
bunx vitest run src/components/chat/usage-meter.test.tsx   # while writing
```

Один раз, перед пушем — из корня репозитория:

```bash
make lint-frontend && make test-frontend-cov && make build-frontend
```

!!! danger "`test:coverage`, а не `test:run`"

    Задание, которое запускает CI, измеряет покрытие и падает при покрытии ниже
    100% строк, инструкций и функций или 97,5% ветвей. Набор, в котором проходят
    все тесты, всё равно может быть красным — и бывал.

Мёртвую ветвь проще удалить, чем покрыть: `?? ""` за проверкой, которая уже
доказала значение, — именно то, что порог правильно замечает.

**Если тест упирается в тайм-аут, виновата обычно машина.**
`testTimeout` равен 15 с, `asyncUtilTimeout` — 5 с, и оба измерены, а не взяты на
глаз. Ни то, ни другое не повод держать тест, который монтирует больше, чем
читают его проверки.

## Итог { #recap }

- Браузер обращается к **`/api/*` этого приложения**, никогда напрямую к
  FastAPI: один модуль пересылки, и он ставит `no-store`.
- Серверные данные живут в **слое запросов**; хранилища держат только состояние
  интерфейса.
- Элемент управления, которым вызывающий не вправе пользоваться, **не
  отрисовывается**, а списки ролей **вычисляются, а не перечисляются**.
- Тексты проходят через **`next-intl`**, числа — это `plural` из ICU, а в
  каталоге лежат тексты и только тексты.
- Новый экран обязан дать **остановку экскурсии**, а если у него есть состояние,
  видимое с одного взгляда, — ещё и виджет: оба реестра молчаливые.

## Оценки в консоли { #evals-in-the-console }

Оценки переиспользуют консольные `PageHeader`, `ListCard`, размеры диалогов, вкладки и `WizardSteps`. Изменения данных инвалидируют зарегистрированные семейства запросов через `/ws/events`; ручной вердикт к тому же обновляет наборы проверок, сеансы улучшения и защитные проверки окружений. Неудачное чтение показывает действие повтора, а не пустое состояние с видом успеха. В узких раскладках поля форм остаются 16 px, а снизу оставлено место для «Архитектора».

Наборы данных сохраняют собственные настройки общего доступа и выданные доступы к ресурсам и могут использоваться разными агентами. Модель оценки и инструкции принадлежат набору данных; у настроек генерации и улучшения своя вкладка «Настройки». Помощники, заданные кодом, сохраняют внутренние идентификаторы запусков для атрибуции, но не появляются в каталоге пользовательских агентов. Кейсы и оценки используют общие таблицы консоли; подробности кейса и проверки открываются в боковых панелях.

«Архитектор» не получает на этом этапе новой возможности записи в наборы данных. Создание вопросов — явно оцениваемое по стоимости действие с проверкой разрешений в сценарии улучшения; помощник в углу не может молча запустить эту платную работу. Его кнопка остаётся доступной рядом с экранами оценок.

`e2e/improvement.mobile.spec.ts` проходит через настоящий API и фоновый воркер. Он проверяет кейсы набора данных, редактор кейса, оценивание, проверку, результат оценки, мастер улучшения и подтверждённую публикацию с защитной проверкой окружения. Подменяется только внешняя модель. GitHub Actions сохраняет снимки экрана в светлой и тёмной теме для ширины телефона и компьютера — для визуальной проверки.
