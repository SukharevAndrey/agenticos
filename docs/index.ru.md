AgenticOS — самостоятельно размещаемая многоорганизационная платформа для
создания, управления и запуска ИИ-агентов компании.

Главное вот в чём:

!!! quote "Код определяет, конфигурация собирает"

    Бизнес-команда собирает агентов в браузере — инструкции, модель, набор
    возможностей, бюджет — и результат одинаково работает везде: веб-чат, HTTP
    API, Slack, Telegram, встроенный виджет. Сама консоль — веб-приложение;
    [приложение для компьютера](desktop.md) — та же консоль в собственном окне,
    дополнение для тех, кто хочет держать её в доке.

    Инженеры расширяют то, из чего можно собирать, на типизированном Python.
    Конфигурация получает доступ только к тому, что зарегистрировал код, —
    поэтому Конструктор без кода можно безопасно отдать человеку, который не
    инженер.

Всё остальное на этом сайте следует из одной этой фразы. Потолок — не файл
конфигурации, а то, что ваши инженеры положили в реестр, и исходный код ваш.

## Почему это называется операционной системой { #why-it-is-called-an-operating-system }

Потому что слово здесь работает. Операционная система запускает процессы и
изолирует их, применяет ограничения ресурсов, управляет доступом, добирается до
оборудования через драйверы, ведёт файловую систему, даёт многим интерфейсам одну
оболочку и пишет журнал аудита.

AgenticOS делает каждое из этого для агентов: запуски, бюджеты, проверяемые до
запроса к модели, каталог разрешений с согласованиями в роли его `sudo`, MCP и
профили моделей в роли драйверов, коллекции в вашем собственном Postgres, один
механизм выполнения за каждым способом доступа и журнал аудита, который пишется,
даже когда запуск завершился ошибкой.

[Все семь, одно за другим, и что проверить в любом другом продукте →](about/index.md#what-makes-something-an-operating-system-for-agents)

## Зачем это существует { #why-it-exists }

Большинство фреймворков для агентов дают библиотеку. Вы пишете Python,
развёртываете его, и каждое изменение поведения агента — это пул-реквест,
проверка и выпуск.

Для функции продукта это правильная форма. Для сорока небольших агентов, которые
компании на самом деле нужны, — неправильная, потому что **человек, который знает,
что агент должен говорить, — не тот человек, у которого есть доступ на коммит.**

Поэтому AgenticOS выносит агента из кода и ставит вокруг него управление.

<div class="grid cards" markdown>

- :material-shield-check:{ .lg .middle } **Бюджеты, которые останавливают запуск**

    Проверяются *до* каждого запроса к модели, а не после. Запуск, завершившийся
    ошибкой, всё равно записывает, что потратил: бюджет, который игнорирует
    ошибки, — не бюджет.

- :material-hand-back-right:{ .lg .middle } **Согласование настраивается для поддерживаемых инструментов**

    Настроенная проверка оставляет запуск ждать уполномоченного человека. Охват
    зависит от возможности, инструмента и политики.

- :material-account-key:{ .lg .middle } **Разрешения в коде, роли собираются из них**

    Места вызова проверяют разрешения, а не названия ролей. Выданный доступ
    расширяет то, что один человек может сделать с одной строкой, и никогда не
    сужает.

- :material-database-lock:{ .lg .middle } **Изоляция организаций на уровне схемы**

    Не только в слое сервисов. Шифротекст одной организации нельзя расшифровать
    для другой.

</div>

## Требования { #requirements }

Развёртывания на Podman используют [ручной путь с провайдером Docker
Compose](deploy.md#podman-support) с дополнительным переопределением для сокета
песочницы и разрешений рабочего пространства. Быстрый старт поддерживает Docker;
`podman-compose` 1.6.0 не поддерживается.

Docker и Docker Compose. Это весь список — Postgres (с pgvector), Redis, API,
воркер и консоль поднимаются вместе.

Хотите запускать сервисы вручную? Нужны Python 3.15, Node с
[bun](https://bun.sh), PostgreSQL 16 с
[pgvector](https://github.com/pgvector/pgvector) и Redis.

## Установка { #installation }

```bash
git clone https://github.com/vstorm-co/agenticos.git
cd agenticos
make dev
```

Это поднимает Postgres, Redis, API, воркер и фронтенд.

Затем создайте организацию, владельца, модель и первого агента:

```bash
make platform-bootstrap BOOTSTRAP_API_KEY=sk-...
```

И откройте консоль:

```bash
open http://localhost:3000
```

Войдите с `admin@example.com` / `admin123`.

!!! tip

    Не уверены, что экземпляр вообще может запустить агента? Спросите его.

    ```bash
    uv run agenticos cmd doctor
    ```

## Из чего состоит агент { #what-an-agent-is-made-of }

Шесть решений, и ни одно из них не код. Человек, который знает, что агент должен
говорить, принимает все шесть в браузере; публикация замораживает сочетание как
версию, и отвечает именно эта версия.

| | Что решает |
|---|---|
| **Инструкции** (Instructions) | Что агент делает, простыми словами, — и от чего он должен отказаться |
| **Профиль модели** (A model profile) | Какая модель отвечает, с какими параметрами и на что переключается во время сбоя |
| **Возможности** (Capabilities) | Что он вообще может делать: искать по вашим знаниям, читать страницу, запускать Python, рисовать диаграмму |
| **Знания** (Knowledge) | По каким коллекциям он может искать и ни по каким за их пределами |
| **Согласование** (Approval) | Какие из этих действий ждут человека, прежде чем коснуться внешнего мира |
| **Бюджет** (A budget) | Сколько он может потратить за месяц — проверяется *до* каждого запроса, а не считается после |

Измените любое из них, и ничего не уйдёт, пока вы не опубликуете. Действующая
версия остаётся читаемой, поэтому на вопрос *каким этот агент был в марте* есть
ответ.

=== "Что кто-то редактирует"

    > **Снимок экрана готовится — «Агенты».** Новые снимки в светлой и тёмной
    > темах заменят прежние изображения интерфейса.

=== "Что из него получается"

    Замороженная версия и файл, который можно выгрузить в свой git-репозиторий,
    проверить в пул-реквесте и из него восстановить:

    ```yaml
    name: Support Copilot
    instructions: |
      Answer from the product wiki and cite the document you used.
      If the wiki does not cover it, say so rather than guessing.
    model_profile_id: 8f1c...
    capabilities:
      - id: knowledge
        config: { default_top_k: 8 }
      - id: web_research
        approval: required
    collection_ids: [b2a9...]
    budget:
      monthly_usd: 50
    ```

## Проверьте это { #check-it }

Опубликуйте его, и он будет работать одинаково при любом способе доступа: чат
консоли, размещённая страница, встроенный виджет, HTTP API, Slack, Teams, Telegram,
Mattermost, Discord, Matrix.

```bash
curl -X POST http://localhost:8000/api/v1/agents/$AGENT_ID/run \
    -H "Authorization: Bearer $TOKEN" \
    -H "X-Organization-Id: $ORG_ID" \
    -H "Content-Type: application/json" \
    -d '{"prompt": "How do I rotate a provider key?"}'
```

За всеми ними один механизм выполнения, поэтому ответ не зависит от того, откуда
пришёл вопрос.

## Итоги { #recap }

- Агент — это **файл**, а не модуль. Инструкции, модель, возможности, бюджет.
- Он **публикуется как версия**, и работает именно эта версия.
- Его **можно выгрузить как YAML** в свой репозиторий и проверить в
  пул-реквесте.
- Им **управляют**: бюджеты, которые останавливают запуск, согласования, которые
  ждут человека, разрешения, проверяемые в каждом месте вызова.
- Он **ваш**: ваш Postgres, ваше оборудование.

## Стек { #stack }

FastAPI и Pydantic v2 на PostgreSQL, [Pydantic AI](https://ai.pydantic.dev) для
среды выполнения агента, pgvector для поиска, очередь задач в том же PostgreSQL
для фоновой работы и Next.js 15 для консоли.

Внешние получатели данных зависят от настроек модели, парсера, эмбеддингов,
инструментов, канала, песочницы и трассировки. Прочитайте [описание потоков данных](security.md).
