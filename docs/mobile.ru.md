# Мобильное приложение { #the-phone-app }

Встроенные экраны приватности скрывают содержимое учётных записей до того, как iOS
и Android снимут предпросмотр в переключателе приложений, — в том числе когда
биометрическая блокировка выключена. Возврат в приложение по-прежнему следует его
биометрической политике. Уведомления и другие ссылки, не связанные с
аутентификацией, не отменяют вход через OAuth, уже ожидающий в системном браузере.

Собственный OAuth использует S256 PKCE. Приложение хранит закрытый верификатор, а
обратный вызов несёт только производное от него публичное значение. Верификатор
отправляется в теле запроса обмена, никогда в URL. Выход очищает предпросмотр
уведомлений на телефоне.

Консоль работает в браузере телефона, и её можно добавить на главный экран как
приложение. Мобильное приложение AgenticOS для iOS и Android добавляет то, что может
только приложение: экран блокировки, Dynamic Island, виджеты, меню «Поделиться»,
push, пока оно закрыто, и собственную блокировку. Как и
[приложение для компьютера](desktop.md), это оболочка вокруг собственной консоли
экземпляра, поэтому вход, разрешения и проверки организации — консольные.

> **Скриншот готовится — мобильное приложение, Live Activity и виджеты.**

Это приложение на [Tauri](https://tauri.app) в `mobile/`, а нативные половины —
Swift для iOS, Kotlin для Android — лежат в `mobile/src-tauri/`.

## Доступность и самостоятельная установка { #availability-and-self-installation }

!!! info "Мобильные сборки доступны для разработки, а не для публичного распространения"

    Мы собираем мобильное приложение в CI, но пока не публикуем его через
    TestFlight, App Store или Google Play и не предоставляем поддерживаемую сборку
    мобильного релиза. Чтобы пользоваться нативным приложением уже сейчас, соберите
    и установите его сами и подключите к экземпляру AgenticOS, которым управляете вы
    или ваша организация. Мы не предоставляем размещённый сервер AgenticOS и учётные
    записи Apple для подписи вместе с приложением.

Рабочий процесс **Apps** собирает отладочный APK для Android и неподписанное
приложение для симулятора iOS. Это проверки разработки, а не релизы для магазинов.
Сборку для симулятора iOS нельзя установить на настоящий iPhone. Для работы на
реальном устройстве нужны собственная подпись и профили подготовки для приложения и
его расширений.

Из клона установите Rust и инструментарий платформы: Xcode на macOS для iOS или
Android SDK, NDK и JDK для Android. Затем:

```bash
cd mobile
bun install --frozen-lockfile
bun run ios        # iOS development on macOS
# or
bun run android    # Android development
```

Когда приложение запустится, введите адрес вашего экземпляра. Он должен быть доступен
с телефона; `localhost` на телефоне означает сам телефон, а не ваш компьютер для
разработки. [Версия для браузера и главного
экрана](#installing-the-console-instead) остаётся вариантом без сборки нативного
приложения.

Публичное распространение мобильного приложения по умолчанию отключено в рабочем
процессе релиза. Чтобы включить его позже, нужен
`AGENTICOS_MOBILE_RELEASES_ENABLED=true`; для iOS также нужны
`AGENTICOS_TESTFLIGHT_ENABLED=true` и конфигурация подписи из
[релизов приложения](desktop.md#installers-and-updates). Обычные сборки CI остаются
включёнными.

## Вход { #signing-in }

Сканирование сначала показывает имя и адрес почты целевой учётной записи. Подтвердите
учётную запись, чтобы войти; отмена оставляет текущий сеанс без изменений.
Предпросмотр никогда не расходует код и не продлевает его минутный срок жизни.

**Настройки → Мобильное приложение** (Settings → Mobile app) в консоли показывает
QR-код; отсканируйте его приложением, чтобы подтвердить вход от своего имени. Код
действует один раз, в течение минуты, а сеанс на телефоне открывается только после
подтверждения и под собственным именем телефона. Можно и просто ввести адрес сервера
и войти. Сеанс переживает перезапуски, а приложение блокируется за Face ID, Touch ID
или отпечатком пальца после пяти минут отсутствия.

**Активные сеансы** (Active sessions) в разделе **Настройки → Профиль**
(Settings → Profile) перечисляют каждое устройство со входом: «AgenticOS for iOS
0.2.0» для приложения, иначе браузер, и какие из них получают push. Отзыв одного из
них сразу завершает сеанс этого приложения.

Если первоначальное подключение или возврат после входа не загрузились за 30 секунд,
приложение возвращается к форме сервера с сохранённым адресом и сообщением о
подключении. Повторите попытку или введите другой адрес. Успешно загруженная
кэшированная страница офлайн остаётся открытой.

## Готовность подключения и сохранённые серверы { #connection-readiness-and-saved-servers }

После входа **Завершите настройку телефона** (Finish setting up this phone) проверяет
учётную запись, доступного опубликованного агента, блокировку приложения и
уведомления. Существующие учётные записи получают ту же проверку, пока настройки ещё
не полны. «Продолжить» откладывает необязательную настройку; вернуться к ней можно в
разделе **Настройки → Мобильное приложение**. Изменённый набор недостающих настроек
проверяется снова. Доступ к камере запрашивается при сканировании, к микрофону — при
запуске голоса, и никогда — проверками готовности. Отклонённые уведомления iOS
предлагают кнопку системных настроек; при возврате в приложение разрешение
проверяется заново.

**Настройки → Мобильное приложение → Сменить сервер** (Switch server) открывает
сохранённые подключения. Дайте серверу имя, отсканируйте другой код сопряжения или
введите другой адрес. Хранится до 20 серверов. Существующие установки переносят
текущий адрес автоматически. Возврат к сохранённому серверу открывает его «Обзор» и
использует его постоянный сеанс. Cookie и офлайн-хранилище не копируются между
источниками; выход или смена учётной записи по-прежнему очищают кеш устройства для
этой учётной записи. Разные сохранённые серверы должны использовать разные имена
хостов: cookie не разделяются по порту. Удаление сохранённой записи не стирает её
хранилище браузера; выйдите из системы, прежде чем передавать телефон другому.

Переключение снимает регистрацию push с предыдущего сервера, прежде чем открыть
выбор; связь с этим сервером нужна, если у него есть регистрация push. На следующем
сервере push включается явно. Приложение не держит фоновый push нескольких серверов
включённым одновременно. Политики сервера и блокировки, управляемые организацией,
имеют приоритет; отключение блокировки приложения требует аутентификации на
устройстве.

Переключение также очищает старые Live Activities, ожидающие действия и закреплённые
виджеты. Нажатия на системные уведомления привязаны к тому входу, который
зарегистрировал push, поэтому запоздавшее уведомление не может открыть диалог другого
сервера.

Смена привязанной учётной записи очищает уже показанные уведомления Android.
Переключение серверов также убирает закреплённых агентов из быстрых действий на
значке приложения iOS.

## Приватность уведомлений { #notification-privacy }

Настройки уведомлений телефона принадлежат текущему входу. **Настройки →
Уведомления** (Settings → Notifications) могут скрыть текст уведомления; настройки
чата могут отключить уведомления для диалога. И то и другое применяется на сервере до
отправки данных APNs или Web Push, поэтому работает и при закрытом приложении.
Видимый и активный чат каждые 30 секунд продлевает 90-секундный срок подавления.
Уход из чата или сворачивание приложения снимает фокус; процесс, завершённый без
очистки, оставляет не больше срока подавления. Этот выбор влияет на push, а не на
«Входящие» в приложении или идущие Live Activities.

Проверка сообщает о приёме службой push, а не о подтверждённом показе на конкретном
телефоне. Смотрите экран блокировки или центр уведомлений. Android использует
UnifiedPush и предлагает руководство по установке ntfy, когда дистрибьютор не
установлен; iOS сообщает об отсутствующей конфигурации APNs организации отдельно от
отклонённого разрешения ОС. Зависимость от Firebase не добавляется.

## Push { #push }

| Где | Через что | Где включается |
|---|---|---|
| iPhone | Служба push Apple, с собственным ключом APNs организации (**Администрирование → Настройки** (Admin → Settings)) | «Настройки → Уведомления» в приложении |
| Android | ntfy (ntfy.sh или собственный сервер компании), не Google | «Настройки → Уведомления» в приложении, с установленным ntfy |
| Браузер или консоль, добавленная на главный экран | Web Push, с собственным ключом экземпляра | «Настройки → Уведомления» |

Уведомления о каждом событии — почтой, push — выбираются для каждого события в
разделе «Настройки → Уведомления». Уведомление открывает свою страницу через
блокировку приложения.

Push, зарегистрированный входом, прекращается, когда сеанс отозван или истекает.
Связанному токену доставка идёт только тогда, когда его сеанс принадлежит тому же
пользователю. Старые подписки без записанного сеанса сохраняют постоянное разрешение;
удалите и зарегистрируйте их снова, чтобы привязать к текущему устройству.

Предпросмотр APNs сокращается, чтобы уложиться в полные 4 KiB полезной нагрузки;
слишком длинный URL маршрутизации вместо этого открывает «Обзор». Несовпадение темы
или окружения APNs сохраняет регистрацию устройства, чтобы администратор мог
исправить конфигурацию. Если хотя бы одно устройство приняло push до крайнего срока
доставки, проход помечает его отправленным, а не повторяет попытку для уже
уведомлённых устройств.


## Вне приложения { #outside-the-app }

**Live Activities** — экран блокировки и Dynamic Island на iOS, постоянное
уведомление на Android — показывают, что сейчас идёт у вас:

- ваши идущие запуски с часами;
- согласование, ожидающее вас, с кнопкой «Проверить согласование» (Review approval);
- вопрос, ответа на который агент ждёт от вас, — он открывает диалог;
- идущий голосовой звонок с часами, который сообщает, когда агент что-то
  спрашивает.

Ссылки в Live Activities открывают очередь согласований. Сами они никогда не
одобряют и не отклоняют инструмент: изучите его аргументы и выберите явно в
приложении. Старые ссылки «одобрить/отклонить» тоже открывают проверку, ничего не
решая.

**Виджеты.** Виджет быстрого взгляда считает ожидающие вас согласования и ваши
запуски в работе, указывает время подсчёта и, если у организации есть лимит, долю её
месячного бюджета, которая осталась. Виджет закреплённых агентов открывает новый чат
с агентом, закреплённым на его странице; на Android закрепление ещё и создаёт ярлык в
списке приложений с лицом агента. Числа — консольные и обновляются всякий раз, когда
консоль их читает.

**Быстрые действия.** Долгое нажатие на значок приложения, «Команды» (Shortcuts) и
Siri, кнопка действия (Action Button) и Пункт управления (Control Center) на iOS, а
также плитка быстрых настроек (Quick Settings) на Android запускают голосовой звонок,
диктовку, новый чат или согласования.

**Поделиться в AgenticOS.** Меню «Поделиться» любого приложения предлагает
AgenticOS: текст, ссылки, фотографии и файлы (до 20 МБ каждый) попадают в новое
сообщение. Пока приложение заблокировано, ничего не прикрепляется.

## В приложении { #in-the-app }

- **Чат как в мессенджере.** Кнопка `+` в поле ввода открывает «Камера», «Фото» и
  «Файлы», затем голосовой ввод и команды, звонок, модель и согласования. При
  открытии чата предлагается фотография, снятая мгновение назад; в сообщение
  попадают только те фотографии, которые вы выбрали.
- **Жесты.** Смахните ожидающее согласование вправо, чтобы одобрить его, или влево,
  чтобы отклонить, и потяните страницу вниз, чтобы перечитать её, — с тактильным
  откликом, когда отпускание что-то сделает.
- **Страницы движутся как в самом телефоне.** Открытая страница въезжает с заднего
  края, а та, к которой вернулись, — с переднего. Режим уменьшения движения это
  отключает.

Форма входа и чат укладываются в видимую область над клавиатурой, включая строку
состояния и индикатор Home. Элементы управления сохраняют полную область касания,
даже когда их значок маленький; действия вроде копирования и закрытия подсказок
остаются видимыми без наведения. Собственный вход не покрывается баннером cookie
браузера.

## Без сети { #without-a-network }

Мобильное приложение, приложение для компьютера и консоль, добавленная на главный
экран, держат копию на устройстве семь дней: список диалогов, двадцать последних
открытых диалогов с их новейшими файлами, очередь согласований и расходы, сбои и
диалоги «Обзора», которые нужно продолжить. Копия запечатана ключом, который ни один
скрипт не может прочитать, и удаляется при выходе или смене организации; обычная
вкладка браузера не хранит ничего.

Офлайн консоль показывает эту копию под баннером с временем сохранения. Сообщение,
написанное офлайн, ждёт над полем ввода, переживает закрытие приложения и
отправляется, когда связь возвращается; отклонённое сервером возвращается с пометкой
«Не отправлено» (Not sent) и причиной.

## Установка консоли вместо этого { #installing-the-console-instead }

В браузере, который умеет устанавливать, полоса под заголовком консоли предлагает
отдельное окно, push и значок на главном экране — без нативных дополнений выше. На
iPhone она объясняет как: «Поделиться», затем «Добавить на экран „Домой“». Если
закрыть её один раз, в этом браузере она больше не появится.

## Управление устройством { #device-management }

Организация может задать сервер, к которому подключается приложение, заблокировать
его, чтобы человек не мог указать приложению другой адрес, и принудительно включить
или выключить биометрическую блокировку — ключи `serverUrl`, `serverLocked` и
`biometricLock` (`person` | `on` | `off`) в управляемых конфигурациях Android и в
управляемой конфигурации приложения (AppConfig) на iOS. Политика, которую нельзя
прочитать, игнорируется, а не блокирует доступ кому-либо.

## Где он лежит в дереве { #where-it-sits-in-the-tree }

- `mobile/src-tauri/src/` — плагины Rust, которые вызывает консоль: Live Activities
  (`live.rs`), виджеты (`widget.rs`), закрепления, «Поделиться», push и управляемая
  конфигурация.
- `mobile/src-tauri/ios/Sources/AgenticOSNative/` — плагины iOS и типы, которые
  расширение виджетов разделяет с приложением.
- `mobile/src-tauri/gen/apple/Widgets/` — виджеты, элементы управления и Live
  Activity.
- `mobile/src-tauri/gen/android/` — проект Android: плагины, виджеты и их разметка.
- `frontend/src/components/mobile/` — консольная половина: что сейчас идёт, числа
  виджета, действия, которые приложение возвращает.

## Коротко { #recap }

- **Консоль остаётся на сервере.** Приложение открывает её и добавляет то, что умеет
  сам телефон.
- **Всё видно вне приложения**: запуски, согласования, вопросы и звонки на экране
  блокировки; числа, бюджет и закреплённые агенты на виджетах.
- **Push без Google** на Android, с собственным ключом организации на iPhone.
- **Копия на устройстве**, запечатанная, — на случай, когда сети нет.
