# Сравните AgenticOS { #compare-agenticos }

Большинство продуктов в этой области — одно из пяти: приложение-ассистент,
конструктор агентов, сервис ИИ-коллег, готовая корпоративная платформа или агент
для работы с кодом. AgenticOS — суверенный слой для агентов компании, который вы
запускаете сами. Эти руководства показывают, где подходит каждый вариант и что
добавляет AgenticOS.

Страницы ведёт команда AgenticOS. Источники проверены 21 октября 2026 года, у
OpenAI Frontier — 14 октября. Базовая версия AgenticOS: v1.10.0. Пересмотр — до
21 ноября 2026 года или раньше, если вендор изменит предложение, о котором
говорит руководство. Каждое руководство называет свои источники. Ни одна
учётная запись конкурента для этих руководств не использовалась.

Сведения о возможностях AgenticOS обновлены 2 ноября 2026 года по версии
v1.35.0. Дата проверки источников вендора выше не менялась; это не новый аудит
тарифов вендоров.

## Что AgenticOS даёт в любом сравнении { #what-agenticos-brings-to-every-comparison }

Это проходит через каждое руководство, поэтому сказано здесь один раз.

- **Экземпляр принадлежит вам.** Он работает на вашем оборудовании с вашим
  Postgres и хранилищем, а новый экземпляр никуда не отправляет промпты и
  документы; диагностика экземпляра включена по умолчанию и её можно отключить.
  Возможна полностью локальная установка — с локальными чат-моделями, локальными
  эмбеддингами и локальным разбором документов. См.
  [что уходит по умолчанию](../data-protection.md#nothing-leaves-by-default).
- **Любая модель, переключаемая в одном месте.**
  [28 провайдеров](../models.md#providers) стоят за
  [профилем модели](../models.md#a-model-profile) с
  [резервными моделями](../models.md#fallbacks). Смените профиль — и все агенты,
  которые его используют, перейдут на новую модель без повторной публикации.
- **Агент — это документ с версиями.** Публикация фиксирует
  [версию](../concepts.md#version),
  [окружения](../environments.md#what-an-environment-is) указывают на версии, а
  спецификация
  [экспортируется в YAML](../features.md#exportable-into-your-own-repository) в
  ваш собственный git-репозиторий.
- **Управление входит в продукт с открытым исходным кодом.**
  [Бюджеты](../governance.md#enforcement-is-before-the-request) проверяются перед
  каждым запросом к модели. [Согласования](../governance.md#approvals)
  приостанавливают запуск, пока кто-то не решит.
  [Журнал аудита](../governance.md#audit) защищён от подделки. Ничто из этого не
  ждёт корпоративного тарифа.
- **Много команд, один экземпляр.** Организации изолированы на уровне схемы. В
  [модели разрешений](../permissions.md#the-built-in-roles) шесть ролей и выданные
  доступы к отдельным ресурсам.
  [Единый вход OIDC, LDAP и Kerberos](../directory.md#signing-in-with-a-directory-account)
  сопоставляют группы каталога с ролями.
- **Один агент, все способы доступа.** Один и тот же опубликованный агент
  отвечает в веб-чате, виджете, размещённой странице, HTTP API, WebSocket, Slack,
  Telegram и Mattermost, а другие агенты обращаются к нему по
  [A2A](../channels.md#a2a). См. [способы доступа](../channels.md).
- **Люди и агенты в одном месте.** [Проект](../projects.md) даёт команде и её
  агентам общие файлы, инструкции и чаты, а
  [агент для работы с кодом](../reference/capabilities.md#coding-agent) отдаёт
  работу с кодом в Claude Code или Codex в песочнице.
  [AgenticOS — ещё и MCP-сервер](../mcp.md#agenticos-as-an-mcp-server), поэтому
  эти инструменты могут перечислять и запускать агентов компании.
- **Расширяется кодом.** [Возможность](../howto/add-capability.md) — это
  типизированный Python, а [любой MCP-сервер](../mcp.md) подключается по URL.
  Конфигурация может добраться только до того, что зарегистрировано в коде.
- **Без платы за места.** Вы платите провайдерам моделей напрямую и обслуживаете
  инфраструктуру. Vstorm предлагает помощь с внедрением по отдельному соглашению;
  см. [эксплуатация и внедрение](../rollout.md).

## Чего AgenticOS пока не делает { #what-agenticos-does-not-do-yet }

Сравнение, которое скрывает собственные пробелы, — это реклама. Проверьте всё это
на своих требованиях до пилота.

- Роли — только шесть встроенных; пользовательских ролей пока нет.
- Во входе пока нет SAML и SCIM; SAML работает через посредника идентификации,
  например Keycloak. См.
  [чего вход через каталог пока не делает](../directory.md#what-this-does-not-do-yet).
- Нет стенда для оценок и панели трассировки. Оценки и история запусков есть. См.
  [где это не закончено](index.md#where-this-one-is-not-finished).
- Нет канала для Microsoft Teams, WhatsApp, телефона или почты.
  [Голосовые звонки](../voice.md) работают в веб-чате, виджете и на размещённой
  странице, но не по телефонной линии.
- Теперь в AgenticOS есть визуальный холст сценариев с типизированными шагами,
  ветвлениями и циклами. Сравнивайте нужные типы узлов и интеграции, а не
  исходите из того, что любой холст закрывает одни и те же задачи.
- Привязка MCP со значением `writes` доверяет собственным отметкам сервера о
  режиме «только чтение», поэтому инструмент, который он ошибочно помечает как
  доступный только для чтения, выполняется без запроса; `all` приостанавливает
  каждый вызов до согласования. См.
  [чего не даёт MCP](../mcp.md#what-mcp-does-not-get-you).
- OpenShift не проверялся. Поддерживаемый
  [Helm-чарт для Kubernetes](../kubernetes.md) разворачивает API, воркер и
  консоль с внешними службами данных; Docker Compose остаётся путём для одного
  хоста.
- Вы эксплуатируете систему сами или договариваетесь об эксплуатации с Vstorm или
  другим партнёром.

## Общая проверка { #a-shared-trial }

Возьмите [набор для первого агента по документам](../howto/first-document-agent.md)
и используйте его в обоих продуктах. Задайте вопрос, на который ответ есть, и
вопрос, на который политики нет. Смените владельца запроса, переиндексируйте
источник и повторите. Сохраняйте настоящие ответы и конфигурацию, включая
неудачи.

Запишите версию продукта или тариф, модель, обработку источников, идентификацию,
доступ к инструментам, настройку согласований, канал, стоимость и ответственного
за эксплуатацию. Начните только с поиска. Если действие инструмента важно,
договоритесь о безобидном тестовом действии и ожидаемом согласовании, прежде чем
его добавлять.

## Что означают доказательства { #what-the-evidence-means }

Описание вендора подтверждает наличие задокументированной возможности, а не её
качество на вашей нагрузке. Ни одна учётная запись конкурента для этих
руководств не использовалась. Непроверенное поведение остаётся неизвестным, а не
превращается в отметку об отсутствии функции. Цены и состав тарифов меняются
часто, поэтому сверяйте их на странице по ссылке, прежде чем на них ссылаться.

Для опубликованного испытания указывайте точные входные данные, фактические
результаты, неудачные попытки и конфигурацию. Отделяйте использование моделей от
инфраструктуры, внедрения и текущей эксплуатации. Проверьте
[лицензии](../licenses.md), условия провайдера и редакцию, которую вы собираетесь
разворачивать.

## Частые вопросы { #frequently-asked-questions }

### AgenticOS — открытый исходный код? { #is-agenticos-open-source }

Да. AgenticOS распространяется под Apache-2.0 и работает на вашей инфраструктуре
с Docker Compose. У некоторых входящих в поставку компонентов свои лицензии; они
перечислены на странице [лицензий](../licenses.md).

### AgenticOS — альтернатива ChatGPT Enterprise или Claude Enterprise на собственной инфраструктуре? { #is-agenticos-a-self-hosted-alternative-to-chatgpt-enterprise-or-claude-enterprise }

Для агентов, которыми владеет ваша организация, — да. AgenticOS запускает
агентов на любом из 28 провайдеров моделей, включая OpenAI и Anthropic, с
бюджетами, согласованиями и журналами аудита в каждом экземпляре. Это не личный
ассистент для каждого сотрудника; см. руководства [ChatGPT](chatgpt.md) и
[Claude](claude-apps.md).

### Сколько стоит AgenticOS? { #how-much-does-agenticos-cost }

Платы за лицензию или за места нет. Вы платите провайдерам моделей по их тарифам
и обслуживаете инфраструктуру: хватает [4 vCPU и 8 ГБ ОЗУ](../deploy.md). Помощь
с внедрением от Vstorm согласуется отдельно.

### С какого сравнения начать? { #which-comparison-should-i-read-first }

Начните с того, какой продукт вы взвешиваете: приложение-ассистент, конструктор в
облачном пакете, конструктор на собственной инфраструктуре, сервис ИИ-коллег,
готовая платформа или агент для работы с кодом.
[Таблица в начале](#pick-the-guide-for-your-decision) указывает на каждое
руководство.

## Другие точки отсчёта { #other-starting-points }

Библиотека вроде [Pydantic AI](https://ai.pydantic.dev/) подходит агенту,
встроенному в ваше собственное приложение; AgenticOS работает на ней и добавляет
приложение для настройки и эксплуатации агентов.
[OpenClaw](https://github.com/openclaw/openclaw) описывает развёртывания для
личного и общего использования командой.
[Lindy](https://www.lindy.ai/) предлагает сервис ИИ-коллег. Это дальнейшие
кандидаты, а не продукты, отклонённые здесь.
