# Об AgenticOS { #about-agenticos }

AgenticOS — операционная система для ИИ-агентов компании: на собственной
инфраструктуре, с открытым исходным кодом, для нескольких организаций.

Он появился из-за одного наблюдения. Большинство фреймворков для агентов
дают вам библиотеку: вы пишете на Python, разворачиваете её, и каждое изменение
поведения агента — это пул-реквест, проверка и выпуск. Это точно верно для
функции продукта и точно неверно для сорока маленьких агентов, которые на самом
деле нужны компании, потому что человек, который знает, что агент должен
говорить, — не тот, у кого есть доступ к коммитам.

Поэтому здесь **код определяет, а конфигурация собирает**. Бизнес-команда
собирает агентов в браузере — инструкции, модель, набор возможностей, бюджет, —
а инженеры расширяют то, из чего можно собирать, на типизированном Python.
Конфигурация может дотянуться только до того, что зарегистрировал код, и именно
поэтому конструктор без кода безопасно отдать человеку, который не инженер.

Спецификация — это документ, поэтому она получает версию при публикации и
экспортируется в YAML в ваш собственный репозиторий git. Потолок — не этот
документ, а то, что ваши инженеры положили в реестр.

## Что делает систему операционной системой для агентов { #what-makes-something-an-operating-system-for-agents }

В этой категории слово используют вольно, и это справедливая претензия. Стоит
сказать, что оно обязано означать, потому что операционная система — не
настроение: это семь задач, и продукт либо выполняет их, либо нет.

Возьмите это как тест. Проверьте по нему AgenticOS и всё, с чем его сравниваете.

| Операционная система… | …а для агентов это |
|---|---|
| **Запускает и изолирует процессы** | Запуск и есть процесс. Он начинается, его можно остановить, он изолирован от других организаций и оставляет запись о том, что сделал |
| **Принудительно ограничивает ресурсы** — квоты, cgroups | Бюджет, который проверяется *до* допуска работы, а не подсчитывается после, на единице, за которую кто-то отвечает |
| **Управляет доступом** — пользователи, разрешения, `sudo` | Разрешения проверяются в месте вызова, а не по названиям ролей; и путь повышения прав для всего, что действует во внешнем мире |
| **Достигает оборудования через драйверы** | Один интерфейс к множеству провайдеров моделей и множеству серверов инструментов, поэтому замена любого из них не требует переписывать то, что им пользуется |
| **Ведёт файловую систему** | Долговечное место для собственных знаний организации, с прикреплёнными к нему правилами доступа |
| **Даёт многим интерфейсам одну оболочку** | Один и тот же агент отвечает через каждый способ запуска одним путём выполнения, а не так, что каждый способ запуска собирает свой |
| **Пишет журнал аудита** | Кто что запустил, когда, сколько это стоило, кто одобрил, — записано независимо от того, удался ли запуск |

### Как AgenticOS отвечает на каждую задачу { #how-agenticos-answers-each-one }

| | |
|---|---|
| Процессы | Запуски — полноправные объекты: история, стоимость, статус и изоляция организаций, обеспечиваемая ограничениями базы данных, а не кодом сервиса |
| Ограничения ресурсов | [Месячные бюджеты](../governance.md) для каждого агента, проверяемые перед каждым запросом к модели. Запуск, который завершился с ошибкой, всё равно записывает, сколько потратил, потому что бюджет, игнорирующий ошибки, — не бюджет |
| Управление доступом | [Каталог разрешений](../permissions.md) в коде, роли, собранные из него, выданные доступы на отдельные ресурсы, которые расширяют и никогда не сужают. `approval: required` — это `sudo`: запуск приостанавливается и ждёт человека |
| Драйверы | [28 провайдеров моделей](../models.md) за профилем модели и [любой MCP-сервер по URL](../mcp.md). Смените профиль, и переедут все агенты, которые им пользуются, и ни одного не нужно публиковать заново |
| Файловая система | [Коллекции, навыки и контекст](../file-processing.md) в вашем собственном Postgres, эмбеддинги с ключом по организации |
| Оболочка | Один механизм выполнения обслуживает [веб-чат, API, Slack, Telegram, виджет, размещённую страницу и расписание](../channels.md) |
| Журнал аудита | Каждый запуск, каждое решение по согласованию, каждая ротация секрета — со значениями, никогда со строками и никогда с ключом в открытом виде |

!!! info "Почему этот тест написан так, чтобы его применили и к нам"

    Список проверок, который всегда даёт один ответ, — это маркетинг. Этот
    действительно применим к любому продукту в категории, и именно так мы
    хотели бы, чтобы нас оценивали, — включая строку ниже, где ответ пока
    недостаточно хорош.

### Где он пока не закончен { #where-this-one-is-not-finished }

Мониторинг — самый слабый из семи. Каждый запуск записывает
`logfire_trace_id`, но его пока никто не читает, поэтому сегодня вы получаете
историю запусков, стоимость и статус, а не тренд, на который можно опереться.
Это есть в [плане развития](https://github.com/vstorm-co/agenticos/blob/main/docs/ROADMAP.md) как R11.

Ещё два пробела, о которых стоит знать до сравнения: SAML и SCIM пока нет —
вход выполняется по JWT, API-ключам, Google OAuth и magic links, — а механизма
оценки нет, поэтому агента перед публикацией проверяют вручную.

## Для кого это { #who-it-is-for }

Для компании, которой нужно больше трёх агентов и управление ими.

- **Тот, кто собирает агента**, не пишет на Python. Он пишет инструкции,
  включает возможности, указывает коллекцию знаний и задаёт бюджет.
- **Тот, кто отвечает за счёт**, получает бюджеты, которые останавливают
  запуск, согласования на выбранных им инструментах и след в журнале аудита.
- **Инженер** получает спецификацию, которая экспортируется в YAML в его
  собственный репозиторий git, HTTP API и платформу, исходный код которой можно
  прочитать.

## Чем он намеренно не является { #what-it-deliberately-is-not }

**Это не фреймворк для написания одного агента.**
[Pydantic AI](https://ai.pydantic.dev) — среда выполнения в его основе, и если вам
нужен один агент на Python как часть продукта, используйте Pydantic AI напрямую.

Это не значит, что он закрыт для кода. Расширять его — это и *есть* Python:
[возможность](../howto/add-capability.md) — типизированный, покрытый тестами код
в этом репозитории, а коннектор, канал или стратегия индексации следуют тому же
образцу. Разница в том, что инструмент пишут один раз, а дальше им пользуются
все.

**Это не облачный сервис.** Ваши промпты, диалоги и документы
остаются в вашем экземпляре, в его базе данных и хранилище. Исходящие
запросы — только те, что делают ваши агенты, и те, что нужны парсеру коллекции
или провайдеру эмбеддингов, плюс [диагностика экземпляра](../configuration.md#diagnostics),
которая включена по умолчанию, и её можно отключить. Цены моделей берутся из
снимка, входящего в выпуск. Операционная система ставится на вашу машину;
никто не сдаёт ядро в аренду за место.

**Это не место для написания интеграций.** Интеграция с SaaS-продуктом —
это [подключение MCP](../mcp.md), а не модуль на Python, который кто-то в этом
репозитории поддерживает под API того продукта. Поэтому каталог возможностей
короткий и таким остаётся.

## Часть, которая и есть продукт { #the-part-that-is-actually-the-product }

Большая часть ценности здесь в том, что платформа **отклоняет**: чтение из
другой организации, невыданную область доступа, превышение бюджета, повторное
решение по уже решённому согласованию, спецификацию, не прошедшую проверку при
публикации.

Успешный путь — вызов модели с подключёнными инструментами — это лёгкая
половина, и дюжина библиотек справляется с ней хорошо. Отказы — та половина,
которая решает, можно ли передать агента кому-то, кто не вы.

## Когда стоит использовать другое { #when-to-use-something-else }

Четыре из семи задач библиотека не сделает за вас никогда, а три из них
облачная платформа сделает, но не отдаст вам машину. Ни то ни другое не упрёк;
это разные продукты.

## Откуда он взялся { #where-it-came-from }

Он вырос из
[Full-Stack AI Agent Template](https://github.com/vstorm-co/full-stack-ai-agent-template),
поэтому «слой платформы» и «унаследованное от шаблона» — различия, которые
встречаются в документации для участников. Слой платформы — всё, что AgenticOS
добавляет сверху, — держится на 100% покрытия тестами в CI. Об унаследованных
подсистемах сообщают, но они не блокируют сборку, потому что держать код,
который мы не проектировали, на той же планке — значит купить цифру покрытия, а
не уверенность.

Шесть решений, определивших его форму, — почему агент — это файл, почему формат
спецификации движется только вперёд, почему проверка происходит при
публикации, — написаны для участников в
[`docs/about/design.md`](https://github.com/vstorm-co/agenticos/blob/main/docs/about/design.md).

## Кто его делает { #who-builds-it }

[Vstorm](https://vstorm.co) и каждый, кто присылает пул-реквест.

## Итог { #recap }

- **Код определяет, конфигурация собирает**: бизнес-команда собирает агентов,
  инженеры расширяют то, из чего можно собирать, и никто не ждёт другого.
- «Операционная система» здесь — **спецификация, а не ярлык**: семь задач, за
  каждой стоит механизм.
- Тест предназначен и **для других продуктов**, и для него: мониторинг —
  строка, где честный ответ «пока нет».
- Продукт — это в основном **отказы**, а не успешный путь.
- Он работает на **вашей машине**, потому что именно это делает операционная
  система.
