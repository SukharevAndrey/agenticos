# AgenticOS vs Dify { #agenticos-vs-dify }

Оба продукта разворачиваются самостоятельно, и оба умеют искать по документам, так что разница в другом. Dify — визуальный холст для приложений и сценариев на LLM: несколько рабочих пространств, SSO и журналы аудита в редакции Enterprise. AgenticOS распространяется по Apache-2.0 и поддерживает множество организаций уже в открытой версии, включая бюджеты, согласования, вход через каталог и журнал аудита с защитой от подмены.

Страницу ведёт команда AgenticOS. Источники проверены 21 октября 2026 года. Базовая версия AgenticOS: v1.10.0. Что проверено у Dify: публичный репозиторий на версии 1.17.1, его лицензия, документация и страница цен, а не протестированный облачный тариф и не закреплённое развёртывание.

Утверждения о возможностях AgenticOS обновлены 2 ноября 2026 года по версии v1.35.0. Дата проверки источников вендора выше не изменилась; это не новая проверка цен вендора.

## Где AgenticOS идёт дальше { #where-agenticos-goes-further }

### Несколько организаций без коммерческой лицензии { #multi-tenant-without-a-commercial-licence }

Лицензия Dify разрешает коммерческое использование и добавляет два условия. Нельзя эксплуатировать среду для нескольких организаций без письменного разрешения; при этом одна организация — это одно рабочее пространство. Нельзя удалять или менять логотип и сведения об авторских правах во фронтенде. Участники также соглашаются, что производитель может изменить условия лицензии.

AgenticOS распространяется по Apache-2.0. [Организации](../concepts.md#organizations) изолированы на уровне схемы, и один экземпляр может обслуживать все отделы, дочерние компании или клиентов. Вы можете менять консоль и оформлять её под своим брендом. Настройки [идентичности экземпляра](../deployment.md) охватывают название и уведомления.

### Корпоративные средства контроля в открытом продукте { #the-controls-an-enterprise-asks-for-in-the-open-source-product }

Страница цен Dify относит SSO только к Enterprise, а его документация относит свои роли и несколько рабочих пространств к Enterprise. AgenticOS поставляет единый вход и множество организаций в продукте под Apache-2.0, а вместе с ними:

- [единый вход OIDC](../configuration.md#single-sign-on-generic-oidc) с Entra, Okta, Keycloak и другими, [LDAP и Kerberos](../directory.md#signing-in-with-a-directory-account) и [сопоставление групп каталога](../directory.md#directory-group-mappings) с ролями;
- [шесть ролей и выданные доступы на отдельные ресурсы](../permissions.md#layer-3-visibility-and-grants), которые расширяют доступ к одному агенту или коллекции;
- [журнал аудита с защитой от подмены](../governance.md#audit), записываемый в той же транзакции, что и действие, о котором он сообщает;
- [сроки хранения](../governance.md#retention) для каждого класса данных и [секреты с конвертным шифрованием](../secrets.md#envelope-encryption), запечатанные для каждой организации.

Шесть ролей фиксированы. Свои роли, как и SCIM, пока недоступны.

### Бюджет, который останавливает следующий вызов модели { #a-budget-that-stops-the-next-model-call }

Документация Dify не описывает лимит расходов, применяемый до вызовов модели в Community Edition. На ваших собственных ключах оплата уходит на счёт каждого провайдера.

AgenticOS проверяет [месячный бюджет](../governance.md#budgets) каждого агента и лимит организации [перед каждым запросом к модели](../governance.md#enforcement-is-before-the-request) и записывает и стоимость неудачного запуска. [Порученная работа](../governance.md#delegation-spends-the-parents-budget) расходует бюджет родительского агента, поэтому субагент не может потратить в обход него.

### Согласование на инструменте, а не только в потоке { #approval-on-the-tool-not-only-in-the-flow }

Узел Human Input в Dify приостанавливает сценарий и отправляет форму, а запрос закрывается после первого ответа. В AgenticOS [согласование](../governance.md#approvals) задаётся для каждой возможности и может быть переопределено для каждого инструмента. У подключения MCP есть собственная [политика](../mcp.md#which-calls-wait-for-a-person): нет, запись или всё. Запуск приостанавливается, выбранные вами люди получают [оповещение](../governance.md#alerts), а повторное решение по уже решённому согласованию отклоняется.

### Изменение, которое может внести бизнес-команда { #a-change-a-business-team-can-make }

В Dify процесс меняют, редактируя холст. В AgenticOS владелец из бизнеса правит инструкции, включает возможность или редактирует визуальный сценарий, а затем публикует. Каждая [версия](../concepts.md#version) остаётся читаемой, протестированную версию можно перевести в [окружение](../environments.md#the-workflow-it-is-for), а спецификация [экспортируется в YAML](../features.md#exportable-into-your-own-repository) для проверки в пул-реквесте. Настройка может дотянуться только до того, что зарегистрировали инженеры.

## Когда Dify подходит лучше { #when-dify-is-the-better-fit }

- Вам больше нравится именно эта библиотека узлов, интеграции и опыт редактирования сценариев. У AgenticOS тоже есть визуальный конструктор сценариев; доступные узлы и семантика выполнения различаются.
- Вам нужны его плагины из маркетплейса, его гибридный поиск с переранжированием или множество интеграций для наблюдаемости. У AgenticOS пока нет переранжировщика и панели трассировок.
- Одного рабочего пространства достаточно, или условия редакции Enterprise вам подходят.

## Сравните изменение, а не только ответ { #compare-a-change-not-only-an-answer }

Возьмите одинаковый [синтетический справочник](../howto/first-document-agent.md), вопросы и контрольные проверки. Запишите версию, модель, настройки обработки источников и идентификацию на каждой стороне. Затем смените владельца запроса в источнике и повторите после обработки.

Добавьте две проверки, которые показывают различия выше. Создайте вторую организацию для второй команды и дайте агенту бюджет в несколько центов, а затем запустите его сверх этого лимита. Запишите, что каждый продукт разрешает, отклоняет и записывает в журнал, по [методике сравнения](comparison.md#a-shared-trial).

## Частые вопросы { #frequently-asked-questions }

### AgenticOS — альтернатива Dify с открытым исходным кодом? { #is-agenticos-an-open-source-alternative-to-dify }

Да. Оба разворачиваются самостоятельно, и оба умеют искать по документам. AgenticOS распространяется по Apache-2.0 без условий о нескольких организациях и о логотипе и включает SSO, роли, бюджеты, согласования и журнал аудита с защитой от подмены без редакции Enterprise.

### Может ли Dify работать как сервис для нескольких организаций? { #can-dify-run-as-a-multi-tenant-service }

Лицензия Dify требует письменного разрешения на эксплуатацию среды для нескольких организаций, где одна организация — это одно рабочее пространство. AgenticOS обслуживает множество организаций из одного экземпляра по Apache-2.0.

### Есть ли у AgenticOS визуальный конструктор сценариев, как у Dify? { #does-agenticos-have-a-visual-workflow-builder-like-dify }

Да. AgenticOS включает визуальный конструктор сценариев с типизированными шагами, ветвлениями, циклами и опубликованными версиями. Dify остаётся отдельным продуктом со своей библиотекой узлов и экосистемой; сравните узлы, которые действительно нужны вашей задаче.

### Что дешевле в эксплуатации? { #which-one-costs-less-to-run }

Dify Community Edition и AgenticOS оба бесплатны при самостоятельном размещении; вы платите за модели и инфраструктуру. Возможности Dify уровня Enterprise оценивает его отдел продаж. В AgenticOS эти механизмы контроля уже есть в открытом продукте.
