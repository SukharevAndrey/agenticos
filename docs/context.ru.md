# Файлы контекста { #context-files }

**Файл контекста** — это часть постоянных знаний, написанная один раз и
привязанная ко многим агентам: глоссарий, голос бренда, матрица эскалации,
список продуктов, которые вы действительно продаёте.

Если вы писали `AGENTS.md` для агента для работы с кодом, это та же идея в той же
форме — файл Markdown, который говорит, как здесь всё делается, и хранится рядом
с работой, а не внутри одного промпта. Разница в том, кто его читает: `AGENTS.md`
в репозитории читает любой инструмент, который его откроет, а файл контекста
здесь привязан к выбранным вами агентам, версионируется вместе с ними и доступен
для редактирования человеку, который действительно знает ответ.

Это ответ на проблему, с которой каждая компания сталкивается на третьем
агенте: одни и те же три абзаца, вставленные в три набора инструкций и потом
отредактированные в одном из них.

В Конструкторе **Контекст → Новый файл контекста** (Context → New context file)
создаёт файл прямо в панели возможности и привязывает его к текущему черновику,
включая возможность «Контекст». Дальше вы можете выбрать, как этот агент использует файл.
Публикация остаётся отдельным шагом. Для создания нужны разрешения на
редактирование и агента, и файлов контекста.

## Место между навыками и знаниями { #where-it-sits-between-skills-and-knowledge }

Есть три вещи, которые ставят текст перед моделью, и неверный выбор обычно
приводит к агенту, который либо игнорирует то, что ему сказали, либо вообще
ничего не читает.

| | Что в нём | Что видит модель |
|---|---|---|
| **Файл контекста** | Постоянные факты, небольшие и стабильные — глоссарий, руководство по тону, схема организации | Всегда или по требованию — выбираете вы |
| **[Навык](skills.md)** | Процедура для одного вида задач — как обработать запрос на возврат | Когда модель решает, что происходит именно эта задача |
| **[Коллекция знаний](file-processing.md)** | Корпус, слишком большой, чтобы его прочитать, — каждый документ политик, каждая заявка | Только фрагменты, которые вернул поиск |

Эмпирическое правило: **если текст короткий и всегда уместен, это файл
контекста. Если длинный — это знания. Если это процедура — это навык.**

Страница **Контекст** (Context) показывает начало каждого файла на его карточке.
`GET
/api/v1/context` возвращает его как `excerpt`: несколько ограниченных строк,
никогда не всё тело.

## Два режима, и разница в стоимости { #two-modes-and-the-difference-is-cost }

У каждого привязанного файла контекста есть режим в настройках возможности
**Контекст** агента. Один и тот же общий файл может быть в режиме `inject` для
одного агента, в режиме `link` для другого или выключен для третьего.

=== "`inject` — всегда внутри"

    Тело дословно вставляется в инструкции агента. Модель всегда его знает, не
    решая, заглянуть ли, и без вызова инструмента.

    Используйте это для того, в чём агент не должен ошибаться: как называются
    ваши продукты, к кому эскалировать, как называть компанию.

    **Он читается на каждом ходе диалога**, поэтому входит в стоимость каждого
    сообщения. Держите внедрённые файлы короткими.

=== "`link` — чтение по требованию"

    Тело остаётся вне промпта и доступно через инструмент. Модель читает его,
    только когда решает, что файл уместен, выбирая по имени и однострочному
    описанию, которое пишете вы.

    Используйте это для справочных сведений, которые нужны иногда: редко
    требуемая политика, региональное отличие, длинный список.

    Ничего не стоит на ходах, где он не нужен, и совсем ничего — если модель так
    и не заглянет, что тоже риск.

!!! tip "Пишите описание для модели, а не для человека"

    Связанный файл выбирается только по имени и описанию. «Политика возвратов»
    говорит модели меньше, чем «когда клиент может вернуть товар, сроки и три
    исключения», — и от этой разницы зависит, откроют ли файл вообще.

## Привязка к агенту { #attaching-them-to-an-agent }

Файлы контекста принадлежат организации, а не агенту. Вы пишете один файл, и к
нему привязывается любое число агентов.

Включите возможность **Контекст** у агента, затем привяжите файлы, которые ему
нужны. Последующее редактирование файла меняет то, что знает каждый привязанный
агент, **на его следующем запуске** — без повторной публикации ни у одного из
них.

В этом весь смысл и в этом же осторожность: изменение внедрённого файла — это
изменение каждого агента, который его несёт. Относитесь к нему как к общему
несущему тексту, которым он и является.

В Конструкторе у каждого выбранного файла есть **Использовать для этого агента**
(Use in this agent) и селектор режима. Эти настройки принадлежат черновику агента
и вступают в силу при публикации. Редактор библиотеки меняет только общее
содержимое и описание; формат файла определяется его именем. Существующие версии
агентов без переопределений для отдельных файлов сохраняют прежний режим и
доступность.

Возможность также управляет тем, доступен ли её инструмент чтения. Если выключить
инструмент чтения (**Выключено** (off)), до модели доходят только внедрённые
файлы, и ничего не читается по требованию — разумный выбор, когда вы хотите,
чтобы входные данные агента были полностью предсказуемы.

Можно начать и с файла: **Добавить агенту** (Add to an agent) на его карточке
добавляет файл в черновик агента с включённой возможностью «Контекст», а карточка
говорит, какие агенты уже его несут. У базы знаний такое же действие на её
собственной странице.

## Изменения, которые предлагает помощник { #changes-the-assistant-proposes }

**Улучшить с помощником** (Improve with the assistant) в редакторе файла просит
[помощника по редактированию](authoring.md#context-files) написать лучшее тело на
основе запусков агентов, которые читают файл. Предложенное не применяется: оно
ждёт над списком на странице «Контекст», с объяснением почему, запусками, на
которые опирается, и агентами, привязанными к файлу.

Применение делает то же, что ручное редактирование файла: сразу действует у
каждого агента, чья опубликованная версия читает файл. Поэтому сначала идёт
**Проверить с оценками** (Check with evals) на одном из этих агентов. Рядом с
**Применить** (Apply) изменение говорит, что даст применение: каждый агент и
окружение, где оно станет действующим, наборы проверок оценок, которые оно ставит в
очередь, и обязательные проверки, которые сработают только при следующем
переводе агента в окружение. Файл, который кто-то отредактировал после того, как
изменение было предложено, отклоняет изменение; правка никогда не записывается
поверх.

Повторная просьба помощнику перезаписывает ожидающее изменение, а не добавляет
второе. Решение называет ту версию изменения, которую вы прочитали, поэтому из
двух одновременных решений засчитывается только одно, а страница, открытая до
перезаписи, отклоняется с сообщением «The proposal changed since you opened it»,
пока вы не просмотрите новую версию. Изменение, которое говорит то же, что уже
сказано в файле, не предлагается вовсе.

Любая правка файла — применённая или сделанная вручную — и его удаление ставят в
очередь наборы проверок оценок, которые запускаются при изменении зависимости,
для каждого читающего его агента, а применение изменения уведомляет владельцев
этих агентов.

## Доступ { #access }

У файла контекста есть владелец и видимость, как у любого другого ресурса здесь,
а чтение каталога закрыто `context:view`. Файл, к которому человеку не выдан
доступ, — это файл, который он не может привязать, и это решают
[те же три слоя](permissions.md), что и везде.

Всё по-настоящему секретное в него не попадает: файл контекста — это текст,
который агент прочитает вслух, если задать правильный вопрос. Учётным данным
место в [хранилище секретов](secrets.md).

## Итог { #recap }

- Файл контекста — это **постоянные знания, написанные один раз и привязанные ко
  многим агентам**.
- **`inject`** всегда в промпте и стоит на каждом ходе; **`link`** читается по
  требованию и ничего не стоит, пока его не прочитали.
- Связанный файл выбирают по его **описанию**, поэтому пишите его для модели.
- Редактирование файла обновляет **каждого привязанного агента на его следующем
  запуске**, ничего не публикуя заново.
- Коротко и всегда уместно → контекст. Длинно → [знания](file-processing.md).
  Процедура → [навык](skills.md).
