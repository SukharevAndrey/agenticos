# Как внести вклад в AgenticOS

[English](CONTRIBUTING.md) · [Polski](CONTRIBUTING.pl.md) · [Deutsch](CONTRIBUTING.de.md) · [Español](CONTRIBUTING.es.md) · **Русский**

В этом документе мало церемоний и много конкретики о том, что действительно
приводит к отклонению пул-реквестов.

## Планка

Код попадает в репозиторий тогда, когда мейнтейнер слил бы его без изменений.
Конкретно:

- **Полная типизация.** Никакого `Any`, никакого `# type: ignore`, никакого
  `except:`, после которого ошибка исчезает. Моделируйте точными типами, а не
  рыхлыми словарями.
- **Ошибки не молчат.** Падайте с понятным сообщением; никогда не проглатывайте
  исключение и не замазывайте ошибку резервным вариантом. Молчаливый неверный
  ответ хуже падения.
- **Никакого балласта.** Ни умозрительных абстракций, ни неиспользуемых
  параметров, ни закомментированного кода, ни веток «на всякий случай».
- **Комментарии объясняют *почему*.** Что делает код, видно; почему он делает
  это так — нет, а именно это нужно читателю через полгода.
- **Следуйте окружающему коду.** Его идиомы важнее личных предпочтений.

## Подготовка окружения

```bash
make dev            # postgres, redis, api, worker, frontend
make seed           # an organization, an owner, a default model profile
```

Бэкенду нужен `VAULT_MASTER_KEY`. Без него он откатывается на `SECRET_KEY`:
локально это допустимо, а в рабочей среде отклоняется.

## Запуск тестов

Полная картина — в [`AGENTS.md`](AGENTS.md#testing). Коротко:

```bash
make test               # backend, with the coverage gate
make test-frontend      # vitest unit + integration, no coverage
make test-frontend-cov  # the same, plus the gate CI applies
make test-e2e           # playwright
make check              # every CI job except e2e — run this before a pull request
```

**`make test-frontend` не измеряет покрытие, а единственное условие прохождения
для фронтенда — порог покрытия.** Это быстрый цикл; ответ — `make check`.

**Слой платформы держится на 100% покрытия**, и CI это проверяет. Речь об
`app/agents/`, каталоге разрешений, хранилище секретов и сервисах, построенных
поверх них. Подсистемы, унаследованные от шаблона (конвейер RAG, коннекторы,
адаптеры каналов), попадают в отчёт, но не являются условием прохождения
сборки — держать код, который мы не проектировали, на той же планке значило бы
писать тесты, набитые моками, которые покупают цифру, а не уверенность.

Если вы добавляете файл в слой платформы, ему нужны тесты, которые упали бы при
изменении поведения. Тест, проходящий только по счастливому пути, не считается.

## Архитектура в одном абзаце

Агент — это **данные**, а не код. `AgentSpec` — контракт: его редактирует
Конструктор, база данных версионирует его, `app/agents/factory.py` создаёт по
нему экземпляр, а клиент может закоммитить его как YAML в свой репозиторий git.
Всё, из чего собирается агент, — это **возможность**: поиск по знаниям,
исследование в интернете, контроль бюджета, набор навыков, — объявленная в коде
с метаданными и собранная конфигурацией. Конфигурация может дотянуться только
до того, что зарегистрировал код.

Отсюда следуют два правила, и большинство замечаний на ревью сводятся к ним:

**Идентификаторы постоянны.** Идентификатор возможности встречается в
сохранённых спецификациях и в репозиториях клиентов. Переименовывайте класс
Python свободно; изменение идентификатора — несовместимое изменение.

**Проверяйте при публикации, а не во время выполнения.** Сломанный агент должен
отклоняться, пока кто-то смотрит на форму, а не в три часа ночи в разговоре с
клиентом.

## Добавление возможности

Одна папка в `app/agents/capabilities/`, повторяющая устройство остальных:

```
app/agents/capabilities/your_thing/
    __init__.py        # registration + public exports
    _capability.py     # the AbstractCapability subclass
    _toolset.py        # its tools, if it has any
    README.md          # the decisions behind it, not a description of the code
```

Зарегистрируйте её в `load_builtins()` в `_registry.py` — иначе для Конструктора
она не существует; эта связанность намеренная.

Если возможность может действовать во внешнем мире, пометьте её
`side_effecting=True`. Тогда согласование человеком становится поведением по
умолчанию, а забытый флаг — это то, из-за чего агент в итоге рассылает письма
без участия человека.

## Пул-реквесты

- Одна тема на пул-реквест. Рефакторинг и новая функция в одном диффе не будут
  рассмотрены ни как то, ни как другое.
- Исправление ошибки идёт вместе с регрессионным тестом, который падает без
  этого исправления.
- Напишите в описании, что вы решили и почему. Что именно — показывает код.
