AgenticOS даёт каждой команде ИИ-коллег: агентов, которые работают с файлами, выполняют код, просматривают сайты и используют инструменты и знания вашей компании. Ваши сотрудники и ваши агенты работают в одном общем чате, а любой агент может передать код в Claude Code или Codex — в рамках подписки на ChatGPT или Claude, которую вы уже оплачиваете. Платформа открыта (Apache-2.0) и работает на собственной инфраструктуре: это слой, который вы запускаете сами. Создавайте агентов и публикуйте их в браузере, делитесь ими с коллегами и управляйте их доступом, стоимостью и результатами в одном месте.

**Впервые здесь?** Пролистайте [вводную презентацию из 17 слайдов](https://vstorm-co.github.io/agenticos/presentation/): проблема, идея, продукт на настоящих экранах, его механизмы контроля и ограничения, а также первые шаги. ## Новое в последних выпусках

- **Ваш локальный Claude Code или Codex в чате приложения для компьютера.** Выберите агента для работы с кодом для каждого диалога, работайте в одобренной локальной папке, возобновляйте его сеанс и вносите правки, пока он работает. Вход выполняется в терминале самого агента для работы с кодом.
- **Ваши навыки и инструкции проекта.** Разрешите диалогу в приложении для компьютера использовать локальные навыки и `AGENTS.md` / `CLAUDE.md`, прочитанные с вашего компьютера. В каждом новом чате этот общий доступ выключен.
- **Discord присоединяется к Slack, Teams, Telegram и Mattermost.** Отвечайте на упоминания, личные сообщения и `/ask`; просматривайте согласования и вопросы прямо в канале. [Настройте канал](https://vstorm-co.github.io/agenticos/ru/channels/).
- **Больше полезных визуализаций и приложений.** Рисуйте карты стран, метки и маршруты встроенным `AOWorldMap` или собирайте презентацию как приложение с помощью навыков для презентаций. Возможность «Наблюдение за командой» показывает вывод тестов или журналов, пока агент работает.

## 💡 Что такое AgenticOS?

**AgenticOS — открытый (Apache-2.0) слой на собственной инфраструктуре для создания, совместного использования и управления ИИ-агентами во всей компании.** Команды настраивают агента в браузере: пишут инструкции, выбирают модель и включают инструменты. Они подключают его к корпоративным документам и приложениям и публикуют в веб-чате, Slack, Teams, Discord, Mattermost, Telegram, в виджете для встраивания или через API. Администраторы определяют, кто может пользоваться каждым агентом, сколько он может тратить и какие действия требуют согласования с человеком. Каждый запуск записывается.

Большинство фреймворков для агентов дают библиотеку, поэтому любое изменение поведения агента — это pull request, проверка и выпуск. Для небольших агентов, которые на самом деле нужны компании, это неподходящая форма: человек, который знает, что агент должен отвечать, не имеет прав на коммит. **Код определяет, конфигурация собирает:** инженеры расширяют набор того, что можно собрать, а конфигурация может дотянуться только до того, что зарегистрировал код.

Он работает на вашей инфраструктуре с Docker Compose и поддерживает 28 провайдеров моделей, включая вашу подписку ChatGPT и локальные модели через Ollama и vLLM. Агенты работают на [Pydantic AI](https://ai.pydantic.dev) и [pydantic-ai-harness](https://pydantic.dev/docs/ai/harness/); слой вокруг них использует FastAPI, PostgreSQL с pgvector и Next.js. Проект поддерживает [Vstorm](https://vstorm.co).

**Для кого:**

- Компании, которым нужен **внутренний слой ИИ-агентов**, принадлежащий им, а не ассистенты за рабочее место в облаке поставщика.
- Команды с **повторяющейся работой по документам и инструментам**: отчёты, ответы в поддержке, проверка договоров, анализ данных.
- ИТ- и службы безопасности, которым для ИИ-агентов нужны **суверенитет данных, корпоративный вход, бюджеты, согласования и журнал аудита**.
- Инженеры, которым нужны **типизированные точки расширения на Python** и консоль, которой смогут пользоваться их нетехнические коллеги.

**Как AgenticOS встраивается в компанию:** отделы вроде финансового, операционного или совета директоров используют общих агентов в веб-чате, Slack или приватном рабочем пространстве. ## Запустите на своём сервере. Открывайте где угодно.

Сервер хранит рабочее пространство. Браузер, приложение для компьютера и телефон подключаются к этому экземпляру с его учётными записями, агентами и контролем доступа.

<a id="server-setup"></a>

### Разверните сервер компании

Ваш ИТ-отдел один раз настраивает рабочее пространство, затем выдаёт адрес HTTPS и создаёт вам учётную запись. Этот адрес можно открыть в браузере или в приложении для компьютера. Если нужна помощь с внедрением, [поговорите с Vstorm](https://vstorm.co/contact-us/).

<details>
<summary>Настройка сервера для ИТ-отдела и разработчиков</summary>

Возьмите хост Linux с **4 vCPU и 8 ГБ ОЗУ**, Docker Engine 24+, Compose 2.24+ и `make`. Направьте на него два имени DNS — например, `app.example.com` и `api.example.com` — и разрешите HTTPS через обратный прокси. Поддерживаемый вариант развёртывания — Docker Compose на одном хосте.

```bash
# On the server. Start from a released version so code and images stay aligned.
git clone --branch v1.38.2 --depth 1 https://github.com/vstorm-co/agenticos.git
cd agenticos
bash scripts/server-init.sh
```

Установщик спросит имена хостов сайта и API и адрес эл. почты для сертификата, а затем создаст `backend/.env`. Укажите там `AGENTICOS_VERSION=1.38.2`, чтобы закрепить этот выпуск. Для нового хоста со встроенным прокси Traefik:

```bash
docker network create traefik_webgateway
docker compose --env-file backend/.env -f docker-compose-traefik.yml up -d
make prod PROXY=traefik
make prod-frontend PROXY=traefik
```

Затем [создайте первую организацию, владельца и агента](https://vstorm-co.github.io/agenticos/ru/deploy/#start-it-and-create-the-first-account), откройте адрес сайта по HTTPS и добавьте учётные данные моделей вашей организации. Руководство также описывает готовый прокси, Nginx, обновления и резервные копии. Делайте резервную копию базы данных **и ключа хранилища секретов из `backend/.env`**.

```bash
docker compose --env-file backend/.env -f docker-compose-prod.yml \
  exec -T app agenticos cmd bootstrap \
  --email you@example.com --password '<your-password>' \
  --org 'Your Company' --provider anthropic --api-key '<your-api-key>'
```

[Полное руководство по развёртыванию сервера](https://vstorm-co.github.io/agenticos/ru/deploy/) · [Список настроек для эксплуатации](https://vstorm-co.github.io/agenticos/ru/configuration/#production-checklist)

### Используйте AgenticOS на телефоне

**Доступно уже сейчас, без сборки:** откройте адрес экземпляра по HTTPS в мобильном браузере и войдите. Используйте подсказку установки в поддерживаемом браузере; на iPhone выберите **Поделиться → На экран «Домой»**. Консоль подстраивается под телефон, включая чат, файлы и согласования.

**Нативные iOS и Android:** исходный код лежит в `mobile/`, есть блокировка по биометрии, общий доступ, виджеты и встроенные уведомления. Сейчас это **сборки для разработки**: нет публичного App Store, Google Play, TestFlight и поддерживаемой загрузки выпуска. Чтобы попробовать нативное приложение, установите Rust и Xcode на macOS (для iOS) либо Android SDK/NDK и JDK (для Android), затем:

```bash
cd mobile
bun install --frozen-lockfile
bun run ios        # iOS development on macOS
# or: bun run android
```

Устанавливайте со своей подписью и профилем подготовки, если это требуется. Введите адрес сервера, доступный с телефона, или привяжитесь из раздела **Настройки → Мобильное приложение** (Settings → Mobile app) по одноразовому QR-коду и подтвердите учётную запись. `localhost` на телефоне означает сам телефон. Для встроенных уведомлений нужна конфигурация экземпляра под конкретную платформу; [руководство по мобильному приложению](https://vstorm-co.github.io/agenticos/ru/mobile/) описывает подготовку к сборке, привязку и уведомления.

### 🤖 Создавайте агентов, которых команда может переиспользовать

Выберите модель, инструкции и инструменты агента в браузере. Опубликуйте версию, которой будут пользоваться коллеги; просматривайте прежние версии и откатывайтесь к ним при необходимости. Держите специализированных агентов для исследований, отчётности, работы с кодом и операций в одном каталоге.

<img src="docs/assets/readme/builder-annotated.webp" alt="Конструктор агента с четырьмя пронумерованными областями: имя и статус, вкладки, инструкции и модель." width="100%">

У конструктора агента четыре области: **(1)** имя и статус публикации — черновик остаётся приватным, пока вы не опубликуете версию; **(2)** вкладки для набора инструментов, MCP-серверов, лимитов, доступности и истории версий; **(3)** инструкции, написанные простым языком, как бриф для нового коллеги; и **(4)** модель, которая выбирается для каждого агента из настроенных провайдеров.

Коллеги могут пользоваться опубликованным агентом в **веб-чате, Slack, Mattermost или Telegram**, если эти каналы настроены, в **виджете для встраивания** или на **размещённой странице**, а также через **API** и **WebSocket**. ### 📂 Работайте с файлами и кодом

Попросите агента проанализировать таблицу, построить график, подготовить документ или поработать с репозиторием. Если настроена песочница на контейнерах и включено выполнение команд, он может **читать и изменять файлы, запускать команды оболочки и выполнять код Python или JavaScript**. Встроенный набор инструментов включает средства для данных, диаграмм и документов, в том числе LibreOffice.

Если вы пользуетесь [Claude Code](https://code.claude.com/docs/en/overview) или [Codex](https://developers.openai.com/codex/cli/), работа с файлами и командами покажется знакомой. AgenticOS переносит такую работу в общий слой на собственной инфраструктуре — со знаниями компании, переиспользуемыми агентами и контролем доступа в организации. То, чего агент сможет добиться, зависит от его модели, включённых инструментов и инструкций. [Настройка песочницы](https://vstorm-co.github.io/agenticos/ru/sandbox/)

### 🧠 Научите агентов тому, как работает ваша команда

- **Навыки** хранят повторно используемые процедуры: как проверять код, писать отчёт или изучать рынок. Поддерживайте их в одном месте и применяйте во многих агентах.
- **Контекст** хранит постоянные знания: глоссарий, политику или стиль бренда. Добавьте его в промпт или позвольте агенту читать его по запросу.
- **Базы знаний (RAG)** делают загруженные документы доступными для поиска. Выбирайте параметры разбора, смотрите состояние обработки и фрагменты или синхронизируйте документы из источника, перечисленного ниже.

<img src="docs/assets/readme/rag-pipeline.webp" alt="От файла к ответу с цитатами: источники, чтение, разбиение, эмбеддинги, ответ." width="100%">

**Как работает генерация с дополнением поиском (RAG) в AgenticOS:** документы загружают или синхронизируют из Google Drive, S3/MinIO, Git, с сайтов, из SharePoint или OneDrive. Их читает парсер: PyMuPDF и LiteParse работают локально, со сканами через OCR, а LlamaParse — облачный сервис. Затем документы разбиваются на фрагменты, для них строятся эмбеддинги моделью OpenAI, OpenRouter или локальной Ollama, и всё это сохраняется в PostgreSQL с pgvector. Во время вопроса агент ищет по векторам с фильтрами и отвечает с цитатами.

Безопасность строится слоями. Учётные данные лежат в хранилище секретов с конвертным шифрованием. Код выполняется в изолированных песочницах. Опубликованные страницы тоже изолированы. У каждой организации есть журнал аудита с цепочкой хешей. Сеансы короткоживущие и отзываемые, действуют лимиты запросов. Журналы очищаются от чувствительных данных, а данные удаляются по графику хранения.

| Исходящее направление | Когда используется | Локальная альтернатива |
|---|---|---|
| Провайдер модели | При каждом запуске агента | Ollama, vLLM или LM Studio на вашем оборудовании |
| Провайдер эмбеддингов | Индексация и поиск по документам | Локальные модели эмбеддингов Ollama |
| LlamaParse | Коллекции, настроенные на этот парсер | PyMuPDF или LiteParse, оба локальные |
| Поиск в интернете | Агенты с включённым поиском в интернете | Отключите эту возможность |
| MCP-серверы, каналы чата | Только те, что вы подключили | Серверы на собственной инфраструктуре, веб-чат |
| Трассировка Logfire | Только когда настроен токен | Встроенная история запусков |

- **Хранилище секретов:** отдельный ключ данных для каждого секрета, завёрнутый по организации и версии ключа; мастер-ключи ротируются; значения больше никогда не показываются.
- **Песочницы:** у API нет доступа к сокету Docker; контейнеры не получают сеть без необходимости, действуют лимиты процессора, процессов и времени; gVisor — по желанию.
- **Журнал аудита:** цепочка хешей для каждой организации, проверяемая и выгружаемая.
- **Профиль HIPAA:** [`deploy/profiles/hipaa/`](deploy/profiles/hipaa/) и `agenticos cmd doctor --profile hipaa` проверяют работающий экземпляр на соответствие техническим мерам §164.312. Это проверка конфигурации, а не сертификация. [Чего профиль не обещает](https://vstorm-co.github.io/agenticos/ru/security/#the-hipaa-profile-and-what-it-does-not-claim)

## Для разработчиков и операторов

AgenticOS построен на FastAPI, Pydantic AI, PostgreSQL с pgvector, Redis и Next.js. Инженеры добавляют возможности, коннекторы синхронизации и записи каталога MCP на типизированном Python; команды собирают агентов в консоли из зарегистрированных возможностей.

| Слой | Что там работает |
|---|---|
| Консоль | Next.js |
| API | FastAPI |
| Среда выполнения агентов | [Pydantic AI](https://ai.pydantic.dev) и [pydantic-ai-harness](https://pydantic.dev/docs/ai/harness/), один механизм выполнения за каждым способом доступа |
| Фоновая работа | Очередь задач в PostgreSQL, которую обслуживает `python -m app.worker` |
| Данные | PostgreSQL с pgvector |
| Выполнение кода | Контейнеры, запускаемые `sandboxd` |

Вызовите опубликованного агента через `POST /api/v1/agents/{id}/run` как участник, прошедший проверку подлинности или передавайте токены потоком по WebSocket.

## ❓ Частые вопросы

<details>
<summary><b>Можно ли пользоваться AgenticOS коммерчески бесплатно?</b></summary>

Да. AgenticOS распространяется по лицензии Apache-2.0, которая разрешает коммерческое использование, изменение и закрытое развёртывание. Вы платите за инфраструктуру, на которой он работает, и за выбранных провайдеров моделей и внешние сервисы. Название и логотип AgenticOS лицензией не покрываются.

</details>

<details>
<summary><b>Может ли AgenticOS работать только на локальных моделях?</b></summary>

Да. Настройте Ollama, LiteLLM или совместимый с OpenAI сервер вроде vLLM или LM Studio как провайдера моделей, используйте локальные модели эмбеддингов через Ollama и разбирайте документы с помощью PyMuPDF или LiteParse. Размещение одной консоли на собственной инфраструктуре не делает локальными все модели, парсеры и инструменты: проверяйте каждое настроенное направление. [Модели](https://vstorm-co.github.io/agenticos/ru/models/) · [Потоки данных](https://vstorm-co.github.io/agenticos/ru/security/)

</details>

<details>
<summary><b>Какие способы входа и роли поддерживаются?</b></summary>

Эл. почта и пароль с одноразовыми ссылками для входа, Google, универсальный единый вход OIDC (Entra ID, Okta, Keycloak, Auth0, Authentik, Google Workspace), LDAP и Kerberos. Шесть встроенных ролей (Owner, Admin, Builder, Operator, Member, Viewer) сочетаются с группами отделов и общим доступом к отдельным ресурсам. Многофакторную аутентификацию обеспечивает ваш провайдер идентификации; собственных MFA, SAML и SCIM пока нет. [Разрешения](https://vstorm-co.github.io/agenticos/ru/permissions/)

</details>

<details>
<summary><b>Как AgenticOS удерживает агентов под контролем?</b></summary>

Месячные бюджеты агента и организации проверяются перед каждым запросом к модели. Чувствительные инструменты ждут одобрения человека. Необязательные защитные проверки скрывают секреты и персональные данные, а каждый запуск записывается вместе с версией агента, инструментами, токенами и стоимостью. [Управление и контроль](https://vstorm-co.github.io/agenticos/ru/governance/)

</details>

<details>
<summary><b>Чем он отличается от ChatGPT Enterprise, Copilot Studio или n8n?</b></summary>

AgenticOS работает на вашей инфраструктуре с любым из 28 провайдеров моделей и не берёт собственной платы за рабочие места или кредиты. Он создаёт агентов для организации, опубликованных в чатах, на сайтах и в API, а не места ассистента для отдельных сотрудников. В отличие от n8n он начинается с агента, а не с канвы сценария, и многие команды используют оба. Руководства также описывают самостоятельно размещаемый конструктор [Dify](https://vstorm-co.github.io/agenticos/ru/about/dify/) и агентов для работы с кодом вроде Claude Code. [Сравнения](https://vstorm-co.github.io/agenticos/ru/about/comparison/)

</details>

<details>
<summary><b>Что нужно, чтобы его запустить?</b></summary>

Docker Compose на одном хосте. Достаточно машины с 4 vCPU и 8 ГБ ОЗУ, а два воркера API подойдут для команды из десяти человек. Кто-то должен отвечать за обновления, резервные копии (включая ключ хранилища секретов), доступ и подключённые внешние сервисы. [Развёртывание](https://vstorm-co.github.io/agenticos/ru/deploy/) · [Внедрение](https://vstorm-co.github.io/agenticos/ru/rollout/)

</details>
